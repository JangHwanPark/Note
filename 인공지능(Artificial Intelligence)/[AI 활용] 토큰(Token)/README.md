## 토큰이란 ?
- LLM이 글을 읽고 쓰는 최소 단위. 모델은 글을 토큰으로 잘라 숫자로 바꾼 뒤 처리한다
- 모델이 한 번에 볼 수 있는 양(컨텍스트 창, Context Window)과 요금이 모두 토큰 수로 정해진다
- 그래서 AI를 활용할 때는 무엇을 넣을지와 함께 얼마나 넣을지도 설계해야 한다
- 토큰의 사전적 의미와 기본 개념은 [인공지능](../README.md) 노트에 있다. 이 문서는 실제로 쓸 때 알아야 할 내용을 다룬다

<br/>

## 글은 어떻게 토큰으로 잘릴까
### 토큰화 (Tokenization)
글을 토큰으로 자르는 일을 토큰화라 하고, 자르는 규칙을 가진 프로그램을 토크나이저(Tokenizer)라 한다. 토크나이저는 회사와 모델 세대에 따라 다르다. 그래서 같은 글이라도 어느 모델에 넣느냐에 따라 토큰 수가 달라질 수 있다.
tiktoken 같은 토크나이저는 글에서 자주 붙어 나오는 조각을 하나로 합쳐 조각 사전을 만들어 둔다(BPE, Byte Pair Encoding, 참고 자료 3). 그래서 자주 쓰는 단어는 통째로 한 조각이 되고, 드문 단어는 여러 조각으로 나뉜다.

### 직접 세어 보기
아래는 OpenAI의 토크나이저 라이브러리 tiktoken(0.14.0, 참고 자료 3)의 `o200k_base` 인코딩으로 실제로 세어 본 결과다. Claude의 토크나이저는 공개되어 있지 않아 같은 결과를 기대할 수는 없다. 여기서는 공개된 토크나이저로 토큰이 잘리는 일반적인 모습만 본다.

```python
import tiktoken
enc = tiktoken.get_encoding("o200k_base")
enc.encode("Hello, how are you today?")
```

| 입력 | 글자 수 | 토큰 수 | 잘린 모양 |
| --- | --- | --- | --- |
| `Hello, how are you today?` | 25 | 7 | `Hello` `,` ` how` ` are` ` you` ` today` `?` |
| `안녕하세요, 오늘 기분이 어떠세요?` | 19 | 11 | `안` `녕하세요` `,` ` 오늘` ` 기` `분` `이` (어떠의 일부) (나머지) `세요` `?` |
| `tokenization` | 12 | 2 | `token` `ization` |
| `토큰화` | 3 | 3 | `토` `큰` `화` |

결과에서 세 가지를 볼 수 있다.

- 영어는 자주 쓰는 단어가 앞의 공백까지 합쳐 토큰 하나가 된다
- 한국어는 토큰 하나에 담기는 글자 수가 영어의 절반 정도였다. 영어 문장은 25글자가 7토큰(약 3.6글자당 1토큰), 한국어 문장은 19글자가 11토큰(약 1.7글자당 1토큰)이다. 그래서 같은 뜻의 문장도 영어보다 토큰이 많이 들 수 있다
- 토큰은 글자보다 잘게 잘리기도 한다. 한글 한 글자는 컴퓨터 안에서 바이트 3개로 저장되는데(UTF-8), `어떠` 는 이 바이트 중간에서 잘려 토큰 하나만 떼어 보면 깨진 글자로 보인다

### 같은 회사 모델 사이에서도 달라진다
Anthropic 문서에 따르면 Claude Opus 4.7부터 새 토크나이저를 써서, 같은 글이 이전 모델보다 토큰이 약 30% 더 나온다. 정확한 증가 폭은 내용에 따라 다르다(참고 자료 1). 그래서 모델을 바꿀 때는 이전 모델에서 잰 토큰 수를 다시 쓰지 말고, 쓸 모델로 다시 세라고 안내한다.

## 컨텍스트 창 (Context Window)
### 정의
window는 창문이다. 창문 크기만큼만 바깥이 보이듯, 모델이 답을 만들 때 한 번에 볼 수 있는 범위를 컨텍스트 창이라 한다.
Anthropic 문서는 컨텍스트 창을 모델이 답을 만들 때 참고할 수 있는 모든 글이며 답 자체도 포함한다고 정의하고, 학습 데이터와 달리 모델의 작업 기억(working memory)에 해당한다고 설명한다(참고 자료 2).

### 무엇이 들어갈까
문서에 따르면 요청에 담긴 모든 것이 컨텍스트 창을 차지한다(참고 자료 2).

- 시스템 프롬프트
- 지금까지 주고받은 모든 메시지. 도구 실행 결과, 이미지, 문서도 포함한다
- 도구 정의
- 모델이 이번에 만드는 답. 답하기 전에 거치는 확장 사고(Extended Thinking) 토큰도 포함한다

대화가 길어지면 이전 대화가 계속 쌓이므로, 같은 질문이라도 대화 뒤쪽에서 할수록 더 많은 토큰을 쓴다.

### 넘치면 어떻게 될까
입력만으로 컨텍스트 창을 넘으면 API는 `prompt is too long` 오류를 돌려준다(참고 자료 2). 크기는 모델마다 다르고, 2026-10-21 기준 문서에는 Claude Opus 4.6, Claude Sonnet 4.6, Claude Haiku 5.5 이후의 최신 모델들이 100만 토큰, Claude Sonnet 4.5를 비롯한 그 밖의 모델이 20만 토큰으로 적혀 있다.

### 크다고 다 좋은 것은 아니다
문서는 컨텍스트가 클수록 더 길고 복잡한 프롬프트를 다룰 수 있지만, 많이 넣는다고 자동으로 좋아지지는 않는다고 말한다. 토큰이 늘수록 정확도와 기억해 내는 능력이 떨어지고, 문서는 이를 컨텍스트 부패(Context Rot)라고 부른다(참고 자료 2, 용어 뜻은 [컨텍스트 엔지니어링](../%5BAI%20활용%5D%20컨텍스트%20엔지니어링(Context%20Engineering)/README.md) 참고). 그래서 얼마나 넣을 수 있는지만큼 무엇을 넣을지 고르는 일이 중요하다. 이 고르는 일이 [컨텍스트 엔지니어링](../%5BAI%20활용%5D%20컨텍스트%20엔지니어링(Context%20Engineering)/README.md)이다.

<br/>

## 토큰은 요금이다
API 요금은 입력 토큰과 출력 토큰을 따로 세어 매긴다. 확장 사고 토큰도 출력 토큰으로 요금이 붙는다(참고 자료 2). 2026-10-21에 가격 문서를 확인했을 때 기본 단가 표에서는 모든 Claude 모델의 출력 단가가 입력 단가의 5배였다. 예를 들어 Claude Sonnet 4.6은 100만 토큰당 입력 3달러, 출력 15달러다(참고 자료 4). 단가는 자주 바뀌므로 쓸 때마다 가격 문서에서 다시 확인한다.

### 보내기 전에 세어 보기
Anthropic API에는 메시지를 보내기 전에 토큰 수를 세어 주는 기능이 있다(참고 자료 1). 보낼 요청과 같은 형식으로 보내면 입력 토큰 수를 돌려준다. 아래는 문서에 나온 예시와 그 결과다.

```bash
curl https://api.anthropic.com/v1/messages/count_tokens \
  -H "x-api-key: $ANTHROPIC_API_KEY" \
  -H "content-type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "claude-opus-5-5",
    "system": "You are a scientist",
    "messages": [{"role": "user", "content": "Hello, Claude"}]
  }'
```

```json
{ "input_tokens": 14 }
```

문서에 따르면 이 기능은 무료(분당 요청 수 제한은 있음)이고, 돌려주는 값은 추정치라 실제 사용량과 조금 다를 수 있다(참고 자료 1). 같은 문서의 다른 예시에서는 날씨를 묻는 짧은 질문에 도구 정의 하나를 함께 보내자 403토큰, 이미지 하나와 짧은 질문을 보내자 1028토큰이 나왔다. 도구 정의와 이미지는 그 자체로 토큰을 많이 차지한다.
이 예시는 API 키가 필요해서 직접 실행하지는 않았다. 결과 값은 문서에 적힌 것이다.

## 토큰을 아끼는 방법
- 필요한 자료만 넣는다. 파일 전체 대신 관련 함수만, 로그 전체 대신 오류 앞뒤만 붙인다
- 긴 대화는 정리하고 새로 시작한다. 이전 대화가 계속 입력으로 다시 들어가기 때문이다. 대화를 요약해 이어 가는 방법은 [컨텍스트 엔지니어링](../%5BAI%20활용%5D%20컨텍스트%20엔지니어링(Context%20Engineering)/README.md)의 압축(Compaction)에 있다
- 자주 반복되는 앞부분(시스템 프롬프트, 긴 문서)은 프롬프트 캐싱(Prompt Caching)을 쓴다. cache의 사전적 의미는 물건을 숨겨 두는 곳, 저장소다. 프롬프트 캐싱은 반복되는 앞부분을 저장해 두고 다음 요청에서 다시 쓰는 기능이다. 가격 문서 기준 캐시에서 읽은 토큰은 입력 단가의 10분의 1 이하(모델에 따라 20분의 1, 40분의 1)로 매겨지지만, 처음 캐시에 쓸 때는 입력 단가보다 비싸다. 5분 캐시는 1.25배, 1시간 캐시는 2배다(참고 자료 4). 그래서 여러 번 다시 쓰는 앞부분에만 이득이다. 캐시한 토큰도 컨텍스트 창은 그대로 차지한다(참고 자료 2)
- 답의 길이도 정해 준다. 출력도 토큰이고, 위에서 본 것처럼 출력 단가가 입력보다 비싸다

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 토큰 (Token) | 표, 상징 | 모델이 글을 읽는 조각 하나 |
| 토큰화 (Tokenization) | 토큰으로 만들기 | 글을 토큰으로 자르는 일 |
| 토크나이저 (Tokenizer) | 토큰으로 만드는 것 | 글을 자르는 규칙을 가진 프로그램. 모델마다 다르다 |
| 컨텍스트 창 (Context Window) | 맥락을 보는 창문 | 모델이 한 번에 볼 수 있는 토큰의 범위 |
| 컨텍스트 부패 (Context Rot) | 맥락이 썩음 | 넣은 토큰이 많을수록 정확도가 떨어지는 현상 |
| 프롬프트 캐싱 (Prompt Caching) | 캐시: 숨겨 둔 저장소 | 반복되는 앞부분을 저장해 두고 다시 쓰는 기능 |
