## 스펙 주도 개발과 바이브 코딩이란 ?
- AI에게 코드를 맡길 때의 정반대 두 태도
- 바이브 코딩은 코드를 자세히 읽지 않고 AI가 내놓은 변경을 그대로 받아들이며 느낌대로 만들어 간다
- 스펙 주도 개발은 요구 사항과 완료 조건을 문서로 먼저 쓰고 에이전트가 그 문서를 기준으로 구현하고 검증하게 한다
- 에이전트는 도구를 쓰며 여러 단계를 스스로 진행하는 AI를 말한다([워크플로와 에이전트](../%5BAI%20활용%5D%20워크플로와%20에이전트(Workflow%20and%20Agent)/README.md) 참고)
- 전체 흐름은 [AI 활용 방법](../%5BAI%20활용%5D%20AI%20활용%20방법(AI%20Usage%20Methods)/README.md) 문서에 있다
- 원문의 예와 이 레포에서 스펙 주도 개발의 단계가 어떻게 나타나는지는 [스펙 주도 개발과 바이브 코딩 예시](./예시(Examples)/README.md)에 모았다

<br/>

## 바이브 코딩 (Vibe Coding)
### 정의
Vibe의 사전적 의미는 분위기, 느낌이다.
안드레이 카파시(Andrej Karpathy)가 2025년 2월에 쓴 말이다(참고 자료 1). 느낌대로 만든다는 이름 그대로, 결과가 돌아가는지만 보고 코드는 들여다보지 않는다.

### 쓸 때와 피할 때
빠르게 무언가를 만들어 볼 수 있다는 것이 장점이다. 마틴 파울러(Martin Fowler)는 이렇게 만든 소프트웨어가 유지보수성, 정확성, 보안에서 문제를 보이기 쉬워 적은 사람이 쓰고 버릴 소프트웨어에 알맞다고 했다(참고 자료 1).
시제품이나 혼자 쓰는 도구라면 괜찮지만, 다른 사람이 쓰고 오래 고쳐 나갈 코드라면 위험하다.

<br/>

## 스펙 주도 개발 (Spec-driven Development)
### 정의
Spec은 Specification의 줄임말로 사전적 의미는 명세, 자세히 적은 설명서다.
코드를 바로 시키지 않고 요구 사항, 완료 조건, 설계, 작업 목록을 문서로 먼저 쓰고, 에이전트가 그 문서를 기준으로 구현하고 검증하게 하는 방식이다.

### 왜 필요할까
에이전트는 말한 것은 하지만 말하지 않은 것은 짐작으로 채운다. 짐작이 틀리면 엉뚱한 코드가 나온다. GitHub은 2025년 9월 이 방식을 돕는 오픈소스 도구 Spec Kit을 공개하며, 에이전트를 검색 엔진처럼 대하지 말고 말을 글자 그대로 받아들이는 페어 프로그래머(Pair Programmer, 한 화면을 보며 함께 코드를 쓰는 짝)처럼 대하라고 했다(참고 자료 2). 글자 그대로 받아들이는 상대에게는 빠짐없이 적힌 문서가 필요하다.

### 어떻게 할까
1. 무엇을 만들지, 언제 다 된 것으로 볼지 요구 사항과 완료 조건을 쓴다
2. 어떤 구조로 만들지 설계를 쓴다
3. 작업을 작은 단위로 나눈다
4. 에이전트가 작업마다 구현하고, 완료 조건으로 스스로 검증한다

집을 지을 때 설계도부터 그리는 것과 같다. 설계도가 있으면 누가 지어도 같은 집이 나오고, 다 지은 뒤 설계도와 대조해 검수할 수 있다.

<br/>

## 둘을 견주어 보면
바이브 코딩은 빠르지만 결과를 아무도 이해하지 못할 수 있고, 스펙 주도 개발은 느리게 시작하지만 결과를 문서와 대조해 확인할 수 있다. [하네스 엔지니어링](../%5BAI%20활용%5D%20하네스%20엔지니어링(Harness%20Engineering)/README.md)과 [루프 엔지니어링](../%5BAI%20활용%5D%20루프%20엔지니어링(Loop%20Engineering)/README.md)도 스펙 주도 개발처럼 바이브 코딩의 불안정함을 줄이려는 시도로 볼 수 있다.

<br/>

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 바이브 코딩 (Vibe Coding) | 바이브: 분위기, 느낌 | 코드를 안 읽고 AI 결과를 그대로 받아들이는 방식 |
| 스펙 (Spec) | 명세, 설명서 | 구현 전에 먼저 쓰는 요구 사항 문서 |
| 스펙 주도 개발 (Spec-driven Development) | 명세가 이끄는 개발 | 문서를 먼저 쓰고 그 문서로 구현과 검증을 하는 방식 |
| 페어 프로그래머 (Pair Programmer) | 짝 프로그래머 | 한 화면을 보며 함께 코드를 쓰는 짝 |
