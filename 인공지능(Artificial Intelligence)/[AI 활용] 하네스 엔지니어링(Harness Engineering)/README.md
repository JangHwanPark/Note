## 하네스 엔지니어링이란 ?
- AI 모델을 둘러싼 실행 환경(지시 파일, 도구, 권한, 테스트와 자동 검사)을 고쳐서 AI가 안정적으로 일하게 만드는 기법
- 에이전트가 실수할 때마다 다시는 같은 실수를 하지 않도록 장치를 만들어 두는 것이 핵심이다
- 에이전트는 도구를 쓰며 여러 단계를 스스로 진행하는 AI를 말한다([워크플로와 에이전트](../%5BAI%20활용%5D%20워크플로와%20에이전트(Workflow%20and%20Agent)/README.md) 참고)
- 전체 흐름은 [AI 활용 방법](../%5BAI%20활용%5D%20AI%20활용%20방법(AI%20Usage%20Methods)/README.md) 문서에 있다

### 하네스 (Harness)
사전적 의미는 말에 채우는 마구, 또는 몸에 매는 안전띠다. 말의 힘이 아무리 세도 마구가 없으면 수레를 원하는 방향으로 끌게 할 수 없다. 마구는 힘을 쓸모 있는 방향으로 묶어 주는 장비다.
소프트웨어에서는 원래 시험할 코드를 감싸 실행하고 결과를 확인하는 틀을 테스트 하네스(Test Harness)라고 불렀다. AI에서 하네스는 이 뜻이 넓어져 모델을 둘러싼 실행 환경 전체를 말한다. 모델이 말이라면 하네스는 마구다.

### 말이 생긴 배경
하네스 엔지니어링이라는 이름은 HashiCorp 공동 창업자 미첼 하시모토(Mitchell Hashimoto)가 2026년 2월 5일 글 "My AI Adoption Journey"에서 자기는 이렇게 부르게 되었다고 쓰면서 알려졌다. 그는 에이전트가 실수할 때마다 다시는 같은 실수를 하지 않도록 해결책을 만들어 두는 것을 하네스 엔지니어링이라고 설명했다(참고 자료 1). 엿새 뒤인 2월 11일 OpenAI도 사람이 직접 쓴 코드 없이 Codex로 제품을 만든 경험을 같은 이름의 글로 공개했다(참고 자료 2).

<br/>

## 왜 필요할까
프롬프트로 "테스트를 꼭 돌려"라고 매번 말해도 AI는 가끔 빠뜨린다. 말로 하는 부탁은 지켜질 수도 있고 아닐 수도 있다. 하네스는 부탁을 장치로 바꾼다. 테스트가 실패하면 다음 단계로 못 넘어가게 막는 식이다.

신입 사원에게 "꼼꼼히 해"라고 말하는 대신 업무 매뉴얼, 검수 체크리스트, 자동 검사기를 주는 것과 같다. 말은 잊어도 체크리스트는 남는다.

<br/>

## 무엇으로 이루어질까
하시모토는 하네스를 두 가지로 나눴다. 하나는 AGENTS.md 같은 지시 파일을 고쳐 나쁜 행동을 반복하지 않게 하는 것이고, 다른 하나는 스크린샷 스크립트나 일부만 돌리는 테스트처럼 에이전트가 스스로 결과를 확인할 수 있는 도구를 만들어 주는 것이다(참고 자료 1). 실제 도구에서 쓰이는 장치는 아래와 같다.

### 지시 파일
프로젝트 규칙과 금지 사항을 적어 두면 에이전트가 작업할 때마다 읽는다. Codex는 AGENTS.md, Claude Code는 CLAUDE.md를 쓴다.

### 도구 연결, MCP
에이전트가 DB, 이슈 트래커, 브라우저 같은 바깥 시스템을 쓰게 한다.
Protocol의 사전적 의미는 외교 의례, 지켜야 할 절차이고, 통신에서는 주고받는 방식의 약속을 말한다. Anthropic이 2024년 11월 25일 공개한 모델 컨텍스트 프로토콜(Model Context Protocol, MCP)은 AI와 바깥 도구가 주고받는 방식을 표준으로 정한 약속이다(참고 자료 3). 기기마다 충전기가 달랐던 것을 한 가지 단자로 맞춘 것과 비슷하다.

### 스킬 (Skill)
사전적 의미는 솜씨, 숙련된 기술이다. 특정 작업의 절차와 참고 자료를 폴더 하나에 묶어 두고 필요할 때만 불러오게 한다. Anthropic은 2025년 10월 SKILL.md 파일을 중심으로 한 Agent Skills를 발표했다(참고 자료 4).

### 훅 (Hook)
사전적 의미는 갈고리다. 파일 수정, 명령 실행 같은 사건에 갈고리를 걸어 두고 그때마다 검사 스크립트를 자동으로 돌린다.

### 검증 장치
테스트, 린터(코드 규칙 위반을 자동으로 찾는 도구), 타입 검사, 리뷰 전용 에이전트처럼 결과가 맞는지 확인하는 장치다.

### 권한과 격리
에이전트가 할 수 있는 일을 제한하고, 위험한 작업은 사람 승인을 받게 한다.

<br/>

## 이 레포의 예
이 노트 레포에도 하네스가 있다. 노트 형식은 지시 파일과 글쓰기 가이드에 적어 두었고, 노트 작성 절차는 스킬로 묶었다. 금지 문자는 파일을 쓸 때마다 훅이 검사하고, 깨진 링크는 점검 스크립트가, 내용은 리뷰 전용 에이전트가 확인한다.

상위 폴더의 [인공지능](../README.md) 노트를 처음 쓸 때도 리뷰 에이전트가 커밋 전에 오류를 찾아냈다. 약한 AI(Weak AI)를 Narrow AI의 번역어로 소개했는데, 약한 AI는 원래 철학에서 나온 다른 개념이었다. 실수가 나올 때마다 이 장치를 고쳐 나가는 것이 하시모토가 말한 하네스 엔지니어링이다.

<br/>

## 한계
하네스는 AI가 일하는 작업장을 갖춰 줄 뿐, 언제 어떤 일을 시킬지는 여전히 사람이 정한다. 사람이 매번 지시하는 왕복까지 시스템에 넘기는 것은 [루프 엔지니어링](../%5BAI%20활용%5D%20루프%20엔지니어링(Loop%20Engineering)/README.md)이 다룬다.

<br/>

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 하네스 (Harness) | 마구, 안전띠 | 모델을 둘러싼 지시 파일, 도구, 검사 장치 전체 |
| 테스트 하네스 (Test Harness) | 시험용 마구 | 시험할 코드를 감싸 실행하고 결과를 확인하는 틀 |
| 모델 컨텍스트 프로토콜 (MCP) | 프로토콜: 의례, 지켜야 할 절차 | AI와 바깥 도구를 잇는 표준 약속 |
| 스킬 (Skill) | 솜씨, 숙련된 기술 | 특정 작업 절차를 묶어 필요할 때 불러오는 폴더 |
| 훅 (Hook) | 갈고리 | 특정 사건마다 자동으로 도는 검사 |
| 린터 (Linter) | 보푸라기(lint)를 떼어 내는 것 | 코드 규칙 위반을 자동으로 찾는 도구 |
