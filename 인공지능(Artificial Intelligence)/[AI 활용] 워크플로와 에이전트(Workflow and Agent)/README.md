## 워크플로와 에이전트란 ?
- LLM과 도구를 엮어 일을 시키는 두 가지 구조
- 워크플로는 미리 정해 둔 순서를 따르고, 에이전트는 LLM이 스스로 순서와 도구를 정한다
- Anthropic은 둘을 묶어 에이전트 시스템(Agentic System)이라고 부르고, 가장 단순한 방법부터 쓰라고 권한다(참고 자료 1)
- 전체 흐름은 [AI 활용 방법](../%5BAI%20활용%5D%20AI%20활용%20방법(AI%20Usage%20Methods)/README.md) 문서에 있다
- 패턴마다 원문이 든 쓰임새와, 이 레포에서 쓰는 예 또는 설명을 위해 만든 예는 [워크플로와 에이전트 예시](./예시(Examples)/README.md)에 모았다

### 워크플로 (Workflow)
Work는 일, Flow는 흐름이다. 일이 흘러가는 순서를 말한다.
공학적으로는 LLM과 도구가 미리 정해 둔 코드 경로를 따라 움직이는 시스템이다(참고 자료 1). 어떤 단계 다음에 어떤 단계가 올지 사람이 코드로 정해 둔다.

### 에이전트 (Agent)
사전적 의미는 대리인이다. 남을 대신해 일을 처리하는 사람을 말한다.
공학적으로는 LLM이 스스로 진행 순서와 도구 사용을 정하는 시스템이다(참고 자료 1). 목표만 받고, 무엇을 먼저 할지, 어떤 도구를 쓸지, 언제 끝낼지를 모델이 판단한다.

<br/>

## 버스와 택시로 이해하기
워크플로는 정해진 노선을 달리는 버스다. 어디서 서고 어디로 갈지 미리 정해져 있어서 예측하기 쉽지만, 노선 밖으로는 가지 못한다.
에이전트는 목적지만 듣고 길을 고르는 택시다. 막힌 길을 돌아가는 식으로 상황에 맞춰 움직이지만, 어느 길로 갈지 미리 알 수 없고 요금도 더 나올 수 있다.

<br/>

## 언제 무엇을 쓸까
Anthropic은 가장 단순한 방법부터 찾고, 필요할 때만 복잡도를 올리라고 권한다. 에이전트 시스템은 더 나은 성능을 얻는 대신 시간과 비용을 더 쓰는 경우가 많기 때문이다(참고 자료 1).

- 단계가 분명하고 매번 같은 결과가 나와야 하는 일에는 워크플로가 맞다
- 단계를 미리 정할 수 없고 상황에 따라 판단해야 하는 일에는 에이전트가 맞다
- 프롬프트 한 번으로 되는 일이라면 둘 다 필요 없다

에이전트나 [루프](../%5BAI%20활용%5D%20루프%20엔지니어링(Loop%20Engineering)/README.md)가 늘 정답은 아니라는 뜻이다.

<br/>

## 워크플로 패턴 다섯 가지
Anthropic은 자주 쓰는 워크플로를 다섯 가지로 정리했다(참고 자료 1).

### 프롬프트 체이닝 (Prompt Chaining)
Chain의 사전적 의미는 사슬이다. 일을 단계로 나누고 앞 단계 결과를 다음 단계 입력으로 넘긴다. 글 개요 쓰기, 개요 검토하기, 본문 쓰기를 차례로 하는 식이다. [프롬프트 엔지니어링](../%5BAI%20활용%5D%20프롬프트%20엔지니어링(Prompt%20Engineering)/README.md)에서 본 프롬프트 체이닝과 같은 것이다.

### 라우팅 (Routing)
Route의 사전적 의미는 길, 경로다. 입력 종류를 먼저 가려서 알맞은 처리로 보낸다. 고객 문의를 환불, 기술 지원, 일반 문의로 나눠 각각 다른 프롬프트로 보내는 식이다.

### 병렬화 (Parallelization)
Parallel의 사전적 의미는 나란한이다. 여러 일을 동시에 돌리거나, 같은 일을 여러 번 돌려 결과를 모은다.

### 오케스트레이터-워커 (Orchestrator-workers)
Orchestrator는 관현악을 편곡하고 지휘하는 사람이다. 지휘하는 호출이 일을 나눠 여러 일꾼(Worker) 호출에게 맡기고 결과를 모은다. 다섯 가지 중 에이전트에 가장 가깝다.

### 평가자-최적화 (Evaluator-optimizer)
Evaluate는 평가하다, Optimize는 가장 좋게 만들다이다. 한 번의 호출이 답을 만들고 다른 호출이 평가해 고치게 하는 과정을 반복한다. 글쓴이와 편집자가 원고를 주고받는 것과 같다.

<br/>

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 워크플로 (Workflow) | 일의 흐름 | 정해진 순서대로 AI와 도구가 움직이는 구조 |
| 에이전트 (Agent) | 대리인 | 스스로 순서와 도구를 정해 일하는 AI |
| 프롬프트 체이닝 (Prompt Chaining) | 체인: 사슬 | 단계를 나눠 앞 결과를 다음에 넘기기 |
| 라우팅 (Routing) | 길을 정함 | 입력 종류에 따라 다른 처리로 보내기 |
| 병렬화 (Parallelization) | 나란히 놓음 | 여러 일을 동시에 돌리기 |
| 오케스트레이터-워커 (Orchestrator-workers) | 지휘자와 일꾼 | 일을 나눠 맡기고 결과를 모으기 |
| 평가자-최적화 (Evaluator-optimizer) | 평가하는 쪽과 가장 좋게 만드는 쪽 | 만들고 평가하고 고치기를 반복하기 |
