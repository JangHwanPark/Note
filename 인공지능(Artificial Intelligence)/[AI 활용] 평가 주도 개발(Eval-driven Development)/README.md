## 평가 주도 개발이란 ?
- 평가 문제 묶음과 채점 기준을 먼저 만들고, 프롬프트나 모델을 바꿀 때마다 같은 평가를 돌려 점수로 판단하는 방식
- 테스트 주도 개발(Test-Driven Development, TDD), 즉 코드보다 테스트를 먼저 쓰는 방식을 LLM에 옮겨 온 것이다
- 전체 흐름은 [AI 활용 방법](../%5BAI%20활용%5D%20AI%20활용%20방법(AI%20Usage%20Methods)/README.md) 문서에 있다
- 원문의 예와 이 레포의 문체 검사 훅을 실제로 평가해 본 예는 [평가 주도 개발 예시](./예시(Examples)/README.md)에 모았다

### 평가 (Evaluation, Eval)
사전적 의미는 평가, 값어치를 따져 매기는 일이다.
LLM 분야에서는 Evaluation을 줄여 Eval이라고 부르고, 정해 둔 입력 묶음을 모델에 넣어 정해 둔 기준으로 채점하는 시험을 말한다. 이 노트에서는 평가로 쓴다.

<br/>

## 왜 필요할까
LLM은 같은 입력에도 답이 조금씩 달라서, 한두 번 써 보고 괜찮다고 판단하기 어렵다. 프롬프트를 고쳤더니 한 질문은 좋아졌는데 다른 질문은 나빠지는 일도 흔하다. 눈으로 몇 개만 보고 판단하면 이런 변화를 놓친다.

요리사가 새 레시피를 맛볼 때 한 숟가락만 먹고 판단하지 않고, 정해진 손님들에게 같은 기준표로 점수를 받는 것과 같다.

[프롬프트 엔지니어링](../%5BAI%20활용%5D%20프롬프트%20엔지니어링(Prompt%20Engineering)/README.md)에서 본 것처럼 Anthropic 문서도 프롬프트를 고치기 전에 무엇이 성공인지에 대한 기준과, 그 기준으로 결과를 실제로 재 볼 방법을 먼저 갖추라고 한다(참고 자료 1).

<br/>

## 어떻게 할까
1. 성공 기준을 정한다. 무엇이 좋은 답인지 말로 적는다
2. 평가 문제 묶음을 만든다. 실제로 들어올 법한 입력과 까다로운 입력을 모은다
3. 채점 방법을 정한다. 정답과 비교하거나, 규칙으로 검사하거나, 사람이나 다른 LLM이 채점한다
4. 프롬프트나 모델을 바꿀 때마다 같은 평가를 돌리고 점수를 비교한다

Braintrust는 이 방식에서 평가가 LLM 앱의 동작 명세 역할을 하고, 평가 점수가 프롬프트, 모델, 처리 과정을 바꿀 때 목표가 된다고 설명한다(참고 자료 2).

<br/>

## LLM 평가자 (LLM-as-a-Judge)
Judge의 사전적 의미는 판사, 심사위원이다.
채점을 다른 LLM에게 맡기는 방식이다. 요약이 잘 됐는지, 말투가 알맞은지처럼 정답 하나로 채점하기 어려운 결과에 쓴다. 2023년 논문에서 강한 LLM의 판단이 사람의 판단과 상당히 일치한다고 보고했다(참고 자료 3). 다만 채점하는 LLM도 틀릴 수 있어서, 사람이 일부를 다시 보며 채점 기준을 맞춰 나가야 한다.

<br/>

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 평가 주도 개발 (Eval-driven Development) | 평가: 값어치를 따져 매김 | 채점 기준을 먼저 만들고 바꿀 때마다 점수로 판단하기 |
| 평가 (Eval) | 값어치를 따져 매김 | 정해 둔 문제와 기준으로 AI 결과를 채점하는 시험 |
| 테스트 주도 개발 (TDD) | 시험이 이끄는 개발 | 코드보다 테스트를 먼저 쓰는 방식 |
| LLM 평가자 (LLM-as-a-Judge) | 판사, 심사위원 노릇을 하는 LLM | 채점을 다른 LLM에게 맡기기 |
