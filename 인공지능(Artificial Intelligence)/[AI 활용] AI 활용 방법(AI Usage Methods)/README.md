## AI 활용 방법이란 ?
- 거대 언어 모델(LLM)에게 일을 맡겨 원하는 결과를 안정적으로 얻기 위한 방법들
- 처음에는 질문 문장을 잘 쓰는 프롬프트 엔지니어링에서 시작했고, 모델에게 줄 정보를 고르는 컨텍스트 엔지니어링, 모델을 둘러싼 도구와 검증 장치를 만드는 하네스 엔지니어링, 사람 대신 시스템이 AI를 계속 돌리게 하는 루프 엔지니어링으로 범위가 넓어졌다
- 이 문서는 전체 흐름만 잡고, 기법마다 자세한 내용은 아래 주제별 문서에 나눠 썼다
- LLM, 토큰, 프롬프트, 추론, 환각 같은 기본 용어는 [인공지능](../README.md) 노트에 정리했다

### 활용 (Utilization)
사전적 의미는 충분히 잘 이용함이다. 가진 것을 그냥 쓰는 데 그치지 않고 쓸모를 최대한 끌어낸다는 뜻이다.
AI에서 활용이라고 하면 모델 자체를 새로 만들거나 고치는 일이 아니라, 이미 만들어진 모델에게 무엇을 어떻게 맡길지 설계하는 일을 말한다. 같은 모델을 써도 맡기는 방식에 따라 결과가 크게 달라지기 때문에 맡기는 방법 자체를 따로 연구한다.

### 엔지니어링 (Engineering)
사전적 의미는 공학, 즉 과학 지식을 써서 쓸모 있는 것을 설계하고 만드는 일이다.
기법 이름 끝에 엔지니어링이 붙는 것은 감에 기대지 않고 원인을 찾고, 고치고, 다시 재 보는 공학적 방식으로 AI를 다루자는 뜻으로 읽을 수 있다.

### 에이전트 (Agent)
사전적 의미는 대리인이다. 남을 대신해 일을 처리하는 사람을 말한다.
여기서는 사람이 한 번 질문하고 답을 받는 데서 끝나지 않고, 도구를 쓰며 여러 단계를 스스로 진행하는 AI를 말한다. 주제별 문서 대부분이 에이전트를 전제로 하므로 먼저 짚어 둔다. 미리 정한 순서를 따르는 워크플로와의 차이는 [워크플로와 에이전트](../%5BAI%20활용%5D%20워크플로와%20에이전트(Workflow%20and%20Agent)/README.md) 문서에서 다룬다.

## 신입 사원에게 일 맡기기로 이해하기
네 가지 엔지니어링은 새로 온 신입 사원에게 일을 맡기는 과정으로 비유하면 차이가 잘 보인다. 이 사원은 아주 똑똑하지만 회사 사정은 하나도 모르고, 하루가 지나면 어제 일을 잊는다.

| 기법 | 신입 사원에게 하는 일 | AI에게 하는 일 |
| --- | --- | --- |
| 프롬프트 엔지니어링 | 지시를 분명하게 말한다 | 질문과 지시문을 잘 쓴다 |
| 컨텍스트 엔지니어링 | 일에 필요한 자료만 골라 책상에 올려 준다 | 모델이 볼 정보를 고르고 정리한다 |
| 하네스 엔지니어링 | 업무 매뉴얼, 도구, 검수 체크리스트를 갖춰 준다 | 지시 파일, 도구, 테스트, 자동 검사를 만든다 |
| 루프 엔지니어링 | 매일 아침 할 일을 받아 처리하고 검수받는 업무 절차를 만든다 | 사람이 말하지 않아도 AI가 일하고 검증받는 반복 구조를 만든다 |

뒤로 갈수록 한 번의 대화가 아니라 일하는 환경 전체를 설계하는 쪽으로 넓어진다. 2026년 8월 arXiv에 올라온 루프 엔지니어링 연구도 이 흐름을 프롬프트 문장 다듬기에서 컨텍스트 설계로, 다시 모델을 둘러싼 하네스 설정으로, 그리고 사람 대신 시스템이 프롬프트를 보내는 루프로 이어지는 단계로 설명한다(참고 자료 1).

뒤의 기법이 앞의 기법을 대신하는 것은 아니다. 하네스 안에도 프롬프트가 있고, 루프도 결국 컨텍스트를 관리해야 한다. 앞 단계를 잘해야 뒤 단계가 의미가 있다.

## 주제별 문서
네 가지 엔지니어링은 앞의 비유 순서대로 읽으면 된다.

1. [프롬프트 엔지니어링](../%5BAI%20활용%5D%20프롬프트%20엔지니어링(Prompt%20Engineering)/README.md): 지시문을 잘 쓰는 기법
2. [컨텍스트 엔지니어링](../%5BAI%20활용%5D%20컨텍스트%20엔지니어링(Context%20Engineering)/README.md): 모델이 볼 정보를 고르고 관리하는 기법, RAG 포함
3. [하네스 엔지니어링](../%5BAI%20활용%5D%20하네스%20엔지니어링(Harness%20Engineering)/README.md): 지시 파일, 도구, 훅, 검증 장치로 AI의 일하는 환경을 만드는 기법
4. [루프 엔지니어링](../%5BAI%20활용%5D%20루프%20엔지니어링(Loop%20Engineering)/README.md): 사람 대신 시스템이 AI를 일하게 하고 확인하는 반복 구조

함께 알아 두면 좋은 주제는 아래와 같다.

- [워크플로와 에이전트](../%5BAI%20활용%5D%20워크플로와%20에이전트(Workflow%20and%20Agent)/README.md): 정해진 순서로 움직이는 구조와 스스로 판단하는 구조의 차이
- [평가 주도 개발](../%5BAI%20활용%5D%20평가%20주도%20개발(Eval-driven%20Development)/README.md): 채점 기준을 먼저 만들고 점수로 판단하는 방법
- [스펙 주도 개발과 바이브 코딩](../%5BAI%20활용%5D%20스펙%20주도%20개발과%20바이브%20코딩(Spec-driven%20Development%20and%20Vibe%20Coding)/README.md): 문서부터 쓰는 방식과 느낌대로 받아들이는 방식

## 어디서부터 시작할까
1. 한 번 쓰고 끝나는 질문이라면 프롬프트를 구체적으로 쓰는 것으로 충분하다
2. 답이 엉뚱하다면 모델이 필요한 정보를 받았는지부터 본다(컨텍스트)
3. 같은 실수가 반복된다면 말로 부탁하지 말고 지시 파일, 훅, 테스트 같은 장치로 막는다(하네스)
4. 매번 같은 지시를 사람이 반복하고 있다면 그 반복을 시스템에 넘긴다(루프)
5. 어느 단계든 나아졌는지 판단할 기준과 평가가 먼저다([평가 주도 개발](../%5BAI%20활용%5D%20평가%20주도%20개발(Eval-driven%20Development)/README.md))

Anthropic이 권한 것처럼 가장 단순한 방법부터 쓰고, 그것으로 부족할 때만 다음 단계로 넘어간다(참고 자료 2).

<br/>

## 활용의 범위 밖: 파인튜닝 (Fine-tuning)
Fine은 섬세한, Tune은 조율하다이다. 악기 줄을 미세하게 맞추는 일을 떠올리면 된다.
이미 학습된 모델을 특정 데이터로 조금 더 학습시켜 모델 자체를 바꾸는 방법이다. 활용 기법들이 모델 바깥을 설계하는 일이라면 파인튜닝은 모델 안쪽(인공지능 노트에서 본 파라미터)을 고친다. 비용과 준비가 많이 들어서 흔히 권하는 순서는 프롬프트와 컨텍스트(RAG 포함, [컨텍스트 엔지니어링](../%5BAI%20활용%5D%20컨텍스트%20엔지니어링(Context%20Engineering)/README.md) 참고)로 먼저 해결해 보고 부족할 때 고려하는 것이다. 엄밀히는 이 노트에서 말한 활용의 범위 밖이지만, 언제 활용만으로 부족한지 가늠하려고 함께 적었다.

<br/>

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 활용 (Utilization) | 충분히 잘 이용함 | 만들어진 모델에게 일을 잘 맡기는 법 |
| 엔지니어링 (Engineering) | 공학 | 원인을 찾고 고치고 다시 재 보는 방식 |
| 에이전트 (Agent) | 대리인 | 도구를 쓰며 여러 단계를 스스로 진행하는 AI |
| 파인튜닝 (Fine-tuning) | 미세 조율 | 모델을 추가로 학습시켜 안쪽을 고치기 |

기법별 용어는 각 주제 문서 끝에 정리했다.
