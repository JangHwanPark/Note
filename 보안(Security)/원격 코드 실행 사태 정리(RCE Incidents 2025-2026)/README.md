## 먼저 알아둘 용어

### 원격 코드 실행 (Remote Code Execution, RCE)
원격(remote)은 멀리 떨어져 있다는 뜻이다. 공학적으로는 공격자가 서버 앞에 앉아 있지 않고 네트워크 요청만 보내서, 서버가 공격자의 코드를 실행하게 만드는 취약점을 말한다. 서버 권한으로 명령을 돌릴 수 있으므로 데이터 유출, 웹셸 설치, 내부망 이동까지 이어진다. 1장부터 3장까지의 사건에 붙은 2Shell이라는 별명도 요청 하나가 셸(shell) 실행으로 이어진다는 뜻에서 나왔다.

### 웹셸 (Web Shell)
셸은 명령을 받아 운영체제에 전달하는 프로그램이다. 웹셸은 웹 서버 경로에 심어 두고 브라우저 요청으로 명령을 실행하는 스크립트 파일이다. 원격 코드 실행에 한 번 성공한 공격자는 다음에도 쉽게 들어오려고 웹셸을 남기는 경우가 많다. 그래서 패치를 해도 이미 심어진 웹셸은 따로 찾아 지워야 한다.

### CVE, CVSS, KEV
- CVE(Common Vulnerabilities and Exposures)는 공개된 취약점마다 붙이는 공통 식별 번호다. `CVE-연도-번호` 형식이고, 같은 결함을 여러 회사가 같은 이름으로 부를 수 있게 해 준다
- CVSS(Common Vulnerability Scoring System)는 취약점의 심각도를 0.0부터 10.0까지로 매기는 기준이다. 인증이 필요한지, 네트워크로 닿는지, 영향이 얼마나 큰지를 따져 점수를 낸다. v3.1과 v4.0 점수가 따로 있어서 같은 CVE라도 출처마다 점수가 다를 수 있다
- KEV(Known Exploited Vulnerabilities)는 미국 CISA(사이버보안·인프라보안청)가 관리하는, 실제로 악용이 확인된 취약점 목록이다. 미국 연방 기관은 등재된 취약점을 정해진 기한 안에 고쳐야 한다. 점수가 높은 것과 실제로 공격받고 있다는 것은 다른 이야기라서, 우선순위를 정할 때 KEV 등재 여부를 따로 본다

### 제로데이 (Zero-day)
제작사가 취약점을 알고 고칠 시간이 0일이었다는 뜻이다. 패치가 나오기 전에 이미 공격에 쓰인 취약점을 말한다. 4장의 PeopleSoft 사건이 여기에 해당한다. 1장과 2장은 패치와 함께 공개된 뒤 하루에서 며칠 사이에 공격이 시작된 경우로, 이런 경우는 엔데이(N-day)라고 부른다. 3장의 PHP2Shell은 패치 전 악용 보도가 있으나 확인 필요다.

## 사건들의 공통점
언어도 제품도 다르지만 결함이 생긴 자리가 비슷하다. 모두 서버가 바깥에서 들어온 데이터를 해석하는 단계에서 터졌고, 상당수는 애플리케이션의 인증 검사보다 먼저 돈다. React는 요청 본문을 객체로 복원할 때, Node.js는 압축을 풀 때, PHP는 요청을 처리하고 정리할 때, PeopleSoft는 내부에서 온 요청이라고 믿을 때 문제가 생겼다. 그래서 개발자가 짠 인가 로직이 꼼꼼해도 막지 못하는 경우가 많았다.

1장부터 3장까지 세 사건은 공개에서 공격까지 걸린 시간이 짧았다. React2Shell은 공개 당일 공격이 관측됐고, Node2Shell은 패치 다섯 시간 만에 첫 공개 PoC 저장소가 올라왔다. 패치 내용(diff)이 공개되면 무엇이 고쳐졌는지 역으로 읽어 공격 코드를 만들 수 있기 때문이다. 패치를 미룬 시간이 곧 공격당할 수 있는 시간이 된다. 4장의 PeopleSoft는 아예 패치보다 공격이 먼저 왔다.

마지막으로 모든 사건에서 내가 무엇을 쓰고 있는지 아는 것이 대응의 첫 단계였다. Next.js가 React를, Express 5가 Brotli 해제를, Windows용 PHP가 Brotli를, PeopleSoft가 내부 허브 서비스를 품고 있는 식으로, 직접 설치하지 않은 구성 요소가 취약했다. 지원이 끝난 Node.js 20은 패치가 나오지 않았고, PHP 8.1 이하는 정식 릴리스 없이 소스 백포트만 제한적으로 나왔다.
