# 아이디어 노트

## 무엇을 다루나
- 만들어 보고 싶은 작은 도구와 실험을 하나씩 적어 두는 노트다
- 아이디어마다 무엇이 불편한지, 어떻게 만들지, 무엇이 위험한지, 아직 모르는 것이 무엇인지를 쓴다
- 바로 만들 수 있게 뼈대 코드를 붙이는 경우에는 실제로 돌려 본 결과만 적는다

## 1. 컴퓨터를 깔끔하게 정리하는 배치 파일

### 무엇이 문제인가
쓰다 보면 임시 폴더와 다운로드 폴더에 파일이 쌓인다. 다운로드 폴더는 한 번 받고 다시 열지 않는 설치 파일과 압축 파일이 대부분인데, 하나씩 골라 지우기 귀찮아서 그냥 둔다. 그러다 디스크가 차면 그제야 무엇을 지워도 되는지 하나씩 확인하게 된다.

정리할 대상과 규칙을 파일 하나에 적어 두고 실행하면, 매번 같은 판단을 다시 하지 않아도 된다. 이 아이디어는 그 파일을 Windows 배치 파일로 만드는 것이다.

### 배치 파일이란
배치(batch)의 사전적 의미는 한 번에 처리하는 한 묶음, 한 회분이다. 빵을 한 판 구울 때의 그 한 판에 가깝다.

공학적으로 배치 파일(Batch File)은 명령 프롬프트(cmd.exe)에서 칠 명령을 파일에 모아 두고 위에서부터 차례로 실행하게 한 스크립트다. 확장자는 `.bat` 이나 `.cmd` 다. 사람이 하나씩 치던 명령을 한 묶음으로 처리한다는 점에서 이름이 이어진다. 따로 설치할 것 없이 탐색기에서 두 번 누르거나 명령 프롬프트에서 이름을 쳐서 실행한다.

### 이미 있는 기능과 무엇이 다른가
Windows 11 설정에는 저장소 센스(Storage Sense)가 있어서 임시 파일, 휴지통, 다운로드 폴더의 오래된 파일을 정해 둔 주기로 지울 수 있다. 지우는 것만 원하면 이 기능으로 충분하다.

배치 파일로 따로 만들려는 이유는 두 가지다. 하나는 지우지 않고 한 폴더로 옮겨 두는 단계를 넣을 수 있다는 것이고, 다른 하나는 실행 전에 다운로드 폴더에서 옮길 파일 목록과 임시 폴더의 파일 수를 먼저 볼 수 있다는 것이다. 저장소 센스에 미리 보기가 있는지는 확인하지 못했다(확인 필요).

### 무엇을 정리할까
대상마다 지울지 옮길지를 다르게 정한다. 다시 받을 수 있거나 프로그램이 다시 만드는 것은 지우고, 내가 받은 파일은 옮긴다(내 판단).

| 대상 | 처리 | 명령 | 이번 뼈대에 넣었나 |
|---|---|---|---|
| 사용자 임시 폴더(`%TEMP%`) | 지운다 | `del`, `rd` | 넣었다 |
| 다운로드 폴더의 30일 넘은 파일 | `_오래된 파일` 폴더로 옮긴다 | `forfiles`, `robocopy` | 넣었다 |
| 휴지통 | 비운다 | PowerShell의 `Clear-RecycleBin -Force` | 뺐다. 시험하면 실제 휴지통이 비워져서 돌려 보지 못했다 |
| Windows 업데이트가 남긴 구성 요소 | 정리한다 | `Dism.exe /Online /Cleanup-Image /StartComponentCleanup` | 뺐다. 관리자 권한이 필요하다 |

DISM(Deployment Image Servicing and Management)은 Windows 이미지와 구성 요소를 관리하는 명령줄 도구다.

임시 폴더에는 지금 실행 중인 프로그램이 쓰는 파일도 있다. 그런 파일은 잠겨 있어 `del` 이 실패하고 넘어가므로, 지워지지 않은 파일이 남는 것이 정상이다.

### 하지 않을 것
- 레지스트리 정리. 얻는 공간은 거의 없고 잘못 지우면 프로그램이 망가진다(내 판단).
- `C:\Windows\Prefetch` 지우기. 프로그램 시작을 빠르게 하려고 Windows가 만드는 파일이라, 지우면 다음 실행이 오히려 느려질 수 있다고 알려져 있다(확인 필요).
- 브라우저 캐시 지우기. 브라우저가 켜져 있으면 파일이 잠겨 있고, 브라우저마다 경로가 다르다. 브라우저 자체 기능으로 지우는 편이 낫다(내 판단).

### 안전장치
정리 스크립트는 한 줄만 틀려도 지우면 안 되는 것을 지운다. 그래서 아래 네 가지를 먼저 정했다.

- 기본은 미리 보기다. 그냥 실행하면 대상만 보여 주고 키를 누를 때까지 기다린다. 실제로 지우고 옮기려면 명령 프롬프트에서 `clean.bat run` 처럼 `run` 을 붙인다.
- 임시 폴더 경로를 세 번 확인한다. `del /q /f /s "%TEMP%\*"` 에서 `TEMP` 가 비어 있으면 경로가 `\*` 가 되고, `/s` 때문에 현재 드라이브 루트 아래 파일 전체가 대상이 된다. `TEMP` 가 `C:\` 처럼 잘못 들어가 있어도 마찬가지다. 그래서 값이 비었거나, 폴더가 없거나, 경로가 `\Temp` 로 끝나지 않으면 멈춘다.
- 다운로드 폴더가 없으면 멈춘다. 시험할 때 다운로드 폴더를 바꾸는 변수는 `CLEAN_DL` 로 길게 지었다. `DL` 처럼 짧은 이름은 다른 프로그램이 이미 환경변수로 쓰고 있을 수 있다.
- 내 파일은 지우지 않고 옮긴다. 다운로드 폴더의 파일은 다운로드 폴더 안의 `_오래된 파일` 로 옮기고, 그곳에 같은 이름이 이미 있으면 옮기지 않는다. 잘못 옮겼으면 다시 꺼내면 되고, 확인한 뒤에 그 폴더만 직접 지운다.

### 뼈대
UTF-8(BOM 없음), 줄 끝 CRLF로 저장했다. `chcp 65001` 은 콘솔의 코드 페이지(code page)를 UTF-8로 바꿔 한글 안내 문구가 깨지지 않게 한다.

```bat
@echo off
chcp 65001 >nul
setlocal

rem 기본은 미리 보기다. 실제로 정리하려면 run 을 붙여 실행한다
set "MODE=%~1"
set "DAYS=30"
if not defined CLEAN_DL set "CLEAN_DL=%USERPROFILE%\Downloads"
set "ARCHIVE=%CLEAN_DL%\_오래된 파일"

rem TEMP 가 비었거나 엉뚱한 곳을 가리키면 아래 del 이 그 아래를 통째로 지운다
if not defined TEMP (
  echo TEMP 변수가 비어 있어 멈춘다
  exit /b 1
)
if not exist "%TEMP%\" (
  echo TEMP 폴더가 없어 멈춘다
  exit /b 1
)
echo %TEMP%| findstr /i /e "\\Temp" >nul || (
  echo TEMP 경로가 \Temp 로 끝나지 않아 멈춘다
  exit /b 1
)
if not exist "%CLEAN_DL%\" (
  echo 다운로드 폴더가 없어 멈춘다
  exit /b 1
)

echo [임시 폴더 파일 수] %TEMP%
dir /s /b /a-d "%TEMP%" 2>nul | find /c /v ""
echo [%DAYS%일 넘은 다운로드 파일] %CLEAN_DL%
forfiles /p "%CLEAN_DL%" /d -%DAYS% /c "cmd /c if @isdir==FALSE echo @path" 2>nul

if /i not "%MODE%"=="run" (
  echo 미리 보기만 했다. 정리하려면 명령 프롬프트에서 clean.bat run
  pause
  exit /b 0
)

del /q /f /s "%TEMP%\*" >nul 2>&1
for /d %%D in ("%TEMP%\*") do rd /s /q "%%D" 2>nul

rem 같은 이름이 이미 있으면 옮기지 않고 다운로드 폴더에 둔다
robocopy "%CLEAN_DL%" "%ARCHIVE%" /mov /minage:%DAYS% /xc /xn /xo /njh /njs /ndl /np
echo 정리했다
```

몇 줄은 따로 설명이 필요하다.

- `dir /s /b /a-d ... | find /c /v ""` 는 하위 폴더까지 파일만 나열한 뒤 줄 수를 센다. 임시 폴더는 파일이 많아서 목록 대신 개수만 보인다. 이 개수는 실제로 지워지는 수와 다르다. 숨김 파일과 정션 너머의 파일까지 세지만, 아래 `del` 은 둘 다 지우지 않는다(돌려 본 결과에 적었다).
- `echo %TEMP%| findstr /i /e "\\Temp"` 는 경로가 대소문자 구분 없이 `\Temp` 로 끝나는지 본다. `/e` 는 줄 끝에서 맞추라는 뜻이고, `\\` 는 정규식에서 역슬래시 하나다. `echo` 와 `|` 사이를 띄우면 그 공백까지 값에 들어가 끝이 맞지 않는다.
- `forfiles /d -30` 은 마지막으로 수정한 날짜가 30일 전이거나 그보다 오래된 항목을 고른다. 하위 폴더 안까지는 보지 않고, `@isdir==FALSE` 로 폴더는 건너뛴다. 미리 보기에만 쓴다.
- 실제로 옮길 때는 `robocopy` 를 쓴다. `/mov` 는 복사한 뒤 원본 파일을 지우고, `/minage:30` 은 30일보다 새 파일을 뺀다. `/xc /xn /xo` 는 대상 폴더에 같은 이름이 있으면 크기나 날짜가 다르더라도 건너뛰게 한다. `/s` 를 붙이지 않았으므로 다운로드 폴더 바로 아래 파일만 옮기고 `_오래된 파일` 안은 건드리지 않는다. 대상 폴더가 없으면 `robocopy` 가 만든다. 나머지 `/njh /njs /ndl /np` 는 머리말, 요약, 폴더 줄, 진행률을 빼서 옮긴 파일 줄만 남긴다.
- 처음에는 옮기기도 `forfiles` 안에서 `move` 로 했다. 그런데 `_오래된 파일` 에 같은 이름이 있으면 묻지 않고 덮어써서 먼저 옮겨 둔 파일이 사라졌다. 다운로드 폴더에서는 같은 이름의 파일을 몇 달 뒤 다시 받는 일이 흔해서 `robocopy` 로 바꿨다.
- `CLEAN_DL` 은 시험할 때 다운로드 폴더를 바꾸는 데 쓴다. 정해 두지 않으면 `%USERPROFILE%\Downloads` 를 쓴다.

### 돌려 본 결과
Windows 11 Pro(10.0.26200)의 cmd.exe에서 `TEMP` 와 `CLEAN_DL` 을 시험용으로 따로 만든 가짜 폴더로 바꿔 돌렸다.

가짜 임시 폴더에는 다음을 두었다.
- 보통 파일 두 개(하나는 하위 폴더 안)
- 숨김 파일 하나
- 숨김 폴더 하나와 그 안의 파일
- 임시 폴더 바깥 폴더를 가리키는 정션(junction) 하나. 바깥 폴더에는 지워지면 안 되는 파일을 두었다.

가짜 다운로드 폴더에는 40일 전 날짜로 바꾼 `old report.pdf` 와 오늘 만든 `new.zip` 을 두었다.

- 그냥 실행하면 임시 파일 수 `5` 와 `old report.pdf` 경로를 보여 주고 `pause` 에서 기다렸다. 파일은 그대로였다. 5에는 숨김 파일 두 개와 정션 너머의 파일 하나가 들어 있다.
- `run` 을 붙이면 보통 파일과 하위 폴더, 정션이 지워졌다. 숨김 파일과 숨김 폴더는 남았다. 정션 너머 바깥 폴더의 파일은 지워지지 않았다. `old report.pdf` 는 `_오래된 파일` 안으로 옮겨졌고 `new.zip` 은 그대로였다.
- `_오래된 파일` 에 같은 이름의 파일이 있는 상태로 다시 돌리면, 다운로드 폴더의 파일은 옮겨지지 않고 남았다. `_오래된 파일` 에 있던 파일의 내용도 그대로였다.
- `TEMP` 를 `C:\` 로 바꾸면 `TEMP 경로가 \Temp 로 끝나지 않아 멈춘다`, 없는 폴더로 바꾸면 `TEMP 폴더가 없어 멈춘다`, 비우면 `TEMP 변수가 비어 있어 멈춘다` 를 보여 주고 아무것도 지우지 않았다. 다운로드 폴더가 없으면 `다운로드 폴더가 없어 멈춘다` 로 멈췄다.
- `forfiles` 는 고른 항목 앞에 빈 줄을 하나 찍는다. 동작에는 상관없다.

### 아직 모르는 것
- 다운로드한 파일의 수정 날짜가 받은 날짜인지 원래 파일의 날짜인지는 브라우저마다 다를 수 있다. 압축을 풀어 나온 파일도 zip 안에 적힌 원래 수정 날짜를 가질 수 있다. 어느 쪽이든 원래 날짜가 남으면 방금 받거나 푼 파일도 바로 옮겨진다(확인 필요).
- 숨김 파일은 일부러 지우지 않았다. `del /a` 로 숨김 파일까지 지울지는 정하지 않았다.
- 진짜 임시 폴더와 진짜 다운로드 폴더로는 돌려 보지 않았다. 탐색기에서 두 번 눌러 실행해 보지도 않았다.
- 휴지통 비우기와 DISM 정리는 실행해 보지 않았다.
