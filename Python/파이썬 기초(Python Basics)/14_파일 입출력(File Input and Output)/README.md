## 파일 입출력이란 ?
- 프로그램의 데이터를 파일에 쓰고(출력), 파일에 저장된 데이터를 읽어 오는(입력) 것
- 파이썬은 `open()` 으로 파일을 열고, `read()` 나 `write()` 로 읽고 쓴 뒤 닫는다
- 파일을 닫는 일은 `with` 문으로 자동으로 처리하는 것이 기본이다

<br/>

## 왜 필요할까
지금까지 변수에 담은 값은 프로그램이 끝나면 모두 사라진다. 변수는 메모리(RAM)에 있고, 메모리는 프로그램이 끝나거나 전원이 꺼지면 내용을 잃기 때문이다. 칠판에 적은 내용이 수업이 끝나면 지워지는 것과 같다.
게임 저장 기록, 설정값, 작업 결과처럼 다음 실행에도 남아 있어야 하는 데이터는 디스크에 파일로 저장해야 한다. 칠판 내용을 공책에 옮겨 적어 두는 것과 같다. 6장의 입출력이 키보드와 화면을 상대했다면, 이 장에서는 파일을 상대한다.

<br/>

## 파일 (File)
사전적 의미는 서류철. 관련 서류를 한데 모아 철해 둔 묶음이다.
공학적으로는 디스크 같은 저장 장치에 이름을 붙여 저장한 데이터 묶음을 말한다. 사무실에서 서류철에 이름표를 붙여 캐비닛에 넣어 두듯, 컴퓨터는 데이터에 파일 이름을 붙여 폴더에 보관한다.

### 텍스트 파일과 바이너리 파일
- 텍스트 파일은 사람이 읽을 수 있는 글자로 된 파일이다. `.txt`, `.csv`, `.py` 가 해당한다
- 바이너리(Binary) 파일은 글자가 아닌 0과 1의 데이터 그대로 저장된 파일이다. binary는 둘로 이루어진이라는 뜻이다. 이미지, 음악, 실행 파일이 해당한다

이 장은 텍스트 파일을 중심으로 다룬다.

<br/>

## 파일을 다루는 순서
1. `open()` 으로 파일을 연다
2. 읽거나 쓴다
3. `close()` 로 파일을 닫는다

책을 펼치고, 읽거나 적고, 덮어서 꽂아 두는 순서와 같다.

```python
f = open("memo.txt", "w", encoding="utf-8")
f.write("안녕")
f.close()
```

### 왜 닫아야 할까
`write()` 로 쓴 내용은 바로 디스크에 저장되지 않고, 잠시 메모리에 모아 두었다가 한꺼번에 저장된다. 닫을 때 남은 내용이 마저 저장되므로 닫지 않으면 마지막 내용이 빠질 수 있다. 또 운영체제가 한 프로그램이 동시에 열 수 있는 파일 수를 제한하고 있어서, 닫지 않고 계속 열기만 하면 더 이상 파일을 열 수 없게 된다.

<br/>

## with 문
### 왜 필요할까
`close()` 를 직접 부르면 빠뜨리기 쉽다. 게다가 읽고 쓰는 도중에 예외가 나면 그 아래의 `close()` 까지 가지 못한다. 12장의 `finally` 로 막을 수는 있지만 매번 쓰기 번거롭다.

### 동작
`with` 블록 안에서 파일을 쓰고, 블록을 벗어나면 파이썬이 자동으로 파일을 닫는다. 블록 안에서 예외가 나도 닫는다. 도서관 열람실처럼 나갈 때 책이 자동으로 반납되는 것과 같다.

```python
with open("memo.txt", "w", encoding="utf-8") as f:
    f.write("안녕")
# 여기서는 이미 닫혀 있다
```

`as f` 는 열린 파일을 `f` 라는 이름으로 받겠다는 뜻이다. 파일을 다룰 때는 특별한 이유가 없으면 항상 `with` 를 쓴다.

<br/>

## open()
`open(파일 경로, 모드, encoding=인코딩)` 형태로 쓴다.

### 모드 (Mode)
파일을 어떤 목적으로 열지 정한다. 생략하면 읽기 모드(`"r"`)다.

| 모드 | 의미 | 파일이 없으면 | 파일이 있으면 |
| --- | --- | --- | --- |
| `"r"` | 읽기 (read) | `FileNotFoundError` | 처음부터 읽는다 |
| `"w"` | 쓰기 (write) | 새로 만든다 | 기존 내용을 지우고 처음부터 쓴다 |
| `"a"` | 이어 쓰기 (append) | 새로 만든다 | 기존 내용 끝에 이어 쓴다 |
| `"x"` | 새 파일 쓰기 (exclusive) | 새로 만든다 | `FileExistsError` |

`"w"` 는 기존 내용을 경고 없이 지운다. 기록을 쌓아 가는 로그 파일처럼 내용을 유지해야 하면 `"a"` 를 쓴다.
바이너리 파일은 모드 뒤에 `b` 를 붙인다(`"rb"`, `"wb"`). 이때는 문자열이 아니라 바이트(bytes)를 읽고 쓴다.

### 인코딩 (Encoding)
encode는 암호나 부호로 바꾸다라는 뜻이다. 컴퓨터는 글자를 숫자로 바꿔 저장하는데, 어떤 글자를 어떤 숫자로 바꿀지 정한 규칙이 인코딩이다. 쓸 때와 읽을 때 같은 규칙을 써야 글자가 제대로 나온다. 다른 규칙으로 읽으면 한글이 깨지거나 `UnicodeDecodeError` 가 난다.
`encoding` 을 생략하면 운영체제의 기본 인코딩을 쓰는데, 한국어 Windows는 이 기본값이 UTF-8이 아닐 수 있다. 같은 코드가 컴퓨터마다 다르게 동작하지 않도록 텍스트 파일은 `encoding="utf-8"` 을 항상 적는다.

<br/>

## 읽기
아래 내용의 `fruits.txt` 가 있다고 하자.

```
사과
배
귤
```

### read()
파일 전체를 문자열 하나로 읽는다.

```python
with open("fruits.txt", encoding="utf-8") as f:
    text = f.read()
print(text)   # 사과\n배\n귤 (줄바꿈 포함 전체)
```

### 한 줄씩 읽기
파일 객체를 `for` 문에 넣으면 한 줄씩 꺼낸다. 파일 전체를 한 번에 메모리에 올리지 않으므로 큰 파일도 다룰 수 있다. 가장 많이 쓰는 방식이다.

```python
with open("fruits.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())   # 사과, 배, 귤
```

각 줄 끝에는 줄바꿈 문자 `\n` 이 붙어 있다. 그대로 `print` 하면 `print` 의 줄바꿈과 겹쳐 빈 줄이 생기므로 4장의 `strip()` 으로 떼어 낸다.

### readline(), readlines()
`readline()` 은 한 줄만 읽고, `readlines()` 는 모든 줄을 리스트로 읽는다.

```python
with open("fruits.txt", encoding="utf-8") as f:
    first = f.readline()    # '사과\n'
    rest = f.readlines()    # ['배\n', '귤']
```

`readline()` 으로 한 줄을 읽은 뒤 `readlines()` 가 둘째 줄부터 읽은 것을 볼 수 있다. 파일 객체는 어디까지 읽었는지 위치를 기억하고, 다음 읽기는 그 위치부터 이어 간다. 책갈피를 꽂아 두고 이어 읽는 것과 같다. 그래서 끝까지 읽은 파일을 다시 `read()` 하면 빈 문자열이 나온다.

<br/>

## 쓰기
### write()
문자열을 파일에 쓴다. `print()` 와 달리 줄바꿈을 자동으로 붙이지 않으므로 필요하면 `\n` 을 직접 넣는다. 문자열만 쓸 수 있어서 숫자는 `str()` 이나 f-string으로 바꿔 넣는다.

```python
with open("score.txt", "w", encoding="utf-8") as f:
    f.write("kim 90\n")
    f.write(f"lee {85}\n")
```

### 리스트를 여러 줄로 쓰기
```python
fruits = ["사과", "배", "귤"]
with open("fruits.txt", "w", encoding="utf-8") as f:
    for fruit in fruits:
        f.write(fruit + "\n")
```

`print()` 에 `file=` 을 넘기면 화면 대신 파일에 출력한다. 줄바꿈이 자동으로 붙어 편하다.

```python
with open("log.txt", "a", encoding="utf-8") as f:
    print("실행 기록", file=f)
```

## 파일 경로
### 절대 경로와 상대 경로
- 절대 경로는 드라이브나 최상위 폴더부터 전체 위치를 적은 것이다 (`C:/Users/kim/memo.txt`). 주소를 시, 구, 동부터 모두 적는 것과 같다
- 상대 경로는 현재 작업 폴더를 기준으로 적은 것이다 (`memo.txt`, `data/memo.txt`). 여기서 두 블록 옆 집처럼 지금 위치 기준으로 말하는 것과 같다. `..` 은 한 단계 위 폴더를 뜻한다

### 현재 작업 폴더 기준이다
상대 경로의 기준은 실행한 `.py` 파일이 있는 폴더가 아니라, 프로그램을 실행한 터미널의 현재 위치(작업 폴더)다. 같은 코드라도 어느 폴더에서 실행했느냐에 따라 다른 파일을 찾으므로, 분명히 있는 파일인데 `FileNotFoundError` 가 나면 작업 폴더부터 확인한다. 13장의 `os.getcwd()` 로 볼 수 있다.

### Windows 경로의 백슬래시
Windows 경로의 `\` 는 6장의 이스케이프 문자와 겹친다. `"C:\new\test.txt"` 에서 `\n` 은 줄바꿈, `\t` 는 탭으로 읽힌다. 슬래시(`/`)로 쓰면 Windows에서도 동작하므로 슬래시를 쓰거나, 따옴표 앞에 `r` 을 붙여 이스케이프를 끈다(raw string).

```python
open("C:/new/test.txt")
open(r"C:\new\test.txt")
```

## 파일 입출력과 예외 처리
파일은 지워졌거나, 경로가 틀렸거나, 권한이 없는 등 실행해 봐야 알 수 있는 문제가 많다. 12장에서 말한 예외 처리가 필요한 대표적인 경우다.

```python
try:
    with open("config.txt", encoding="utf-8") as f:
        config = f.read()
except FileNotFoundError:
    config = ""   # 설정 파일이 없으면 기본값으로 시작
```

## JSON 파일
### 왜 필요할까
텍스트 파일에는 문자열만 쓸 수 있다. 10장의 딕셔너리 `{"name": "kim", "age": 20}` 를 저장하려고 `str()` 로 바꿔 쓰면, 읽어 올 때 다시 딕셔너리로 되돌리기가 번거롭다. 리스트와 딕셔너리 같은 구조를 그대로 저장하고 되살릴 형식이 필요하다.

### 정의
JSON(JavaScript Object Notation)은 자바스크립트의 객체 표기법에서 온 데이터 형식이다. notation은 표기법이라는 뜻이다. 이름은 자바스크립트에서 왔지만 지금은 언어에 상관없이 데이터를 주고받는 표준 형식으로 쓰인다. 모양이 파이썬의 딕셔너리, 리스트와 거의 같아서 표준 라이브러리의 `json` 모듈로 쉽게 바꿀 수 있다.

```python
import json

user = {"name": "kim", "age": 20, "tags": ["a", "b"]}

# 저장
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(user, f, ensure_ascii=False, indent=2)

# 읽기
with open("user.json", encoding="utf-8") as f:
    loaded = json.load(f)

loaded["name"]   # 'kim'
```

`ensure_ascii=False` 는 한글을 `\uae40` 같은 코드 대신 글자 그대로 저장하게 하고, `indent=2` 는 사람이 읽기 좋게 두 칸씩 들여써서 저장한다.
JSON은 문자열, 숫자, 불리언, `null`(파이썬의 `None`), 배열(리스트), 객체(딕셔너리)만 표현할 수 있다. 튜플은 리스트로 바뀌어 저장되고, 집합은 저장하려 하면 `TypeError` 가 난다.
