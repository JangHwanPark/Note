## 모듈과 패키지란 ?
- 모듈(Module)은 파이썬 코드를 담은 `.py` 파일 하나, 패키지(Package)는 모듈 여러 개를 폴더로 묶은 것
- `import` 로 다른 파일의 변수, 함수, 클래스를 가져와 쓴다
- 다른 사람이 만든 패키지는 `pip` 로 설치하고, 프로젝트마다 가상환경(venv)을 따로 두어 관리한다

<br/>

## 왜 필요할까
지금까지는 코드를 파일 하나에 썼다. 프로그램이 커지면 수천 줄이 한 파일에 쌓여 원하는 코드를 찾기 어렵고, 다른 프로그램에서 쓰려면 필요한 부분을 복사해 가야 한다.
코드를 역할별로 파일을 나눠 두고 필요한 곳에서 가져다 쓰면 찾기 쉽고, 한 곳만 고치면 쓰는 곳 모두에 반영된다. 11장의 함수가 코드 몇 줄을 묶어 이름을 붙였다면, 모듈은 그 함수들을 파일 단위로 묶는 것이다.
또 날짜 계산, 난수, 수학 함수처럼 누구나 필요한 기능을 직접 만들 필요 없이, 이미 만들어진 모듈을 가져다 쓸 수 있다.

<br/>

## 모듈 (Module)
### 정의
사전적 의미는 규격화된 구성 단위. 조립식 가구나 모듈 주택처럼 따로 만들어 끼워 맞출 수 있는 부품이다.
공학적으로는 독립적으로 만들어 다른 코드에 끼워 쓸 수 있는 코드 단위를 말한다. 파이썬에서는 `.py` 파일 하나가 곧 모듈이고, 파일 이름(확장자 제외)이 모듈 이름이 된다.

### 직접 만든 모듈 가져오기
같은 폴더에 두 파일이 있다고 하자.

```python
# calc.py
PI = 3.14

def add(a, b):
    return a + b
```

```python
# main.py
import calc

print(calc.add(2, 3))   # 5
print(calc.PI)          # 3.14
```

`import calc` 는 `calc.py` 를 찾아 실행하고, 그 안에서 만든 이름들을 `calc` 라는 이름 아래 묶어 가져온다. 그래서 `calc.add` 처럼 모듈 이름을 앞에 붙여 쓴다.

<br/>

## import 하는 여러 방법
### import 모듈
모듈 전체를 가져오고 `모듈.이름` 으로 쓴다. 어느 모듈에서 온 이름인지 코드에 드러나서 가장 기본으로 쓰는 형태다.

```python
import math
math.sqrt(16)   # 4.0
```

### from 모듈 import 이름
모듈에서 필요한 이름만 꺼내 온다. 모듈 이름을 붙이지 않고 바로 쓸 수 있다.

```python
from math import sqrt, pi
sqrt(16)   # 4.0
pi         # 3.141592653589793
```

### as로 별칭 붙이기
as는 ~로서라는 뜻이다. 이름이 길거나 다른 이름과 겹칠 때 별칭을 붙인다. 데이터 분석에서 쓰는 `import numpy as np` 처럼 관례로 굳은 별칭도 있다.

```python
import datetime as dt
from math import sqrt as root
```

### from 모듈 import * 는 피한다
`*` 는 모듈의 이름을 전부 가져온다. 편해 보이지만 어떤 이름이 어디서 왔는지 알 수 없고, 내 코드의 변수와 이름이 겹치면 조용히 덮어써진다. 필요한 이름을 직접 적는다.

<br/>

## 표준 라이브러리 (Standard Library)
라이브러리(Library)의 사전적 의미는 도서관. 필요할 때 빌려 볼 수 있게 책을 모아 둔 곳이다. 공학적으로는 가져다 쓸 수 있게 모아 둔 코드 묶음을 말한다.
파이썬을 설치하면 따로 설치하지 않아도 쓸 수 있는 모듈이 함께 들어 있는데, 이를 표준 라이브러리라 한다. 동네 도서관에 기본으로 비치된 책과 같다.

```python
import math
math.ceil(3.2)       # 4 (올림)
math.floor(3.8)      # 3 (내림)

import random
random.randint(1, 6)            # 1 이상 6 이하 정수 하나 (주사위)
random.choice(["가", "나"])     # 리스트에서 하나 고르기

from datetime import date
date.today()         # 오늘 날짜

import os
os.getcwd()          # 현재 작업 폴더 경로
```

무언가를 직접 만들기 전에 표준 라이브러리에 이미 있는지 먼저 찾아본다. 어떤 모듈이 있는지는 공식 문서(https://docs.python.org/ko/3/library/)에서 볼 수 있다.

<br/>

## import는 어떻게 동작할까
### 동작 순서
1. 이미 가져온 적이 있는 모듈인지 확인한다. 있으면 그것을 그대로 쓴다
2. 처음이면 정해진 경로에서 모듈 파일을 찾는다
3. 찾은 파일을 위에서부터 한 번 실행한다
4. 실행하면서 만들어진 이름들을 모듈 객체에 담아 돌려준다

같은 모듈을 여러 파일에서 `import` 해도 실제 실행은 처음 한 번뿐이다. 도서관에서 한 번 빌려 온 책은 다시 빌리러 가지 않는 것과 같다.

### 모듈을 찾는 경로
파이썬은 실행한 파일이 있는 폴더를 먼저 보고, 그다음 표준 라이브러리, 그다음 `pip` 로 설치한 패키지 폴더 순서로 찾는다. 실제 경로 목록은 `sys.path` 로 볼 수 있다.

```python
import sys
print(sys.path)
```

실행한 파일의 폴더를 가장 먼저 보기 때문에, 내 파일 이름을 `random.py` 나 `math.py` 처럼 표준 라이브러리와 같게 지으면 표준 모듈 대신 내 파일을 가져온다. 그러면 `random.randint` 같은 기능이 없다는 엉뚱한 에러가 난다. 파일 이름은 표준 모듈과 겹치지 않게 짓는다.

<br/>

## `__name__` 과 `"__main__"`
### 왜 필요할까
`import` 는 모듈 파일을 실행한다. 그래서 모듈 맨 아래에 테스트용 `print` 를 써 두면, 다른 파일에서 `import` 할 때마다 그 `print` 도 실행된다. 파일을 직접 실행했을 때만 돌고, `import` 될 때는 돌지 않는 코드를 구분할 방법이 필요하다.

### 동작
모든 모듈에는 `__name__` 이라는 변수가 자동으로 생긴다. 파일을 `python calc.py` 로 직접 실행하면 `__name__` 에 `"__main__"` 이 들어가고, 다른 파일에서 `import` 되면 모듈 이름 `"calc"` 가 들어간다. 이 값을 조건문으로 확인한다.

```python
# calc.py
def add(a, b):
    return a + b

if __name__ == "__main__":
    print(add(2, 3))   # python calc.py로 직접 실행할 때만 출력된다
```

main은 주된, 중심이라는 뜻이다. 여러 파일 중 지금 실행의 시작점이 된 파일이라는 의미로 붙은 이름이다.

<br/>

## 패키지 (Package)
### 정의
사전적 의미는 꾸러미, 포장. 여러 물건을 한 상자에 담아 묶은 것이다.
공학적으로는 관련된 모듈 여러 개를 폴더 하나로 묶은 것을 말한다. 모듈이 책 한 권이라면 패키지는 책을 주제별로 꽂아 둔 책장 한 칸이다. 폴더 안에 폴더를 넣어 계층을 만들 수도 있다.

### 구조와 가져오기
```
shop/
├── main.py
└── payment/
    ├── __init__.py
    ├── card.py
    └── cash.py
```

```python
# main.py
from payment import card
from payment.cash import pay

card.pay(1000)
pay(500)
```

폴더와 파일을 점(`.`)으로 이어 경로를 적는다. `payment.cash` 는 `payment` 폴더의 `cash.py` 라는 뜻이다.

### `__init__.py`
init은 initialize(초기화하다)의 줄임말이다. 이 파일이 있으면 그 폴더를 패키지로 본다는 표시가 되고, 패키지를 처음 `import` 할 때 이 파일이 먼저 실행된다. 보통은 빈 파일로 둔다.
파이썬 3.3부터는 `__init__.py` 가 없는 폴더도 가져올 수 있게 바뀌었지만(네임스페이스 패키지), 일반적인 패키지는 관례대로 `__init__.py` 를 둔다.

<br/>

## pip
### 외부 패키지
표준 라이브러리에 없는 기능은 다른 사람이 만들어 공개한 패키지를 설치해 쓴다. 파이썬 패키지는 PyPI(Python Package Index, https://pypi.org)라는 공개 저장소에 모여 있다. 웹 요청을 보내는 `requests`, 데이터 분석의 `pandas` 같은 패키지가 여기 있다.

### pip로 설치하기
pip는 PyPI에서 패키지를 내려받아 설치하는 도구로, 파이썬을 설치하면 함께 들어 있다. 터미널에서 실행한다.

```bash
pip install requests        # 설치
pip install requests==2.31.0  # 버전을 지정해 설치
pip uninstall requests      # 삭제
pip list                    # 설치된 패키지 목록
```

설치한 뒤에는 표준 라이브러리와 똑같이 `import requests` 로 쓴다.

### requirements.txt
프로젝트에 필요한 패키지와 버전을 적어 두는 파일이다. 다른 사람이나 다른 컴퓨터에서 같은 환경을 만들 때 쓴다. requirements는 필요 조건이라는 뜻이다.

```bash
pip freeze > requirements.txt     # 지금 설치된 패키지와 버전을 파일로 저장
pip install -r requirements.txt   # 파일에 적힌 패키지를 한 번에 설치
```

## 가상환경 (venv)
### 왜 필요할까
pip로 설치한 패키지는 기본적으로 컴퓨터 전체에서 함께 쓰는 한 곳에 들어간다. 그런데 프로젝트 A는 어떤 패키지의 1버전이, 프로젝트 B는 2버전이 필요하면 한 곳에 둘 다 둘 수 없다. 또 여러 프로젝트의 패키지가 섞이면 어떤 프로젝트에 무엇이 필요한지 알 수 없게 된다.

### 정의
가상(Virtual)의 사전적 의미는 실제가 아니지만 실제처럼 작동하는 것이다.
가상환경은 프로젝트마다 따로 만드는 독립된 파이썬 실행 환경이다. 가상환경을 켜고 설치한 패키지는 그 가상환경 폴더에만 들어가고, 다른 프로젝트에 영향을 주지 않는다. 프로젝트마다 자기 공구함을 따로 두는 것과 같다. venv는 virtual environment의 줄임말이고, 표준 라이브러리에 들어 있는 가상환경 도구다.

### 사용 순서
```bash
# 1. 프로젝트 폴더에서 가상환경 만들기 (.venv 폴더가 생긴다)
python -m venv .venv

# 2. 켜기
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS, Linux

# 3. 켜진 상태에서 설치하면 이 가상환경에만 설치된다
pip install requests

# 4. 끄기
deactivate
```

가상환경이 켜지면 터미널 앞에 `(.venv)` 처럼 가상환경 이름이 표시된다. `-m` 은 모듈을 프로그램처럼 실행하라는 옵션이다.
`.venv` 폴더는 각자의 컴퓨터에서 다시 만들 수 있으므로 git에 올리지 않는다. 대신 `requirements.txt` 를 올려 두고, 받은 사람이 가상환경을 만든 뒤 설치한다.
