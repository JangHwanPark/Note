## 이터레이터와 제너레이터란 ?
- 이터레이터(Iterator)는 값을 하나씩 차례로 꺼내 주는 객체, 제너레이터(Generator)는 `yield` 로 이터레이터를 쉽게 만드는 방법이다
- `yield` 가 든 함수를 제너레이터 함수, 그 함수가 돌려주는 이터레이터를 제너레이터 객체라 한다
- `for` 문은 내부에서 이터레이터로 값을 하나씩 꺼내며 돈다
- 값을 미리 다 만들어 두지 않고 필요할 때 하나씩 만들 수 있어서, 데이터가 크거나 끝이 없어도 다룰 수 있다

<br/>

## 왜 필요할까
100만 개의 제곱수를 더하려고 리스트를 만들면, 100만 개를 모두 메모리에 올린 뒤에야 더하기를 시작한다. 그런데 더하기에는 한 번에 값 하나만 있으면 된다. 다 만들어 두는 것은 메모리 낭비다.
파일을 한 줄씩 읽는 경우도 같다. 14장에서 `for line in f` 가 큰 파일도 다룰 수 있다고 했는데, 파일 전체를 올리지 않고 줄이 필요할 때마다 하나씩 읽어 주기 때문이다. 이렇게 필요할 때 하나씩 값을 내주는 구조가 이터레이터이고, 그런 구조를 직접 쉽게 만드는 방법이 제너레이터다.

<br/>

## 반복 가능한 객체와 이터레이터
### 반복 가능한 객체 (Iterable)
8장에서 값을 하나씩 꺼낼 수 있는 대상을 반복 가능한 객체라고 했다. iterable은 iterate(되풀이하다)에 -able(할 수 있는)이 붙은 말로, 되풀이해 꺼낼 수 있는이라는 뜻이다. 리스트, 문자열, 튜플, 딕셔너리, 집합, `range` 가 해당한다.

### 이터레이터 (Iterator)
iterator는 되풀이하는 것, 반복자라는 뜻이다.
공학적으로는 값을 하나씩 차례로 내주고, 지금 어디까지 내줬는지를 기억하는 객체를 말한다. 반복 가능한 객체가 값들이 들어 있는 책이라면, 이터레이터는 그 책에 꽂힌 책갈피다. 책 한 권에 책갈피를 여러 개 꽂아 각자 다른 위치를 읽을 수 있듯, 리스트 하나에서 이터레이터를 여러 개 만들 수 있다.

### iter()와 next()
`iter()` 는 반복 가능한 객체에서 이터레이터를 꺼내고, `next()` 는 이터레이터에서 다음 값 하나를 꺼낸다. 더 꺼낼 값이 없으면 `StopIteration` 이라는 예외가 발생한다. 12장의 `ValueError` 처럼 예외의 한 종류로, 이름은 반복(iteration)을 멈추라(stop)는 뜻이다.

```python
nums = [1, 2, 3]
it = iter(nums)
next(it)   # 1
next(it)   # 2
next(it)   # 3
next(it)   # StopIteration
```

## for 문은 어떻게 동작할까
8장의 `for` 문은 내부에서 이터레이터를 쓴다.

1. `for` 뒤의 반복 가능한 객체에 `iter()` 를 불러 이터레이터를 얻는다
2. `next()` 로 값을 하나 꺼내 변수에 넣고 블록을 실행한다
3. 2번을 되풀이한다
4. `StopIteration` 이 발생하면 예외를 조용히 처리하고 반복을 끝낸다

그래서 아래 두 코드는 같은 일을 한다.

```python
for n in [1, 2, 3]:
    print(n)

it = iter([1, 2, 3])
while True:
    try:
        n = next(it)
    except StopIteration:
        break
    print(n)
```

`for` 문을 쓸 수 있는 대상이 리스트에 한정되지 않고 문자열, 딕셔너리, 파일까지 다양한 이유가 이것이다. `iter()` 로 이터레이터를 꺼낼 수 있기만 하면 된다.

<br/>

## 이터레이터는 한 번 쓰면 끝이다
이터레이터는 어디까지 꺼냈는지 기억하므로, 끝까지 꺼낸 이터레이터에서는 더 나올 값이 없다. 끝 페이지까지 넘어간 책갈피가 저절로 첫 페이지로 돌아가지 않는 것과 같다.

```python
it = iter([1, 2])
list(it)   # [1, 2]
list(it)   # [] (이미 다 꺼냈다)
```

리스트는 `for` 문을 돌 때마다 새 이터레이터를 만들어 주므로 몇 번이든 처음부터 돌 수 있다. 다시 돌아야 하는 데이터라면 이터레이터를 넘기지 말고 리스트를 넘긴다.

### range는 이터레이터가 아니다
`range` 는 숫자를 미리 다 만들어 두지 않는다는 점에서 이터레이터와 닮았지만, 이터레이터가 아니라 반복 가능한 객체다. 그래서 `next()` 를 바로 쓸 수 없고, 몇 번이든 처음부터 다시 돌 수 있다.

```python
next(range(3))         # TypeError: 'range' object is not an iterator
it = iter(range(3))    # 이터레이터를 꺼내면 next()를 쓸 수 있다
next(it)               # 0
```

## 이터레이터를 직접 만들기
15장의 특별한 메서드로 이터레이터를 만들 수 있다. `__iter__` 는 `iter()` 가, `__next__` 는 `next()` 가 부르는 메서드다. 이터레이터는 `__iter__` 에서 자기 자신을 돌려준다. `for` 문은 받은 대상에 먼저 `iter()` 를 부르므로, 이터레이터도 `for` 문에 넣을 수 있으려면 `iter()` 에 자기 자신을 내줘야 하기 때문이다.

```python
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value


for n in Countdown(3):
    print(n)   # 3, 2, 1
```

동작은 분명하지만, 현재 위치를 속성에 저장하고 끝에서 `StopIteration` 을 일으키는 코드를 매번 직접 써야 해서 번거롭다. 제너레이터는 이 일을 파이썬이 대신 하게 한다.

<br/>

## 제너레이터 (Generator)
### 정의
사전적 의미는 발전기, 만들어 내는 것. generate(만들어 내다)에서 왔다.
공학적으로는 값을 미리 만들어 두지 않고, 요청이 올 때마다 하나씩 만들어 내는 이터레이터를 말한다. 이런 이터레이터를 돌려주는 함수를 제너레이터 함수라 한다. 생수를 박스째 사 두는 것이 리스트라면, 제너레이터는 버튼을 누를 때마다 한 컵씩 물을 내주는 정수기다. 미리 쌓아 둘 공간이 필요 없다.

### yield
함수 안에 `yield` 가 하나라도 있으면 그 함수는 제너레이터 함수가 된다. yield는 내주다, 산출하다라는 뜻이다. 위의 `Countdown` 클래스를 제너레이터 함수로 쓰면 이렇게 짧아진다.

```python
def countdown(start):
    current = start
    while current > 0:
        yield current
        current -= 1


for n in countdown(3):
    print(n)   # 3, 2, 1
```

### 동작
제너레이터 함수는 호출해도 본문이 바로 실행되지 않는다. 대신 제너레이터 객체를 돌려준다. 그 뒤 `next()` 가 불릴 때마다 아래 순서로 움직인다.

1. 직전에 멈춘 자리부터 본문을 실행한다 (처음이면 맨 위부터)
2. `yield` 를 만나면 그 값을 내주고 그 자리에서 멈춘다. 지역 변수의 값도 그대로 기억한다
3. 다음 `next()` 가 오면 멈췄던 `yield` 바로 다음부터 이어서 실행한다
4. 함수 끝이나 `return` 에 도달하면 `StopIteration` 을 일으킨다

```python
def steps():
    print("1번째 실행")
    yield "A"
    print("2번째 실행")
    yield "B"


s = steps()      # 아무것도 출력되지 않는다
next(s)          # "1번째 실행" 출력 후 'A'
next(s)          # "2번째 실행" 출력 후 'B'
next(s)          # StopIteration
```

`return` 은 값을 돌려주고 함수를 끝내지만, `yield` 는 값을 내주고 잠시 멈출 뿐이다. 11장에서 지역 변수는 함수가 끝나면 사라진다고 했는데, 제너레이터는 끝나지 않고 멈춰 있는 것이라 지역 변수가 살아 있다.

<br/>

## 제너레이터 표현식 (Generator Expression)
expression은 표현, 식이라는 뜻이다. 값 하나를 만들어 내는 코드 조각을 식이라 하고, 제너레이터 표현식은 제너레이터 객체를 만들어 내는 식이다.
9장의 리스트 컴프리헨션에서 대괄호를 소괄호로 바꾸면 제너레이터 표현식이 된다. 리스트를 만들지 않고 제너레이터 객체를 만든다. 아래 코드의 `1_000_000` 처럼 숫자 사이에 쓴 `_` 는 자릿수를 읽기 쉽게 끊어 주는 표기로, 값에는 영향이 없다.

```python
squares_list = [x * x for x in range(1_000_000)]   # 100만 개를 모두 만든다
squares_gen = (x * x for x in range(1_000_000))    # 아직 아무것도 만들지 않는다
```

`sys.getsizeof()` 로 두 객체 자체의 크기를 재 보면 차이가 크다. 아래는 Python 3.13에서 실행한 값이고, 환경에 따라 숫자는 조금 다를 수 있다.

```python
import sys
sys.getsizeof(squares_list)   # 8448728 (약 8MB)
sys.getsizeof(squares_gen)    # 200
```

리스트의 크기에는 안에 든 숫자 객체들의 크기가 들어 있지 않아서, 실제로 쓰는 메모리는 이보다 더 크다.

값을 한 번 훑고 끝나는 계산이라면 제너레이터 표현식으로 충분하다. 제너레이터 표현식이 함수의 유일한 인자라면 괄호를 한 겹 생략할 수 있다.

```python
sum(x * x for x in range(5))   # 30
```

반대로 인덱스로 꺼내거나, 길이를 재거나, 여러 번 돌아야 하면 리스트를 쓴다. 제너레이터 객체도 이터레이터라 한 번 다 쓰면 끝이다.

<br/>

## 끝이 없는 제너레이터
값을 필요할 때만 만들기 때문에, 끝이 없는 값의 흐름도 표현할 수 있다. 리스트로는 불가능한 일이다. 쓰는 쪽에서 `break` 로 멈춘다.

```python
def naturals():
    n = 1
    while True:
        yield n
        n += 1


for n in naturals():
    if n > 3:
        break
    print(n)   # 1, 2, 3
```

8장의 `while True:` 는 안에서 `break` 를 만나야 끝났다. 제너레이터 함수 안의 `while True` 는 `break` 가 없어도 `yield` 마다 멈추므로, 값을 꺼내는 만큼만 실행된다.

## 이터레이터를 돌려주는 내장 함수
앞에서 쓴 `map()`, `enumerate()` 와 이 장에서 처음 보는 `zip()`, `filter()` 는 리스트가 아니라 이터레이터를 돌려준다. 결과를 바로 보려면 `list()` 로 감싼다.

```python
names = ["kim", "lee"]
scores = [90, 85]

list(zip(names, scores))                     # [('kim', 90), ('lee', 85)]
list(map(int, ["1", "2"]))                   # [1, 2]
list(filter(lambda x: x % 2 == 1, range(6))) # [1, 3, 5]
list(enumerate(["a", "b"]))                  # [(0, 'a'), (1, 'b')]
```

- `zip()` 은 여러 묶음에서 같은 순서의 값을 하나씩 짝지어 준다. zip은 지퍼를 잠그다라는 뜻으로, 양쪽 이를 하나씩 맞물리는 모양에서 왔다
- `map()` 은 각 값에 함수를 적용한다. 6장의 `map(int, input().split())` 이 이것이다
- `filter()` 는 함수 결과가 참인 값만 남긴다
- `enumerate()` 는 8장에서 본 것처럼 순번과 값을 짝지어 준다

이들이 이터레이터를 돌려주는 이유도 같다. 결과가 실제로 필요해질 때까지 계산을 미뤄 메모리를 아낀다.
