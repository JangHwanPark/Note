## 예외 처리란 ?
- 프로그램이 실행 중에 만난 예상하지 못한 상황(예외)을 붙잡아 대응하는 문법
- 처리하지 않은 예외는 프로그램을 그 자리에서 멈추게 한다
- 파이썬은 `try`, `except`, `else`, `finally` 로 예외를 처리하고, `raise` 로 직접 예외를 일으킨다

<br/>

## 예외 (Exception)
사전적 의미는 일반적인 규칙에서 벗어나는 일. 늘 하던 대로 되지 않는 경우다.
공학적으로는 코드 문법은 맞지만 실행하는 도중 정상적으로 계속할 수 없는 상황이 생긴 것을 말한다. 0으로 나누기, 없는 파일 열기, 숫자가 아닌 글자를 숫자로 바꾸기 같은 경우다. 평소에는 잘 다니던 길이 공사로 막힌 상황과 같다. 길 자체(문법)는 맞았지만 지금은 그대로 갈 수 없다.

### 문법 오류와 무엇이 다를까
문법 오류(SyntaxError)는 콜론을 빠뜨리거나 괄호를 닫지 않는 것처럼 코드를 잘못 쓴 것이다. 파이썬은 실행 전에 코드를 읽는 단계에서 이를 발견하고, 한 줄도 실행하지 않는다. 문장이 문법부터 틀려 읽을 수조차 없는 것과 같다. 고치는 방법은 코드를 바로 쓰는 것뿐이다.
예외는 문법상 문제가 없어 실행은 시작됐는데, 그 줄에 도착해 보니 계속할 수 없는 경우다. 같은 코드라도 입력에 따라 생길 수도 있고 안 생길 수도 있다. 그래서 미리 대비해 둘 수 있고, 이 장에서 다루는 예외 처리가 그 대비다.

```python
print("hi"     # SyntaxError, 실행 전에 발견된다

int("abc")     # ValueError, 실행하다가 이 줄에서 발생한다
```

<br/>

## 왜 필요할까
사용자에게 나이를 입력받는 프로그램에서 누군가 `스무살` 이라고 입력하면 `int()` 에서 예외가 나고 프로그램이 통째로 멈춘다. 이 상황을 미리 알고 있다면 멈추는 대신 "숫자로 입력해 주세요"라고 안내하고 다시 받을 수 있다.
조건문으로 모든 경우를 미리 검사할 수도 있지만, 파일이 지워졌는지, 네트워크가 끊겼는지처럼 실행해 봐야 아는 일은 미리 다 막을 수 없다. 예외 처리는 일단 해 보고, 문제가 생기면 그때 대응하는 방식이다.

<br/>

## 트레이스백 (Traceback) 읽기
처리하지 않은 예외가 나면 파이썬은 프로그램을 멈추고 트레이스백을 출력한다. trace back은 거슬러 올라가 추적하다라는 뜻이다. 예외가 어떤 호출 경로를 거쳐 발생했는지를 순서대로 보여 준다.

```
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    print(divide(10, 0))
          ~~~~~~^^^^^^^
  File "main.py", line 2, in divide
    return a / b
           ~~^~~
ZeroDivisionError: division by zero
```

`most recent call last` 는 가장 최근 호출이 마지막에 있다는 뜻이다. 그래서 아래에서부터 읽는다. 맨 아래 줄이 예외 종류와 메시지이고, 바로 위가 실제로 예외가 난 위치다. 코드 아래의 `~` 와 `^` 표시는 그 줄에서 문제가 된 부분을 가리킨다. 파이썬 3.11부터 들어간 표시라 이전 버전에서는 나오지 않는다.

### 자주 만나는 예외
| 예외 | 언제 나는가 | 예시 |
| --- | --- | --- |
| `ValueError` | 자료형은 맞지만 값이 올바르지 않을 때 | `int("abc")` |
| `TypeError` | 연산에 맞지 않는 자료형을 쓸 때 | `"1" + 1` |
| `ZeroDivisionError` | 0으로 나눌 때 | `10 / 0` |
| `IndexError` | 없는 인덱스로 꺼낼 때 | `[1, 2][5]` |
| `KeyError` | 딕셔너리에 없는 키로 꺼낼 때 | `{"a": 1}["b"]` |
| `NameError` | 정의하지 않은 이름을 쓸 때 | `print(undefined_var)` |
| `FileNotFoundError` | 없는 파일을 열 때 | `open("none.txt")` |

## try, except
### 기본 형태
예외가 날 수 있는 코드를 `try` 블록에 넣고, 예외가 났을 때 할 일을 `except` 블록에 쓴다. try는 시도하다, except는 제외하다라는 뜻이다. 일단 시도해 보고, 예외가 나면 그 경우만 따로 처리한다.

```python
try:
    age = int(input("나이: "))
    print(f"내년에 {age + 1}살")
except ValueError:
    print("숫자로 입력해 주세요")
```

### 동작 순서
1. `try` 블록을 위에서부터 실행한다
2. 예외가 나지 않으면 `except` 블록은 건너뛴다
3. 예외가 나면 그 줄에서 바로 `try` 블록을 빠져나온다. 남은 줄은 실행하지 않는다
4. 발생한 예외 종류와 맞는 `except` 블록을 찾아 실행한다
5. 맞는 `except` 가 없으면 예외는 처리되지 않은 채 바깥으로 전달되고, 끝까지 아무도 처리하지 않으면 프로그램이 멈춘다

위 예시에서 `스무살` 을 입력하면 `int()` 에서 예외가 나므로 `print(f"내년에...")` 는 실행되지 않고 바로 안내 문구가 출력된다.

### 여러 예외 처리
예외 종류마다 다르게 대응하려면 `except` 를 여러 개 쓴다. 위에서부터 차례로 검사하고 처음 맞는 하나만 실행한다. 같은 방식으로 처리할 예외는 튜플로 묶는다.

```python
try:
    nums = [10, 20]
    i = int(input("번호: "))
    print(100 / nums[i])
except ValueError:
    print("숫자로 입력해 주세요")
except IndexError:
    print("없는 번호입니다")
except (ZeroDivisionError, TypeError):
    print("계산할 수 없는 값입니다")
```

### 예외 정보 받기 (as)
`as` 로 예외 객체를 변수에 받으면 파이썬이 만든 에러 메시지를 꺼내 쓸 수 있다.

```python
try:
    int("abc")
except ValueError as e:
    print(f"에러: {e}")   # 에러: invalid literal for int() with base 10: 'abc'
```

## else, finally
### else
`try` 블록에서 예외가 나지 않았을 때만 실행한다. 성공했을 때만 할 일을 `try` 안에 함께 넣으면, 그 코드에서 난 예외까지 `except` 가 잡아 버려 어디서 문제가 났는지 흐려진다. 예외를 확인할 코드는 `try` 에, 성공 후에 할 일은 `else` 에 나눠 두면 범위가 분명해진다.

```python
try:
    age = int(input("나이: "))
except ValueError:
    print("숫자로 입력해 주세요")
else:
    print(f"내년에 {age + 1}살")
```

### finally
finally는 마지막으로, 결국이라는 뜻이다. 예외가 나든 안 나든, `except` 에서 처리했든 못 했든 항상 마지막에 실행한다. 식당에서 손님이 주문을 했든 그냥 나갔든 문을 닫을 때는 반드시 불을 끄는 것과 같다. 열어 둔 파일이나 연결을 닫는 정리 작업에 쓴다.

```python
try:
    print(10 / 0)
except ZeroDivisionError:
    print("0으로 나눌 수 없음")
finally:
    print("항상 실행")
```

파일을 다룰 때는 `with` 문이 이 정리를 자동으로 해 주므로 `finally` 대신 `with` 를 더 많이 쓴다. `with` 는 파일 입출력과 함께 별도 장으로 정리한다.

### 전체 순서
네 블록을 모두 쓰면 `try` 를 실행하고, 예외가 나면 `except`, 안 나면 `else` 를 실행한 뒤, 어느 쪽이든 마지막에 `finally` 를 실행한다.

```python
try:
    # 예외가 날 수 있는 코드
except 예외종류:
    # 예외가 났을 때
else:
    # 예외가 안 났을 때
finally:
    # 항상
```

## raise
### 직접 예외 일으키기
raise는 들어 올리다, 제기하다라는 뜻이다. 문제를 제기하듯 코드에서 직접 예외를 일으킨다. 파이썬 입장에서는 문제없는 값이지만, 내 프로그램의 규칙에서는 잘못된 값일 때 쓴다. 나이가 음수인 경우처럼 문법적으로는 정상인 숫자라 파이썬이 알아서 예외를 내 주지 않는다.

```python
def set_age(age):
    if age < 0:
        raise ValueError("나이는 0 이상이어야 합니다")
    return age

try:
    set_age(-1)
except ValueError as e:
    print(e)   # 나이는 0 이상이어야 합니다
```

### 왜 return 대신 raise일까
잘못된 값일 때 `return None` 이나 `return -1` 을 돌려줄 수도 있다. 하지만 호출한 쪽이 이 값을 확인하지 않으면 잘못된 값이 그대로 다음 계산으로 흘러가 엉뚱한 곳에서 문제가 드러난다. 예외는 처리하지 않으면 프로그램이 멈추므로 문제가 생긴 그 자리에서 바로 드러난다.

### 다시 일으키기
`except` 안에서 `raise` 만 쓰면 잡았던 예외를 그대로 다시 바깥으로 보낸다. 기록만 남기고 처리는 바깥에 맡길 때 쓴다.

```python
try:
    int("abc")
except ValueError:
    print("변환 실패 기록")
    raise
```

## 주의할 점
### 예외 종류를 지정한다
`except:` 처럼 종류 없이 쓰거나 `except Exception:` 으로 넓게 잡으면 예상하지 못한 예외까지 모두 삼킨다. 변수 이름을 잘못 쓴 `NameError` 같은 버그도 조용히 넘어가서 원인을 찾기 어려워진다. 특히 종류 없는 `except:` 는 사용자가 Ctrl + C로 프로그램을 멈추려 할 때 나는 `KeyboardInterrupt` 까지 잡아 버린다.
대응 방법을 알고 있는 예외만 구체적으로 지정해 잡는다.

```python
# 피할 방식
try:
    age = int(input("나이: "))
except:
    pass   # 무슨 일이 있었는지 아무도 모른다

# 권장 방식
try:
    age = int(input("나이: "))
except ValueError:
    print("숫자로 입력해 주세요")
```

### try 블록은 좁게 쓴다
`try` 안에 코드를 많이 넣을수록 어느 줄에서 난 예외인지 구분하기 어렵다. 예외가 날 수 있는 줄만 넣고 나머지는 `else` 나 바깥으로 뺀다.

### 조건문으로 충분하면 조건문을 쓴다
딕셔너리에 키가 있는지는 `in` 이나 `get()` 으로, 리스트가 비었는지는 `len()` 으로 미리 확인할 수 있다. 예외 처리는 미리 확인하기 어렵거나, 실행해 봐야 알 수 있는 상황에 쓴다.
