# 노트 작성 절차

요청: $ARGUMENTS

작성 기준은 `.claude/CLAUDE.md`와 같은 폴더의 [writing-guide.md](writing-guide.md)다. 가이드에는 규칙마다 피할 예와 고친 예가 있다. 3단계 작성에 들어가기 전에 가이드를 읽는다. 아래 순서대로 진행한다.

## 1. 요청 종류 판단

- 새 노트: 주제 폴더를 새로 만든다.
- 이어 쓰기: 책 형태 노트(번호 붙은 장 폴더와 목차 README)의 다음 장을 쓴다. 목차의 TODO에 있는 주제인지 확인한다.
- 개정: 기존 노트를 고친다. 고치기 전에 원문을 읽고, 바꾸는 범위를 요청 범위로 제한한다.

어느 쪽인지 애매하면 한 번 묻는다.

## 2. 위치 결정

- 루트 README의 폴더 구조 목록을 보고 맞는 카테고리를 고른다. 맞는 곳이 없으면 새로 만들기 전에 묻는다.
- 같은 주제 노트가 이미 있는지 Grep으로 찾는다. 있으면 새로 쓸지, 그 노트를 고칠지 묻는다.
- 폴더명은 `한글명(English Name)`. 책 형태 노트의 장은 `NN_한글명(English Name)`으로 번호를 붙인다.

## 3. 작성

- 첫 섹션은 개념 노트면 "OO이란 ?", 문제·방법·변경 정리 노트면 내용에 맞는 제목(예: "무엇이 바뀌었나"). 대주제 `##`, 하위 `###`, 대주제 사이 `<br/>`.
- 정의 다음에 왜 필요한지, 어떻게 동작하는지를 쓴다.
- 핵심 용어는 사전적 의미에서 공학적 의미로 잇는다. 처음 나올 때 한글(영문).
- 입문 노트는 개념마다 일상 비유 하나.
- 이어 쓰기라면 앞 장에서 배운 개념을 쓸 때 몇 장인지 짚는다.
- 라이브러리나 언어 버전에 따라 달라지는 사실은 Context7이나 공식 문서로 확인한다.

## 4. 검증

- 출력이나 결과를 주석으로 적은 코드 예시는 scratchpad에서 실제로 실행해 주석과 비교한다. 다르면 문서를 고친다.
- 링크를 점검한다.

  ```bash
  node .claude/scripts/check-links.js "<노트 폴더>"
  ```

- 긴 대시, 이모지, 콜론 줄바꿈, 코드 스팬 뒤 대시는 훅이 잡는다. 훅이 지적하면 그 자리에서 고친다.

## 5. 리뷰

`note-reviewer` 에이전트에게 작성한 파일 경로를 넘겨 검토를 맡긴다. 지적 중 타당한 것은 반영하고, 반영하지 않은 것은 이유와 함께 보고에 적는다.

## 6. 연결 갱신

- 책 형태 노트: 목차에 새 장 추가, 바로 앞 장 하단에 다음 장 링크 추가, TODO에서 다룬 항목 제거, 이번에 미룬 주제는 TODO에 추가.
- 새 카테고리를 만들었다면 루트 README 폴더 구조 목록에 추가할지 묻는다.

## 7. 보고

무엇을 썼는지, 무엇을 확인했는지, 무엇을 확인하지 못했는지 순서로 보고한다. 끝에 커밋 메시지 후보 `note: 주제`를 준다.

커밋과 push는 사용자가 그 자리에서 명령형으로 맡겼을 때만 한다. 맡았을 때는 아래처럼 단계마다 별도 명령으로 실행하고 결과를 보고 다음으로 넘어간다.

1. `git fetch`, 현재 브랜치 확인, `git diff --cached --name-only`로 미리 스테이징된 파일 확인
2. 노트 폴더만 `git add`, 스테이징 목록 확인
3. `git commit`
4. `git log origin/<브랜치>..<브랜치>`로 나갈 커밋 확인. 내 커밋이 아닌 것이 있으면 push하지 말고 묻는다
5. `git push`, 다시 fetch해서 동기화 확인
