# Note 레포 글쓰기 지침

개인 학습 노트 레포다. 전역 CLAUDE.md의 글쓰기 규칙을 기본으로 따르고, 이 파일은 노트 작성에만 해당하는 기준을 둔다. 규칙을 실제 문장으로 보여 주는 피할 예와 고친 예는 아래 가이드에 있다.

@docs/writing-guide.md

## 작업 도구

- 노트를 새로 쓰거나 이어 쓰거나 개정할 때는 `/note` 스킬 절차를 따른다.
- 다 쓴 노트는 `note-reviewer` 에이전트로 검토한다.
- 링크 점검은 `node .claude/scripts/check-links.js <폴더>`로 한다.
- .md를 쓰면 `.claude/hooks/check-note-style.js`가 이모지, 청크, 콜론 줄바꿈, 코드 스팬 뒤 대시를 검사한다. 긴 대시는 전역 훅이 검사한다.

## 파일 구조

- 주제마다 폴더를 하나 만들고 본문은 그 안의 README.md에 쓴다. 폴더명은 `한글명(English Name)` 형식으로 한다.
- 카테고리 폴더(CS_Basic, React, Database 등)에 맞는 곳에 둔다. 맞는 곳이 없으면 새로 만들기 전에 묻는다.
- 여러 장으로 이어지는 주제는 책처럼 나눈다. 상위 폴더 README.md를 목차로 두고, 장마다 `NN_한글명(English Name)` 폴더를 만든다. 장 끝에는 목차, 이전 장, 다음 장 링크를 둔다.
- 커밋 메시지는 `note: 주제` 형식으로 한다.

## 문서 형식

- 대주제는 `##`, 하위 항목은 `###`로 쓰고, 대주제 사이에는 `<br/>`을 넣는다.
- 첫 섹션은 "OO이란 ?"으로 시작해 정의를 두세 줄로 쓴다.
- 표는 비교 항목이 세 개 이상일 때만 쓴다.
- 초안 요청이면 끝에 "더 볼 것 (TODO)" 섹션을 두고 이어서 정리할 주제를 적는다. 책 형태 노트는 TODO를 목차에만 둔다.

## 내용 기준

- 노트의 성격을 지킨다. CS_Basic은 특정 직군이나 프레임워크 관점이 아닌 일반 CS 이론으로 쓴다. 프론트엔드나 실무 적용 이야기는 별도 문서로 분리하고 TODO에 적는다.
- CS_Basic은 입문자가 읽을 수 있는 난이도로 쓴다. 개념마다 일상 비유를 하나 두고, 깊은 구현 내용은 별도 문서로 분리해 TODO에 적는다.
- 용어는 처음 나올 때 한글(영문)으로 함께 쓰고, 이후에는 한쪽으로 통일한다.
- 핵심 용어는 사전적 의미를 먼저 쓰고 이어서 공학적 의미를 쓴다. 단어의 원래 뜻이 기술 용어로 어떻게 이어지는지 드러나게 한다.
- 정의 다음에는 왜 필요한지, 어떻게 동작하는지를 쓴다. 특징만 나열하고 끝내지 않는다.
- 확실하지 않은 내용은 쓰지 않거나 확인 필요로 표시한다.
- 출력이나 결과를 적은 코드 예시는 실행해 본 값을 쓴다. 실행하지 못한 예시는 보고에 적는다.
