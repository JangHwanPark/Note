정말 중요한 질문입니다! 코딩 테스트에서 BFS를 이해하는 핵심이라고 할 수 있어요.

BFS (너비 우선 탐색)에서 **큐(Queue)**를 사용해야 하는 이유는 BFS의 탐색 원리, 즉 너비 우선이라는 특성 때문입니다.

BFS의 핵심 원리: '동일 레벨' 우선 탐색
BFS는 다음과 같은 순서로 노드를 방문합니다.

현재 노드를 방문한다.

현재 노드의 모든 자식 노드들을 방문한다. (즉, 동일 레벨의 노드들을 모두 방문한다)

그 다음 레벨로 내려가서, 그 레벨의 모든 노드들을 방문한다.

이 과정을 반복하며 트리를 층별로, 너비 순서대로 탐색한다.

예를 들어, 다음과 같은 트리가 있다고 생각해 봅시다.

      A (Level 0)
     / \
B (Level 1)  C (Level 1)
/ \     / \
D (Level 2) E (Level 2) F (Level 2)
BFS 탐색 순서는 A -> B -> C -> D -> E -> F가 됩니다.

왜 큐가 이 원리를 구현하는 데 최적일까요?
큐는 FIFO (First-In, First-Out), 즉 먼저 들어온 것이 먼저 나가는 자료구조입니다. 이 특성이 BFS의 탐색 순서와 정확히 일치합니다.

BFS가 동작하는 과정을 큐와 함께 시뮬레이션해 볼게요.

시작: 루트 노드 A를 큐에 넣습니다.

Queue: [A]

1단계: 큐에서 A를 꺼냅니다. A를 방문합니다. 그리고 A의 모든 자식들(B, C)을 큐에 순서대로 넣습니다.

Queue: [B, C]

2단계: 큐에서 맨 앞의 B를 꺼냅니다. B를 방문합니다. 그리고 B의 자식들(D, E)을 큐에 순서대로 넣습니다.

Queue: [C, D, E]

3단계: 큐에서 맨 앞의 C를 꺼냅니다. C를 방문합니다. 그리고 C의 자식들(F)을 큐에 넣습니다.

Queue: [D, E, F]

4단계: 큐에서 맨 앞의 D를 꺼냅니다. D를 방문합니다. D는 자식이 없으므로 큐에 넣을 노드가 없습니다.

Queue: [E, F]

5단계: 큐에서 맨 앞의 E를 꺼냅니다. E를 방문합니다. 자식이 없습니다.

Queue: [F]

6단계: 큐에서 맨 앞의 F를 꺼냅니다. F를 방문합니다. 자식이 없습니다.

Queue: []

종료: 큐가 비었으므로 탐색을 종료합니다.

결과를 보세요. 큐에서 노드를 꺼내는 순서가 A -> B -> C -> D -> E -> F가 되었습니다.

이것이 바로 FIFO의 힘입니다. 큐에 B와 C가 먼저 들어왔기 때문에, D, E, F보다 먼저 처리될 수 있었던 거죠. 만약 큐가 아닌 다른 자료구조를 썼다면 이러한 '층별 순서'가 깨졌을 겁니다.

**스택(Stack)**을 사용한다면 LIFO (Last-In, First-Out) 원리에 따라 A의 자식들 중 나중에 들어간 C가 먼저 처리됩니다. 이 경우 탐색 순서는 A -> B -> D -> E -> C -> F가 되어 **DFS (깊이 우선 탐색)**와 유사한 결과가 나옵니다.

따라서, BFS의 핵심인 '동일 레벨 우선 탐색'을 구현하기 위해 '먼저 들어간 노드(먼저 발견된 노드)를 먼저 처리해야 한다'는 원칙을 지켜주는 큐를 사용하는 것입니다.
