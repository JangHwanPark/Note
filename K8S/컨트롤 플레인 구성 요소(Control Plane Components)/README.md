## 컨트롤 플레인이란 ?
- 쿠버네티스 클러스터 전체의 상태를 저장하고, 무엇을 어디에 띄울지 결정하는 관리 계층
- 사용자의 애플리케이션 컨테이너가 도는 곳은 워커 노드(Worker Node)이고, 컨트롤 플레인은 그 노드들에게 일을 나눠 주고 상태를 지켜본다. 컨트롤 플레인 구성 요소도 설치 방식에 따라 노드 위에서 Pod(스태틱 Pod)로 돌기도 한다
- 노드(Node)는 클러스터에 속한 컴퓨터 한 대(실제 서버나 가상 머신)이고, Pod는 쿠버네티스가 배포하는 가장 작은 단위로 컨테이너 하나 이상을 묶은 것이다
- 예전 자료에서는 마스터(Master), 마스터 컴포넌트라고 불렀다. 지금 공식 문서는 컨트롤 플레인(Control Plane)이라는 이름만 쓴다
- 이 노트는 [kubernetes.io의 Kubernetes Components](https://kubernetes.io/docs/concepts/overview/components/) 문서를 기준으로 정리했다(2026-10-22 확인)

### 컨트롤 플레인 (Control Plane)
control은 통제, plane은 평면, 층이다.
네트워크 장비에서 패킷을 실제로 나르는 층(data plane)과 경로를 결정하는 층(control plane)을 나눠 부르던 말을 가져왔다. 쿠버네티스에서도 결정하는 층과 실행하는 층(노드)을 나눈다는 뜻이다.

공항 관제탑과 활주로에 비유할 수 있다. 관제탑(컨트롤 플레인)은 어느 비행기를 어느 활주로에 보낼지 정하고, 실제로 비행기가 뜨고 내리는 곳은 활주로(워커 노드)다.

## 컨트롤 플레인 구성 요소
| 구성 요소 | 하는 일 | 비고 |
| --- | --- | --- |
| kube-apiserver | 쿠버네티스 HTTP API를 여는 핵심 서버. 모든 요청이 이곳을 거치며, 요청의 인증과 인가, 검증을 처리한다 | 다른 구성 요소도 이 서버를 통해서만 상태를 읽고 쓴다 |
| etcd | API 서버의 모든 데이터를 저장하는 일관성 있고 가용성이 높은 키-값 저장소 | 클러스터 상태의 원본이라 백업 대상이다 |
| kube-scheduler | 아직 노드가 정해지지 않은 Pod를 찾아 알맞은 노드에 배정한다 | 배정만 하고 실행은 하지 않는다 |
| kube-controller-manager | 여러 컨트롤러를 실행해 원하는 상태와 실제 상태를 맞춘다(예: Pod 개수 유지) | |
| cloud-controller-manager | AWS, GCP 같은 클라우드와 연동한다(로드 밸런서 생성, 노드 상태 확인 등) | 선택 구성 요소. 클라우드가 아니면 없다 |

<br/>

## 노드 구성 요소
| 구성 요소 | 하는 일 | 비고 |
| --- | --- | --- |
| kubelet | 노드마다 실행되며 Pod와 그 안의 컨테이너가 실제로 돌고 있게 한다 | 모든 노드에서 도는 에이전트 |
| kube-proxy | 노드에 Service를 구현하는 네트워크 규칙을 유지한다 | 선택 구성 요소. 같은 일을 하는 네트워크 플러그인을 쓰면 없을 수 있다 |
| 컨테이너 런타임 | 컨테이너를 실제로 실행하는 소프트웨어(예: containerd, CRI-O) | |

<br/>

## 문제 풀이
### 컨트롤 플레인 구성 요소 설명으로 틀린 것은?
1. etcd: 쿠버네티스에 필요한 모든 데이터를 저장하는 데이터베이스 역할
2. kube-apiserver: 클러스터로 온 요청이 유효한지 검사한다
3. kube-scheduler: 클러스터 안 모든 노드에서 실행되는 쿠버네티스 에이전트다
4. kube-controller-manager: Pod를 관찰하며 개수를 보장한다

정답은 3번이다. kube-scheduler는 컨트롤 플레인에서 돌며 새 Pod를 어느 노드에 둘지 정한다. 모든 노드에서 실행되는 에이전트는 kubelet이다.

### 워커 노드 구성 요소가 아닌 것은?
1. kubelet
2. kube-proxy
3. 컨테이너 런타임
4. cloud-controller-manager

정답은 4번이다. cloud-controller-manager는 컨트롤 플레인 구성 요소로, 클러스터를 클라우드 서비스의 자원(로드 밸런서, 노드 등)과 연결한다.
