# FSD(Feature-Sliced Design)
FSD(Feature-Sliced Design)는 프론트엔드 아키텍처로 애플리케이션의 코드를 특정 규칙에 따라 `슬라이스(Slice)`라는 단위로 나누어 모듈화하고 구성하는 방법론으로, 특히 복잡성이 높은 대규모 프론트엔드 프로젝트의 확장성과 유지보수성을 높이는 데 중점을 둔다.

FSD는 코드를 수평적인 `레이어(Layer)`와 수직적인 `슬라이스(Slice)`로 나누어 관리

수평적 구조 (레이어)
코드의 책임에 따라 계층을 나눕니다. 의존성(참조)은 항상 상위 -> 하위로만 흐릅니다.

직적 구조 (슬라이스)
코드를 기능 단위로 나눕니다. 한 기능(슬라이스)은 다른 기능(슬라이스)의 내부를 직접 참조하지 않습니다.

슬라이스 예시: features/auth, features/user, entities/study-room

FSD는 이러한 구조를 통해 코드가 특정 레이어나 슬라이스에 고립되도록 강제하여, 순환 참조를 방지하고 모듈 간의 결합도(Coupling)를 낮추는 것을 목표로 합니다.

| 레이어          | 역할(책임)                               | 예시                                          |
| ------------ | ------------------------------------ | ------------------------------------------- |
| **App**      | 전역 설정, 라우팅, 전역 Provider 초기화          | `main.js`, `App.tsx`, 전역 컨텍스트 초기화           |
| **Pages**    | 페이지 단위의 조합 및 레이아웃 구성                 | `/login`, `/dashboard`, 각 페이지의 컴포넌트 조합      |
| **Features** | 사용자 시나리오 및 비즈니스 로직 구현                | 로그인 폼 제출, 스터디룸 생성 로직, 비즈니스 로직 훅             |
| **Entities** | 핵심 도메인 모델, DTO/Repository, 도메인 객체 정의 | `User`, `StudyRoom` 도메인, API Repository 구현체 |
| **Shared**   | 재사용 가능한 유틸리티 및 UI 요소                 | 버튼, 훅, API 클라이언트, 공통 타입                     |
