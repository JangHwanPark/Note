## SaaS란 ?
- SaaS(Software as a Service, 서비스형 소프트웨어)는 소프트웨어를 내 컴퓨터에 설치하지 않고, 제공자가 운영하는 것을 인터넷으로 접속해 쓰는 방식이다
- 보통 월이나 연 단위 구독료를 내고 쓴다
- 클라우드 서비스를 나누는 세 모델(SaaS, PaaS, IaaS) 중 사용자가 관리할 것이 가장 적은 모델이다
- 세 모델의 정의는 미국 국립표준기술연구소(NIST)의 클라우드 정의 문서(SP 800-145, 2011년 9월)를 기준으로 정리했다

### 서비스형 (as a Service)
service는 남을 위해 해 주는 일, 봉사다. as a Service는 물건을 파는 대신 그 물건이 하는 일을 서비스로 제공한다는 뜻이다.
소프트웨어에서는 프로그램을 사서 설치하는 대신, 제공자가 돌리고 있는 프로그램을 빌려 쓰는 것을 말한다.

차를 사는 대신 택시를 타는 것과 같다. 정비, 보험, 주유는 택시 회사가 맡고, 승객은 목적지만 말하면 된다.

예로 Gmail, Notion, Figma, Slack, Dropbox, Salesforce가 있다.

<br/>

## 왜 쓸까
설치형 소프트웨어는 사용자가 설치, 업데이트, 백업, 서버 관리를 직접 해야 한다. SaaS는 이 일을 제공자가 맡는다. 사용자는 브라우저나 앱으로 접속하기만 하면 되고, 새 기능도 제공자가 서버에 올리면 모두에게 바로 적용된다.

대신 데이터가 제공자의 서버에 저장되고, 제공자가 서비스를 바꾸거나 멈추면 사용자가 손쓸 수 없다. 구독을 끊으면 쓸 수 없게 된다는 점도 설치형과 다르다.

<br/>

## SaaS, PaaS, IaaS의 차이
NIST SP 800-145는 세 서비스 모델을 사용자가 무엇을 직접 관리하느냐로 구분한다. 아래로 갈수록 사용자가 관리할 범위가 넓어진다.

| 모델 | 제공하는 것 | 사용자가 관리하는 것 | 예시 |
| --- | --- | --- | --- |
| SaaS | 완성된 애플리케이션 | 사용자별 설정 정도 | Gmail, Notion, Slack |
| PaaS | 애플리케이션을 올려 돌릴 플랫폼(실행 환경, 런타임) | 내가 만든 애플리케이션과 그 설정 | Vercel, Heroku |
| IaaS | 처리 능력, 저장소, 네트워크 같은 기본 컴퓨팅 자원 | 운영체제, 저장소, 배포한 애플리케이션, 일부 네트워크 구성 요소(방화벽 등) | AWS EC2, Google Compute Engine |

제공하는 것과 사용자가 관리하는 것은 NIST SP 800-145의 정의를 옮긴 것이다. IaaS에서도 그 아래의 물리 인프라(데이터센터, 하드웨어)는 제공자가 관리한다. 흔히 보는 비교 그림에는 IaaS 사용자가 미들웨어도 관리한다고 나오지만, 미들웨어는 NIST 정의에 나오는 말이 아니다. 예시 서비스 열도 NIST 문서가 아니라 흔히 드는 예이고, 실제 서비스는 경계가 섞인 경우가 많다.
