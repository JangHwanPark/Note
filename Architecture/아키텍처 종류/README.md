시스템 아키텍처나 소프트웨어 아키텍처 중에서도 특히 폴더 및 코드 구조에 초점을 맞춘 것입니다.

가장 정확한 용어는 폴더 아키텍처보다는 코드베이스 아키텍처 또는 모듈 아키텍처이며, 개발팀 내부에서는 흔히 폴더 구조 컨벤션이나 프로젝트 구조

아키텍처 용어 구분
용도에 따라 다음과 같이 구분할 수 있습니다.

| 용어 | 정의 | 초점 |
| :--- | :--- | :--- |
| **시스템 아키텍처** | 전체 IT 시스템의 컴포넌트(서버, DB, 네트워크, 외부 서비스) 배치 및 상호작용 방식. | 인프라, 기술 스택, 컴포넌트 간 통신. |
| **소프트웨어 아키텍처** | 단일 소프트웨어 내 레이어, 모듈, 컴포넌트의 분리 원칙과 상호작용 정의. (예: Layered, Microservices, Clean, Hexagonal) | 설계 원칙, 레이어 분리. |
| **폴더/코드베이스 아키텍처** | 소프트웨어 아키텍처 원칙을 실제로 폴더와 파일 구조에 매핑한 것. | 파일/폴더 명명법, 배치, 코드 분할 방식. |

결론: 가장 적합한 용어
현재 작성하고 계신 문서는 다음과 같은 이름으로 명시하는 것이 가장 적절합니다.

가장 공식적인 명칭: 코드베이스 아키텍처 (Codebase Architecture)

현업에서 많이 쓰는 명칭: 프론트엔드/백엔드 폴더 구조 컨벤션

현재의 맥락을 반영: 모듈 및 피쳐 분리 컨벤션

현재 문서의 내용(FSD, Clean Architecture 레이어, 네이밍 규칙)을 고려할 때, "모듈 아키텍처 및 네이밍 컨벤션" 또는 **"코드베이스 아키텍처"**가 가장 적합합니다.
