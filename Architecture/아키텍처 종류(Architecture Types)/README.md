## 아키텍처라는 말이 가리키는 범위
- 아키텍처는 무엇을 대상으로 하느냐에 따라 시스템 아키텍처, 소프트웨어 아키텍처, 코드베이스 아키텍처로 나눠 부를 수 있다
- 폴더와 파일을 어떻게 나눌지 정하는 문서는 이 중 코드베이스 아키텍처에 해당한다
- 이 세 이름은 표준으로 정해진 분류가 아니라 실무에서 범위를 구분하려고 흔히 쓰는 말이다

<br/>

## 세 가지 범위
| 용어 | 다루는 것 | 예시 |
| --- | --- | --- |
| 시스템 아키텍처 | 서버, DB, 네트워크, 외부 서비스 같은 구성 요소를 어떻게 배치하고 연결하는지 | 웹 서버와 API 서버를 나누고 그 앞에 로드 밸런서를 둔다 |
| 소프트웨어 아키텍처 | 프로그램 하나 안의 레이어와 모듈을 어떻게 나누고, 서로 어떻게 의존하게 할지 | 레이어드, 클린, 헥사고날 아키텍처 |
| 코드베이스 아키텍처 | 소프트웨어 아키텍처의 원칙을 실제 폴더, 파일 이름, 배치 규칙으로 옮긴 것 | FSD의 레이어와 슬라이스 폴더, 파일 이름 규칙 |

위로 갈수록 범위가 넓고, 아래로 갈수록 코드에 가깝다. 마이크로서비스(MSA)처럼 서비스를 어떻게 나눌지에 대한 결정은 시스템 아키텍처와 소프트웨어 아키텍처에 걸쳐 있다.

<br/>

## 폴더 구조 문서를 무엇이라 부를까
프론트엔드에서 `src/` 아래를 어떻게 나눌지 정하는 문서는 "폴더 아키텍처"라고 부르기도 하지만, 범위를 드러내려면 코드베이스 아키텍처나 모듈 아키텍처가 더 정확하다. 팀 안에서는 폴더 구조 컨벤션, 프로젝트 구조라고도 부른다.

이 폴더의 노트를 이 기준으로 나누면 아래와 같다.

- 서비스와 시스템 구조: [BFF](../BFF(Backend%20For%20Frontend)/README.md), [SaaS](../SaaS(Software%20as%20a%20Service)/README.md)
- 코드베이스 아키텍처: [FSD](../FSD(Feature-Sliced%20Design)/README.md), [모노레포](../모노레포(Monorepo)/README.md)
