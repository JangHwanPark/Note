## 값에 의한 전달과 참조에 의한 전달이란 ?
- 함수를 부를 때 넘긴 값(인자)이 함수 안의 이름(매개변수)과 어떻게 이어지는지를 정하는 규칙이다
- 값에 의한 전달은 인자의 값을 복사해 넘기고, 참조에 의한 전달은 호출한 쪽의 변수 자체를 넘긴다
- 자바, 자바스크립트, 파이썬처럼 객체를 참조로 다루는 언어는 객체를 가리키는 참조값을 값으로 넘긴다. 값에 의한 전달의 한 형태지만 결과가 달라 보여서 공유에 의한 전달이라고 따로 부르기도 한다. 이 노트에서 가장 헷갈리는 부분이다

변수가 이름, 주소, 값을 가진다는 것과 값을 직접 담는 방식과 참조로 담는 방식의 차이는 [변수 노트의 값을 담는 두 가지 방식](../변수(Variable)/README.md#값을-담는-두-가지-방식)에서 다뤘다. 함수를 부르면 매개변수가 새 스택 프레임 안에 자리를 잡는다는 것은 [스택 프레임 노트의 프레임 하나에 들어가는 것](../스택%20프레임(Stack%20Frame)/README.md#프레임-하나에-들어가는-것)에서 다뤘다. 이 노트는 그 둘을 이어, 인자가 그 자리에 어떤 모습으로 들어가는지를 본다.

<br/>

## 단어의 뜻
### 인자와 매개변수 (Argument, Parameter)
argument의 사전적 의미는 논거, 주장의 근거다. 수학에서는 함수에 넣는 값을 함수의 argument라고 불렀고, 프로그래밍도 이 뜻을 이어받았다. 공학적으로 인자(Argument)는 함수를 부르는 쪽이 괄호 안에 넣어 건네는 값이나 식이다. `add(x, 3)` 의 `x` 와 `3` 이 인자다.

parameter의 사전적 의미는 어떤 체계의 조건을 정하는 요소다. 공학적으로 매개변수(Parameter)는 함수를 정의할 때 적어 둔 이름으로, 호출될 때 인자를 받아 함수 안에서 쓰는 변수다. `function add(a, b)` 의 `a` 와 `b` 가 매개변수다. 이후로는 인자, 매개변수로 쓴다.

### 전달 (Pass)
pass는 건네다라는 뜻이다. 공학적으로 인자 전달(Argument Passing)은 호출하는 쪽의 인자를 호출되는 함수의 매개변수에 이어 주는 일을 말한다. 무엇을 건네느냐가 방식마다 다르다. 값의 복사본을 건넬 수도 있고, 변수 자체를 건넬 수도 있다.

호출(call)과 묶어 값에 의한 호출(Call by Value), 참조에 의한 호출(Call by Reference)이라고도 부른다. 이 노트에서는 전달로 통일한다.

<br/>

## 왜 구분해야 할까
함수 안에서 매개변수를 바꿨을 때, 그 변화가 함수를 부른 쪽에도 보이느냐가 방식마다 다르다.

이걸 모르면 두 방향으로 틀린다. 함수가 원본을 고쳐 주리라 기대했는데 원본이 그대로이거나, 반대로 원본은 건드리지 않으리라 믿고 넘겼는데 함수가 끝나고 보니 원본이 바뀌어 있다. 뒤쪽은 [함수 설계 원리 노트의 부수효과](../함수%20설계%20원리(Function%20Design%20Principles)/README.md#부수효과-side-effect)가 생기는 흔한 경로이기도 하다. 함수를 쓰는 쪽에서 보면 넘긴 값이 안전한지가 곧 이 규칙에 달려 있다.

<br/>

## 값에 의한 전달 (Pass by Value)
### 정의
함수를 부를 때 인자의 값을 계산하고, 그 값을 매개변수에 복사해 넣는 방식이다. 매개변수는 인자와 따로 있는 새 변수이고, 처음 값만 같다.

이 노트에서는 고치는 동작을 보여 주려고 변수 노트의 사물함 속 물건을 문서로 바꿔 본다. 사물함으로 보면, 내 사물함 속 문서를 복사기로 한 부 복사해 그 복사본을 건네는 것과 같다. 받은 사람이 복사본에 낙서를 해도 내 사물함의 원본은 그대로다.

### 동작
1. 호출하는 쪽에서 인자 식을 계산해 값을 얻는다
2. 호출된 함수의 스택 프레임에 매개변수 자리가 생긴다
3. 1에서 얻은 값을 그 자리에 복사한다
4. 함수 안에서 매개변수에 무엇을 대입하든 바뀌는 것은 프레임 안의 복사본이다. 함수가 끝나면 프레임과 함께 사라진다

C 표준이 이 방식을 그대로 적고 있다. 함수를 부를 준비를 하면서 인자를 계산하고, 각 매개변수에 대응하는 인자의 값을 대입한다(C11 6.5.2.2 4항). 같은 절의 각주는 함수가 매개변수의 값을 바꿔도 그 변화가 인자의 값에 영향을 줄 수 없다고 덧붙인다(각주 93).

### 예시
아래 예시는 Windows 11에서 2026-10-28에 Python 3.13.14, Node.js v24.22.1, Java 17.0.12로 실행했다. 숫자 하나를 넘기고 함수 안에서 1을 더해 본다.

```python
def add_one(n):
    n = n + 1
    print("함수 안:", n)

x = 10
add_one(x)
print("함수 밖:", x)
```

```
함수 안: 11
함수 밖: 10
```

같은 코드를 자바스크립트와 자바로 옮겨 실행해도 `함수 안: 11`, `함수 밖: 10` 이 나왔다. 함수 안의 `n` 은 바뀌었지만 밖의 `x` 는 그대로다. 숫자 같은 단순한 값에서는 세 언어 모두 값에 의한 전달과 같은 결과를 낸다(파이썬은 속사정이 조금 다른데, 아래 공유에 의한 전달에서 본다).

### 장단점
원본이 안전하다. 함수가 무슨 짓을 해도 넘긴 변수는 바뀌지 않으니, 함수를 부르는 쪽은 함수 안을 들여다보지 않아도 된다.

대신 값이 크면 복사 비용이 든다. 정수 하나는 문제가 없지만, 큰 구조체(Struct, 여러 값을 하나로 묶은 자료형)를 통째로 값으로 넘기면 호출할 때마다 그만큼을 복사한다. C의 배열은 인자로 넘기면 첫 원소를 가리키는 포인터로 바뀌어 통째로 복사되지 않는다. 이 규칙은 TODO로 미룬다. 그리고 함수가 호출한 쪽의 변수를 바꿔 주는 일(두 변수의 값을 맞바꾸기 등)은 이 방식만으로는 할 수 없다.

## 참조에 의한 전달 (Pass by Reference)
### 정의
인자로 쓴 변수 자체를 함수에 넘기는 방식이다. 매개변수는 새 변수가 아니라 호출한 쪽 변수의 또 다른 이름(별칭, Alias)이 된다. 그래서 함수 안에서 매개변수에 새 값을 대입하면 호출한 쪽 변수의 값이 바뀐다.

사물함으로 보면, 내 사물함에 상대의 이름표를 하나 더 붙여 주는 것과 같다. 사물함은 하나이고 이름표만 둘이다. 상대가 그 사물함의 문서를 통째로 다른 문서로 바꿔 넣으면, 나중에 내 이름표로 열어 봐도 바뀐 문서가 들어 있다.

### 동작
흔히 컴파일러가 인자 변수의 주소를 함수에 넘기고, 함수 안에서 매개변수를 쓰는 곳마다 그 주소를 따라가 원래 변수를 읽고 쓰도록 번역하는 방식으로 설명한다. 프로그래머는 주소를 직접 다루지 않고 평범한 변수처럼 쓴다. 다만 C++ 표준은 참조가 저장 공간을 차지하는지조차 정하지 않으므로([dcl.ref] 4항), 실제로 어떻게 번역할지는 컴파일러가 정한다.

중요한 것은 인자로 변수(왼쪽 값이 될 수 있는 것)를 넘겨야 한다는 점이다. 변수 노트의 [왼쪽 값과 오른쪽 값](../변수(Variable)/README.md#왼쪽-값과-오른쪽-값)에서 본 것처럼 `5` 같은 값에는 쓸 위치가 없으므로, 고칠 수 있는 참조로 넘길 수 없다.

### C++ 참조 매개변수
C++는 매개변수 타입에 `&` 를 붙여 참조 매개변수를 만든다. C++ 표준은 참조를 객체의 이름으로 생각해도 된다고 설명한다([dcl.ref]의 주석). 함수를 부르면 각 매개변수가 대응하는 인자로 초기화되는데([expr.call]), 매개변수가 참조이면 인자로 넘긴 변수에 묶인다.

```cpp
#include <iostream>

void swap(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 1, y = 2;
    swap(x, y);
    std::cout << x << " " << y << "\n";
}
```

`a` 와 `b` 는 `x` 와 `y` 의 다른 이름이므로, 함수가 끝나면 `x` 는 2, `y` 는 1이 된다. 이 예시는 실행 환경에 C++ 컴파일러가 없어 실행하지 못했다(확인 필요). 위 설명은 표준의 규칙에 따른 것이다.

### C의 포인터는 참조에 의한 전달이 아니다
C에는 참조에 의한 전달이 없다. 앞에서 본 대로 C의 인자는 언제나 값으로 복사된다. 대신 변수의 주소를 값으로 꺼내 넘기면 비슷한 효과를 낼 수 있다. 주소를 담는 변수를 포인터(Pointer)라고 한다. pointer는 가리키는 것이라는 뜻이다.

C++ 예시의 `int& a` 처럼 타입에 붙은 `&` 는 참조를 뜻하고, 아래 C 예시의 `&x` 처럼 변수 앞에 붙은 `&` 는 그 변수의 주소를 꺼내는 연산자다. 기호만 같고 뜻이 다르다.

```c
#include <stdio.h>

void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main(void) {
    int x = 1, y = 2;
    swap(&x, &y);
    printf("%d %d\n", x, y);
}
```

`&x` 는 `x` 의 주소이고, `*a` 는 `a` 에 담긴 주소를 따라가 그곳의 값을 뜻한다. 함수는 주소의 복사본을 받았지만, 복사본이라도 같은 곳을 가리키므로 그곳의 값을 바꿀 수 있다. 그래서 `x` 와 `y` 가 맞바뀐다. C 표준의 각주 93도 매개변수를 바꿔서는 인자에 영향을 줄 수 없지만, 객체를 가리키는 포인터를 넘기면 함수가 그 객체의 값을 바꿀 수 있다고 쓴다. 이 예시도 C 컴파일러가 없어 실행하지 못했다(확인 필요).

C++ 참조와 비교하면 차이가 보인다. C에서는 호출하는 쪽이 `&x` 로 주소를 직접 꺼내고, 함수 안에서도 `*a` 로 직접 따라간다. 넘어가는 것은 어디까지나 주소라는 값이다. 함수 안에서 `a = NULL;` 처럼 포인터 자체에 새 값을 대입하면 함수 안의 복사본만 바뀌고 밖의 `x` 와는 상관이 없다. C++ 참조는 그런 중간 단계가 코드에 드러나지 않고, 매개변수가 곧 원래 변수다.

### 장단점
큰 값을 복사하지 않고 넘길 수 있고, 함수가 호출한 쪽 변수를 바꿔 줄 수 있다. 결과를 여러 개 돌려줘야 할 때 매개변수로 받아 채우는 식으로 쓴다.

대신 호출하는 코드 `swap(x, y)` 만 보고는 `x` 가 바뀔지 알 수 없다. 함수 선언을 봐야 한다. 그래서 C++에서는 복사 비용은 피하되 바꾸지는 않겠다는 뜻으로 `const` 를 붙인 참조(`const int&` 처럼)를 많이 쓴다. 자세한 규칙은 TODO로 미룬다.

## 공유에 의한 전달 (Call by Sharing)
### 정의
자바, 자바스크립트, 파이썬에서 객체를 넘길 때 쓰는 방식이다. 이 언어들에서 객체를 담은 변수는 객체 자체가 아니라 객체를 가리키는 참조를 담고 있다([변수 노트의 위치를 담기](../변수(Variable)/README.md#위치를-담기-참조)). 함수를 부르면 그 참조가 값으로 복사되어 매개변수에 들어간다. 그래서 인자와 매개변수가 같은 객체를 함께 쓰게 된다.

이름이 여럿이다. 참조값을 값으로 전달한다고도 하고, 객체를 나눠 쓴다는 뜻에서 공유에 의한 전달(Call by Sharing)이라고도 한다. 파이썬 공식 튜토리얼은 객체 참조에 의한 호출(Call by Object Reference)이 더 나은 표현이라고 적는다. 이 노트에서는 공유에 의한 전달로 부른다. 영문은 Call by Sharing이 널리 쓰이는 이름이라 그대로 둔다. 이 이름이 처음 어디서 쓰였는지는 확인하지 못했다(확인 필요).

변수 노트의 쪽지로 보면, 문서가 들어 있는 사물함 번호를 쪽지에 베껴 건네는 것과 같다. 쪽지는 두 장이 되었지만 사물함은 하나다. 상대가 쪽지를 보고 사물함에 가서 문서에 글을 더 쓰면 나도 그 글을 본다. 하지만 상대가 자기 쪽지의 번호를 지우고 다른 번호를 적어도 내 쪽지는 그대로다.

### 두 가지 동작이 다른 결과를 낸다
이 방식에서는 함수 안에서 무엇을 하느냐에 따라 결과가 갈린다.

- 매개변수를 따라가 객체의 내용을 고치면 호출한 쪽에서도 보인다. 같은 객체이기 때문이다
- 매개변수에 새 객체를 대입하면 호출한 쪽에는 아무 일도 없다. 바뀐 것은 함수 안의 참조 복사본뿐이다

자바스크립트로 보면 아래와 같다.

```js
function changeName(user) {
  user.name = 'Kim';
}

function replaceUser(user) {
  user = { name: 'Lee' };
}

const me = { name: 'Park' };
changeName(me);
console.log(me.name); // Kim
replaceUser(me);
console.log(me.name); // Kim
```

`changeName` 은 `me` 가 가리키는 객체의 속성을 고쳤으므로 밖에서도 `Kim` 이 보인다. `replaceUser` 는 매개변수 `user` 가 새 객체를 가리키게 바꿨을 뿐이라 `me` 는 여전히 원래 객체를 가리키고, 그 이름은 앞에서 바꾼 `Kim` 이다. 참조에 의한 전달이었다면 두 번째 출력은 `Lee` 였을 것이다.

파이썬과 자바도 같은 결과를 냈다.

```python
def change_item(items):
    items.append(4)

def replace_list(items):
    items = [100, 200]

nums = [1, 2, 3]
change_item(nums)
print(nums)  # [1, 2, 3, 4]
replace_list(nums)
print(nums)  # [1, 2, 3, 4]
```

```java
static void changeName(User user) {
    user.name = "Kim";
}

static void replaceUser(User user) {
    user = new User("Lee");
}

// main 안에서
User me = new User("Park");
changeName(me);
System.out.println(me.name); // Kim
replaceUser(me);
System.out.println(me.name); // Kim
```

자바 예시는 `User` 클래스(문자열 필드 `name` 하나)와 `main` 메서드를 갖춘 파일로 실행했고, 위에는 필요한 부분만 옮겼다.

### 공식 문서는 어떻게 말하나
네 문서 모두 같은 그림을 그린다.

자바 언어 명세(JLS)는 값의 종류를 기본형 값과 참조값 두 가지로 나누고, 둘 다 변수에 담기고 인자로 넘어간다고 쓴다(4.1절). 참조값은 객체를 가리키는 포인터라고 설명하며, 두 변수가 같은 객체의 참조를 담고 있으면 한 변수로 바꾼 객체 상태를 다른 변수로 볼 수 있다고 한다(4.3.1절). 그리고 메서드를 호출하면 인자 식의 값이 새로 만든 매개변수 변수를 초기화한다고 쓴다(8.4.1절). 넘어가는 것은 참조값이고, 매개변수는 새 변수라는 뜻이다.

MDN의 자바스크립트 함수 안내서는 매개변수가 본질적으로 값으로 넘어간다고 쓴다. 함수 안에서 매개변수에 완전히 새 값을 대입해도 호출한 쪽에는 반영되지 않지만, 객체를 넘기고 함수가 그 객체의 속성을 바꾸면 그 변화는 함수 밖에서도 보인다고 덧붙인다.

파이썬 튜토리얼은 인자가 값에 의한 호출로 넘어가되 그 값은 언제나 객체의 참조라고 쓴다(4.8절). 각주에서는 가변 객체를 넘기면 함수가 바꾼 내용을 호출한 쪽이 보게 되므로 객체 참조에 의한 호출이 더 나은 표현이라고 한다. 파이썬 FAQ는 인자가 대입으로 넘어가며, 대입은 객체의 참조를 만들 뿐이라 호출한 쪽 이름과 함수 안 이름 사이에 별칭 관계가 없고, 따라서 참조에 의한 호출이 없다고 정리한다.

### 바꿔치기로 구분하기
어떤 언어가 참조에 의한 전달인지 헷갈리면 두 변수의 값을 맞바꾸는 함수를 짜 보면 된다. 참조에 의한 전달이면 C++ 예시처럼 밖의 변수가 맞바뀐다. 값이나 참조값의 복사본을 넘기는 언어에서는 함수 안의 이름만 맞바뀌고 밖은 그대로다.

```python
def swap(a, b):
    a, b = b, a

x, y = 1, 2
swap(x, y)
print(x, y)  # 1 2
```

자바스크립트로 같은 함수를 짜서 실행해도, 자바로 `int` 두 개를 받는 같은 함수를 짜서 실행해도 `1 2` 가 나왔다.

### 파이썬의 숫자는 왜 안 바뀌나
파이썬에서는 숫자도 객체이고, 변수는 그 객체의 참조를 담는다. 그러면 앞의 `add_one` 예시에서도 `n` 과 `x` 가 같은 객체를 가리키는데 왜 밖의 `x` 는 그대로일까.

`n = n + 1` 은 객체의 내용을 고치는 동작이 아니라, 계산 결과인 다른 숫자 객체를 `n` 이 가리키게 하는 동작이기 때문이다. 앞에서 본 두 동작 가운데 두 번째, 매개변수에 새 객체를 대입하는 경우다. 파이썬의 숫자는 내용을 고칠 수 없는 불변 객체(Immutable Object)라서 첫 번째 동작이 애초에 불가능하다. 결과만 보면 값에 의한 전달과 같아 보이는 이유다.

파이썬 관점의 자세한 설명은 [가변과 불변 자료형 노트의 함수에 값을 넘길 때](../../Python/16_가변과%20불변%20자료형(Mutable%20and%20Immutable)/README.md#함수에-값을-넘길-때)에 있다. 그 노트에서 매개변수를 객체에 붙는 이름표로 비유하는데, 이 노트의 쪽지에 해당한다. 이 노트에서 참조에 의한 전달을 설명할 때 쓴 이름표는 사물함(변수 자리)에 붙는 것이라 서로 다르다. 기본값에 가변 객체를 쓰면 생기는 문제는 같은 노트의 [기본값에 가변 객체를 쓰면 생기는 문제](../../Python/16_가변과%20불변%20자료형(Mutable%20and%20Immutable)/README.md#기본값에-가변-객체를-쓰면-생기는-문제)에서 다뤘다.

### 왜 참조에 의한 전달로 오해할까
자바는 명세에서 객체를 담은 변수가 참조값을 담는다고 설명하고, 자바스크립트도 흔히 그렇게 설명한다. 그리고 실제로 함수 안에서 객체를 고치면 밖에서도 바뀐다. 이 두 가지가 합쳐져 참조에 의한 전달이라고 부르기 쉽다. 하지만 참조에 의한 전달에서 참조는 호출한 쪽 변수에 대한 참조이고, 공유에 의한 전달에서 참조는 객체에 대한 참조다. 무엇을 가리키느냐가 다르다. 변수에 대한 참조가 없으니 함수는 호출한 쪽 변수가 다른 객체를 가리키게 만들 수 없다.

## 세 방식 비교

| 방식 | 함수에 넘어가는 것 | 매개변수에 새 값을 대입하면 | 매개변수로 객체 내용을 고치면 | 예 |
|---|---|---|---|---|
| 값에 의한 전달 | 값의 복사본 | 밖은 그대로 | 복사본만 바뀌고 밖은 그대로 | C의 모든 인자, 자바의 기본형 |
| 참조에 의한 전달 | 호출한 쪽 변수 자체(별칭) | 밖의 변수도 바뀐다 | 밖에서도 보인다 | C++의 `&` 매개변수 |
| 공유에 의한 전달 | 객체를 가리키는 참조의 복사본 | 밖은 그대로 | 밖에서도 보인다 | 자바, 자바스크립트, 파이썬의 객체 |

공유에 의한 전달은 넘기는 값이 참조라는 점만 다를 뿐, 값에 의한 전달의 한 갈래로 보기도 한다. 매개변수에 새 값을 대입했을 때의 결과가 두 줄에서 같은 이유다. C의 포인터 전달은 표에서 값에 의한 전달 줄에 속한다. 넘기는 값이 주소일 뿐이다. 주소를 따라가 그곳을 고치면 밖에서 보인다는 점에서 공유에 의한 전달과 닮았다.

<br/>

## 원본을 지키고 싶을 때
공유에 의한 전달에서 함수가 넘겨받은 객체를 고치면 호출한 쪽 객체가 바뀐다. 원본을 건드리지 않으려면 함수 안에서 복사본을 만들어 그것을 고치고, 결과를 돌려준다.

```python
def change_copy(items):
    items = items.copy()
    items.append(4)
    return items

nums = [1, 2, 3]
result = change_copy(nums)
print(nums)    # [1, 2, 3]
print(result)  # [1, 2, 3, 4]
```

첫 줄의 `items = items.copy()` 로 매개변수가 새 리스트를 가리키게 한 뒤 고쳤으므로 `nums` 는 그대로다. 다만 `copy()` 는 바깥 리스트만 새로 만든다. 리스트 안에 또 리스트가 있으면 안쪽은 여전히 나눠 쓴다. 이 차이(얕은 복사와 깊은 복사)는 [가변과 불변 자료형 노트의 복사](../../Python/16_가변과%20불변%20자료형(Mutable%20and%20Immutable)/README.md#복사)에서 다뤘다.

넘겨받은 값을 고치지 않고 새 값을 만들어 돌려주는 함수는 [함수 설계 원리 노트](../함수%20설계%20원리(Function%20Design%20Principles)/README.md#순수-함수와-불순-함수)에서 본 순수 함수에 가까워진다. 인자 전달 방식을 몰라도 안전하게 쓸 수 있는 함수다.
