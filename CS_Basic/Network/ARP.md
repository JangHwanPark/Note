ping 192.168.1.20

ARP 는 2개의 패킷을 가지고 있다.  
목적지 주소를 모르면 ARP 캐시를 조회해보고 없다면 ARP 리퀘스트를 보낸다.

목적지의 맥 주소를 알고싶다면 ARP 의 도움을 받아야함.
라우터는 브로드캐스트 방식으로 폐기한다.

1. ARP 캐시테이블 조회 (1.20의 맥주소)
2. ARP Request (브로드 캐스트 받식)
3. ARP Reply (유니캐스트 방식)
4. 수신받는 정보를 ARP 캐시테이블에 목적지(1.20) 맥 주소 등록
5. echo request (질문)
6. echo reply (질문에 대한 응답)

## 스위치

## 게이트웨이 왜써 ?
목적지가 외부망일때 사용한다. (외부로 나갈때 사용함)
예를들어 21.7 -> 34.250 같이 외부 망에 사용
없는걸 나에게 물어보니 ? (Destination host unreachable)

ex _ 특정 사이트(외부망 - 네이버 등)접속시 게이트웨이를 이용하여 접속한다.
실제 운영할때는 게이트웨이가 여러개가 있을 수 있다.

게이트웨이가 ARP Request 를 밖으로 절대 안내보낸다.

## 라우팅 테이블
라우팅테이블에는 브로드 캐스트 주소가 기록되지않는다.

## 스위치 (2계층 장비)
스위치는 IP를 확인할수 없음
스위치장비는 수신지 맥주소만 보고있음
목적지 정보 없어도 괜찮음
스위치가 브로드캐스트 패킷을 받으면 플러딩

## 라우터 (3계층)
IP만 확인함
라우터 전송방법 1가지 (Forwarding) 하나의 송신지 포트에서 하나의 수진지 포트로 트래픽 전송
라우터가 브로드 캐스트 패킷을 받으면 폐기한다.

## Media Translation (굉장히 중요)
3계층 이상의 장비에서 처리
-  패킷이 출발지에서 목적지까지 가는 동안 3계층 장비를 거칠 때마다 L2 헤더(프레임 헤더) 변경
- 3계층 주소(IP주소) 변환 없음
- 2 계층주소는 스위칭 환경에 따라 변환

## 암기
만약에 목적지가 외부망이면 Destination MAC 에는 목적지의 맥 주소가 오는게 아니라 게이트웨이의 맥 주소가 들어간다.

2 계층 주소는 계속 바뀜
3 계층 (IP Add)로 관제함

데이터 | 포트번호 | 솔신지 IP | 수신지 IP | 송신지 MAC | 수신지 MAC

문자주소를 아이피로 변환하는걸 DNS 라고한다.
