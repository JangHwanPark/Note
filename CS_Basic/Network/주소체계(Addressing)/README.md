## 주소체계란 ?
- 네트워크에서 장치와 목적지를 찾기 위해 붙이는 주소들의 규칙
- 장치마다 하드웨어에 붙은 물리적 주소(MAC 주소)와 네트워크가 정해 주는 논리적 주소(IP 주소)가 있고, 사람이 기억하기 쉽게 이름으로 부르는 도메인 이름이 그 위에 있다
- 서브넷 마스크는 IP 주소 안에서 어디까지가 네트워크이고 어디부터가 장치인지 나누는 기준이다

### 주소 (Address)
사전적 의미는 사람이 살거나 기관이 있는 곳을 행정 구역으로 나타낸 이름이다. 편지를 보낼 때 받는 사람을 찾아가는 기준이 된다.
공학적으로는 데이터를 받을 장치나 위치를 가리키는 식별 값이다. 네트워크에서는 데이터 묶음(패킷)에 출발지와 목적지 주소를 적어 보내고, 중간 장비들은 이 주소를 보고 어디로 넘길지 정한다.

<br/>

## 왜 주소가 여러 종류일까
택배를 떠올리면 된다. 송장에는 받는 사람의 집 주소가 적혀 있고, 택배는 지역 터미널을 거쳐 동네까지 간다. 동네에 도착한 뒤에는 기사가 그 집 사람이 누구인지 보고 건넨다.

네트워크도 같은 일을 두 단계로 나눠 한다.

1. 다른 네트워크까지 찾아가는 일은 IP 주소가 맡는다. IP 주소는 앞부분이 네트워크, 뒷부분이 장치를 나타낸다. 서로 다른 네트워크를 이어 길을 골라 주는 장비인 라우터(Router)는 앞부분만 보고 다음 경로를 고를 수 있다.
2. 같은 네트워크 안에서 실제 장치에 건네는 일은 MAC 주소가 맡는다. 그래서 IP 주소를 알아도 MAC 주소를 따로 알아내야 하고, 이 일을 하는 프로토콜이 [ARP](../ARP(Address%20Resolution%20Protocol)/README.md)다.

사람은 숫자로 된 IP 주소를 외우기 어려우니 그 위에 도메인 이름을 하나 더 둔다. 도메인 이름을 IP 주소로 바꾸는 일은 도메인 이름 시스템(DNS, Domain Name System)이 한다. 찾는 과정은 [DNS](../DNS(Domain%20Name%20System)/README.md) 문서에 정리했다.

| 구분 | 도메인 이름 | IP 주소 | MAC 주소 |
| --- | --- | --- | --- |
| 성격 | 사람이 부르는 이름 | 논리적 주소 | 물리적 주소 |
| 예 | www.example.com | 192.168.1.10 | 00:1A:2B:3C:4D:5E |
| 크기 | 가변 길이 문자열 | IPv4 32비트, IPv6 128비트 | 48비트 |
| 정해지는 곳 | 도메인 등록 | 연결한 네트워크(관리자가 직접, 또는 DHCP가 자동으로) | 랜카드 제조 시 |

DHCP(Dynamic Host Configuration Protocol)는 장치에 IP 주소를 자동으로 나눠 주는 프로토콜이다. 와이파이에 붙자마자 IP 주소가 생기는 것은 공유기가 DHCP로 나눠 주기 때문이다. 주소를 받는 과정은 [DHCP](../DHCP(Dynamic%20Host%20Configuration%20Protocol)/README.md) 문서에 정리했다.

<br/>

## MAC 주소
### MAC 주소 (Media Access Control Address)
MAC은 매체 접근 제어라는 뜻이다. 여러 장치가 같은 선(매체)을 나눠 쓸 때 누가 언제 보내고 누가 받을지 정하는 규칙이 MAC이고, 그 규칙에서 장치를 구분하는 값이 MAC 주소다.
공학적으로는 랜카드(NIC, Network Interface Card)에 제조할 때 기록되는 고유 번호다. 원래는 장치를 어느 네트워크에 연결하든 그대로라서 물리적 주소라고 부른다.

주민등록번호와 비슷하다. 원래는 어디로 이사해도 바뀌지 않고 그 사람 자체를 가리킨다.

### 구조
MAC 주소는 48비트(6바이트)다. 보통 8비트씩 끊어 16진수 두 자리로 쓴다.

```text
00:1A:2B : 3C:4D:5E
앞 24비트  뒤 24비트
제조사 번호  제조사가 매긴 일련번호
```

- 앞 24비트는 OUI(Organizationally Unique Identifier)다. 국제 전기전자 기술자 협회(IEEE, Institute of Electrical and Electronics Engineers)가 제조사에 나눠 주는 번호로, 제품이 많은 제조사는 여러 개를 받는다.
- 뒤 24비트는 제조사가 자기 제품에 매기는 일련번호다.

이렇게 나누면 제조사끼리 번호를 맞춰 보지 않아도 전 세계에서 겹치지 않는 주소를 만들 수 있다.

MAC 주소는 위치 정보가 없는 평평한 번호라서 이것만으로는 다른 네트워크까지 길을 찾을 수 없다. 같은 네트워크 안에서 쓴다. 장비들을 한 네트워크로 묶어 주는 스위치(Switch)가 데이터 묶음(같은 네트워크 안에서는 프레임, Frame이라고 부른다)을 어느 포트로 보낼지 정할 때 MAC 주소를 본다. 스위치 동작은 [ARP](../ARP(Address%20Resolution%20Protocol)/README.md#스위치에서-보면) 문서에 정리했다.

랜카드에는 제조 때 기록된 값이 있지만, 운영체제가 다른 값을 대신 쓰게 할 수 있다. 최근 휴대폰과 노트북은 사생활 보호를 위해 와이파이마다 무작위 MAC 주소를 쓰기도 한다(기기와 운영체제 버전에 따라 다르다).

<br/>

## IP 주소
### IP 주소 (Internet Protocol Address)
IP는 인터넷 프로토콜, 즉 인터넷에서 데이터를 주고받는 약속이다. IP 주소는 그 약속 안에서 장치를 가리키는 주소다.
공학적으로는 장치가 연결된 네트워크에서 받는 번호다. 같은 노트북이라도 집 와이파이와 카페 와이파이에서 다른 IP 주소를 받는다. 하드웨어가 아니라 네트워크가 정해 주므로 논리적 주소라고 부른다.

집 주소와 비슷하다. 사람은 그대로여도 이사하면 주소가 바뀌고, 주소에는 시, 동처럼 지역 정보가 들어 있어 찾아가는 길을 알려 준다.

### 크기
- IPv4는 32비트다. 8비트씩 네 덩어리로 나눠 10진수로 쓴다(예: 192.168.1.10). 덩어리 하나는 0부터 255까지다.
- IPv6는 128비트다. IPv4 주소가 모자라서 만들어졌고 16비트씩 여덟 덩어리를 16진수로 쓴다(예: 2001:db8::1).

### 네트워크 ID와 호스트 ID
IP 주소는 두 부분으로 나뉜다.

- 네트워크 ID(Network ID)는 장치가 속한 네트워크를 나타낸다. 집 주소의 서울시 ○○동에 해당한다.
- 호스트 ID(Host ID)는 그 네트워크 안의 장치 하나를 나타낸다. ○○번지에 해당한다.

라우터는 네트워크 ID만 보고 다음에 보낼 곳을 고른다. 모든 장치를 하나하나 기억하지 않고 네트워크 단위로 길을 기억하면 되니 인터넷처럼 큰 망에서도 길 찾기가 가능하다.

그런데 IP 주소만 봐서는 어디까지가 네트워크 ID인지 알 수 없다. 이 경계를 알려 주는 것이 서브넷 마스크다.

<br/>

## 서브넷 마스크
### 서브넷 마스크 (Subnet Mask)
서브넷(Subnet)은 큰 네트워크를 나눈 작은 네트워크라는 뜻이다. 마스크(Mask)는 얼굴의 일부를 가리는 가면이다.
마스크를 씌우듯 IP 주소의 일부를 가려 필요한 부분만 남긴다는 데서 온 이름이다.
공학적으로는 IP 주소와 같은 길이의 비트열로, 네트워크 ID 자리는 1, 호스트 ID 자리는 0으로 채운다. IP 주소에 겹쳐 놓고 1인 자리만 남기면 네트워크 ID가 보인다.

주소 위에 번지 부분만 가리는 종이를 대는 것과 같다. 종이를 대면 동네 이름만 보인다.

### 동작
IP 주소와 서브넷 마스크를 비트 단위로 AND 하면 네트워크 ID가 나온다. 마스크가 0인 자리에 남은 값이 호스트 ID다.

```text
IP 주소        192.168.1.10   11000000.10101000.00000001.00001010
서브넷 마스크  255.255.255.0  11111111.11111111.11111111.00000000
네트워크 ID    192.168.1.0    (1인 자리만 남김)
호스트 ID      0.0.0.10       (0인 자리만 남김)
```

255.255.255.0은 앞에서부터 1이 24개라서 /24로 줄여 쓰기도 한다. 이렇게 쓰는 방식을 CIDR(Classless Inter-Domain Routing) 표기라고 한다. 192.168.1.10/24는 위와 같은 뜻이다.

### 왜 네트워크를 나눌까
하나의 네트워크를 서브넷 마스크로 여러 개로 나누는 것을 서브넷팅(Subnetting)이라고 한다.

예를 들어 192.168.1.0/24를 /25로 바꾸면 1이 하나 늘어나서 네트워크가 둘로 나뉜다.

- 192.168.1.0/25는 192.168.1.0부터 192.168.1.127까지
- 192.168.1.128/25는 192.168.1.128부터 192.168.1.255까지

나누는 이유는 브로드캐스트 때문이다. ARP Request처럼 네트워크 안의 모든 장치에게 보내는 메시지(브로드캐스트)는 라우터를 넘어가지 않는다. 나눈 서브넷 사이에 라우터를 두면 브로드캐스트가 닿는 범위(브로드캐스트 도메인)가 서브넷 하나로 줄어들어 쓸데없는 트래픽이 줄고, 부서별로 네트워크를 나눠 관리하기도 쉬워진다. 마스크 숫자만 바꾸고 모든 장치가 같은 스위치에 그대로 붙어 있으면 브로드캐스트는 여전히 전부에게 퍼진다.

<br/>

## 도메인 이름과 FQDN
### 도메인 (Domain)
사전적 의미는 영역, 영토. 누군가가 관리하는 구역이다.
공학적으로는 인터넷에서 한 조직이 관리하는 이름의 구역을 말한다. example.com이라는 도메인을 가진 조직은 그 아래 이름(www.example.com, mail.example.com)을 직접 정할 수 있다.

### 완전한 도메인 이름 (FQDN, Fully Qualified Domain Name)
Fully Qualified는 빠짐없이 다 갖춘다는 뜻이다.
공학적으로는 호스트 이름부터 최상위 도메인(com, kr 등)까지 생략 없이 쓴 이름을 말한다. 호스트 이름이 앞에, 도메인 이름이 뒤에 온다.

```text
www . example.com
호스트 이름  도메인 이름
```

이름표에 홍길동만 쓰면 누군지 헷갈리지만 ○○회사 홍길동이라고 쓰면 한 사람으로 정해지는 것과 같다. 다만 순서는 반대여서, 도메인 이름은 오른쪽으로 갈수록 큰 구역이다.

엄밀하게는 맨 끝에 모든 이름의 맨 위 구역인 루트(Root)를 뜻하는 점을 붙여 `www.example.com.` 로 쓰는 것이 완전한 형태지만, 보통은 생략한다.

<br/>

## 주소를 서로 바꾸는 프로토콜
주소가 여러 종류라서 하나를 알 때 다른 하나를 알아내는 프로토콜이 따로 있다.

| 프로토콜 | 아는 것 | 알아내는 것 |
| --- | --- | --- |
| DNS | 도메인 이름 | IP 주소 |
| ARP | IP 주소 | MAC 주소 |
| RARP | 자기 MAC 주소 | 자기 IP 주소 (지금은 거의 안 쓰고 DHCP가 대신한다) |
| DHCP | 자기 MAC 주소 | 쓸 IP 주소(와 서브넷 마스크, 게이트웨이 등) |

ARP의 동작 순서는 [ARP](../ARP(Address%20Resolution%20Protocol)/README.md) 문서에 정리했다.

## 확인 문제
### 1. 주소체계에 대한 설명으로 옳지 않은 것은?
1. 논리적 주소인 IP 주소는 네트워크 ID와 호스트 ID로 구성되어 있다.
2. 물리적 주소인 MAC 주소의 크기는 128비트이다.
3. 물리적 주소인 MAC 주소는 제조회사 식별번호와 일련번호로 구성되어 있다.
4. 논리적 주소인 IP 주소의 크기는 32비트이다.

정답은 2번이다. MAC 주소는 48비트다. 128비트는 IPv6 주소의 크기다. 4번은 IPv4 기준으로 맞는 설명이다.

### 2. 서브넷 마스크에 대한 설명으로 올바른 것은?
1. IP 주소는 효율적으로 관리하나 트래픽 관리 및 제어가 어렵다.
2. 하나의 네트워크를 두 개 이상의 네트워크로 나눌 수 없다.
3. 불필요한 브로드캐스트 메시지를 제한할 수 없다.
4. IP 주소에서 네트워크 ID와 호스트 ID를 구분하는 기능을 수행한다.

정답은 4번이다. 서브넷 마스크로 네트워크를 나눌 수 있고(2번 틀림), 나누면 브로드캐스트 도메인이 작아져 트래픽을 제한하고 관리하기 쉬워진다(1번, 3번 틀림).

### 3. 수신지 IP 주소에 대한 물리적 주소를 매핑시키는 프로토콜은?
1. DHCP
2. ARP
3. RARP
4. DNS

정답은 2번 ARP다. RARP는 방향이 반대(MAC에서 IP)이고, DNS는 도메인 이름에서 IP 주소를 찾고, DHCP는 IP 주소를 나눠 준다.

### 4. 주소들에 대한 설명으로 틀린 것은?
1. FQDN은 도메인명 뒤에 호스트명을 나타내고 있다.
2. 서브넷 마스크의 기능은 네트워크 ID와 호스트 ID를 구분한다.
3. MAC 주소는 제조회사번호와 카드일련번호로 구성되어 있다.
4. IP 주소는 네트워크 ID와 호스트 ID로 구성되어 있다.

정답은 1번이다. FQDN은 호스트 이름이 앞, 도메인 이름이 뒤다(www.example.com에서 www가 호스트 이름).
