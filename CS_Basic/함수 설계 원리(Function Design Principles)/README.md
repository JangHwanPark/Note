## 함수 설계 원리란 ?
- 함수가 무엇을 받아 무엇을 돌려주고, 바깥에 어떤 영향을 남기는지 정하는 기준
- 함수는 값을 계산해 돌려주는 역할과, 바깥 상태를 바꾸는 역할 두 가지로 나눠 볼 수 있다
- 두 역할을 구분해 두면 함수를 읽고, 테스트하고, 다시 쓰기 쉬워진다

함수(Function)의 사전적 의미는 기능, 작용이다. 수학에서는 입력 하나에 출력 하나를 대응시키는 규칙을 뜻했고, 프로그래밍에서는 이름을 붙여 묶어 둔 코드 덩어리로 넓어졌다.

<br/>

## 함수의 두 가지 역할
### 값 기반 함수
입력을 받아 계산한 값을 돌려주는 것이 목적인 함수다. 수학에서 말하는 함수와 같은 뜻이다. 계산기 버튼과 비슷하다. 숫자를 넣으면 결과가 나올 뿐 계산기 밖의 무언가가 바뀌지는 않는다.

```js
const add = (a, b) => a + b;
console.log(add(2, 3)); // 5
```

### 효과 기반 함수 (Procedure)
프로시저(Procedure)의 사전적 의미는 절차, 순서다. 정해진 절차를 실행해서 바깥에 변화를 남기는 것이 목적인 함수를 말한다. 화면에 출력하기, 파일에 쓰기, 전역 변수 바꾸기가 여기에 속한다. 돌려주는 값이 없거나, 있어도 중요하지 않다. 전등 스위치와 비슷하다. 누르면 무언가를 돌려받는 게 아니라 방이 밝아지는 변화가 남는다.

```js
let count = 0;
const increase = () => {
  count += 1; // 함수 바깥의 count를 바꾼다
};

increase();
increase();
console.log(count); // 2
```

같은 "함수"라는 문법으로 쓰지만, 앞의 것은 계산을 맡기는 것이고 뒤의 것은 일을 시키는 것이다.

<br/>

## 반환값과 return
### return의 의미
return의 사전적 의미는 돌아가다, 돌려주다이다. 함수에서 return은 두 가지 일을 한다. 계산한 값을 호출한 곳으로 돌려주고, 그 즉시 함수 실행을 끝낸다. return 아래의 코드는 실행되지 않는다. 심부름과 비슷하다. 물건을 사서 건네주는 순간 심부름은 끝나고, 그 뒤에 할 일은 남지 않는다.

### void 함수
void의 사전적 의미는 빈, 공허한이다. C나 Java에서 void는 "이 함수는 돌려주는 값이 없다"고 표시하는 반환 타입이다. 효과 기반 함수는 일을 하는 것 자체가 목적이라 돌려줄 값이 필요 없어서 void로 선언한다. 택배를 보내고 빈손으로 돌아오는 것과 같다. 할 일은 끝났지만 손에 쥐고 오는 것은 없다.

반환값이 없을 때 언어마다 실제로 돌려주는 것은 조금씩 다르다.

| 언어 | 반환값이 없음을 나타내는 방법 | 실제로 받는 값 |
|---|---|---|
| C, Java | 반환 타입을 `void`로 선언 | 받을 수 없음 (변수에 담으면 컴파일 오류) |
| JavaScript | return을 쓰지 않음 | `undefined` |
| Python | return을 쓰지 않음 | `None` |

## 부수효과 (Side Effect)
side effect의 사전적 의미는 약의 부작용이다. 약이 원래 목적 말고 다른 곳에도 영향을 주는 것처럼, 함수가 값을 돌려주는 일 말고 바깥에 남기는 영향을 부수효과라고 한다.

부수효과의 예는 아래와 같다.
- 함수 밖의 변수를 바꾼다
- 화면이나 콘솔에 출력한다
- 파일, DB, 네트워크로 데이터를 보낸다
- 인자로 받은 객체의 내용을 바꾼다

부수효과 자체가 나쁜 것은 아니다. 프로그램이 화면에 무언가를 보여 주거나 저장하려면 반드시 필요하다. 다만 부수효과가 있는 함수는 언제, 몇 번 부르느냐에 따라 결과가 달라지므로 따로 관리해야 한다.

<br/>

## 순수 함수와 불순 함수
### 순수 함수 (Pure Function)
같은 입력에는 언제나 같은 결과를 돌려주고, 부수효과가 없는 함수다. 앞의 `add`가 순수 함수다. 구구단 표와 비슷하다. 3단의 4번째 칸은 언제 찾아봐도 12이고, 표를 찾아본다고 표가 바뀌지도 않는다.

순수 함수는 입력과 출력만 보면 되기 때문에 테스트하기 쉽다. 몇 번을 불러도, 어떤 순서로 불러도 결과가 같아서 결과를 저장해 두고 다시 쓸 수도 있다.

### 불순 함수 (Impure Function)
결과가 바깥 상태에 따라 달라지거나, 부수효과를 남기는 함수다. 오늘 시세로 계산하는 환전과 비슷하다. 같은 돈을 내도 날마다 받는 금액이 다르다.

```js
let rate = 0.1;
const withTax = (price) => price + price * rate; // 바깥의 rate에 따라 결과가 달라진다

console.log(withTax(1000)); // 1100
rate = 0.2;
console.log(withTax(1000)); // 1200
```

같은 1000을 넣었는데 결과가 다르다. 이 함수를 이해하려면 함수 안만 봐서는 안 되고 rate가 어디서 바뀌는지까지 찾아야 한다. rate를 인자로 받게 고치면 순수 함수가 된다.

```js
const withTax = (price, rate) => price + price * rate;
console.log(withTax(1000, 0.1)); // 1100
```

## 입력과 출력 구조
함수를 설계할 때는 무엇을 받아(입력) 무엇을 돌려주는지(출력)를 먼저 정한다. 함수가 필요한 값은 바깥에서 몰래 읽지 말고 인자로 받고, 결과는 바깥 변수에 몰래 쓰지 말고 반환값으로 돌려준다. 그러면 함수 시그니처(Signature)만 보고도 무슨 일을 하는지 알 수 있다. signature의 사전적 의미는 서명이고, 함수에서는 이름, 매개변수, 반환값의 형태를 묶어 부르는 말이다. 서명이 사람을 알려 주듯 시그니처는 함수가 무엇을 받고 돌려주는지 알려 준다.

요리 레시피와 비슷하다. 재료와 완성 요리가 레시피에 다 적혀 있으면, 부엌에 몰래 숨겨 둔 재료가 없는지 찾아다닐 필요가 없다.

계산과 효과가 한 함수에 섞여 있으면 둘을 나눈다. 계산하는 부분은 순수 함수로 빼고, 출력이나 저장 같은 효과는 가장 바깥의 함수 하나에 모은다.

```js
// 계산: 순수 함수
const total = (items) => items.reduce((sum, item) => sum + item.price, 0);

// 효과: 결과를 출력만 한다
const printTotal = (items) => {
  console.log(`합계 ${total(items)}원`);
};

printTotal([{ price: 1000 }, { price: 2500 }]); // 합계 3500원
```

`total`은 출력 없이도 테스트할 수 있고, 출력 방식을 바꿔도 `total`은 그대로 쓸 수 있다.

## 호출 스택과 반환 메커니즘
함수가 끝나면 어떻게 호출한 자리로 돌아갈까. 프로그램은 호출 스택(Call Stack)에 함수 호출 기록을 쌓아서 이를 해결한다. 스택(Stack)의 사전적 의미는 차곡차곡 쌓아 올린 더미다.

책상 위에 메모지를 쌓는 것과 비슷하다. 함수를 부를 때마다 "어디까지 했는지"를 적은 메모를 맨 위에 올리고, 함수가 끝나면 맨 위 메모를 떼어 내고 그 아래 메모에 적힌 곳으로 돌아간다.

```js
const square = (n) => n * n;
const sumOfSquares = (a, b) => square(a) + square(b);

console.log(sumOfSquares(3, 4)); // 25
```

1. `sumOfSquares(3, 4)`가 호출되어 스택에 쌓인다.
2. 안에서 `square(3)`이 호출되어 그 위에 쌓인다.
3. `square(3)`이 9를 돌려주며 스택에서 빠지고, `sumOfSquares`로 돌아온다.
4. `square(4)`도 같은 방식으로 16을 돌려준다.
5. `sumOfSquares`가 25를 돌려주며 스택에서 빠진다.

return은 결국 스택 맨 위의 기록을 지우고, 그 아래 기록에 값을 넘겨주는 일이다.
