## 변수란 ?
- 메모리의 한 공간에 이름을 붙여, 그 이름으로 값을 저장하고 꺼내 쓰는 장치
- 이름, 위치(주소), 값, 타입을 함께 가지며, 언제부터 언제까지 존재하는지(수명)와 어디서 보이는지(범위)가 정해져 있다
- 특정 언어의 문법이 아니라, 거의 모든 프로그래밍 언어가 공유하는 개념이다

<br/>

## 단어의 뜻
### 변수 (Variable)
사전적 의미는 변할 수 있는 수다. 수학에서 `x` 처럼 여러 값이 들어갈 수 있는 자리를 가리키는 말이었다.

공학적으로는 프로그램이 실행되는 동안 값이 바뀔 수 있는 저장 공간을 말한다. 수학의 변수가 아직 정해지지 않은 값의 자리라면, 컴퓨터의 변수는 그 자리가 실제 메모리 위에 있다는 점이 다르다. 자리가 물리적으로 있으니 값을 넣었다가 나중에 다른 값으로 바꿔 넣을 수 있다.

<br/>

## 왜 필요할까
### 메모리는 번호로만 구분된다
컴퓨터의 메모리(Memory)는 아주 긴 칸의 줄이다. 보통 한 칸은 1바이트이고, 칸마다 0번부터 차례로 번호가 붙는다. 이 번호를 주소(Address)라고 한다. CPU는 "몇 번 칸을 읽어라", "몇 번 칸에 써라"라는 식으로만 메모리를 다룬다.

사물함이 수천 개 있는 보관소와 같다. 보관소 직원은 사물함 번호로만 물건을 찾는다.

### 번호만으로는 프로그램을 짜기 어렵다
사람이 "3,072번 칸의 값에 1을 더해 3,072번 칸에 다시 써라"처럼 주소로 프로그램을 짜면 금방 틀린다. 그 칸에 무엇이 들어 있는지 기억하기 어렵고, 프로그램을 고쳐 데이터 위치가 바뀌면 그 주소를 쓰는 곳을 모두 찾아 고쳐야 한다.

변수는 이 번호에 사람이 읽을 수 있는 이름을 붙여 준다. `count` 라는 이름만 쓰면 실제 주소는 코드를 기계가 실행할 형태로 바꾸는 번역기(컴파일러나 인터프리터)와 운영체제가 정하고 기억한다. 사물함 번호 대신 "운동화 사물함"이라고 이름표를 붙여 두는 것과 같다.

## 변수를 이루는 요소
변수 하나에는 아래 여섯 가지가 얽혀 있다. 프로그래밍 언어론에서 변수를 설명할 때 흔히 쓰는 분류다.

### 이름 (Name)
코드에서 변수를 부르는 식별자다. 이름은 기본적으로 사람과 번역기를 위한 것이다. 컴파일 언어에서는 번역 과정에서 이름이 주소로 바뀌어 실행 중인 기계는 이름을 쓰지 않는다. 인터프리터 언어는 실행 중에도 이름으로 값을 찾기도 한다.

### 주소 (Address)
값이 실제로 놓인 메모리 위치다. 같은 이름이라도 실행할 때마다, 또는 함수가 호출될 때마다 주소가 달라질 수 있다.

### 값 (Value)
그 주소의 칸에 들어 있는 비트(0과 1)의 묶음이다.

### 타입 (Type)
사전적 의미는 유형, 종류다. 공학적으로는 그 칸의 비트를 어떻게 읽을지, 몇 칸을 차지할지를 정하는 약속이다.

메모리에는 비트만 있을 뿐 그것이 숫자인지 글자인지 표시가 없다. 같은 비트 `01000001` 도 정수로 읽으면 65, ASCII 문자로 읽으면 `A` 다. 메모지에 적힌 1102가 비밀번호 칸에 있으면 번호이고, 날짜 칸에 있으면 11월 2일인 것과 같다. 타입이 정해져 있어야 값을 올바르게 해석하고, 정수끼리 더하기처럼 그 값에 허용되는 연산도 정할 수 있다.

### 수명 (Lifetime)
변수에 메모리가 실제로 잡혀 있는 기간이다. 아래 "변수가 사는 곳"에서 다시 본다.

### 범위 (Scope)
코드에서 그 이름이 보이는, 즉 이름으로 부를 수 있는 영역이다. 아래 "범위와 수명"에서 다시 본다.

## 바인딩 (Binding)
### 바인딩이란 ?
사전적 의미는 묶기, 묶는 것이다. 공학적으로는 프로그램의 어떤 요소에 속성을 묶어 정하는 일을 말한다. 변수에서는 이름을 주소에, 이름을 타입에, 주소에 값을 묶는 일이 모두 바인딩이다.

사물함에 이름표를 붙이는 순간이 바인딩이다. 이름표(이름)와 사물함(주소)이 그때부터 짝이 된다.

### 바인딩 시점
같은 바인딩이라도 언제 묶이느냐가 언어마다 다르고, 이 차이가 언어의 성격을 크게 가른다.

- 정적 바인딩(Static Binding)은 프로그램을 실행하기 전, 보통 컴파일할 때 묶이고 실행 중에는 바뀌지 않는다. 실행 전에 변수의 타입이 정해지는 언어가 이름과 타입을 이렇게 묶는다. 이를 정적 타입 언어라고도 한다.
- 동적 바인딩(Dynamic Binding)은 실행 중에 묶이고 실행 중에 바뀔 수 있다. 같은 이름에 숫자를 넣었다가 문자열을 넣을 수 있는 언어는 이름과 타입이 실행 중에 묶인다. 이를 동적 타입 언어라고도 한다.

정적 바인딩은 실행 전에 오류를 잡기 쉽고 실행이 빠른 편이다. 동적 바인딩은 코드를 유연하게 쓸 수 있지만, 타입이 맞지 않는 오류를 실행해 봐야 알게 된다.

객체지향에서 말하는 동적 바인딩(호출할 메서드를 실행 중에 고르는 것)은 같은 원리를 변수가 아닌 메서드 호출에 쓴 말이다.

<br/>

## 대입은 어떻게 동작할까
### 읽기와 쓰기
변수를 쓰는 동작은 결국 두 가지다. 이름이 가리키는 칸에서 값을 읽는 것(Load)과, 그 칸에 값을 쓰는 것(Store)이다.

```text
x = x + 1
```

위 한 줄은 아래 순서로 실행된다.

1. 오른쪽의 `x` 가 가리키는 칸에서 값을 읽는다
2. 읽은 값에 1을 더한다
3. 왼쪽의 `x` 가 가리키는 칸에 결과를 쓴다

이 순서는 칸에 값을 직접 담는 언어 기준이다. 값을 참조로 다루는 언어(파이썬 등)에서는 3번이 칸을 덮어쓰는 동작이 아니다. 새 값을 만든 뒤 이름이 그 값을 가리키도록 다시 묶는다. 두 방식의 차이는 아래 "값을 담는 두 가지 방식"에서 본다.

### 왼쪽 값과 오른쪽 값
같은 `x` 인데 오른쪽에서는 값을 뜻하고, 왼쪽에서는 값을 쓸 위치를 뜻한다. 그래서 위치를 뜻하는 쪽을 왼쪽 값(l-value), 값을 뜻하는 쪽을 오른쪽 값(r-value)이라고 부른다. 이름은 대입 기호의 왼쪽과 오른쪽에서 왔다.

`x = 5` 는 되지만 `5 = x` 가 안 되는 이유가 여기 있다. `5` 는 값일 뿐 쓸 수 있는 위치가 없다.

<br/>

## 값을 담는 두 가지 방식
### 값을 직접 담기
칸 안에 값 자체를 넣는다. 다른 변수에 대입하면 값이 복사되어 칸이 두 개가 된다. 한쪽을 바꿔도 다른 쪽은 그대로다. 사물함의 물건과 똑같은 것을 하나 더 사서 옆 사물함에 넣은 것과 같다.

### 위치를 담기 (참조)
값은 다른 곳에 두고, 칸에는 그 값이 있는 주소를 넣는다. 이렇게 다른 위치를 가리키는 것을 참조(Reference)라고 한다. 영어 reference는 무언가를 가리켜 언급한다는 뜻이고, 공학적으로는 값 자체 대신 값이 있는 곳을 가리키는 것을 말한다.

다른 변수에 대입하면 주소만 복사된다. 두 변수가 같은 값을 가리키므로 한쪽에서 그 값을 고치면 다른 쪽에서도 바뀐 값이 보인다. 물건이 아니라 물건이 있는 사물함 번호를 쪽지에 적어 건넨 것과 같다. 쪽지는 두 장이지만 사물함은 하나다.

어떤 값을 어느 방식으로 담는지는 언어와 타입마다 다르다. 크기가 작고 정해진 값(정수 등)은 직접 담고, 크거나 크기가 바뀌는 값(목록 등)은 참조로 다루는 경우가 많다.

<br/>

## 범위와 수명
### 범위 (Scope)
사전적 의미는 미치는 테두리다. 공학적으로는 변수의 이름이 유효한 코드 영역을 말한다.

함수 안에서 만든 변수는 보통 그 함수 안에서만 이름으로 부를 수 있다. 이를 지역 변수(Local Variable)라고 하고, 프로그램 어디서든 부를 수 있는 변수를 전역 변수(Global Variable)라고 한다. 범위가 좁을수록 그 변수를 바꿀 수 있는 코드가 적어서, 값이 어디서 바뀌었는지 추적하기 쉽다. 교실 안에서만 통하는 별명과 같다. 교실 밖에서 부르면 아무도 모른다.

### 수명 (Lifetime)
범위가 코드 위의 공간에 대한 개념이라면, 수명은 실행 중의 시간에 대한 개념이다. 메모리가 잡힌 순간부터 풀리는 순간까지다. 호텔 방이 체크인부터 체크아웃까지만 내 방인 것과 같다.

둘은 비슷해 보이지만 다르다. 함수 안에서 만들되 함수가 끝나도 값을 유지하는 변수(C의 `static` 지역 변수 등)는 범위는 함수 안으로 좁지만 수명은 프로그램 전체만큼 길다.

### 변수가 사는 곳
수명은 변수가 메모리의 어느 영역에 놓이느냐와 이어진다. 실행 중인 프로그램의 메모리는 보통 아래처럼 나뉜다.

| 영역 | 무엇이 놓이나 | 언제 잡히고 풀리나 |
|---|---|---|
| 정적 영역 (Static / Data) | 전역 변수, 정적 변수 | 프로그램 시작에 잡혀 끝날 때 풀린다 |
| 스택 (Stack) | 함수의 지역 변수, 매개변수 | 함수를 호출하면 잡히고 함수가 끝나면 풀린다 |
| 힙 (Heap) | 실행 중 필요할 때 만드는 값 | 프로그램이 요청할 때 잡히고, 직접 해제하거나 가비지 컬렉터가 풀 때까지 남는다 |

스택은 사전적으로 쌓아 올린 더미다. 접시를 쌓듯이 함수를 호출할 때마다 그 함수의 변수들을 위에 얹고, 함수가 끝나면 맨 위부터 걷어 낸다. 그래서 함수가 끝나면 지역 변수도 함께 사라진다.

힙은 사전적으로 무더기다. 필요할 때 빈자리에 값을 놓고, 다 쓰면 치운다. 직접 치우는 언어도 있고, 더 이상 아무도 가리키지 않는 값을 자동으로 치우는 가비지 컬렉터(Garbage Collector)가 있는 언어도 있다. 앞에서 본 참조 방식은 보통 값을 힙에 두고, 스택이나 정적 영역의 변수 칸에는 그 주소만 넣는다.

<br/>

## 상수 (Constant)
사전적 의미는 늘 같은 값을 가지는 수다. 공학적으로는 한 번 값을 묶은 뒤에는 바꿀 수 없는 이름을 말한다.

변수와 마찬가지로 이름과 값이 있지만, 값을 다시 쓰는 동작(Store)이 금지된다. 바뀌면 안 되는 값을 실수로 바꾸는 일을 막고, 읽는 사람에게 이 값이 고정되어 있다는 뜻을 전한다. 유성 매직으로 적어 지울 수 없는 이름표와 같다.

다만 참조로 담는 값이라면, 이름이 다른 값을 가리키지 못하게 막는 것과 값의 내용을 못 바꾸게 막는 것은 다를 수 있다. 언어에 따라 상수 이름이 가리키는 목록의 내용은 바꿀 수 있다.
