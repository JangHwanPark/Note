## 함수형 프로그래밍과 불변성이란 ?
- 함수형 프로그래밍은 프로그램을 값을 바꾸는 명령의 순서가 아니라, 값을 받아 새 값을 돌려주는 함수의 조합으로 짜는 방식이다
- 불변성은 한 번 만든 값을 고치지 않는 성질이다. 바꿔야 하면 원래 값은 그대로 두고 바뀐 내용을 담은 새 값을 만든다
- 둘은 짝을 이룬다. 함수가 받은 값을 고치지 않아야 순수 함수가 되고, 값이 바뀌지 않아야 함수의 결과를 믿고 조합할 수 있다

순수 함수와 부수효과가 무엇인지는 [함수 설계 원리 노트의 순수 함수와 불순 함수](../함수%20설계%20원리(Function%20Design%20Principles)/README.md#순수-함수와-불순-함수)에서 다뤘다. 이 노트는 그 순수 함수를 중심에 두고 프로그램 전체를 짜는 방식과, 그 방식을 받쳐 주는 불변성을 다룬다.

예시 코드는 2026-10-29에 Windows 11에서 Node.js v24.22.1과 Python 3.13.14로 실행했다. 자바스크립트로 쓴 예시가 많지만, 노트의 내용은 특정 언어에 묶이지 않는 일반 개념이다.

## 함수형 프로그래밍 (Functional Programming)
### 단어의 뜻
functional은 함수(function)의 형용사형이다. 여기서 함수는 수학의 함수, 즉 입력 하나에 출력 하나가 정해지는 대응 규칙을 말한다. 함수 설계 원리 노트에서 본 것처럼 프로그래밍의 함수는 바깥 상태를 바꾸는 절차까지 포함하는 넓은 말이 되었는데, 함수형이라는 이름은 그 가운데 수학의 함수에 가까운 쪽을 기본 단위로 삼는다는 뜻이다.

공학적으로 함수형 프로그래밍은 순수 함수를 만들고 조합해서 프로그램을 짜는 프로그래밍 패러다임(Paradigm)이다. 패러다임의 사전적 의미는 본보기, 틀이고, 프로그래밍에서는 프로그램을 어떤 단위로 나누고 조합할지 정하는 생각의 틀을 말한다. 상태를 바꾸는 부수효과는 꼭 필요한 곳에만 모으고, 나머지는 값을 받아 값을 돌려주는 계산으로 채운다.

### 명령형과 선언형
프로그램을 짜는 방식은 흔히 명령형과 선언형으로 나눠 비교한다.

명령형(Imperative)의 사전적 의미는 명령하는, 지시하는 형태다. 공학적으로는 컴퓨터가 어떤 순서로 무엇을 할지를 한 단계씩 지시하는 방식이다. 변수를 만들고, 반복하며 그 변수를 고쳐 나가는 코드가 전형적이다.

선언형(Declarative)의 사전적 의미는 밝혀 알리는 형태다. 공학적으로는 어떻게 할지보다 무엇을 원하는지를 밝히는 방식이다. 반복과 변수 관리 같은 세부는 이미 만들어진 함수에 맡긴다. 함수형 프로그래밍은 선언형에 속한다.

택시를 탔을 때를 떠올리면 된다. 명령형은 "100미터 가서 좌회전, 신호에서 우회전"처럼 길을 하나하나 지시하는 것이고, 선언형은 "서울역으로 가 주세요"라고 목적지만 말하는 것이다.

### 같은 일을 두 방식으로
1부터 6까지의 수 가운데 짝수만 골라 제곱한 뒤 모두 더해 본다.

```js
// 명령형
const nums = [1, 2, 3, 4, 5, 6];
let total = 0;
for (let i = 0; i < nums.length; i++) {
  if (nums[i] % 2 === 0) {
    total += nums[i] * nums[i];
  }
}
console.log(total); // 56

// 선언형
const total2 = nums
  .filter((n) => n % 2 === 0)
  .map((n) => n * n)
  .reduce((sum, n) => sum + n, 0);
console.log(total2); // 56
console.log(nums);   // [ 1, 2, 3, 4, 5, 6 ]
```

명령형 코드는 `total` 과 `i` 를 계속 고쳐 가며 답을 만든다. 읽는 사람은 반복이 한 바퀴 돌 때마다 두 변수가 어떻게 바뀌는지 머릿속으로 따라가야 한다. 선언형 코드는 짝수를 고르고, 제곱하고, 더한다는 세 단계가 그대로 읽힌다. 중간에 고쳐지는 변수가 없고, 원래 배열 `nums` 도 그대로다.

두 방식은 어느 한쪽만 옳은 것이 아니다. 선언형 코드도 결국 안쪽에서는 명령형 반복으로 실행된다. 차이는 그 반복을 내가 직접 쓰느냐, 검증된 함수에 맡기느냐에 있다.

## 일급 함수와 고차 함수
### 일급 함수 (First-class Function)
일급(First-class)의 사전적 의미는 가장 높은 등급이다. 일급 시민(First-class Citizen)이라는 말에서 왔는데, 차별 없이 모든 권리를 누리는 시민이라는 뜻이다.

공학적으로 일급 함수는 함수를 숫자나 문자열 같은 다른 값과 똑같이 다룰 수 있다는 성질이다. MDN 용어집은 일급 함수가 있는 언어를 함수가 다른 변수처럼 다뤄지는 언어라고 설명하고, 예로 함수를 다른 함수의 인자로 넘기기, 다른 함수가 함수를 돌려주기, 함수를 변수에 담기를 든다. 함수가 값으로서 받을 수 있는 대우를 모두 받는다는 점이 일급 시민이라는 원래 뜻과 이어진다.

요리법을 적은 카드와 비슷하다. 카드는 다른 서류처럼 서랍에 넣어 둘 수도 있고, 다른 요리사에게 건넬 수도 있고, 봉투에 담아 돌려받을 수도 있다. 요리법이라는 일하는 방법 자체가 주고받을 수 있는 물건이 된다.

```js
const double = (n) => n * 2;
const fn = double;                  // 변수에 담는다
console.log(fn(4));                 // 8
console.log([1, 2, 3].map(double)); // [ 2, 4, 6 ] (인자로 넘긴다)

const makeAdder = (x) => (y) => x + y; // 함수를 돌려준다
const add10 = makeAdder(10);
console.log(add10(5));              // 15
```

`makeAdder(10)` 은 받은 값에 10을 더하는 함수를 만들어 돌려준다. 그래서 `add10(5)` 는 15다. 돌려받은 함수가 10을 기억하는 원리는 클로저(Closure)라고 하며 TODO로 미룬다.

### 고차 함수 (Higher-order Function)
고차(Higher-order)의 사전적 의미는 한 단계 위의 것이다. 함수를 다루는 함수라서 보통 함수보다 한 단계 위에 있다는 뜻으로 읽으면 된다. 이 이름이 수학이나 논리학의 어느 용어에서 왔는지는 확인하지 못했다(확인 필요).

공학적으로 고차 함수는 함수를 인자로 받거나 함수를 돌려주는 함수다. MDN 용어집도 같은 뜻으로 정의한다. 위 예시의 `map` 은 `double` 을 인자로 받으니 고차 함수이고, `makeAdder` 는 함수를 돌려주니 고차 함수다. 고차 함수를 만들려면 함수를 값처럼 넘기거나 돌려줄 수 있어야 하고, 일급 함수가 있는 언어에서는 이것이 자연스럽다.

고차 함수가 필요한 이유는 반복하는 틀과 그 안에서 할 일을 나눌 수 있기 때문이다. 배열을 처음부터 끝까지 도는 틀은 한 번만 만들어 두고, 각 원소에 할 일만 함수로 넘겨 바꿔 끼운다. 세탁기와 비슷하다. 빨래를 넣고 돌리는 틀은 같고, 표준 코스나 울 코스 같은 처리 방법만 골라 넣는다.

### map, filter, reduce
고차 함수 가운데 가장 많이 쓰는 셋이다. 이름과 동작은 언어마다 조금씩 다르지만 대부분의 언어에 같은 일을 하는 함수가 있다.

- map은 사전적으로 대응시키다라는 뜻이다. 모든 원소에 같은 함수를 적용해, 결과를 같은 개수의 새 배열로 돌려준다. 사진을 한 장씩 복사기에 넣어 흑백 사본을 뽑는 것과 같다. 사본은 원본과 같은 장수이고 원본 사진은 그대로다
- filter는 거르다라는 뜻이다. 함수가 참을 돌려주는 원소만 남긴 새 배열을 돌려준다. 체로 굵은 알갱이만 거르는 것과 같다
- reduce는 줄이다라는 뜻이다. 원소를 차례로 하나씩 누적값과 합쳐 값 하나로 줄인다. 동전을 하나씩 저금통에 넣어 합계 하나를 얻는 것과 같다

세 함수 모두 원래 배열을 고치지 않고 새 값을 돌려준다. 앞의 예시에서 `nums` 가 그대로였던 이유다. MDN의 `reduce` 문서도 누적값을 고치기보다 새 배열이나 객체를 만들어 쓰라고 권한다. 다만 같은 문서는 복사가 너무 느리면 누적값을 고쳐 써도 되고, 그때도 고친 누적값을 꼭 돌려줘야 한다고 덧붙인다.

## 참조 투명성 (Referential Transparency)
### 정의
referential은 가리키는, 참조하는이라는 뜻이고 transparency는 투명함이다. 이름이나 식이 가리키는 대상이 투명하게 들여다보인다는 말이다.

공학적으로 참조 투명성은 어떤 식을 그 식의 결과 값으로 바꿔 써도 프로그램의 동작이 달라지지 않는 성질이다. `add` 가 순수 함수라면 코드의 `add(2, 3)` 을 모두 `5` 로 바꿔도 결과가 같다. 식이 무엇을 가리키는지가 투명하게 보이니, 식 대신 값을 써도 된다는 뜻이다.

영수증에 적힌 "커피 두 잔 값"을 "9,000원"으로 바꿔 적어도 뜻이 같은 것과 비슷하다. 커피값이 날마다 바뀐다면 그렇게 바꿔 적을 수 없다.

### 왜 중요할까
함수 설계 원리 노트의 `withTax` 처럼 바깥 변수 `rate` 에 따라 결과가 달라지는 식은 참조 투명하지 않다. `withTax(1000)` 을 `1100` 으로 바꿔 적었다가 누군가 `rate` 를 고치면 틀린 값이 된다.

참조 투명한 식은 반대로 아래 일들을 할 수 있게 해 준다.

- 식 하나만 보고 이해할 수 있다. 그 식이 언제 실행되는지, 그 전에 무슨 일이 있었는지 찾지 않아도 된다
- 한 번 계산한 결과를 저장해 두고 다시 써도 된다. 이를 메모이제이션(Memoization)이라 하고, [캐싱 노트](../캐싱(Caching)/README.md)에서 본 캐시를 함수 결과에 쓰는 것이다
- 서로 의존하지 않는 식은 순서를 바꾸거나 동시에 계산해도 된다

함수가 받은 객체가 나중에 바뀔 수 있다면, 같은 인자를 넘긴 것처럼 보여도 결과가 달라진다. 이런 함수는 바깥 변수를 읽지 않아 순수해 보여도 같은 입력에 같은 결과라는 조건을 지키지 못한다. 아래 불변성 절의 `render` 예시가 그렇다. 그래서 순수 함수와 참조 투명성을 제대로 지키려면 불변성이 함께 필요하다.

## 불변성 (Immutability)
### 정의
immutable은 변할 수 있다는 뜻의 mutable에 부정의 im-이 붙은 말로, 변할 수 없다는 뜻이다. immutability는 그 명사형이다.

공학적으로 불변성은 값(객체)을 만든 뒤에는 그 내용을 바꿀 수 없거나, 바꾸지 않기로 하는 성질이다. 다른 내용이 필요하면 새 값을 만든다. 파이썬 용어집은 불변 객체를 값이 고정된 객체라고 정의하고, 다른 값을 저장하려면 새 객체를 만들어야 한다고 쓴다.

인쇄된 신문과 비슷하다. 이미 배달된 신문의 기사를 고칠 수는 없다. 틀린 내용이 있으면 다음 호에 바로잡은 기사를 새로 싣는다. 지난 호는 그대로 남는다.

언어가 바꿀 수 없게 막아 주는 경우도 있고, 언어는 막지 않지만 코드를 쓰는 사람이 고치지 않기로 약속하는 경우도 있다. 파이썬의 문자열과 튜플은 앞쪽이고, 자바스크립트의 보통 객체를 고치지 않고 다루는 것은 뒤쪽이다. 파이썬에서 어떤 자료형이 가변이고 불변인지는 [가변과 불변 자료형 노트](../../Python/16_가변과%20불변%20자료형(Mutable%20and%20Immutable)/README.md)에서 다뤘다.

### 상수와는 다르다
[변수 노트의 상수](../변수(Variable)/README.md#상수-constant)는 이름이 다른 값을 가리키지 못하게 막는 것이다. 불변성은 값의 내용을 바꾸지 못하게 하는 것이다. 자바스크립트의 `const` 로 만든 이름에 객체를 담으면, 그 이름에 다른 객체를 대입할 수는 없지만 객체의 속성은 고칠 수 있다. 이름표를 유성 매직으로 써서 못 바꾸게 한 것과, 이름표가 붙은 물건을 못 고치게 한 것은 다른 일이다.

### 고치면 어떤 일이 생길까
객체를 참조로 다루는 언어에서는 같은 객체를 여러 곳에서 나눠 쓴다([값에 의한 전달과 참조에 의한 전달 노트의 공유에 의한 전달](../값에%20의한%20전달과%20참조에%20의한%20전달(Pass%20by%20Value%20and%20Pass%20by%20Reference)/README.md#공유에-의한-전달-call-by-sharing)). 그중 한 곳이 객체를 고치면 다른 곳도 영향을 받는다.

```js
const config = { theme: 'light', size: 12 };
function render(c) { return `${c.theme} ${c.size}`; }
function enlarge(c) { c.size = c.size + 4; return c; } // 받은 객체를 고친다

console.log(render(config)); // light 12
enlarge(config);
console.log(render(config)); // light 16
```

`render(config)` 를 같은 인자로 두 번 불렀는데 결과가 다르다. `render` 는 바깥 변수를 읽지도, 무언가를 고치지도 않는데 그렇다. 사이에 `enlarge` 가 같은 객체를 고쳤기 때문이다. 코드가 길어지면 이런 고침은 멀리 떨어진 파일에서 일어나고, 결과가 왜 바뀌었는지 찾으려면 그 객체를 받는 모든 함수를 뒤져야 한다.

## 왜 불변이 좋을까
### 코드를 따라가기 쉽다
값이 바뀌지 않으면 그 값을 만든 곳만 보면 된다. 어디서 고쳐졌는지 찾을 일이 없다. 앞 예시에서 `enlarge` 가 `config` 를 고치지 않고 새 객체를 돌려주게 바꾸면, `config` 가 만들어진 줄만 보고 `render(config)` 의 결과를 알 수 있다. 앞에서 본 참조 투명성도 이 성질 위에서 지켜진다.

### 나눠 써도 안전하다
불변 값은 여러 함수, 여러 모듈이 같은 객체를 가리켜도 아무도 내용을 바꿀 수 없으니 서로 영향을 주지 않는다. 그래서 넘겨받은 값을 지키려고 미리 복사해 두는 방어적 복사(Defensive Copy)가 필요 없다. 게시판에 붙은 공지문과 같다. 몇 명이 함께 읽어도 공지문은 그대로이니 사람마다 한 장씩 복사해 줄 필요가 없다.

### 여러 스레드가 락 없이 읽을 수 있다
[동기화 도구 노트의 경쟁 상태](../동기화%20도구(Synchronization%20Primitives)/README.md#경쟁-상태-race-condition)는 여러 스레드가 같은 데이터를 고치려 할 때 생긴다. 아무도 고치지 않는 데이터에는 경쟁할 일이 없다. 여러 스레드가 동시에 읽기만 하면 순서가 어떻든 같은 값을 보므로 [락](../동기화%20도구(Synchronization%20Primitives)/README.md#락-lock)을 걸지 않아도 된다. 파이썬 용어집도 불변 객체는 만든 뒤 상태를 바꿀 수 없어서 본래부터 스레드 안전(Thread-safe)하다고 쓰고, 가변 객체를 스레드끼리 나눠 쓰면 경쟁 상태를 피하려고 조심스럽게 동기화해야 한다고 쓴다.

다만 이것은 값 자체에 대한 이야기다. 여러 스레드가 함께 보는 변수 하나가 지금 어느 버전의 값을 가리키는지를 바꾸는 일은 여전히 쓰기이므로, 그 부분에는 [원자적 연산](../동기화%20도구(Synchronization%20Primitives)/README.md#원자적-연산-atomic-operation)이나 락이 필요하다. 불변성은 동기화가 필요한 범위를 그 한 지점으로 줄여 준다.

### 바뀌었는지 빨리 알 수 있다
가변 객체는 그 자리에서 고쳐지므로 내용이 바뀌어도 같은 객체다. 그래서 바뀌었는지 알려면 이전 내용을 따로 저장해 두고 속성을 하나하나 비교해야 한다.

불변 방식에서는 내용이 바뀌면 반드시 새 객체가 생긴다. 그래서 두 값이 같은 객체인지만 비교하면 바뀌었는지 알 수 있다. 같은 객체인지 비교하는 일은 내용이 아무리 커도 주소 하나를 비교하는 것이라 빠르다. 택배 상자 안을 다 열어 볼 필요 없이 운송장 번호가 바뀌었는지만 보면 되는 것과 같다.

```js
const user = { name: 'Park', age: 30 };
const older = { ...user, age: 31 }; // 새 객체를 만든다
console.log(user);           // { name: 'Park', age: 30 }
console.log(older);          // { name: 'Park', age: 31 }
console.log(user === older); // false (바뀌었다)

const same = user;
console.log(user === same);  // true (그대로다)
```

이 방식은 화면을 다시 그릴지, 저장해 둔 계산 결과를 다시 쓸지를 정할 때 많이 쓰인다. 프론트엔드에서 쓰이는 방식은 별도 문서로 미룬다.

다만 다른 객체라고 해서 내용이 바뀐 것은 아니다. 내용이 같아도 따로 새로 만든 두 객체는 다른 객체로 비교된다. 그래서 바뀌지 않았으면 새 객체를 만들지 않고 원래 객체를 그대로 돌려주는 습관이 함께 필요하다.

## 불변으로 다루는 방법
### 고치지 말고 새 값을 만든다
가장 기본은 원래 값을 고치는 대신 바뀐 내용을 담은 새 값을 만들어 돌려주는 것이다. 위 예시의 `{ ...user, age: 31 }` 에서 `...` 는 전개 구문(Spread Syntax)이다. `user` 의 속성을 펼쳐 새 객체에 담고 `age` 만 덮어쓴다. `user` 는 그대로다.

배열도 같다. MDN은 자바스크립트 배열 메서드를 원래 배열을 고치는 메서드와 새 배열을 돌려주는 메서드로 나누고, 고치는 메서드마다 대신 쓸 수 있는 메서드를 표로 정리해 두었다. 예를 들어 `push(v)` 대신 `concat([v])`, `sort()` 대신 `toSorted()`, `reverse()` 대신 `toReversed()` 를 쓰면 원래 배열이 남는다. `toSorted()` 와 `toReversed()` 는 비교적 최근에 추가된 메서드라 오래된 실행 환경에는 없을 수 있다(추가된 표준 판과 지원 버전은 확인 필요). 이 노트의 Node.js v24.22.1에서는 동작했다. 앞에서 본 `map`, `filter` 도 새 배열을 돌려주는 쪽이다.

[값에 의한 전달과 참조에 의한 전달 노트의 원본을 지키고 싶을 때](../값에%20의한%20전달과%20참조에%20의한%20전달(Pass%20by%20Value%20and%20Pass%20by%20Reference)/README.md#원본을-지키고-싶을-때)에서 본, 복사본을 고쳐 돌려주는 함수도 같은 방법이다.

### 얕은 복사와 깊은 복사
새 값을 복사로 만들 때는 얼마나 깊이 복사하는지를 알아야 한다. 얕은 복사(Shallow Copy)는 겉의 객체만 새로 만들고 안에 든 객체는 원본과 나눠 쓴다. 깊은 복사(Deep Copy)는 안에 든 객체까지 끝까지 따라가며 모두 새로 만든다. 두 복사의 차이와 비유는 [가변과 불변 자료형 노트의 복사](../../Python/16_가변과%20불변%20자료형(Mutable%20and%20Immutable)/README.md#복사)에서 파이썬으로 다뤘다. 자바스크립트로 보면 아래와 같다.

```js
const user = { name: 'Park', address: { city: 'Seoul' } };
const copy = { ...user };            // 얕은 복사
copy.name = 'Kim';
copy.address.city = 'Busan';
console.log(user.name);              // Park
console.log(user.address.city);      // Busan (안쪽 객체는 나눠 쓴다)

const deep = structuredClone(user);  // 깊은 복사
deep.address.city = 'Daegu';
console.log(user.address.city);      // Busan
console.log(deep.address.city);      // Daegu
```

전개 구문으로 만든 복사는 얕다. MDN도 자바스크립트에 들어 있는 배열 복사 방법(전개 구문, `Array.from()`, `slice()`, `concat()`)은 모두 얕은 복사를 만든다고 쓴다. 그래서 안쪽 값을 바꾸고 싶으면 그 안쪽 객체도 새로 만들어야 한다. 이 방법은 아래 구조적 공유에서 다시 본다.

깊은 복사는 원본과 완전히 떨어진 값을 얻지만, 안에 든 모든 것을 새로 만드니 값이 크면 느리고 메모리를 많이 쓴다. `structuredClone` 은 브라우저와 Node.js에서 쓸 수 있는 깊은 복사 함수인데, 복사할 수 없는 값이 들어 있으면 오류를 낸다(MDN의 `structuredClone` 문서). 어떤 값이 복사되지 않는지는 TODO로 미룬다.

### 얼리기
새 값을 만드는 방법은 고치지 않겠다는 약속이라, 누군가 실수로 고치면 막지 못한다. 그래서 값을 고칠 수 없게 얼려 두는 기능을 주는 언어가 있다.

자바스크립트의 `Object.freeze()` 는 객체에 속성을 추가, 삭제하거나 속성 값을 바꾸지 못하게 한다. 그런데 MDN은 freeze가 얕다고 분명히 적는다. 얼린 객체의 속성이 다시 객체라면 그 안쪽 객체는 얼지 않는다. 물건 목록표를 코팅해 고칠 수 없게 했지만, 목록에 적힌 물건 자체는 코팅되지 않은 것과 같다.

```js
const point = Object.freeze({ x: 1, y: 2, tags: ['a'] });
point.x = 100;            // 오류 없이 무시된다
console.log(point.x);     // 1
point.tags.push('b');     // 안쪽 배열은 얼지 않았다
console.log(point.tags);  // [ 'a', 'b' ]
console.log(Object.isFrozen(point), Object.isFrozen(point.tags)); // true false
```

엄격 모드(Strict Mode)는 실수하기 쉬운 문법을 오류로 바꿔 주는 자바스크립트의 실행 방식이다. 위 코드는 엄격 모드가 아닌 스크립트(확장자 .js, 모듈 설정 없음)로 실행했고, 이때 얼린 객체를 고치려는 대입은 오류 없이 그냥 무시된다. 파일 맨 위에 `'use strict';` 를 넣어 실행하면 같은 대입이 `TypeError` 를 던졌다. ES 모듈(확장자 .mjs)로 실행해도 `'use strict';` 없이 `TypeError` 가 났다. 모듈은 처음부터 엄격 모드로 실행되기 때문이다. 메시지는 `Cannot assign to read only property 'x' of object '#<Object>'` 였다. MDN도 얼린 객체를 고치려는 시도는 조용히 실패하거나 `TypeError` 를 던지는데, 오류는 주로 엄격 모드에서 난다고 쓴다. 안쪽까지 얼리려면 속성을 따라가며 하나하나 `Object.freeze()` 를 부르는 깊은 얼리기(Deep Freeze)를 직접 해야 한다고 MDN은 안내한다.

파이썬은 처음부터 불변인 자료형을 따로 준다. 튜플(tuple)은 불변 시퀀스이고, 집합의 불변판인 frozenset이 있다. 파이썬 공식 문서는 `set` 은 가변이라 해시값이 없어 딕셔너리 키나 다른 집합의 원소가 될 수 없고, `frozenset` 은 불변이고 해시 가능해서 둘 다 될 수 있다고 쓴다.

```python
point = (1, 2)
try:
    point[0] = 100
except TypeError as e:
    print(e)                 # 'tuple' object does not support item assignment

tags = frozenset({"a", "b"})
try:
    tags.add("c")
except AttributeError as e:
    print(e)                 # 'frozenset' object has no attribute 'add'

more = tags | {"c"}          # 새 frozenset을 만든다
print(sorted(tags), sorted(more))  # ['a', 'b'] ['a', 'b', 'c']

d = {tags: "키로 쓸 수 있다"}
print(d[frozenset({"b", "a"})])    # 키로 쓸 수 있다
```

`frozenset` 에는 `add` 같은 고치는 메서드가 아예 없고, 합집합 연산은 새 frozenset을 돌려준다. 다만 파이썬의 튜플도 얕다. 튜플 안에 리스트가 있으면 그 리스트는 고칠 수 있다([가변과 불변 자료형 노트의 튜플 안의 가변 객체](../../Python/16_가변과%20불변%20자료형(Mutable%20and%20Immutable)/README.md#튜플-안의-가변-객체)). 겉만 막고 안쪽은 막지 않는다는 점은 `Object.freeze()` 와 튜플이 같다.

## 비용과 구조적 공유
### 매번 새로 만들면 느리지 않을까
값을 하나 바꿀 때마다 전체를 복사한다면 데이터가 클수록 느려지고 메모리도 많이 쓴다. 원소가 백만 개인 배열에서 하나를 바꾸려고 백만 개를 모두 복사하는 것은 낭비다. 불변성의 가장 큰 비용이 이것이다.

### 구조적 공유 (Structural Sharing)
그래서 바뀐 부분만 새로 만들고, 바뀌지 않은 부분은 이전 값과 나눠 쓴다. 이를 구조적 공유라고 한다. 이전 값의 구조를 새 값이 함께 쓴다는 뜻이다. 나눠 쓰는 부분도 불변이라 아무도 고치지 않으니, 나눠 써도 서로 영향이 없다. 가변 데이터였다면 이렇게 나눠 쓰는 것이 위험했을 것이다.

바인더로 묶은 문서와 비슷하다. 문서의 한 쪽만 고친 개정판을 만들 때, 그 쪽만 새로 인쇄하고 나머지 쪽은 원래 종이를 그대로 끼워 쓰는 것이다. 원래 종이에 아무도 낙서하지 않는다는 약속이 있으니 가능하다.

```js
const state = {
  user: { name: 'Park' },
  settings: { theme: 'light' },
};
const next = { ...state, user: { ...state.user, name: 'Kim' } };
console.log(next.settings === state.settings); // true (그대로 나눠 쓴다)
console.log(next.user === state.user);         // false (바뀐 쪽만 새로 만들었다)
console.log(state.user.name);                  // Park
```

`next` 는 바뀐 `user` 와 그것을 담는 겉 객체만 새로 만들었고, `settings` 는 `state` 의 것을 그대로 가리킨다. 그리고 앞에서 본 변경 감지가 여기서도 쓰인다. `settings` 가 같은 객체이니 설정은 바뀌지 않았다고 바로 알 수 있다.

### 영속 자료구조 (Persistent Data Structure)
위 예시는 손으로 한 구조적 공유다. 이 일을 자료구조 차원에서 해 주는 것이 영속 자료구조다. persistent의 사전적 의미는 끈질기게 남아 있는이다. 값을 바꿔도 이전 버전이 사라지지 않고 그대로 남아 있다는 뜻이다. 보통 트리 모양으로 데이터를 저장해서, 하나를 바꾸면 그 원소에서 뿌리까지 이르는 경로의 노드만 새로 만들고 나머지 가지는 나눠 쓴다. 내부 구조와 비용은 별도 문서로 미룬다.

## 부수효과는 어디에 두나
함수형 프로그래밍도 부수효과를 없애지는 않는다. 화면에 보여 주지도, 파일에 쓰지도, 네트워크로 보내지도 않는 프로그램은 쓸모가 없다. [함수 설계 원리 노트의 입력과 출력 구조](../함수%20설계%20원리(Function%20Design%20Principles)/README.md#입력과-출력-구조)에서 계산은 순수 함수로 빼고 효과는 가장 바깥 함수에 모은다고 했다. 함수형 프로그래밍은 이 원칙을 프로그램 전체로 넓힌 것이다. 안쪽의 넓은 부분은 불변 값을 주고받는 순수 함수로 짜고, 부수효과는 바깥 가장자리의 좁은 부분에만 둔다. 그러면 테스트하고 따라가기 쉬운 부분이 커지고, 조심해야 할 부분이 작아진다. 식당과 비슷하다. 주방 안에서는 들어온 재료로 요리만 만들고, 손님을 맞고 돈을 받는 일은 입구의 계산대 한곳에서만 한다.
