## 게임 관점의 클라이언트-서버란 ?
- 온라인 게임에서 클라이언트는 플레이어가 실행하는 게임 프로그램이고, 서버는 여러 플레이어가 같은 세계를 공유하도록 게임 상태를 관리하는 프로그램이다
- 웹과 같은 구조를 쓰지만, 요청이 있을 때만 응답하는 웹과 달리 초당 수십 번씩 상태를 주고받아야 한다는 점이 다르다
- 일반 이론은 [클라이언트-서버 구조](../클라이언트-서버%20구조(Client-Server%20Architecture)/README.md) 문서에 정리했고, 이 문서는 실시간 게임에서 그 구조가 어떻게 바뀌는지를 다룬다

<br/>

## 웹과 다른 점
웹에서는 사용자가 무언가를 요청하고 응답을 기다리는 동안 몇백 밀리초가 걸려도 크게 문제가 되지 않는다. 게임에서는 플레이어가 키를 누른 순간 캐릭터가 움직여야 하고, 다른 플레이어의 움직임도 끊김 없이 보여야 한다.

그래서 게임 네트워크는 두 가지 문제를 함께 풀어야 한다. 하나는 모든 플레이어가 같은 게임 상태를 보게 하는 동기화 문제, 다른 하나는 네트워크 지연이 있어도 조작이 즉각적으로 느껴지게 하는 반응성 문제다. 둘은 서로 부딪힌다. 정확하게 맞추려면 서버의 확인을 기다려야 하고, 기다리면 반응이 늦어진다.

<br/>

## 권위 서버
### 권위 (Authority)
사전적 의미는 권위, 권한. 무엇이 옳은지 최종적으로 결정할 수 있는 힘이다.
공학적으로는 게임 상태의 정답을 누가 결정하느냐를 말한다. 권위를 가진 쪽의 판단이 다른 모든 쪽의 판단보다 우선한다.

### 권위 서버 (Authoritative Server)
서버가 게임 상태의 유일한 정답을 갖는 구조. 클라이언트는 결과가 아니라 입력(키 입력, 마우스 조작)만 서버에 보내고, 서버가 그 입력으로 게임을 진행시킨 뒤 결과를 클라이언트에 알려 준다.

클라이언트가 내 체력은 100이다, 나는 벽을 통과했다처럼 결과를 직접 보고하게 하면 조작된 클라이언트가 거짓 결과를 보낼 수 있다. 권위 서버는 클라이언트를 믿지 않는다는 전제에서 출발하며, 치트를 막는 가장 기본적인 구조다.

### 틱 (Tick)
사전적 의미는 시계의 째깍 소리. 시간이 한 칸씩 흘러가는 단위다.
공학적으로는 서버가 게임 상태를 한 번 갱신하는 주기를 말한다. 서버는 정해진 간격마다 그사이 들어온 입력을 모아 처리하고, 결과를 클라이언트에 보낸다. 1초에 몇 번 갱신하는지를 틱레이트(Tick Rate)라고 하며, 높을수록 정밀하지만 서버와 네트워크 부담이 커진다.

<br/>

## 지연을 숨기는 기법
권위 서버만으로는 반응성 문제가 남는다. 입력을 보내고 서버의 결과가 돌아올 때까지 왕복 시간(RTT: Round Trip Time)만큼 캐릭터가 늦게 움직이기 때문이다. 그래서 클라이언트에서 지연을 숨기는 기법을 함께 쓴다.

### 클라이언트 측 예측 (Client-side Prediction)
클라이언트가 서버의 결과를 기다리지 않고, 자기 입력의 결과를 먼저 계산해 화면에 보여 주는 방식. 대부분의 경우 서버도 같은 결과를 내기 때문에 플레이어는 지연을 느끼지 못한다.

### 서버 조정 (Server Reconciliation)
사전적 의미에서 조정(Reconciliation)은 화해, 불일치를 맞추는 일이다.
공학적으로는 예측한 결과와 서버가 보낸 정답이 다를 때 클라이언트가 서버 쪽으로 맞추는 과정을 말한다. 서버가 어느 입력까지 처리했는지 알려 주면, 클라이언트는 그 시점의 서버 상태에서 아직 처리되지 않은 입력을 다시 적용해 현재 위치를 다시 계산한다. 차이가 크면 캐릭터가 순간 이동하는 것처럼 보이는데, 흔히 말하는 렉으로 인한 되돌림이 이것이다.

### 보간 (Interpolation)
사전적 의미는 사이에 끼워 넣기. 알고 있는 두 값 사이의 값을 채워 넣는 일이다.
공학적으로는 서버에서 띄엄띄엄 도착하는 다른 플레이어의 위치 사이를 부드럽게 이어 그리는 방식을 말한다. 대신 받은 두 상태 사이를 그리려면 다음 상태를 기다려야 하므로, 다른 플레이어는 실제보다 조금 과거의 모습으로 보인다.

### 지연 보상 (Lag Compensation)
보간 때문에 내가 보는 상대는 과거의 위치에 있다. 그래서 내가 조준해서 쐈는데 서버에서는 이미 상대가 움직여서 빗나가는 문제가 생긴다. 지연 보상은 서버가 상태 기록을 남겨 두었다가, 판정할 때 쏜 플레이어가 보고 있던 시점으로 되돌려 맞았는지를 계산하는 방식이다. 쏜 사람 입장에서는 공정하지만, 맞은 사람 입장에서는 이미 엄폐물 뒤로 숨었는데 맞는 일이 생긴다.

## 동기화 방식
### 상태 동기화 (State Synchronization)
서버가 게임 상태(위치, 체력 등)를 계산해 클라이언트에 보내는 방식. 위에서 설명한 권위 서버 구조가 여기에 해당하며, FPS나 MMORPG에서 주로 쓴다.

### 락스텝 (Lockstep)
사전적 의미는 발맞춰 걷기. 대열이 앞사람과 정확히 같은 보폭으로 걷는 행진 방식이다.
공학적으로는 모든 참여자가 같은 턴의 입력을 다 받은 뒤에야 다음 턴으로 넘어가는 동기화 방식을 말한다. 상태가 아니라 입력만 주고받고, 각자 같은 입력으로 같은 계산을 해서 같은 결과를 얻는다. 유닛이 수백 개인 RTS처럼 상태를 다 보내기엔 양이 너무 많은 게임에 맞는다. 모든 참여자가 완전히 같은 결과를 계산해야 하므로 계산이 결정적(Deterministic)이어야 하고, 가장 느린 참여자에게 전체 속도가 맞춰진다.

### 롤백 (Rollback)
입력 기반 동기화에서 상대의 입력을 기다리지 않고, 상대 입력을 직전과 같다고 예측해 먼저 진행하는 방식. 실제 입력이 도착해 예측이 틀렸다면 그 시점으로 되돌아가 다시 계산한다. 프레임 단위 반응이 중요한 대전 격투 게임에서 많이 쓴다.

<br/>

## 서버 형태
### 데디케이티드 서버 (Dedicated Server)
사전적 의미에서 Dedicated는 전념하는, 전용의.
공학적으로는 게임 진행만을 위해 따로 운영하는 서버를 말한다. 공정하고 안정적이지만 운영 비용이 든다.

### 리슨 서버 (Listen Server)
플레이어 중 한 명의 게임 클라이언트가 서버 역할을 겸하는 방식. 별도 서버 비용이 없지만, 호스트가 나가면 게임이 끊기고 호스트는 지연이 없어 유리해진다.

### P2P
고정된 서버 없이 참여자끼리 직접 통신하는 방식. 락스텝이나 롤백 같은 입력 기반 동기화와 함께 쓰는 경우가 많다. 권위를 가진 쪽이 없어 치트를 막기 어렵다.

<br/>

## 전송 프로토콜
웹은 대부분 TCP를 쓰지만, 실시간 게임은 UDP를 많이 쓴다.

TCP는 데이터가 순서대로 빠짐없이 도착하도록 보장한다. 패킷 하나가 유실되면 다시 보낼 때까지 뒤의 데이터도 함께 기다린다. 게임에서는 0.1초 전 위치보다 지금 위치가 중요하기 때문에, 오래된 데이터를 기다리느라 최신 데이터가 늦어지는 것이 더 큰 문제다.

UDP는 순서와 도착을 보장하지 않는 대신 기다리지 않는다. 게임은 UDP 위에 필요한 만큼만 신뢰성을 직접 구현해 쓴다. 위치처럼 최신 값만 중요한 데이터는 유실돼도 버리고, 아이템 획득처럼 반드시 전달돼야 하는 데이터만 재전송하는 식이다.
