## 콜스택이란 ?
- 콜스택(Call Stack)은 지금 실행 중인 함수와, 그 함수를 부른 함수들의 순서를 기억하는 구조다
- 자바스크립트는 콜스택이 하나인 싱글 스레드(Single Thread) 방식이라 한 번에 함수 하나만 실행한다
- 오래 걸리는 일은 실행 환경(브라우저, Node.js)에 맡겨 두고, 콜스택이 비면 이벤트 루프(Event Loop)가 대기 중인 콜백을 하나씩 콜스택에 올린다

### 콜스택 (Call Stack)
call의 사전적 의미는 부르다, stack은 쌓아 올린 더미다.
프로그래밍에서는 함수를 부를 때마다 그 함수의 실행 정보를 위에 쌓고, 함수가 끝나면 맨 위에서 걷어 내는 구조를 말한다. 나중에 들어간 것이 먼저 나오는 LIFO(Last In, First Out, 후입선출) 방식이다.

접시를 쌓는 것과 같다. 새 접시는 맨 위에 올리고, 꺼낼 때도 맨 위 접시부터 꺼낸다.

### 왜 알아야 할까
자바스크립트는 콜스택이 하나라서, 어떤 함수가 오래 걸리면 그동안 다른 코드는 하나도 실행되지 못한다. 브라우저라면 화면이 멈추고 클릭에도 반응하지 않는다. 콜스택이 어떻게 쌓이고 비는지 알아야 오류 메시지의 호출 순서를 읽을 수 있고, `setTimeout` 이나 프로미스 콜백이 왜 나중에 실행되는지도 이해할 수 있다.

<br/>

## 콜스택이 쌓이고 비는 순서
```javascript
function a() {
  return 1;
}

function b() {
  return a() + 1;
}

function c() {
  return b() + 1;
}

const result = c();
console.log(result); // 3
```

`c()` 를 호출하면 다음 순서로 실행된다.

1. `c` 가 콜스택에 들어간다.
2. `c` 는 `b()` 의 결과에 1을 더해야 하므로 `b` 를 호출한다. `b` 가 `c` 위에 쌓인다.
3. `b` 는 `a()` 의 결과에 1을 더해야 하므로 `a` 를 호출한다. `a` 가 맨 위에 쌓인다.
4. `a` 가 1을 돌려주고 콜스택에서 빠진다.
5. `b` 가 1에 1을 더한 2를 돌려주고 빠진다.
6. `c` 가 2에 1을 더한 3을 돌려주고 빠진다.
7. 전역 코드가 이어서 `console.log(result)` 를 실행한다. 파일의 전역 코드까지 모두 끝나야 콜스택이 완전히 빈다.

가장 늦게 들어간 `a` 가 가장 먼저 끝나고, 가장 먼저 들어간 `c` 가 가장 늦게 끝난다.

### 스택 오버플로 (Stack Overflow)
콜스택의 크기는 무한하지 않다. 재귀 함수에 끝나는 조건이 없으면 함수가 끝없이 쌓이다가 한도를 넘어 오류가 난다.

```javascript
function forever() {
  forever();
}

forever(); // RangeError: Maximum call stack size exceeded (V8 기준 메시지)
```

한도가 정확히 몇 단계인지, 오류 메시지가 어떤 문구인지는 엔진과 실행 환경에 따라 다르다. 위 메시지는 Node.js와 Chrome이 쓰는 V8 엔진의 것이다.

## 비동기 코드의 실행 순서
`setTimeout` 이나 네트워크 요청은 자바스크립트 엔진이 아니라 실행 환경이 처리한다. 엔진은 일을 맡기기만 하고 바로 다음 줄로 넘어간다. 맡긴 일이 끝나면 그 콜백이 대기열(Queue)에 들어간다.

### 이벤트 루프 (Event Loop)
loop의 사전적 의미는 고리, 반복이다.
이벤트 루프는 콜스택이 비었는지 확인하고, 비었으면 대기열의 콜백을 콜스택으로 옮기는 일을 계속 되풀이하는 장치다. 이벤트 루프는 자바스크립트 언어가 아니라 실행 환경(브라우저, Node.js)이 제공한다.

### 마이크로태스크와 태스크
대기열은 크게 두 가지로 나눠 생각하면 된다. 프로미스의 `then`, `catch`, `finally` 콜백은 마이크로태스크 큐(Microtask Queue)에 들어간다. `setTimeout`, `setInterval` 콜백과 이벤트 핸들러는 태스크 큐(Task Queue)에 들어간다.

콜스택이 비면 이벤트 루프는 마이크로태스크 큐를 먼저 모두 비우고, 그다음 태스크 큐에서 하나를 꺼낸다. 실제로는 브라우저와 Node.js 모두 큐를 더 잘게 나누고 있고 그 구성도 서로 다르다. 여기서는 두 가지로 줄여 설명한다.

```javascript
console.log('1 동기 시작');
setTimeout(() => console.log('4 setTimeout'), 0);
Promise.resolve().then(() => console.log('3 then'));
console.log('2 동기 끝');
```

```text
1 동기 시작
2 동기 끝
3 then
4 setTimeout
```

1. 동기 코드인 1과 2가 콜스택에서 먼저 실행된다. `setTimeout` 과 `then` 은 콜백을 맡겨 두기만 한다.
2. 동기 코드가 끝나 콜스택이 비면 마이크로태스크 큐의 `then` 콜백(3)이 먼저 실행된다.
3. 마지막으로 태스크 큐의 `setTimeout` 콜백(4)이 실행된다. 대기 시간을 0으로 줘도 동기 코드와 프로미스 콜백보다 늦다.

## 한눈에 보는 용어
| 용어 | 사전적 의미 | 쉽게 말하면 |
| --- | --- | --- |
| 콜스택 (Call Stack) | 부른 것을 쌓은 더미 | 실행 중인 함수의 순서를 쌓아 둔 곳 |
| 싱글 스레드 (Single Thread) | 한 가닥 실 | 한 번에 한 가지 일만 하는 실행 흐름 |
| 이벤트 루프 (Event Loop) | 사건의 반복 고리 | 콜스택이 비면 대기 중인 콜백을 올려 주는 장치 |
| 마이크로태스크 (Microtask) | 아주 작은 일 | 프로미스 콜백, 태스크보다 먼저 처리된다 |

예시의 출력은 Node.js 22.13.0(V8 엔진)에서 실행한 결과다.
