## MDA 프레임워크란 ?
- 게임을 메커닉스(Mechanics), 다이내믹스(Dynamics), 에스테틱스(Aesthetics) 세 층으로 나눠 분석하고 설계하는 틀이다
- 출처는 휴니키, 르블랑, 주벡의 2004년 논문 「MDA: A Formal Approach to Game Design and Game Research」다(저자와 배경은 [2장](../02.게임에서%20재미란(Fun%20in%20Games)/README.md) 참고)
- 이 장은 MDA가 왜 나왔는지(1절), 게임을 어떻게 보는지(2~3절), 실제 설계에 어떻게 쓰는지(4절), 어떤 한계가 지적됐는지(5절)를 차례로 보고, 쓰는 법으로 정리한다(6절)

### 용어
프레임워크(Framework)의 사전적 의미는 뼈대, 골조다. 설계에서는 무엇을 어떤 순서로 따질지 정해 주는 생각의 틀을 말한다.

| 층 | 원래 뜻 | 게임에서의 뜻 |
|----|--------|--------------|
| 메커닉스 | 역학, 기계가 돌아가는 짜임새 | 게임이 돌아가는 짜임새. 규칙과 구성 요소 |
| 다이내믹스 | 동역학, 힘을 받아 시간에 따라 변하는 움직임 | 규칙이 플레이어 입력을 받아 만들어 내는 실제 판의 흐름 |
| 에스테틱스 | 미학, 아름다움을 느끼는 감각 | 플레이어에게 일어나기를 바라는 감정 반응 |

메커닉스를 기계의 짜임새로, 다이내믹스를 그 짜임새가 움직이는 모습으로 보면 원래 뜻이 이어진다(해석).

<br/>

## 1. 왜 MDA가 필요한가
게임은 다른 오락과 달리 만든 사람도 결과를 다 알 수 없는 물건이다. MDA는 이 문제에서 출발한다.

### 게임은 소비가 예측되지 않는다
- 책, 음악, 영화, 연극과 달리 게임은 어떤 일이 벌어질지, 결과가 어떨지가 제품이 완성된 때에도 정해져 있지 않다
- 컴퓨터 게임은 여러 하위 시스템이 맞물려 복잡하고 예측하기 어려운 동작을 만든다. 그래서 하나를 고치기 전에 서로의 영향을 따져야 한다

### 재미라는 말로는 설계를 논의할 수 없다
- 게임과 놀이를 이야기하기 어려운 이유는 어휘가 좁기 때문이다. "재미"나 "게임플레이"만으로는 무엇을 노리고 무엇을 고칠지 말할 수 없다(2장)
- 게임 개발에는 프로그래머, 디자이너, 연구자처럼 배경이 다른 사람이 함께한다. 코드의 작은 결정이 최종 플레이까지 번지고, 반대로 원하는 경험은 결국 어딘가의 코드로 구현돼야 한다

### MDA의 역할
논문은 MDA를 이 사이를 오가게 해 주는 번역 도구로 제안한다. 시스템과 코드에서 콘텐츠와 플레이 경험까지, 그리고 다시 거꾸로, 추상화의 모든 수준을 오갈 수 있게 하자는 것이다.

<br/>

## 2. MDA는 게임을 어떻게 보는가
세 층을 렌즈처럼 바꿔 끼우며, 디자이너와 플레이어 양쪽에서 본다.

### 세 층은 렌즈다
- 세 층은 게임을 보는 각각의 렌즈(lens), 보기(view)다
- 셋은 따로 떨어져 있지만 원인과 결과로 이어져 있다("separate, but causally linked")
- 카메라에 광각과 망원을 바꿔 끼우듯, 같은 게임을 층마다 다르게 본다

### 디자이너와 플레이어는 반대 방향에서 본다
- 디자이너 : 메커닉스 → 다이내믹스 → 에스테틱스. 규칙을 정하면 흐름이 생기고, 흐름에서 감정이 나온다
- 플레이어 : 에스테틱스 → 다이내믹스 → 메커닉스. 분위기를 먼저 느끼고, 흐름을 보고, 마지막에 규칙을 만진다
- 두 방향을 함께 보면 한 층의 작은 변화가 다른 층으로 번지는 것이 보이고, 기능이 아니라 경험을 중심으로 설계하게 된다(2장)

그래서 논문은 플레이어 쪽 순서인 에스테틱스, 다이내믹스, 메커닉스 순으로 설명한다. 다음 절도 이 순서를 따른다.

<br/>

## 3. 층마다 모델을 세운다
층을 나눴으면 각 층을 구체적으로 다룰 도구가 필요하다. 논문은 에스테틱스와 다이내믹스에는 모델을, 메커닉스에는 구체적인 예를 든다.

### 3-1. 에스테틱 모델 : 노리는 감정을 조건으로 바꾼다
에스테틱 모델(Aesthetic Model)은 노리는 감정이 생기려면 무엇이 갖춰져야 하는지 적은 설명이다. 2장의 여덟 가지 에스테틱스를 나침반처럼 써서 세운다.

논문의 예는 경쟁이다. Charades(몸짓으로 단어 맞히기)와 Quake(1인칭 슈팅)는 플레이어가 서로를 이기는 데 마음을 쏟을 때 성공한다. 그러려면 아래가 필요하다.

- 상대가 있어야 한다. Charades는 팀끼리, Quake는 컴퓨터 상대와 겨룬다
- 모두가 이기고 싶어 해야 한다
- 맞서서 겨루는 플레이를 받쳐 주고, 누가 이기고 있는지 분명히 보여 줘야 한다
- 이기는 조건이 안 보이거나 도저히 못 이긴다고 느끼면 흥미가 크게 떨어진다

이렇게 하면 경쟁이 재미있어야 한다는 막연한 목표가, 상대가 있는가, 승패가 보이는가처럼 확인할 수 있는 조건이 된다.

### 3-2. 다이내믹 모델 : 판의 흐름을 미리 계산한다
다이내믹 모델(Dynamic Model)은 판의 흐름을 예측하고 설명하는 모델이다. 먼저 어떤 흐름이 어떤 감정을 만드는지 짝을 짓는다.

| 에스테틱스 | 그 감정을 만드는 다이내믹스의 예 |
|-----------|----------------------------------|
| 도전 (Challenge) | 시간 압박, 상대의 플레이 |
| 동료애 (Fellowship) | 한 팀끼리만 정보 공유, 혼자서는 어려운 승리 조건(적 기지 점령 등) |
| 표현 (Expression) | 아이템을 사고 짓고 얻는 시스템, 레벨과 세계를 만드는 시스템, 나만의 캐릭터를 만드는 시스템 |
| 극적 긴장 (Dramatic tension) | 긴장이 오르고, 풀리고, 마무리되는 흐름 |

극적 긴장은 2장의 여덟 항목에 없지만 논문에 나온다. 여덟 가지가 닫힌 목록이 아니라는 예다.

다음으로 흐름을 숫자나 구조로 그려 본다. 논문은 모노폴리로 두 가지 모델을 보인다.

확률 모델은 주사위 두 개의 합의 확률로 판을 한 바퀴 도는 데 걸리는 시간을 구한다.

```python
from collections import Counter
from fractions import Fraction

counts = Counter(a + b for a in range(1, 7) for b in range(1, 7))
for total in range(2, 13):
    print(total, counts[total])
# 한 줄에 하나씩 찍힌다. 왼쪽은 합, 오른쪽은 36가지 중 경우의 수
# 2 1 / 3 2 / 4 3 / 5 4 / 6 5 / 7 6 / 8 5 / 9 4 / 10 3 / 11 2 / 12 1

mean = Fraction(sum(t * c for t, c in counts.items()), 36)
print("평균:", mean)                                          # 평균: 7
print("40칸 한 바퀴 평균 굴림 수:", round(40 / float(mean), 2))  # 40칸 한 바퀴 평균 굴림 수: 5.71
```

- 합 7이 가장 흔하고(36가지 중 6가지), 평균 이동은 7칸이다
- 40칸 판이면 한 바퀴에 평균 약 5.7번 굴린다. 더블, 감옥, 이동 카드를 뺀 단순 계산이며 논문에는 숫자가 없다
- 이 모델이 있으면 판의 칸 수를 바꿀 때 게임 시간이 얼마나 변할지 미리 계산할 수 있다(4절 튜닝)

피드백 모델은 결과가 다시 원인으로 돌아오는 고리를 찾는다. 논문은 온도 조절기(온도를 재고, 덥거나 추우면 냉난방을 켠다) 그림으로 피드백을 설명한다.

- 모노폴리의 고리 : 부자일수록 남에게 더 큰 손해를 입히고, 가난한 사람은 더 가난해진다
- 결과 : 격차가 벌어지면 몇 사람만 판에 마음을 쏟고, 극적 긴장과 내가 판을 움직인다는 느낌이 사라진다
- 온도 조절기는 차이를 줄이는 고리(음의 피드백), 모노폴리는 차이를 키우는 고리(양의 피드백)다. 이 두 용어는 논문에 없고 제어 이론에서 빌린 것이다

### 3-3. 메커닉스 : 흐름은 규칙에서 나온다
논문은 메커닉스를 두 번 다르게 정의한다.

- MDA 절(2장에서 인용) : 데이터 표현과 알고리즘 수준의 구성 요소
- Mechanics 절 : 게임 안에서 플레이어에게 주어지는 여러 행동, 동작, 조작 장치

메커닉스는 콘텐츠(레벨, 에셋 등)와 함께 다이내믹스를 받친다. [4장](../04.시스템과%20콘텐츠란(Systems%20and%20Content)/README.md)의 시스템과 콘텐츠의 짝과 같다. 논문은 메커닉스에서 다이내믹스가 생겨나는 예를 든다.

| 게임 | 메커닉스 | 생기는 다이내믹스 |
|------|---------|------------------|
| 카드 게임 | 섞기, 트릭 따기(trick-taking), 베팅 | 블러핑 |
| 슈팅 게임 | 무기, 탄약, 부활 지점 | 캠핑(한자리에서 기다리기), 저격 |
| 골프 | 공, 클럽, 벙커, 워터 해저드 | 부러지거나 물에 빠진 클럽 |

블러핑이라는 규칙은 없다. 베팅과 숨겨진 패가 맞물려 생긴다. 규칙에 없던 행동이 생기는 이 현상은 4장의 창발로 볼 수 있다(해석).

## 4. 모델로 게임을 고친다
모델과 메커닉스를 갖췄으면 실제로 게임을 고칠 수 있다. 논문은 모노폴리를 고치는 과정과, 같은 게임을 세 번 설계하는 예를 보인다.

### 4-1. 모노폴리 고치기 : 메커닉스 조정과 튜닝
3절에서 본 문제는 긴 판에서 격차가 벌어져 긴장이 사라진다는 것이었다. 논문은 메커닉스를 두 방향으로 고친다.

- 뒤처진 사람 돕기 : 가난한 사람에게 보너스나 보조금, 부자에게 벌칙이나 세금을 준다. 출발 칸을 지날 때, 감옥에서 나올 때, 일정 금액 이상의 독점을 행사할 때 계산한다. 뒤처진 사람이 더 오래 경쟁하게 하려는 것이다
- 시간 압박 : 게임을 빨리 끝내 긴장이 식기 전에 마무리한다. 일정 비율 세금으로 자원 줄이기(돈을 빨리 쓰게 됨), 독점 수익 두 배(플레이어 간 차이가 빨리 벌어짐), 일정 가치 이하 땅을 무작위 분배가 예다

그다음 단계가 튜닝(Tuning)이다. 사전적 의미는 악기의 음을 맞추는 조율이고, 게임에서는 플레이테스트를 하며 벌칙의 크기, 세율, 보상과 벌칙의 기준값을 되풀이해 다듬어 균형을 맞추는 일이다. 이때 3절의 모델이 쓰인다.

- 에스테틱스 어휘와 모델 : 설계 목표를 말로 정하고, 문제를 논의하고, 진척을 잰다. 예를 들어 새 세금 계산이 복잡하면 돈과 순위를 따라가기 어려워져, 판에 마음을 쏟는 느낌을 오히려 해칠 수 있다
- 다이내믹 모델 : 문제가 어디서 오는지 짚는다. 주사위 모델로 판 크기나 배치를 바꿨을 때 게임 길이를 계산한다

### 4-2. MDA at Work : 같은 게임을 세 번 설계하기
논문은 AI 개발자도 게임 디자인에서 예외가 아니라고 본다. AI를 아무 프로젝트에나 끼우는 블랙박스로 볼 수 없고, 구성 요소는 시스템 동작과 플레이어 경험에 주는 영향과 떼어서 평가할 수 없다는 것이다. 이를 보여 주는 예제가 아기 돌보기 게임이다. 술래잡기를 바탕으로, 베이비시터가 숨은 아기를 찾아 재운다. 논문은 대상을 바꿔 가며 같은 게임을 세 번 설계한다.

| 구분 | 첫째 판 | 둘째 판 | 셋째 판 |
|------|--------|--------|--------|
| 대상 | 3~7세 어린이 | 7~12세 여자아이 (Rugrats 같은 프랜차이즈) | 14~35세 남성 (Splinter Cell, Thief 같은 게임) |
| 에스테틱스 | 탐험과 발견이 도전보다 중요 | 더 도전적으로. 여러 레벨에 걸친 이야기 | 판타지(정예 군인, 도적), 음모와 긴장의 줄거리. 도전은 시간 보내기에 가까울 수 있음 |
| 다이내믹스 | 아기가 놀람, 두려움, 기대를 드러내게 함 | 여러 캐릭터를 한꺼번에 쫓고 상대함 | 장비 얻기, 몰래 움직이고 속이고 피하고 달아나는 전술 |
| 메커닉스 | 말 걸기("I see you!", "boo!"), 쫓기, 잡기. 숨을 곳과 경로는 미리 정함 | 9시 전에 모두 재우기, 어질러짐 정도, 기저귀가 젖으면 울고 울면 점수 감소. 숨을 곳은 아기가 고름 | 기술 트리, 여러 종류의 적, 움직임과 시야가 다른 지역 |
| AI의 일 | 아기를 시야에 들어오게 움직이고 아기다운 반응 만들기 | 아기마다 다른 특성 보여 주기, 세계와 플레이어 판단하기 | 움직임과 공격 맞추기, 넓은 감각 정보 처리. 도전을 주되 결국 성공하게 돕기 |

이 예에서 논문이 끌어내는 결론은 아래와 같다.

- 에스테틱스 요구가 조금만 바뀌어도 AI의 메커닉스가 여러 수준에서 바뀐다. 길 찾기, 판단, 전략 시스템을 새로 만들어야 할 때도 있다
- 따로 떼어 낼 수 있는 "AI 메커닉스"는 없다. 지능과 일관성은 AI 논리와 게임플레이 논리가 맞물려 생긴다
- 그래서 설계 순서는 에스테틱스 목표를 정하고, 그 목표를 받치는 다이내믹스를 끌어내고, 거기에 맞춰 메커닉스의 범위를 정하는 것이다

## 5. MDA의 한계
MDA는 널리 쓰였지만 두 방향에서 비판을 받았다. 원문을 읽은 두 글을 정리한다.

### 5-1. 층을 나누는 기준이 흐리다 : 워크의 DDE
볼프강 워크(Wolfgang Walk)는 2015년 Game Developer(당시 Gamasutra)의 글 「From MDA to DDE」에서 세 가지를 지적한다.

- 메커닉스가 너무 넓다. 그래픽 스타일처럼 기계적이지 않은 것까지 들어간다. 프랭크 랜츠(Frank Lantz)의 말을 빌려, MDA의 메커닉스는 사실상 디자이너가 직접 설계하는 모든 것이라고 한다. 3-3절에서 본 두 정의의 차이와 이어지는 지적이다
- 에스테틱스라는 말이 맞지 않는다. 감정 반응을 뜻하기로 했지만 일상적인 의미의 미학과 섞인다. 게임 디자인은 경험 디자인이어야 한다며 경험(Experience)이라는 말을 제안한다
- 이야기를 다룰 자리가 없다. MDA는 내러티브 디자인의 틀을 주지 못하고, 맞추려 하면 깨지기 직전까지 늘이게 된다고 한다

대안으로 제안한 DDE(Design, Dynamics, Experience)는 아래와 같다. 세부 항목은 글 뒷부분을 요약으로만 읽고 옮긴 것이라 확인 필요다.

| MDA | DDE | 내용 |
|-----|-----|------|
| 메커닉스 | 디자인 (Design) | 블루프린트(개념 설계: 세계관, 규칙, 스타일), 메커닉스(코드 구조, 입출력, 규칙 구현처럼 플레이어가 직접 보고 듣지 않는 부분), 인터페이스(그래픽, 소리, 컷신, 텍스트처럼 게임 세계를 전하는 것) |
| 다이내믹스 | 다이내믹스 | 유지. 미겔 시카트(Miguel Sicart)의 플레이어 주체(player-subject) 개념을 더한다(개념 설명은 확인 필요) |
| 에스테틱스 | 경험 (Experience) | 감각, 감정, 지성의 세 갈래 |

워크는 이 순서가 시간 순서가 아니라 동시에 일어날 수 있다고도 쓴다. 이 제안은 2017년 Springer 『Game Dynamics』에 장으로 실렸다고 알려져 있으나, 원문은 읽지 못했고 공저자 표기는 확인 필요다.

### 5-2. 층을 지나는 순서가 하나가 아니다 : 두아르트의 재검토
루이스 클라우디우 실베이라 두아르트(Luiz Claudio Silveira Duarte)는 2015년 Game Developer(당시 Gamasutra)의 글 「Revisiting the MDA framework」에서 2절의 방향 가정을 문제 삼는다.

- 플레이어가 늘 에스테틱스부터 만난다는 가정은 디지털 게임에서는 맞는 경우가 많지만 보편적이지 않다
- 보드게임은 규칙서부터 읽어야 하므로 메커닉스부터 만난다. 층을 지나는 순서는 한 줄로 정해져 있지 않다
- 논문 저자들이 디지털 게임 경험에서 나온 관점으로 봤다고 진단한다
- 그래도 MDA가 망가진 것은 아니라고 결론짓는다. 세 층의 일관성이 핵심이니 한 줄 순서에 묶이지 말고 더 유연하게 쓰자는 것이다

### 5-3. 두 비판이 남긴 것
| 구분 | 워크 | 두아르트 |
|------|------|---------|
| 문제 삼는 것 | 층을 나누는 기준 | 층을 지나는 순서 |
| 제안 | 새 틀(DDE) | MDA를 더 유연하게 사용 |

두 글 모두 층 사이에 원인과 결과가 이어진다는 생각은 버리지 않는다(해석). 비판이 겨누는 곳은 층의 이름과 순서이고, 층을 오가며 원인과 결과를 따진다는 MDA의 쓰임은 남는다.

<br/>

## 6. 정리 : MDA를 쓰는 법
1~5절을 합치면 MDA는 세 가지를 준다.

- 어휘 : "재미" 대신 노리는 감정을 구체적으로 부를 말(2장의 여덟 가지와 그 밖의 것)
- 모델 : 감정을 확인할 수 있는 조건으로 바꾸는 에스테틱 모델, 흐름을 미리 계산하는 다이내믹 모델
- 순서 : 에스테틱스 목표를 정하고 → 다이내믹스를 끌어내고 → 메커닉스의 범위를 정하고 → 튜닝으로 다듬는다

쓸 때 주의할 점은 5절의 비판에서 나온다(정리).

- 메커닉스라는 말이 무엇까지 가리키는지 팀 안에서 먼저 맞춘다
- 이야기 설계는 MDA만으로 다루기 어렵다
- 플레이어가 층을 지나는 순서는 게임마다 다를 수 있다. 보드게임처럼 규칙부터 만나는 게임도 있다
