## MDA 프레임워크란 ?
- 게임을 메커닉스(Mechanics), 다이내믹스(Dynamics), 에스테틱스(Aesthetics) 세 층으로 나눠 분석하고 설계하는 틀이다
- 출처는 휴니키, 르블랑, 주벡의 2004년 논문 「MDA: A Formal Approach to Game Design and Game Research」다(저자와 배경은 [2장](../02.게임에서%20재미란(Fun%20in%20Games)/README.md) 참고)
- 2장은 세 층의 정의와 여덟 가지 에스테틱스를 다뤘다. 이 장은 논문의 나머지 내용(렌즈, 에스테틱 모델, 다이내믹 모델, 메커닉스, 튜닝, 설계 예시)과 이후의 비판을 정리한다

### 프레임워크 (Framework)
사전적 의미는 뼈대, 골조다. frame(틀)과 work(짜임)가 합쳐진 말이다.
설계에서는 무엇을 어떤 순서로 따질지 정해 주는 생각의 틀을 말한다. 답을 대신 내 주지는 않는다.

### 용어 정리
| 층 | 원래 뜻 | 게임에서의 뜻 |
|----|--------|--------------|
| 메커닉스 (Mechanics) | 역학, 기계가 돌아가는 짜임새 | 게임이 돌아가는 짜임새. 규칙과 구성 요소 |
| 다이내믹스 (Dynamics) | 동역학, 힘을 받아 시간에 따라 변하는 움직임 | 규칙이 플레이어 입력을 받아 시간에 따라 만드는 실제 판의 흐름 |
| 에스테틱스 (Aesthetics) | 미학, 아름다움을 느끼는 감각 | 플레이어에게 일어나기를 바라는 감정 반응 (2장) |

- 메커닉스를 기계의 짜임새로, 다이내믹스를 그 짜임새가 움직이는 모습으로 보면 원래 뜻이 이어진다(해석)
- 논문은 메커닉스를 두 번 다르게 정의한다. 차이는 아래 메커닉스 절에 정리했다

## MDA as Lens : 세 층을 렌즈로 보기
### 핵심
- 세 층은 게임을 보는 각각의 렌즈(lens), 보기(view)다
- 셋은 따로 떨어져 있지만 원인과 결과로 이어져 있다("separate, but causally linked")
- 디자이너는 M → D → A 방향으로, 플레이어는 A → D → M 방향으로 게임을 본다(2장)

### 왜 렌즈로 보나
- 두 방향을 번갈아 보면 한 층의 작은 변화가 다른 층으로 번지는 것을 볼 수 있다
- 플레이어 쪽에서 보면 기능 중심이 아니라 경험 중심으로 설계하게 된다(2장)
- 그래서 논문은 A, D, M 순서로 설명한다. 이 장도 같은 순서를 따른다

비유하면 카메라 렌즈다. 풍경은 하나이고, 광각과 망원을 바꿔 끼우면 보이는 것이 달라진다.

## 에스테틱 모델 (Aesthetic Model)
### 정의
- 노리는 감정이 생기려면 무엇이 갖춰져야 하는지 적은 설명이다
- 2장의 에스테틱스 어휘를 나침반처럼 써서 세운다
- 모델이 있으면 그 감정을 만드는 다이내믹스와 메커닉스를 논의하기 쉬워진다

### 예 : 경쟁
대상 게임은 Charades(몸짓으로 단어 맞히기)와 Quake(1인칭 슈팅)다. 둘 다 플레이어가 서로를 이기는 데 마음을 쏟을 때 성공한다.

| 구분 | 내용 |
|------|------|
| 필요 조건 | 상대가 있다 (Charades는 팀끼리, Quake는 컴퓨터 상대와 겨룬다) |
| 필요 조건 | 모두가 이기고 싶어 한다 |
| 설계 요구 | 맞서서 겨루는 플레이를 받친다 |
| 설계 요구 | 누가 이기고 있는지 분명히 보여 준다 |
| 실패 조건 | 이기는 조건이 안 보이거나, 도저히 못 이긴다고 느끼면 흥미가 크게 떨어진다 |

에스테틱 모델은 막연한 목표(경쟁이 재미있어야 한다)를 확인할 수 있는 조건(상대가 있는가, 승패가 보이는가)으로 바꾼다.

## 다이내믹 모델 (Dynamic Model)
### 정의
- 판의 흐름을 예측하고 설명하는 모델이다
- 다이내믹스를 구체적으로 다루면 흔한 설계 실수를 피할 수 있다

### 에스테틱스별 다이내믹스
| 에스테틱스 | 그 감정을 만드는 다이내믹스의 예 |
|-----------|----------------------------------|
| 도전 (Challenge) | 시간 압박, 상대의 플레이 |
| 동료애 (Fellowship) | 한 팀끼리만 정보 공유, 혼자서는 어려운 승리 조건(적 기지 점령 등) |
| 표현 (Expression) | 아이템을 사고 짓고 얻는 시스템, 레벨과 세계를 만드는 시스템, 나만의 캐릭터를 만드는 시스템 |
| 극적 긴장 (Dramatic tension) | 긴장이 오르고, 풀리고, 마무리되는 흐름 |

극적 긴장은 2장의 여덟 항목에 없지만 논문에 나온다. 여덟 가지가 닫힌 목록이 아니라는 예다.

### 확률 모델 : 주사위 두 개
- 대상 : 모노폴리
- 목적 : 주사위 두 개의 합의 확률로, 판을 한 바퀴 도는 평균 시간을 구한다

```python
from collections import Counter
from fractions import Fraction

counts = Counter(a + b for a in range(1, 7) for b in range(1, 7))
for total in range(2, 13):
    print(total, counts[total])
# 한 줄에 하나씩 찍힌다. 왼쪽은 합, 오른쪽은 36가지 중 경우의 수
# 2 1 / 3 2 / 4 3 / 5 4 / 6 5 / 7 6 / 8 5 / 9 4 / 10 3 / 11 2 / 12 1

mean = Fraction(sum(t * c for t, c in counts.items()), 36)
print("평균:", mean)                                          # 평균: 7
print("40칸 한 바퀴 평균 굴림 수:", round(40 / float(mean), 2))  # 40칸 한 바퀴 평균 굴림 수: 5.71
```

- 합 7이 가장 흔하고(36가지 중 6가지), 평균 이동은 7칸이다
- 40칸 판이면 한 바퀴에 평균 약 5.7번 굴린다
- 5.7은 더블, 감옥, 이동 카드를 뺀 단순 계산이다. 논문에는 숫자가 없다
- 쓰임 : 판의 칸 수나 배치를 바꿀 때 게임 시간이 얼마나 변할지 미리 계산한다(튜닝 절)

### 피드백 모델 : 부자는 더 부자가 된다
- 피드백 : 결과가 다시 원인으로 돌아오는 고리. 논문은 온도 조절기 그림으로 설명한다(온도를 재고, 너무 덥거나 추우면 냉난방을 켠다)
- 모노폴리의 고리 : 부자일수록 남에게 더 큰 손해를 입히고, 가난한 사람은 더 가난해진다
- 결과 : 격차가 벌어지면 극적 긴장과 내가 판을 움직인다는 느낌이 사라진다(2장)

| 고리 | 방향 | 예 |
|------|------|-----|
| 음의 피드백 | 차이를 줄인다 | 온도 조절기 |
| 양의 피드백 | 차이를 키운다 | 모노폴리의 부익부 |

음과 양의 피드백이라는 용어는 논문에 없고, 제어 이론의 용어를 빌려 정리한 것이다.

## 메커닉스 (Mechanics)
### 정의
| 위치 | 정의 |
|------|------|
| 논문 MDA 절 (2장에서 인용) | 데이터 표현과 알고리즘 수준의 구성 요소 |
| 논문 Mechanics 절 | 게임 안에서 플레이어에게 주어지는 여러 행동, 동작, 조작 장치 |

- 한 논문 안에서도 메커닉스의 범위가 다르다. 이 점이 아래 워크의 비판과 이어진다
- 메커닉스는 콘텐츠(레벨, 에셋 등)와 함께 다이내믹스를 받친다. [4장](../04.시스템과%20콘텐츠란(Systems%20and%20Content)/README.md)의 시스템과 콘텐츠 구분과 같은 짝이다

### 메커닉스에서 생기는 다이내믹스
| 게임 | 메커닉스 | 생기는 다이내믹스 |
|------|---------|------------------|
| 카드 게임 | 섞기, 트릭 따기(trick-taking), 베팅 | 블러핑 |
| 슈팅 게임 | 무기, 탄약, 부활 지점 | 캠핑(한자리에서 기다리기), 저격 |
| 골프 | 공, 클럽, 벙커, 워터 해저드 | 부러지거나 물에 빠진 클럽 |

- 블러핑이라는 규칙은 없다. 베팅과 숨겨진 패가 맞물려 생긴다
- 규칙에 없던 행동이 생기는 것은 [4장](../04.시스템과%20콘텐츠란(Systems%20and%20Content)/README.md)의 창발과 같은 현상으로 볼 수 있다(해석)

### 메커닉스를 고쳐 모노폴리 바꾸기
| 방향 | 목적 | 메커닉스 예 |
|------|------|------------|
| 뒤처진 사람 돕기 | 격차를 줄여 뒤처진 사람이 오래 경쟁하게 한다 | 가난한 사람에게 보너스나 보조금, 부자에게 벌칙이나 세금. 출발 칸을 지날 때, 감옥에서 나올 때, 일정 금액 이상의 독점을 행사할 때 계산 |
| 시간 압박 | 게임을 빨리 끝내 긴장이 식기 전에 마무리한다 | 일정 비율 세금으로 자원 줄이기(돈을 빨리 쓰게 됨), 독점 수익 두 배(플레이어 간 차이가 빨리 벌어짐), 일정 가치 이하 땅을 무작위 분배 |

- 같은 문제(긴장이 사라진 긴 판)에 목적이 다른 두 해법이 있다
- 시간 압박 쪽의 독점 수익 두 배는 오히려 격차를 빨리 벌린다(정리)

## 튜닝 (Tuning)
### 정의
- 사전적 의미는 악기의 음을 맞추는 조율이다
- 게임에서는 플레이테스트를 하며 값(벌칙의 크기, 세율, 보상과 벌칙의 기준값)을 되풀이해 다듬어 균형을 맞추는 일이다

### 모델의 쓰임
| 모델 | 튜닝에서 하는 일 | 모노폴리 예 |
|------|---------------|-----------|
| 에스테틱스 어휘와 모델 | 설계 목표를 말로 정하고, 문제를 논의하고, 진척을 잰다 | 새 세금 계산이 복잡하면 돈과 순위를 따라가기 어려워져, 판에 마음을 쏟는 느낌을 해칠 수 있다 |
| 다이내믹 모델 | 문제가 어디서 오는지 짚는다 | 주사위 모델로 판 크기나 배치를 바꿨을 때 게임 길이를 계산한다 |

## MDA at Work : 같은 게임을 세 번 설계하기
### 배경
- 논문은 AI 개발자와 연구자도 게임 디자인에서 예외가 아니며, 게임이 복잡해질수록 AI와 게임 디자인이 합쳐진다고 본다
- AI를 아무 프로젝트에나 끼우는 블랙박스로 볼 수 없다. 게임의 구성 요소는 시스템 동작과 플레이어 경험에 주는 영향과 떼어서 평가할 수 없다
- 예제는 아기 돌보기 게임이다. 술래잡기를 바탕으로, 베이비시터가 숨은 아기를 찾아 재운다

### 세 번의 설계
| 구분 | 첫째 판 | 둘째 판 | 셋째 판 |
|------|--------|--------|--------|
| 대상 | 3~7세 어린이 | 7~12세 여자아이, Nickelodeon의 Rugrats 같은 프랜차이즈 | 14~35세 남성, Splinter Cell이나 Thief 같은 게임 |
| 에스테틱스 | 탐험과 발견이 도전보다 중요 | 더 도전적으로. 여러 레벨에 걸친 이야기 | 판타지(스파이를 쫓는 정예 군인, 보물을 노리는 도적), 도전은 시간 보내기에 가까울 수 있음. 음모와 긴장이 가득한 줄거리 |
| 다이내믹스 | 승리나 경쟁보다 아기가 놀람, 두려움, 기대를 드러내게 함 | 여러 캐릭터를 한꺼번에 쫓고 상대함 | 무기와 장비를 얻거나 사기, 몰래 움직이고 속이고 피하고 달아나는 전술 |
| 메커닉스 | 아기에게 말 걸기("I see you!", "boo!"), 쫓기, 살금살금 다니기, 잡기. 숨을 곳과 경로는 미리 정해 둠 | 시간 압박(9시 전에 모두 재우기), 어질러짐 정도, 감정 관리(기저귀가 젖으면 울고, 울면 점수를 잃음). 숨을 곳은 아기가 스스로 고름 | 넓은 기술 트리, 여러 종류의 적, 움직임과 시야가 다른 지역 |
| AI의 일 | 아기를 시야에 들어오게 움직이고, 아기다운 반응 만들기 | 아기마다 다른 특성을 보여 주기, 세계와 다른 아기와 플레이어를 판단하기 | 움직임과 공격 맞추기, 넓은 감각 정보 처리. 감정 표현은 적게, 플레이어의 기척에는 두려움과 증오 |

셋째 판에서 논문이 던지는 설계 질문은 아래와 같다.
- 적이 장애물을 넘고 험한 지형을 지나가게 할 것인가, 속일 것인가
- 소리 전파를 현실처럼 계산할 것인가, 거리만 보는 단순한 계산으로 충분한가
- 플레이어의 위치와 의도를 읽는 AI는 도전을 느끼게 하되 결국 성공하도록 도와야 한다

### 결론 (Wrapping Up)
- 에스테틱스 요구가 조금만 바뀌어도 AI의 메커닉스가 여러 수준에서 바뀐다. 길 찾기, 판단, 전략 시스템을 새로 만들어야 할 때도 있다
- 따로 떼어 낼 수 있는 "AI 메커닉스"는 없다. 지능과 일관성은 AI 논리와 게임플레이 논리가 맞물려 생긴다
- 설계 순서 : 에스테틱스 목표를 정한다 → 그 목표를 받치는 다이내믹스를 끌어낸다 → 거기에 맞춰 메커닉스의 범위를 정한다

## MDA에 대한 비판
원문을 읽은 두 글을 정리한다.

### 볼프강 워크(Wolfgang Walk), 「From MDA to DDE」 (2015)
Game Developer(당시 Gamasutra)에 실린 글이다.

| 비판 | 내용 |
|------|------|
| 메커닉스가 너무 넓다 | 그래픽 스타일처럼 기계적이지 않은 것까지 들어간다. 프랭크 랜츠(Frank Lantz)의 말을 빌려, MDA의 메커닉스는 사실상 디자이너가 직접 설계하는 모든 것이라고 한다 |
| 에스테틱스라는 말이 맞지 않는다 | 감정 반응을 뜻하기로 했지만 일상적인 의미의 미학(그래픽 스타일 등)과 섞인다. 게임 디자인은 경험 디자인이어야 한다며 경험(Experience)이라는 말을 제안한다 |
| 이야기를 다룰 자리가 없다 | MDA는 내러티브 디자인의 틀을 주지 못하고, 내러티브에 맞추려 하면 MDA를 깨지기 직전까지 늘이게 된다고 한다 |

대안으로 DDE(Design, Dynamics, Experience)를 제안한다. 아래 세부 항목은 글 뒷부분을 요약으로만 읽고 옮긴 것이라 확인 필요다.

| MDA | DDE | 내용 |
|-----|-----|------|
| 메커닉스 | 디자인 (Design) | 블루프린트(Blueprint) : 세계관, 규칙, 그림과 이야기와 소리의 스타일 같은 개념 설계. 메커닉스 : 코드 구조, 입출력 처리, 규칙과 오브젝트 상호작용의 구현처럼 플레이어가 직접 보고 듣지 않는 부분. 인터페이스(Interface) : 그래픽, 소리, 컷신, 텍스트처럼 게임 세계를 플레이어에게 전하는 것 |
| 다이내믹스 | 다이내믹스 | 유지. 미겔 시카트(Miguel Sicart)의 플레이어 주체(player-subject) 개념을 더한다(개념 설명은 확인 필요) |
| 에스테틱스 | 경험 (Experience) | 감각, 감정, 지성의 세 갈래 |

- 워크는 이 순서가 시간 순서가 아니며 모든 단계가 동시에 일어날 수 있다고 쓴다
- 이 제안은 2017년 Springer 『Game Dynamics』에 「Design, Dynamics, Experience (DDE): An Advancement of the MDA Framework for Game Design」으로 실렸다고 알려져 있다. 원문은 읽지 못했고 공저자 표기는 확인 필요다

### 루이스 클라우디우 실베이라 두아르트(Luiz Claudio Silveira Duarte), 「Revisiting the MDA framework」 (2015)
Game Developer(당시 Gamasutra)에 실린 글이다.

| 항목 | 내용 |
|------|------|
| 비판 | 플레이어가 늘 에스테틱스부터 만난다는 가정은 디지털 게임에서는 맞는 경우가 많지만 보편적이지 않다 |
| 근거 | 보드게임은 규칙서부터 읽어야 하므로 메커닉스부터 만난다. 세 층을 지나는 순서가 한 줄로 정해져 있지 않다 |
| 원인 진단 | 논문 저자들이 디지털 게임 경험에서 나온 관점으로 봤다 |
| 결론 | MDA가 망가진 것은 아니다. 세 층의 일관성이 핵심이니 한 줄 순서에 묶이지 말고 더 유연하게 쓰자 |

### 두 비판 비교
| 구분 | 워크 | 두아르트 |
|------|------|---------|
| 문제 삼는 것 | 층을 나누는 기준(무엇이 메커닉스, 에스테틱스인가) | 층을 지나는 순서 |
| 제안 | 새 틀(DDE) | MDA를 더 유연하게 사용 |
| MDA의 인과 구조 (해석) | 유지(디자인 → 다이내믹스 → 경험) | 유지 |

두 글 모두 층 사이에 원인과 결과가 이어진다는 생각은 버리지 않는다(해석).

## 참고 자료
- Robin Hunicke, Marc LeBlanc, Robert Zubek, [MDA: A Formal Approach to Game Design and Game Research](https://users.cs.northwestern.edu/~hunicke/MDA.pdf) (2004). 전체를 읽었다. 이 장에서는 MDA in Detail(MDA as Lens, Aesthetic Models, Dynamic Models, Mechanics, Tuning), MDA at Work(Wrapping Up 포함), Conclusions 절을 썼다. 논문이 실린 학술 행사 이름은 PDF에 적혀 있지 않아 확인 필요
- Wolfgang Walk, [From MDA to DDE](https://www.gamedeveloper.com/design/from-mda-to-dde), Game Developer, 2015-11-11 (2026-11-25 확인). 앞부분은 원문으로, 뒷부분은 요약으로만 읽었다
- Luiz Claudio Silveira Duarte, [Revisiting the MDA framework](https://www.gamedeveloper.com/design/revisiting-the-mda-framework), Game Developer, 2015-02-03 (2026-11-25 확인). 전문을 읽었다. 글에 실린 두 번째 그림의 내용은 확인하지 못했다
- 「Design, Dynamics, Experience (DDE): An Advancement of the MDA Framework for Game Design」, 『Game Dynamics』, Springer, 2017 ([Springer 페이지](https://link.springer.com/10.1007/978-3-319-53088-8_3)). 접근이 막혀 읽지 못했다. 저자 표기는 확인 필요
- 프레임워크, 메커닉스, 다이내믹스, 튜닝의 사전적 의미는 사전을 찾아 확인하지 않고 일반적인 영어 뜻으로 적었다(확인 필요)
- 표와 본문의 "(해석)", "(정리)"는 출처가 아니라 작성자가 덧붙인 판단이다
