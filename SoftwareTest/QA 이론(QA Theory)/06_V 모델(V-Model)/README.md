## V 모델이란 ?
- 개발 단계마다 그 결과물을 검증할 테스트 단계를 하나씩 짝지어 둔 SDLC 모델
- 왼쪽 위에서 아래로 개발이 내려가고, 구현을 꼭짓점으로 오른쪽 아래에서 위로 테스트가 올라가는 모양이 V자라서 이렇게 부른다
- 폭포수처럼 순서대로 진행하는 순차 모델의 하나다

### 모델 (Model)
사전적 의미는 본보기, 틀이다.
SDLC에서 모델은 단계를 어떤 순서로 진행할지 정해 둔 틀을 말한다. V 모델은 그 틀 가운데 개발과 테스트의 짝을 눈에 보이게 그린 것이다.

<br/>

## 그림
```
요구사항 분석 ──────────────────── 인수 테스트
    │                                  ↑
    ↓                                  │
  시스템 설계 ──────────────── 시스템 테스트
      │                            ↑
      ↓                            │
   아키텍처 설계 ────────── 통합 테스트
        │                      ↑
        ↓                      │
     모듈 설계 ─────── 단위(컴포넌트) 테스트
          │                ↑
          ↓                │
          └──── 구현 ──────┘
```

<br/>

## 짝이 되는 단계
| 왼쪽 (개발) | 오른쪽 (테스트) | 무엇을 검증하나 |
|---|---|---|
| 요구사항 분석 | 인수 테스트 | 사용자 요구를 채우는가 |
| 시스템 설계 | 시스템 테스트 | 시스템 전체가 명세대로 동작하는가 |
| 아키텍처 설계 | 통합 테스트 | 모듈 사이의 인터페이스와 상호작용 |
| 모듈 설계 | 단위(컴포넌트) 테스트 | 함수, 클래스 같은 단위가 설계대로 동작하는가 |

각 레벨이 무엇을 검증하는지는 [테스트 레벨](../07_테스트%20레벨(Test%20Levels)/README.md)에 정리했다. ISTQB CTFL v4.0은 통합 테스트를 컴포넌트 통합과 시스템 통합으로 나눠 다섯 레벨로 본다.

<br/>

## 핵심은 미리 준비하는 것
V 모델에서 중요한 것은 그림의 모양이 아니라, 왼쪽 단계를 진행하는 동안 오른쪽 단계의 테스트를 미리 준비한다는 점이다. 요구사항을 분석할 때 인수 테스트 시나리오를 함께 쓰고, 시스템을 설계할 때 시스템 테스트 시나리오를 함께 쓴다. 그래서 [조기 테스트 원칙](../02_테스트%207원칙(ISTQB%20Principles)/README.md)을 구조로 옮긴 모델이라고 설명하기도 한다.

이렇게 하면 요구사항 하나가 어떤 인수 TC로 확인되는지 바로 이어 볼 수 있다. trace의 사전적 의미는 자취, 흔적을 따라가다이다. 이렇게 요구사항에서 TC로, TC에서 결함으로 자취를 따라갈 수 있는 성질을 추적성(Traceability)이라고 한다.

<br/>

## 장점과 한계
테스트 단계가 개발 단계와 1:1로 대응해 무엇을 언제 검증할지가 분명하고, 테스트를 일찍 설계하므로 요구사항과 설계의 문제를 앞에서 발견할 기회가 생긴다.

한계는 순차 모델이라는 데서 온다. 앞 단계가 끝나야 다음으로 넘어가므로 요구사항이 자주 바뀌는 환경에 맞지 않는다. 테스트 실행은 구현 뒤에 몰려 있어서, 요구사항 분석에서 생긴 잘못이 실행으로 드러나는 것은 맨 마지막 인수 테스트 단계일 수 있다.

<br/>

## 면접 답변 (30초)
> "V 모델은 개발의 각 단계에 짝이 되는 테스트 단계를 V자로 배치한 모델입니다. 요구사항 분석에는 인수 테스트, 시스템 설계에는 시스템 테스트, 아키텍처 설계에는 통합 테스트, 모듈 설계에는 단위 테스트가 대응합니다. 핵심은 각 개발 단계에서 짝이 되는 테스트를 미리 설계한다는 점이라, 조기 테스트 원칙을 구조로 만든 모델로 볼 수 있습니다. 다만 순차 모델이라 요구사항 변경이 잦은 환경에는 맞지 않습니다."

<br/>

## 실무에서는
요구사항이 비교적 고정되어 있고 문서와 추적성이 중요한 금융, 의료 같은 규제 산업에서 여전히 쓰인다. 애자일 환경에서는 같은 생각을 스프린트 단위로 줄여, 스토리를 정할 때 인수 조건과 테스트를 함께 쓰는 방식으로 적용한다.
