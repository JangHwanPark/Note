## 프로젝트 제약 3요소란 ?
- 모든 프로젝트는 범위(품질), 비용, 일정이라는 세 가지 제약 안에서 움직이고, 하나를 바꾸면 다른 것도 함께 바뀐다는 개념
- 세 꼭짓점을 삼각형으로 그려 철의 삼각형(Iron Triangle) 또는 삼중 제약(Triple Constraint)이라고 부른다
- 프로젝트 관리 쪽 원래 모델은 범위(Scope), 일정(Time), 비용(Cost)을 꼭짓점에 두고 품질을 그 결과로 가운데에 둔다. QA 면접에서는 흔히 품질, 비용, 일정으로 묻는다

### 제약 (Constraint)
사전적 의미는 조건을 붙여 제한함이다.
프로젝트에서는 마음대로 늘릴 수 없는 한계, 즉 정해진 예산, 정해진 출시일, 정해진 기능 범위를 말한다. 셋이 서로 묶여 있어서 하나만 따로 좋게 만들 수 없다는 점이 핵심이다.

여행 계획과 같다. 예산과 날짜가 정해져 있으면 갈 수 있는 곳의 수가 정해지고, 더 많은 곳을 가려면 돈을 더 쓰거나 날짜를 늘려야 한다.

<br/>

## 세 요소

| 요소 | 의미 | 예 |
| --- | --- | --- |
| 범위, 품질 (Scope, Quality) | 만들 기능의 양과 완성도 | 기능 목록, 허용할 결함 수준 |
| 비용 (Cost) | 쓸 수 있는 돈과 사람 | 예산, 투입 인원 |
| 일정 (Time) | 끝내야 하는 시점 | 출시일, 스프린트 마감 |

```
        범위 / 품질
           /\
          /  \
         /    \
        /      \
   비용 ──────── 일정
```

세 가지를 한꺼번에 최고로 만들 수는 없다. 하나를 고정하거나 욕심을 내면 적어도 하나는 양보해야 한다.

<br/>

## 트레이드오프 예

| 지키는 것 | 양보하는 것 | 예 |
| --- | --- | --- |
| 일정과 품질 | 비용이 는다 | 사람을 더 넣어 마감과 품질을 모두 지킨다 |
| 일정과 비용 | 범위나 품질이 준다 | 기능을 줄인 MVP로 출시하고 일부 결함을 감수한다 |
| 비용과 품질 | 일정이 늦어진다 | 적은 인원으로 꼼꼼하게 만들고 출시를 미룬다 |

사람을 더 넣는다고 일정이 꼭 줄지는 않는다. 늦어진 프로젝트에 사람을 더하면 오히려 더 늦어진다는 브룩스의 법칙(『맨먼스 미신』, 1975)도 함께 알아 둔다.

<br/>

## QA에서 쓰는 곳
테스트도 같은 제약 안에서 한다. 정해진 일정 안에 모든 결함을 찾을 수는 없다는 것을 전제로 무엇을 먼저 할지 정한다.

- 일정이 촉박하면 위험이 큰 곳, 결함이 몰리는 곳부터 테스트한다(리스크 기반 테스트)
- 비용이 부족하면 오래 반복할 회귀 테스트를 자동화해 장기적으로 비용을 줄인다
- 품질이 최우선이면 회귀 테스트와 탐색적 테스트를 함께 돌린다
- 결함 우선순위(P0~P3)를 매길 때도 이번 일정 안에 고칠 것과 미룰 것을 나누는 판단이 이 제약에서 나온다

테스팅 7원칙의 완전한 테스트는 불가능하다는 원칙과 바로 이어진다.
