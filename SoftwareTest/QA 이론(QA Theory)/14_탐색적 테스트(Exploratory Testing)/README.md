## 탐색적 테스트란 ?
- 시스템을 배우는 일, 테스트를 설계하는 일, 실행하는 일을 동시에 하는 테스트. TC를 미리 쓰지 않고 결과를 보며 다음에 무엇을 확인할지 정한다
- ISTQB CTFL v4.0에서는 경험 기반 기법 중 하나다
- 아무렇게나 눌러 보는 즉흥 테스트(Ad-hoc Testing)와 다르다. 탐색적 테스트는 무엇을 볼지 의식하며 배운 것을 다음 테스트에 반영한다. 목표(차터)와 시간 제한(타임박스)을 두면 더 체계적으로 할 수 있다

### 탐색 (Exploration)
사전적 의미는 모르는 곳을 샅샅이 더듬어 찾음이다.
테스트에서는 지도를 미리 다 그려 두지 않고, 시스템을 써 보며 알게 된 것을 바탕으로 다음 테스트를 정해 나가는 방식을 말한다. 이 용어는 켐 카너(Cem Kaner)가 1980년대에 쓰기 시작한 것으로 알려져 있다.

처음 가는 동네를 지도 없이 걷되 "이 동네에서 문 닫은 가게 찾기"처럼 목표와 시간을 정해 두고 걷는 것과 같다. 걷다가 이상한 골목이 보이면 그쪽으로 방향을 바꾼다.

<br/>

## 왜 필요할까
미리 써 둔 TC는 쓴 사람이 떠올린 경우만 확인한다. 같은 TC를 반복하면 같은 곳만 보게 되고 새 결함을 잘 찾지 못한다(살충제 역설). 탐색적 테스트는 실행하면서 본 것을 바로 다음 테스트에 반영하므로 TC가 놓친 결함, 특히 명세에 없던 상황이나 사용성 문제를 찾는 데 강하다.

<br/>

## TC 기반 테스트와 비교

| 구분 | TC 기반 (Scripted) | 탐색적 (Exploratory) |
| --- | --- | --- |
| TC를 쓰는 때 | 실행 전에 미리 | 실행하면서 |
| 강점 | 재현성, 추적성, 자동화 | 새 결함 발견, 살충제 역설 완화 |
| 약점 | 정해진 경우 밖의 결함을 놓침 | 재현성, 추적성이 약함 |
| 맞는 상황 | 안정된 기능, 회귀 테스트 | 새 기능, 명세가 불분명할 때, 시간이 짧을 때 |
| 결과를 재는 방법 | TC 수, 통과율 | 끝낸 차터 수, 찾은 결함 |
| 기대는 것 | TC 문서 | 테스터의 도메인 지식과 경험 |

<br/>

## 언제 쓰나
- 명세가 불분명하거나 자주 바뀌는 새 기능
- 회귀 자동화가 같은 곳만 반복해서 새 결함이 안 나올 때
- 출시 직전 짧은 시간에 핵심 흐름과 예외 흐름을 빠르게 훑을 때
- 사용성, 사용자 경험 쪽 결함을 찾을 때
- 도메인을 배우면서 동시에 검증해야 하는 새 영역

<br/>

## 재현성과 추적성 보완하기

### 차터 (Charter)
세션마다 목표 하나를 문장으로 정한다. 예를 들어 "결제 페이지에서 비정상 입력값을 넣었을 때 오류 처리를 확인한다"처럼 쓴다. 목표 없이 이곳저곳 눌러 보면 즉흥 테스트에 가까워진다.

### 세션 기반 테스트 관리 (SBTM)
Session-Based Test Management는 조너선 바크(Jonathan Bach)와 제임스 바크(James Bach)가 2000년에 정리한 방법이다. 끊기지 않는 시간 단위(세션)로 탐색적 테스트를 하고, 끝나면 세션 리포트를 남긴다.

- 세션 길이는 보통 짧은 세션 60분, 보통 90분, 긴 세션 120분 정도로 잡는다
- 리포트에는 차터, 걸린 시간, 찾은 결함, 남은 의문, 환경 정보를 적는다
- 시간을 어디에 썼는지 TBS 비율로 남긴다. T는 테스트 설계와 실행, B는 결함 조사와 보고, S는 환경 준비(Setup)에 쓴 시간이다. 차터 안의 일(on-charter)과 차터 밖에서 발견한 기회(opportunity)에 쓴 시간도 나눠 적는다

### 발견 즉시 재현 절차 남기기
결함을 찾으면 바로 재현해 보고, 재현되면 정식 결함 리포트로 올린다. 재현이 안 되는 결함도 "재현 불가" 표시와 환경 정보를 남긴다.

### 기록 도구
화면 녹화로 결함 직전 상황을 남기고, 콘솔 로그와 네트워크 탭을 캡처한다. 브라우저, OS, 권한, 데이터 상태도 함께 적는다.

### 자동화 회귀 스위트로 옮기기
탐색적 테스트로 찾은 결함은 재현 TC로 만들어 회귀 자동화에 넣는다. 탐색으로 새 곳을 찾고, 자동화로 그곳을 계속 지키는 식으로 둘이 서로를 채운다.

<br/>

## 차터와 세션 결과 예
차터는 "결제 흐름에서 네트워크 끊김, 타임아웃, 버튼 중복 클릭 상황의 오류 처리를 60분 동안 탐색한다"로 정했다. 세션이 끝난 뒤 리포트에는 차터 진행 80%, 결함 3건, 의문 1건, 환경 정보를 적었다.

<br/>

## 면접 답변 (30초)
> "탐색적 테스트는 학습, 설계, 실행을 동시에 하는 테스트로, 미리 쓴 TC 대신 차터라는 목표와 시간 제한 안에서 구조화해 진행합니다. 명세가 불분명한 새 기능이나 회귀 스위트가 같은 곳만 반복하는 영역에서 새 결함을 찾는 데 강합니다. 약점인 재현성과 추적성은 세션 기반 테스트 관리로 세션마다 리포트를 남기고, 화면 녹화와 환경 정보를 기록하고, 재현되는 결함은 자동화 회귀 스위트로 옮겨 보완합니다."
