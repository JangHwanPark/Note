## 테스트 유형이란 ?
- 무엇을 확인하려고 테스트하느냐(목적)에 따른 분류
- [테스트 레벨](../07_테스트%20레벨(Test%20Levels)/README.md)이 "어떤 대상을"이라면 유형은 "무엇을"이다. 둘은 서로 독립이라 어느 레벨에서든 어느 유형이든 할 수 있다
- ISTQB CTFL v4.0은 기능, 비기능, 블랙박스, 화이트박스의 네 유형을 든다. 확인 테스트와 회귀 테스트는 유형이 아니라 변경 뒤에 하는 테스트로 따로 다룬다(예전 v3.1은 "변경 관련 테스트"를 네 번째 유형으로 두었다)

### 유형 (Type)
사전적 의미는 성질이나 특징이 비슷한 것끼리 묶은 갈래다.
테스트에서는 테스트가 확인하려는 품질의 성질로 묶은 갈래를 말한다. 같은 로그인 화면이라도 "로그인이 되는가"는 기능, "1초 안에 되는가"는 비기능 유형이다.

<br/>

## 네 가지 유형 (CTFL v4.0)
| 유형 | 무엇을 확인하나 | 예시 |
|---|---|---|
| 기능 (Functional) | 시스템이 무엇을 하는가 | 로그인, 결제, 검색 |
| 비기능 (Non-functional) | 시스템이 얼마나 잘 하는가 | 성능, 보안, 사용성 |
| 블랙박스 (Black-box) | 명세에 적힌 동작을 내부를 보지 않고 | 동등 분할, 경계값으로 만든 TC |
| 화이트박스 (White-box) | 코드 같은 내부 구조가 충분히 실행되는가 | 구문, 분기 커버리지 |

블랙박스와 화이트박스는 [4장](../04_블랙박스%20화이트박스%20그레이박스(Black,%20White%20and%20Grey%20Box)/README.md)에서 자세히 다뤘다.

<br/>

## 기능 테스트
요구사항과 명세를 근거로, 정해진 입력에 정해진 결과가 나오는지 본다. "X 화면에서 Y 버튼을 누르면 Z가 나오는가" 같은 형태다. 기능 QA가 가장 많이 하는 일이다.

<br/>

## 비기능 테스트
기능이 맞게 동작해도 느리거나 불안정하면 쓸 수 없다. 비기능 테스트는 이런 품질 특성을 확인한다. CTFL v4.0은 품질 특성을 국제 표준 ISO/IEC 25010:2011을 따라 설명한다. 이 표준은 2023년 개정판에서 일부 특성의 이름이 바뀌고 안전성(Safety)이 추가됐다(세부 확인 필요). 아래 표는 2011년판 기준이다.

| 품질 특성 | 무엇을 보나 | 대표 테스트 |
|---|---|---|
| 성능 효율성 (Performance efficiency) | 응답 시간, 처리량, 자원 사용 | 성능 테스트, 부하(Load) 테스트, 스트레스(Stress) 테스트 |
| 호환성 (Compatibility) | 다른 OS, 브라우저, 기기, 시스템과 함께 동작하는가 | 크로스 브라우저 테스트 |
| 사용성 (Usability) | 배우고 쓰기 쉬운가, 접근성(a11y, WCAG) | 사용성 테스트, 접근성 테스트 |
| 신뢰성 (Reliability) | 오래, 오류 없이 동작하는가(MTBF, 가용성) | 장시간 실행 테스트, 장애 복구 테스트 |
| 보안 (Security) | 인증, 인가, 데이터 보호, 주입 공격 방어 | 보안 테스트, 침투 테스트 |
| 유지보수성 (Maintainability) | 고치고 확장하기 쉬운가 | 정적 분석, 코드 리뷰 |
| 이식성 (Portability) | 다른 환경으로 옮기기 쉬운가 | 설치, 환경 이전 테스트 |

부하 테스트는 예상한 정상 부하에서, 스트레스 테스트는 한계를 넘는 부하에서 어떻게 동작하는지 본다. 둘 다 성능 효율성을 확인하는 방법이다. 부하 테스트 도구는 [JMeter 노트](../../JMeter%20부하%20테스트(JMeter%20Load%20Testing)/README.md)에 정리했다.

<br/>

## 확인 테스트와 회귀 테스트
코드가 바뀐 뒤에는 두 가지를 짝으로 한다. 확인 테스트(Confirmation testing, 재테스트)는 고친 결함이 정말 고쳐졌는지 그 결함만 다시 확인한다. 회귀 테스트(Regression testing)는 그 변경 때문에 원래 잘 되던 기능이 깨지지 않았는지 확인한다. 자세한 차이와 회귀 자동화는 [재테스트와 회귀 테스트](../13_재테스트와%20회귀%20테스트(Retest%20and%20Regression)/README.md)에 정리했다.

<br/>

## 면접 답변 (30초)
> "테스트 유형은 무엇을 확인하느냐에 따른 분류로, ISTQB 최신 실라버스는 기능, 비기능, 블랙박스, 화이트박스 네 가지를 듭니다. 비기능에는 성능, 보안, 사용성, 호환성 같은 품질 특성이 들어갑니다. 코드가 바뀐 뒤에는 고친 결함만 다시 보는 확인 테스트와 기존 기능이 깨지지 않았는지 보는 회귀 테스트를 함께 하는데, 회귀는 자동화의 핵심 영역이지만 같은 TC만 반복하면 효과가 떨어지므로 주기적으로 갱신해야 합니다."

<br/>

## 실무에서는
기능 QA는 기능 테스트와 회귀 테스트가 중심이다. SDET는 회귀를 자동화하고 통합, 성능 테스트 일부를 맡는다. 보안과 성능을 깊게 보는 일은 보안 엔지니어나 SRE 같은 별도 담당이 맡는 경우가 많다.
