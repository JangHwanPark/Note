## 소프트웨어 개발 생명주기란 ?
- 소프트웨어 개발 생명주기(SDLC, Software Development Life Cycle)는 소프트웨어를 계획해서 만들고 운영하다 폐기하기까지의 전체 과정이다
- 흔히 계획, 요구분석, 설계, 구현, 테스트, 유지보수의 6단계로 나눈다. 단계 이름과 개수는 정해진 표준이 아니라 교재와 조직마다 조금씩 다르다
- 외울 때는 앞 글자를 따서 "계요설구테유"로 묶는다

### 생명주기 (Life Cycle)
사전적 의미는 생물이 태어나 자라고 죽기까지 거치는 단계의 반복이다.
소프트웨어도 계획되어 만들어지고, 쓰이다가 고쳐지고, 언젠가 폐기된다. 이 일생을 단계로 나눠 각 단계에서 할 일을 정해 둔 것이 SDLC다.

<br/>

## 6단계와 QA가 하는 일
| # | 단계 | 하는 일 | QA 활동 |
|---|---|---|---|
| 1 | 계획 (Planning) | 범위, 일정, 비용 정하기 | 테스트 계획 초안, 필요한 인력과 환경 산정 |
| 2 | 요구분석 (Requirements) | 사용자와 비즈니스 요구 모으기 | 요구사항 검토, 모호한 표현과 테스트할 수 없는 요구 찾기 |
| 3 | 설계 (Design) | 아키텍처, DB, 화면 설계 | 테스트 설계, TC 작성 시작 |
| 4 | 구현 (Implementation) | 코드 작성 | TC 작성 마무리, 개발자는 단위 테스트 |
| 5 | 테스트 (Testing) | 통합, 시스템, 인수 테스트 | 테스트 실행, 결함 관리, 회귀 테스트 |
| 6 | 유지보수 (Maintenance) | 배포 후 운영과 수정 | 운영 결함 대응, 변경에 따른 회귀 테스트 |

표에서 테스트는 5번 단계에 있지만 QA의 일은 1번부터 시작한다. 2번에서 요구사항을 검토하는 것도 코드를 실행하지 않는 정적 테스트다.

<br/>

## 주요 SDLC 모델
단계를 어떤 순서로, 몇 번 반복하느냐에 따라 여러 모델이 있다.

| 모델 | 특징 | 테스트 위치 |
|---|---|---|
| 폭포수 (Waterfall) | 한 단계를 끝내야 다음 단계로 넘어가는 순차 모델 | 구현이 끝난 뒤 |
| V 모델 (V-Model) | 개발 단계마다 짝이 되는 테스트 단계를 둔 순차 모델 | 각 개발 단계에서 짝이 되는 테스트를 미리 준비 |
| 애자일, 스크럼 (Agile, Scrum) | 짧은 스프린트로 반복하며 조금씩 완성 | 스프린트마다 |
| 나선형 (Spiral) | 반복할 때마다 리스크를 분석 | 반복마다 |
| 데브옵스 (DevOps), CI/CD | 통합과 배포를 자동으로 자주 | 파이프라인 안에서 자동화로 |

V 모델은 [다음 장](../06_V%20모델(V-Model)/README.md)에서 자세히 본다.

<br/>

## 조기 테스트와의 관계
면접에서 SDLC를 물으면 조기 테스트 원칙이 함께 나오는 경우가 많다. 결함은 늦게 찾을수록 고치는 비용이 커지므로, QA는 테스트 단계를 기다리지 않고 요구분석과 설계 단계부터 참여한다. 원칙 자체는 [테스트 7원칙](../02_테스트%207원칙(ISTQB%20Principles)/README.md)의 3번에 정리했다.

<br/>

## 면접 답변 (30초)
> "SDLC는 계획, 요구분석, 설계, 구현, 테스트, 유지보수로 이어지는 소프트웨어 개발의 전 과정입니다. QA는 테스트 단계만 맡는 것이 아니라, 조기 테스트 원칙에 따라 요구분석 단계부터 참여해야 합니다. 요구사항의 모호한 부분과 테스트할 수 없는 부분을 미리 찾아 두면 뒤 단계에서 드는 비용을 크게 줄일 수 있습니다."
