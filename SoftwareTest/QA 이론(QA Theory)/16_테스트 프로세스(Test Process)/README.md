## 테스트 프로세스란 ?
- 테스트를 시작해서 끝낼 때까지 해야 하는 활동들을 묶어 순서를 정한 것
- ISTQB CTFL v4.0(2023)은 테스트 계획, 모니터링과 통제, 분석, 설계, 구현, 실행, 완료의 일곱 활동 묶음으로 나눈다
- 순서대로 한 번 지나가는 단계가 아니라, 프로젝트에 따라 겹치거나 반복된다. 모니터링과 통제는 처음부터 끝까지 나란히 진행된다

### 프로세스 (Process)
사전적 의미는 일이 처리되는 경로나 공정이다.
테스트에서는 무엇을 테스트할지 정하는 일부터 결과를 정리해 다음에 넘기는 일까지를 단계로 나누고, 단계마다 무엇을 만들어 내는지(산출물)를 정한 것을 말한다.

요리와 같다. 메뉴를 정하고(계획), 재료를 살피고(분석), 조리법을 정하고(설계), 재료를 손질해 두고(구현), 실제로 조리하고(실행), 정리하고 다음을 위해 기록한다(완료). 그동안 계속 맛을 보며 불을 조절하는 것이 모니터링과 통제다.

<br/>

## 왜 필요할까
테스트 활동을 정해 두지 않으면 바로 실행부터 하게 되고, 무엇을 왜 테스트했는지, 언제 끝내도 되는지를 설명할 수 없다. 프로세스를 나눠 두면 단계마다 산출물이 남아 진행 상황을 재고, 빠진 활동을 찾고, 다음 프로젝트에 경험을 넘길 수 있다.

<br/>

## 일곱 활동 (CTFL v4.0)

| 활동 | 하는 일 | 주요 산출물 |
| --- | --- | --- |
| 테스트 계획 (Test Planning) | 목표, 범위, 접근법, 일정, 진입과 종료 기준을 정한다 | 테스트 계획서 |
| 모니터링과 통제 (Monitoring and Control) | 계획 대비 진행을 계속 재고, 어긋나면 조치한다 | 진행 보고서, 통제 지시 |
| 테스트 분석 (Test Analysis) | 테스트 베이시스(요구사항 등)를 분석해 무엇을 테스트할지(테스트 조건)를 정한다 | 테스트 조건, 테스트 베이시스의 결함 보고 |
| 테스트 설계 (Test Design) | 테스트 조건을 어떻게 테스트할지 TC로 만든다 | TC, 테스트 데이터 요구사항, 환경 요구사항 |
| 테스트 구현 (Test Implementation) | 실행에 필요한 것을 준비한다 | 테스트 절차, 자동화 스크립트, 테스트 스위트, 환경과 데이터 |
| 테스트 실행 (Test Execution) | 테스트를 돌리고 결과를 기록하고 결함을 보고한다 | 실행 기록, 결함 리포트 |
| 테스트 완료 (Test Completion) | 종료 기준을 확인하고 결과와 교훈을 정리해 남긴다 | 완료 보고서, 정리된 테스트 자산 |

테스트 베이시스(Test Basis)는 테스트 분석과 설계의 근거가 되는 모든 문서와 정보다. 요구사항 명세, 사용자 스토리, 설계 문서, 코드 등이 해당한다.

외울 때는 앞 글자를 따서 "계모분설구실완"으로 묶는다.

분석과 설계를 나누는 기준은 질문이다. 분석은 "무엇을 테스트할까", 설계는 "어떻게 테스트할까"에 답한다.

<br/>

## 이전 판과의 차이
CTFL 2011 판은 계획과 통제, 분석과 설계, 구현과 실행, 종료 기준 평가와 보고, 테스트 종료 활동의 다섯 단계로 묶었다. 그래서 "테스트 프로세스 5단계"라는 설명이 아직 많이 남아 있다. 2018 판(v3.1)부터 이를 일곱 활동으로 풀어 쓰고 모니터링과 통제를 별도 활동으로 떼어 냈으며, v4.0도 같은 일곱 활동을 쓴다. 면접에서는 어느 판 기준인지 밝히고 답하는 편이 안전하다.

<br/>

## 활동별로 더 보면

### 계획
범위(포함과 제외), 일정, 진입 기준과 종료 기준, 리스크와 우선순위, 환경과 도구와 인력을 정한다.

### 분석과 설계
요구사항과 테스트 조건을 짝지어 두고, [테스트 설계 기법](../09_테스트%20설계%20기법(Test%20Design%20Techniques)/README.md)으로 TC와 데이터를 만든다.

### 구현
TC를 스모크, 회귀, 기능별 스위트로 묶고, 자동화 스크립트와 테스트 데이터, 환경을 준비한다.

### 실행
TC를 돌려 통과와 실패를 기록한다. 실패하면 결함을 등록하고([결함 생명주기](../15_결함%20생명주기(Defect%20Lifecycle)/README.md)), 수정되면 [재테스트와 회귀 테스트](../13_재테스트와%20회귀%20테스트(Retest%20and%20Regression)/README.md)를 한다.

### 완료
종료 기준을 채웠는지 확인하고, 남은 결함은 미루거나(Deferred) 다음 작업으로 넘긴다. TC, 자동화 코드, 결함 데이터를 다음에 다시 쓸 수 있게 정리하고 회고로 교훈을 남긴다.

<br/>

## 면접 답변 (30초)
> "ISTQB CTFL v4.0 기준으로 테스트 프로세스는 계획, 모니터링과 통제, 분석, 설계, 구현, 실행, 완료의 일곱 활동입니다. 계획에서 범위와 일정, 종료 기준을 정하고, 분석에서 무엇을 테스트할지, 설계에서 어떻게 테스트할지 정해 TC를 만듭니다. 구현에서 스위트와 환경, 자동화를 준비하고, 실행에서 결함을 등록하고 재테스트와 회귀 테스트를 합니다. 완료에서는 종료 기준을 확인하고 자산과 교훈을 남깁니다. 모니터링과 통제는 이 전체와 나란히 진행됩니다. 2011 판은 이를 다섯 단계로 묶었고, 2018 판부터 일곱 활동으로 나눴습니다."
