# Test Automation
반복되는 테스트를 줄이고 효율적으로 테스트를 진행하기 위해 Playwright, Appium, Selenium 등을 사용하여 테스트 스크립트를 작성한다.

## 수동 테스트에서 자동화 스크립트로 전환하는 기준
어떤 테스트를 자동화할지 판단할 때 보는 다섯 가지 기준이다.

### **반복 빈도.**
릴리즈마다, 매 PR마다 다시 도는 회귀 시나리오가 대상이다. 한 번만 도는 탐색적/임시 검증은 제외한다.

### **결과의 결정성.**
입력이 같으면 항상 같은 결과가 나와야 한다. 시각·감성·UX 판단이 필요한 검증은 자동화 후보에서 제외한다.

### **비즈니스 리스크.**
결제·로그인·데이터 손상처럼 치명적인 테스트를 우선하고, 리스크가 낮은 화면은 후순위로 둔다.

### **수동 비용 대비 자동화 비용.**
수동으로 5분 걸리는 검증을 매 릴리즈 반복하는 비용과, 자동화 작성 2시간 + 유지비를 비교한다.

누적 수동 시간이 자동화 작성과 유지 비용을 6개월 안에 넘기면 전환한다.

### **안정성과 셀렉터 신뢰도.**
UI가 자주 바뀌는 신규 기능은 자동화가 깨지는 비용이 더 크다. 명세가 굳은 뒤에 전환한다.
