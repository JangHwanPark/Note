# 실무 E2E 예외 케이스 정리

> 학습용. spec 안정성을 깨는 대표 사례 모음. 각 항목은 **원인 → 분석 → 해결** 순서로 정리한다.
> 당장 우리 프로젝트에 해당하는 건 아니어도, 도메인 spec 이 늘어나면 한두 번씩은 마주치는 패턴들이다.

## 1. 타이밍 / 비동기

### 1-1. Hydration 미완료 클릭

**원인**: SSR HTML 은 이미 렌더됐는데 React/Next 의 client hydration 이 끝나기 전 클릭. 이벤트 핸들러가 아직 안 붙어서 클릭은 들어가지만 동작이 없다.

**분석**: 헤드리스 환경은 JS 실행이 느려서 hydration 타이밍이 로컬보다 늦게 끝난다. 로컬은 통과, CI 만 깨지는 전형적인 케이스.

**해결**
- 클릭 대상이 활성화되는 "결과 신호" 를 기다린다. `await expect(button).toBeEnabled()` 로 retry 가 자동으로 돈다.
- 폼 schema 가 서버에서 오는 경우 `await expect(form.getByRole('textbox', { name: '이름' })).toBeVisible()` 같이 form 내부 요소 visible 로 신호 잡기.
- 절대 `page.waitForTimeout(N)` 으로 메우지 말 것 — flaky 의 주범.

### 1-2. 애니메이션 중 클릭 / 단언

**원인**: 모달이 열리는 중 (transition 300ms), 클릭 좌표가 이동 중인 요소 위에 떨어져 빗나간다. 또는 fade-in 중인 텍스트를 `toBeVisible` 로 잡으면 opacity 0.5 에서 true 가 되어 다음 단언에서 깜빡임 발생.

**분석**: Playwright auto-wait 은 "visible & stable" 까지 본다. 그래도 transform/opacity 기반 애니메이션은 stable 판정이 흔들릴 수 있다.

**해결**
- `reduce-motion` 미디어 쿼리를 CI 에 강제: `use: { reducedMotion: 'reduce' }`. 앱이 이 쿼리를 존중하면 애니메이션이 0초로.
- 또는 테스트 환경에서 `* { transition: none !important }` CSS 주입.
- 단언은 **최종 상태의 결과** 로: `await expect(modal).toHaveAttribute('data-state', 'open')` 처럼 명시적 상태 마커.

### 1-3. Debounce / Throttle 입력

**원인**: 검색 입력에 300ms debounce 가 걸려 있어서 `fill()` 직후 결과를 단언하면 아직 요청 안 나간 상태.

**분석**: spec 가 빠르게 진행할수록 debounce 가 더 잘 보인다. 사용자는 천천히 타이핑하니 문제 없음.

**해결**
- 결과 자체를 기다린다: `await expect(resultList).toBeVisible()` 또는 결과 항목 텍스트.
- 또는 네트워크 응답을 명시적으로 대기: `await page.waitForResponse(r => r.url().includes('/api/search'))`.
- debounce 시간을 환경별로 환경변수로 줄이는 건 좋지 않다 — 실제 사용자 경험과 spec 이 멀어진다.

### 1-4. Skeleton → 실제 콘텐츠 전환

**원인**: skeleton 컴포넌트가 실제 데이터와 같은 자리에 비슷한 텍스트를 가질 때 `getByText('로딩')` 같은 셀렉터가 의도치 않게 skeleton 을 잡는다.

**해결**
- skeleton 에 `data-testid="skeleton"` 또는 `aria-busy="true"` 명시.
- 단언은 skeleton 이 사라지길 기다린 뒤: `await expect(page.getByTestId('skeleton')).toBeHidden()`.

### 1-5. 무한 스크롤 / lazy load

**원인**: 리스트 하단 항목이 viewport 에 들어와야 fetch 되는 구조. `getByText('마지막 항목')` 은 영원히 안 보임.

**해결**
- `await element.scrollIntoViewIfNeeded()` 로 명시적 스크롤.
- 페이지 분량이 크면 페이지네이션 직접 호출 또는 API 응답을 mock 해서 첫 페이지에 다 보이게.

## 2. 상태 격리

### 2-1. 병렬 worker 가 같은 DB 행을 건드림

**원인**: workers=4 로 돌면 4 개 worker 가 동시에 같은 프로젝트 데이터를 수정. test A 가 만든 케이스를 test B 가 모르고 삭제.

**분석**: 클래식한 격리 부족. 로컬 단일 worker 로는 안 보이고 CI 에서만 터진다.

**해결**
- spec 끼리 같은 DB 행을 안 건드리도록 **fixture 가 고유 데이터 생성**: `name: \`e2e-${Date.now()}-${randomUUID()}\``.
- 또는 `workers: 1` 강제 (느려지지만 안전).
- 진짜 격리가 필요하면 worker 별 DB schema 분리 (Postgres `SET search_path`) — 인프라 복잡도 큼.

### 2-2. 쿠키 / localStorage 가 spec 간에 샘

**원인**: 같은 `BrowserContext` 를 재사용하면 spec A 의 로그인 쿠키가 spec B 에 그대로 남는다.

**해결**
- Playwright 는 기본적으로 test 마다 새 context 를 만든다. `test.describe.configure({ mode: 'serial' })` 같은 옵션을 쓸 때만 주의.
- 진단: `await context.storageState()` 찍어 보면 어느 쿠키가 남아있는지 보임.

### 2-3. test 순서 의존

**원인**: test A 가 항목 생성, test B 가 그 항목을 클릭. A 가 skip 되면 B 는 항상 fail.

**분석**: 안티패턴이다. 각 test 는 **독립적으로 통과 가능** 해야 한다.

**해결**
- 공유 setup 은 `beforeAll` 또는 fixture 로 명시.
- 그래도 순서가 강제로 필요한 시나리오 (마법사 4단계 같은) 는 한 test 안에서 `test.step()` 으로 묶기.

## 3. 인증 / 세션

### 3-1. 토큰이 spec 도중 만료

**원인**: 토큰 TTL 이 5분, spec 가 7분 돌면 중간에 401. 무한 스크롤이나 백그라운드 polling 이 있는 페이지에서 자주 보임.

**해결**
- spec 가 길어지지 않게 잘게 쪼개기.
- globalSetup 의 storageState 를 fixture 로 매 spec 마다 갱신.
- 또는 CI 환경에서만 토큰 TTL 을 길게 (환경변수).

### 3-2. CSRF 토큰 미스매치

**원인**: 폼이 hidden input `_csrf` 를 가지고 있고, server-action 이 토큰 검증. spec 이 직접 form 을 채워 제출하면 토큰이 stale 한 경우.

**해결**
- 가능하면 UI 흐름 그대로 (페이지 로드 → 입력 → 제출) — Playwright 가 토큰을 자연스레 들고 감.
- API 우회 시에는 사전에 `GET /csrf` 같이 토큰부터 받기.

### 3-3. 쿠키 SameSite / domain

**원인**: `SameSite=Strict` 쿠키는 cross-origin 리다이렉트에서 안 따라온다. OAuth callback 같은 흐름에서 토큰이 사라짐. 또는 `domain=.example.com` 쿠키가 `localhost` 에선 안 먹음.

**해결**
- 테스트 도메인을 production 과 비슷하게 (`localhost.test` 같은 별칭 + `/etc/hosts`).
- `context.addCookies()` 로 명시 주입 시 `domain` `path` `sameSite` 정확히 맞추기.

## 4. 외부 의존

### 4-1. Captcha / Stripe / 지도 등 third-party 위젯

**원인**: iframe 안에 외부 도메인 위젯. `networkidle` 도 안 잡히고, iframe 내부는 셀렉터로 못 들어감 (cross-origin).

**해결**
- 위젯이 만들어내는 **결과 hidden input** 을 기다림: Turnstile 은 `cf-turnstile-response`, reCAPTCHA 는 `g-recaptcha-response`.
- 가능한 환경에서는 위젯을 끄거나 always-pass 키로 교체 (Turnstile `1x00000000000000000000AA`).
- Stripe Elements 는 공식 test card (`4242 4242 4242 4242`) + `await stripeFrame.locator('[name="cardnumber"]').fill(...)`.

### 4-2. 이메일 / SMS 인증 흐름

**원인**: 회원가입 → 이메일 링크 클릭 → 인증 완료. 메일 박스를 spec 이 들여다볼 수 없음.

**해결**
- 테스트 전용 메일 캐처: Mailpit, MailHog, MailSlurp 등 SMTP 캐처를 띄우고 spec 에서 HTTP API 로 조회.
- 또는 server 가 테스트 환경에서 토큰을 응답에 포함시키게 (환경변수 가드 필수).
- "이메일 보내기" 단계까지만 spec, 토큰 발급 후 redirect 는 server-action 직접 호출.

### 4-3. 파일 업로드 / 다운로드

**원인**: 시스템 파일 다이얼로그는 OS 레벨이라 클릭으로 못 연다.

**해결**
- 업로드: `await page.setInputFiles('input[type=file]', '/path/to/fixture.png')` — 다이얼로그 거치지 않고 직접 주입.
- 다운로드: `const [download] = await Promise.all([page.waitForEvent('download'), button.click()])` → `await download.path()` 로 임시 파일 경로 얻기.

### 4-4. 클립보드

**원인**: `navigator.clipboard.readText()` 는 보안 컨텍스트 + 사용자 제스처 + 권한 필요. 헤드리스에서 권한이 기본 거부.

**해결**
- `permissions: ['clipboard-read', 'clipboard-write']` 를 context 옵션에 명시.
- 또는 클립보드 쓰기를 검증하는 대신 **앱이 클립보드에 뭘 넣었는지** 를 확인하는 helper 를 앱 측에 노출 (test-only 함수).

## 5. 브라우저 API 제약

### 5-1. 네이티브 다이얼로그 (alert / confirm / prompt)

**원인**: `window.confirm()` 은 모달이라 spec 를 멈춘다.

**해결**
- 핸들러 등록: `page.on('dialog', d => d.accept())` 또는 `d.dismiss()`.
- 가능하면 앱에서 native dialog 를 안 쓰는 방향. 커스텀 모달이 testability + UX 둘 다 낫다.

### 5-2. 권한 (geolocation / camera / notification)

**원인**: 권한 프롬프트가 떠서 spec 멈춤.

**해결**
- context 옵션으로 사전 grant: `permissions: ['geolocation']`, `geolocation: { latitude, longitude }`.
- 카메라/마이크는 `--use-fake-ui-for-media-stream` Chromium 플래그.

### 5-3. Service Worker / PWA 캐싱

**원인**: 첫 방문에 SW 가 등록되고, 두 번째 방문부터는 캐시된 옛 HTML 이 노출. test A 의 변경이 test B 에 반영 안 됨.

**해결**
- `serviceWorkers: 'block'` context 옵션으로 등록 차단.
- 또는 spec 시작에 `await page.evaluate(() => navigator.serviceWorker.getRegistrations().then(rs => rs.forEach(r => r.unregister())))`.

## 6. DOM 인터랙션

### 6-1. iframe 경계

**원인**: 일반 셀렉터는 iframe 안 요소를 못 잡는다. cross-origin iframe 은 아예 접근 불가.

**해결**
- 같은 origin iframe: `const frame = page.frameLocator('iframe[name="x"]'); await frame.getByRole('button').click()`.
- cross-origin: 결과 신호만 사용 (위 4-1 패턴).

### 6-2. Shadow DOM

**원인**: 셀렉터가 shadow root 를 안 뚫는다. 일부 디자인 시스템 (Lit, 일부 web component) 에서 발생.

**해결**
- Playwright 의 `getByRole`, `getByText` 는 shadow DOM 을 자동으로 piercing 한다 — `>>` 같은 옛 문법보다 시맨틱 locator 우선.
- 깊은 shadow 면 `page.locator('css=...').shadow()` (실험적) 또는 외부에 노출된 part attribute 사용.

### 6-3. Virtual scrolling

**원인**: react-window / TanStack Virtual 같은 라이브러리는 viewport 밖 행은 DOM 에 없다. 50 번째 행을 못 찾음.

**해결**
- 명시적 scroll: `await page.locator('[role=row]').nth(0).scrollIntoViewIfNeeded()` 후 점진 스크롤.
- 또는 spec 용 prop 로 virtualization 끄기 (앱 측 협조 필요).

### 6-4. Drag and drop

**원인**: `await source.dragTo(target)` 가 react-dnd / @dnd-kit 에서 안 먹는 경우. 이들 라이브러리는 PointerEvent 시퀀스가 필요한데 dragTo 가 보내는 이벤트가 다름.

**해결**
- 수동 시퀀스: `source.hover()` → `page.mouse.down()` → 중간 좌표 이동 → `target.hover()` → `page.mouse.up()`.
- @dnd-kit 은 KeyboardSensor 지원하면 키보드로: `source.focus()` → Space → 방향키 → Space.

### 6-5. 파일 업로드 — drag-drop 영역

**원인**: input[type=file] 이 아니라 dropzone 위에 drop 해야 하는 UI.

**해결**
- `await page.locator('[data-testid=dropzone]').dispatchEvent('drop', { dataTransfer })` — DataTransfer 객체 직접 만들어 dispatch.
- 가능하면 앱에서 hidden input[type=file] 을 같이 두는 게 testability 좋음.

### 6-6. 새 탭 / 팝업

**원인**: `target=_blank` 링크 클릭하면 새 page 가 열리는데, 기존 page 변수는 그대로.

**해결**
- `const [newPage] = await Promise.all([context.waitForEvent('page'), link.click()])`.
- 이후 `newPage` 로 작업.

## 7. 데이터 / 시간

### 7-1. 타임존 의존

**원인**: spec 에서 `Date.now()` 또는 서버가 KST 기준 날짜를 반환하는데 CI 가 UTC. "오늘" 의 정의가 달라짐.

**해결**
- context 옵션: `timezoneId: 'Asia/Seoul'`.
- 더 안전: 앱이 항상 UTC 로 저장 + 표시 시 명시 변환. spec 는 표시된 값을 직접 단언.

### 7-2. Locale 의존

**원인**: 통화·날짜 포맷이 locale 마다 다름. `1,000` vs `1.000` (de-DE).

**해결**
- context 옵션: `locale: 'ko-KR'`.
- 또는 단언을 숫자값 자체로 (`expect(await el.textContent()).toMatch(/1[.,]000/)`).

### 7-3. 랜덤 ID / UUID 단언

**원인**: 생성된 항목의 ID 가 매번 다른데 spec 가 `toBe('123')` 같이 하드코딩.

**해결**
- ID 는 생성 직후 capture: `const id = await el.getAttribute('data-id')`.
- 단언은 형태로: `expect(id).toMatch(/^[0-9a-f-]{36}$/)`.

## 8. 인프라 / 환경

### 8-1. 로컬은 통과 / CI 만 깨짐

**원인 후보 (자주 발생 순)**
1. 헤드리스 vs 헤드드 차이 (헤드리스는 폰트·viewport·렌더링 미세 차이)
2. CI 가 더 느려서 timing 노출
3. 환경변수 누락 (Turnstile 키, DATABASE_URL)
4. 시간대 / locale 차이
5. CI 의 공유 DB 가 다른 PR 과 충돌

**해결**
- 우선 CI 의 trace.zip + video 다운받아 재생. 거의 다 보임.
- 로컬에서 `--headed` 와 비교, viewport 동일하게 (`viewport: { width: 1280, height: 720 }`).
- 환경변수는 spec 시작 시 `console.log(process.env.X)` 로 한번 찍기 (PR 머지 전 제거).

### 8-2. CDN / 캐시

**원인**: 정적 자산이 CDN 에 캐시돼서 spec 가 옛 JS 로 동작. deploy 직후 처음 돌리면 fail.

**해결**
- CI 에서 cache-busting 쿼리 (`?v=${Date.now()}`) 또는 `context.route` 로 CDN 요청 가로채기.
- 가장 깔끔: deploy 후 첫 health check 가 OK 떨어진 뒤 spec 시작.

### 8-3. CSP (Content Security Policy) 가 test 스크립트 차단

**원인**: 엄격한 CSP 가 Playwright 가 주입하는 helper 스크립트를 차단. `page.evaluate()` 실패.

**해결**
- 테스트 환경에서만 CSP 완화 (환경변수 가드).
- 또는 `evaluate` 대신 외부 selector / API 로 우회.

### 8-4. 네트워크 throttling

**원인**: CI runner 가 네트워크 느려서 일부 fetch 가 timeout.

**해결**
- 단언별 timeout 늘리기보다 응답 자체를 mock 하는 게 안정적: `await page.route('**/api/slow', r => r.fulfill({ json: {...} }))`.
- 진짜 느린 API 검증은 별도 spec / 별도 트랙.

## 9. 그 외 자주 묻는 케이스

### 9-1. 같은 이름의 버튼이 여러 개

**원인**: 페이지에 "삭제" 버튼이 N 개. `getByRole('button', { name: '삭제' })` 가 strict mode 위반으로 실패.

**해결**
- 컨텍스트로 좁히기: `row.getByRole('button', { name: '삭제' })`.
- 또는 `.first()` / `.nth(0)` — 명시적으로 "첫 번째" 임을 표현.

### 9-2. 토스트 / 알림이 사라지기 전에 단언

**원인**: 토스트가 3초 후 자동 사라짐. spec 가 늦게 보면 못 잡음.

**해결**
- 즉시 단언: 클릭 직후 `await expect(toast).toBeVisible()` — auto-wait 덕에 안 보이면 자동 retry.
- 또는 토스트 닫기 동작을 사용자 인터랙션으로 (auto-dismiss 제거) — 접근성도 같이 좋아짐.

### 9-3. 포커스 트랩 / 키보드 네비게이션

**원인**: 모달 안에서 Tab 키 순환이 안 되거나, 모달 닫은 뒤 포커스가 엉뚱한 곳.

**해결**
- 단언: `await expect(page.locator(':focus')).toHaveAttribute('aria-label', '...')`.
- 모달 라이브러리 (Radix Dialog 등) 가 제공하는 포커스 트랩을 신뢰하고, 단언은 결과만.

## 10. 일반 원칙 정리

| 원칙 | 의미 |
| --- | --- |
| 시맨틱 locator 우선 | `getByRole` / `getByLabel` > `getByText` > `data-testid` > CSS |
| 결과를 기다린다 | `networkidle` / `waitForTimeout` 대신 활성화의 결과를 단언 |
| 격리 | test 마다 새 데이터, worker 격리 가능한 fixture |
| 외부 의존 최소화 | 위젯·메일·결제는 결과 신호만 보거나 mock |
| trace / video 신뢰 | flaky 추적은 로그보다 trace.zip 이 빠름 |
| 도메인 spec 안의 일은 도메인 안에서 | cross-domain import 금지 |
