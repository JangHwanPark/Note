## 소프트웨어 테스트란 ?
- 소프트웨어 테스트(Software Test)는 프로그램이 요구한 대로 동작하는지 확인하고 결함을 찾는 활동이다
- test의 사전적 의미는 시험, 검사로, 정해 둔 기준에 맞는지 확인한다는 뜻이다
- 이 폴더는 QA 이론, QA 관점, 게임 QA 프로세스, 테스트 자동화와 Playwright, 부하 테스트, API 테스트를 정리한다

<br/>

## 목차
- [QA 이론](./QA%20이론(QA%20Theory)) : 테스트 레벨과 유형, 테스트 설계 기법, 결함 생명주기 등 핵심 이론을 번호 순서로 정리한 면접 대비 노트
- [QA 관점](./QA%20관점(QA%20Perspective)) : 만드는 눈과 깨뜨리는 눈, 사용자와 리스크, 명세와 목적, 경계와 예외, 품질 특성(ISO/IEC 25010), 테스트의 한계, 테스트 오라클과 휴리스틱으로 제품을 보는 법
- [게임 QA 프로세스](./게임%20QA%20프로세스(Game%20QA%20Process)) : 마일스톤별 QA 활동, 빌드 검증 흐름, 밸런스, 현지화, 플랫폼 인증 같은 게임 특화 테스트, 버그 등급과 출시 판정, 라이브 서비스 검증, 개발사와 퍼블리셔와 외주 QA
- [테스트 자동화](./테스트%20자동화(Test%20Automation)) : 자동화할 케이스를 고르는 기준, POM 설계 순서와 규칙, Locator 우선순위, 피해야 할 패턴
- [Playwright](./Playwright) : Playwright 실행 명령어, POM, 인증 상태 저장, test/expect/page API 레퍼런스
- [JMeter 부하 테스트](./JMeter%20부하%20테스트(JMeter%20Load%20Testing)) : 부하 테스트의 목적과 종류, Thread Group과 Ramp-Up, 요소의 적용 범위, CLI 실행
- [API 테스트 체크리스트](./API%20테스트%20체크리스트(API%20Test%20Checklist)) : RFC 9110 기준 메서드별 검증 포인트와 Postman 예시, 연습용 API가 표준과 다른 곳
