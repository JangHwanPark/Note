# 테스트 커버리지 (Test Coverage)

> **한 줄**: 코드의 **어느 정도가 테스트되었는가**를 정량적으로 측정. White Box 기법.

## 4단계 (점점 엄격)

| 단계 | 영문 | 의미 | 강도 |
|---|---|---|---|
| **구문** | Statement Coverage | 모든 **줄**을 한 번 이상 실행 | ★ |
| **분기 / 결정** | Branch / Decision Coverage | 모든 **분기(if/else)**의 참 / 거짓 한 번씩 | ★★ |
| **조건** | Condition Coverage | 각 **조건식 내부 항**의 참 / 거짓 한 번씩 | ★★★ |
| **MC/DC** | Modified Condition/Decision Coverage | 각 조건이 **독립적으로** 결과에 영향 줌을 입증 | ★★★★ |

## 예시 코드로 비교

```javascript
function check(a, b) {
  if (a > 0 && b > 0) {
    return "OK";
  }
  return "FAIL";
}
```

### 구문 커버리지 100%
- TC: `check(1, 1)` 한 개로 if 안 / 밖 모두 실행 X
- TC: `check(1, 1)` + `check(0, 0)` → if 안 / 밖 모두 실행 ✓

### 결정 커버리지 100%
- 전체 조건식 `(a > 0 && b > 0)` 이 true / false 모두 나오면 됨
- TC: `(1, 1)` → true, `(0, 0)` → false ✓

### 조건 커버리지 100%
- 각 조건 `a > 0`, `b > 0` 가 각각 true / false 나와야 함
- TC: `(1, 1)` → 둘 다 true, `(0, 0)` → 둘 다 false ✓
- 하지만 `(1, -1)` 같은 케이스는 안 다룸 → **결정과 모순 가능** (조건은 둘 다 만족하지만 결과는 동일할 수 있음)

### MC/DC 100% (★ 항공 / 의료 / 금융 규제 산업 표준)
- 각 조건이 **단독으로 결과를 바꿀 수 있는** TC 가 있어야 함
- TC:
  - `(1, 1)` → 전체 true
  - `(0, 1)` → a 변경으로 전체 false
  - `(1, 0)` → b 변경으로 전체 false
- 결정 / 조건 모두 만족 + 각 조건의 독립적 영향 입증

## 면접 답변 템플릿 (30초)
> "테스트 커버리지는 코드의 어느 정도가 테스트되었는가의 정량 지표입니다. 구문 → 분기·결정 → 조건 → MC/DC 순으로 엄격해집니다. 결정 커버리지는 전체 조건식의 참·거짓을 모두 보고, 조건 커버리지는 각 조건 항을 따로 봅니다. MC/DC는 각 조건이 독립적으로 결과에 영향을 주는 케이스를 보장해, 항공·의료·금융 같은 규제 산업에서 요구됩니다."

## 커버리지의 함정 ★
- **커버리지 100% ≠ 결함 0**: 코드 라인을 다 지나도 잘못된 동작 가능
- 커버리지는 **최소 기준**, 충분 조건 아님
- 사용자 입력값 누락 / 비즈니스 로직 오류는 커버리지로 못 잡음

## 실무 적용
- 단위 테스트 도구 (Jest, JUnit, pytest) → 자동으로 구문 / 분기 커버리지 측정
- CI 게이트: "커버리지 80% 이상 통과" 같은 정책
- 일반 SW = 결정 커버리지면 충분 / 금융·항공 = MC/DC 요구
