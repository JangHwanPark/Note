# V-Model

> **한 줄**: 개발 단계와 테스트 단계를 **1:1 대응**시킨 모델. V자 모양이라 V-Model.

## 다이어그램

```
요구사항 분석 ─────────────────────── 인수 테스트
   │                                       ↑
   ↓                                       │
 시스템 설계 ───────────────────── 시스템 테스트
   │                                   ↑
   ↓                                   │
 아키텍처 설계 ─────────────── 통합 테스트
   │                              ↑
   ↓                              │
 모듈 / 단위 설계 ────── 단위 테스트
   │                      ↑
   ↓                      │
       ─────── 구현 ───────
```

## 대응 관계

| 좌측 (개발) | 우측 (테스트) | 검증 대상 |
|---|---|---|
| 요구사항 분석 | **인수 테스트 (UAT)** | 사용자 요구사항 충족 여부 |
| 시스템 설계 | **시스템 테스트** | 전체 시스템 동작 |
| 아키텍처 설계 | **통합 테스트** | 모듈 간 인터페이스 |
| 모듈 / 단위 설계 | **단위 테스트** | 함수 / 메소드 단위 |

## 핵심 메시지
- **각 개발 단계에서 이미 테스트 케이스를 작성**한다 (조기 테스팅 원칙)
- 요구사항 분석 단계에서 인수 테스트 시나리오를 같이 작성
- 시스템 설계 단계에서 시스템 테스트 시나리오를 같이 작성
- 좌측이 끝나면 우측으로 내려갔다가 다시 올라오는 V자 흐름

## 장점
- 각 단계에 명확한 테스트 단계 대응
- 조기 결함 발견
- 추적성 (Traceability): 요구사항 → 인수 TC 직접 매핑

## 단점
- **순차적 모델**의 단점 (Agile 부적합)
- 변경에 취약
- 초기 결함이 후반 단계까지 영향

## 면접 답변 템플릿 (30초)
> "V-Model은 개발의 각 단계에 대응되는 테스트 단계를 V자 형태로 배치한 모델입니다. 요구사항 분석에는 인수 테스트, 시스템 설계에는 시스템 테스트, 아키텍처 설계에는 통합 테스트, 모듈 설계에는 단위 테스트가 대응됩니다. 핵심은 각 개발 단계에서 테스트 케이스를 미리 작성한다는 점으로, ISTQB의 조기 테스팅 원칙을 구조화한 모델이라고 볼 수 있습니다."

## 실무 적용
- Waterfall / 규제 산업(금융 / 의료) 에서 여전히 사용
- Agile 환경에서는 V-Model을 스프린트 단위로 압축해서 적용
