# Severity vs Priority (심각도 vs 우선순위)

> **한 줄**: Severity = **기술적 영향**, Priority = **비즈니스적 긴급도**. 둘은 **독립적**.

## 정의

| 항목 | 의미 | 누가 결정 |
|---|---|---|
| **Severity (심각도)** | 결함이 **시스템·기능에 미치는 영향**의 정도 | QA / 개발자 |
| **Priority (우선순위)** | **얼마나 빨리 고쳐야** 하는지 (비즈니스 관점) | PM / 기획자 / PO |

## Severity 등급

| 등급 | 의미 | 예시 |
|---|---|---|
| **Critical** | 시스템 다운, 데이터 손실, 보안 사고 | 결제 후 주문 미생성, 로그인 불가 |
| **Major** | 핵심 기능 사용 불가, 워크어라운드 없음 | 검색 결과 안 뜸 |
| **Minor** | 부가 기능 오류, 워크어라운드 있음 | 정렬 옵션 일부만 동작 |
| **Trivial** | UI / 오타 / 미미한 시각적 결함 | 버튼 1px 어긋남 |

## Priority 등급

| 등급 | 의미 | SLA 예시 |
|---|---|---|
| **P0** | 즉시 수정 (출시 차단, 운영 장애) | 1시간 내 |
| **P1** | 다음 릴리즈 전 필수 수정 | 1~3일 |
| **P2** | 일반 수정 일정에 포함 | 1~2주 |
| **P3** | 여유 시 수정, 백로그 보관 | 미정 |

## 독립적인 이유 (★ 면접 단골)

| 사례 | Severity | Priority | 설명 |
|---|---|---|---|
| 메인 페이지 회사 로고 오타 | **Trivial** | **P0** | 기능 영향은 거의 없지만 대외 노출이라 즉시 수정 |
| 새벽 3시 배치 통계가 부정확 | **Critical** | **P3** | 영향은 크지만 일부 내부 사용자만 보는 화면 |
| 결제 후 화면 색상 0.1% 비뚤어짐 | **Trivial** | **P3** | 둘 다 낮음 |
| 결제 시 금액이 0원 처리됨 | **Critical** | **P0** | 둘 다 최고 |

## 면접 답변 템플릿 (30초)
> "Severity는 결함이 시스템·기능에 미치는 기술적 영향을 나타내고, Priority는 비즈니스 관점에서 얼마나 빨리 고쳐야 하는지를 나타냅니다. 둘은 독립적입니다. 예를 들어 메인 페이지 회사 로고 오타는 Severity는 Trivial이지만 Priority는 P0가 될 수 있습니다. 기능 영향은 작지만 대외 노출이라 즉시 수정이 필요하기 때문입니다."

## 실무 적용
- **버그 리포트 필수 항목**: 둘을 분리해서 기입
- **우선순위 회의**: PM이 Priority 결정 권한, QA는 Severity 분석 / 제안
- **자동화 회귀 테스트**: P0~P1 영역은 자동화 1순위
