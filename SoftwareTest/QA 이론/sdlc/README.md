# SDLC (Software Development Life Cycle)

> **한 줄**: SW 개발의 전 과정. 6단계: **계획 → 요구분석 → 설계 → 구현 → 테스트 → 유지보수**.

> **외우는 팁**: **"계요설구테유"**

## 6단계

| # | 단계 | 한 줄 | QA 활동 |
|---|---|---|---|
| 1 | **계획** (Planning) | 프로젝트 범위 / 일정 / 비용 정의 | 테스트 계획서 초안, 리소스 산정 |
| 2 | **요구분석** (Requirements) | 사용자·비즈니스 요구사항 수집 | **요구사항 검토**, 테스트 가능성 / 모호성 발견 |
| 3 | **설계** (Design) | 아키텍처 / DB / UI 설계 | 테스트 설계, TC 작성 시작 |
| 4 | **구현** (Implementation) | 코드 작성 | TC 작성 마무리, 단위 테스트 |
| 5 | **테스트** (Testing) | 통합 / 시스템 / 인수 테스트 | **테스트 실행**, 결함 관리, 회귀 |
| 6 | **유지보수** (Maintenance) | 배포 후 운영 / 패치 | 운영 결함 대응, 회귀 테스트 |

## 주요 SDLC 모델

| 모델 | 특징 | QA 위치 |
|---|---|---|
| **Waterfall** | 순차적, 단계별 완료 후 다음 | 테스트는 구현 후 |
| **V-Model** | 각 개발 단계에 대응되는 테스트 단계 ([상세](../v-model/README.md)) | 모든 단계 병행 |
| **Agile / Scrum** | 짧은 스프린트, 반복 / 점증 | 스프린트마다 QA |
| **Spiral** | 리스크 기반, 반복 | 각 반복마다 평가 |
| **DevOps / CI-CD** | 지속적 통합·배포 | 자동화 필수 |

## 조기 테스팅 원칙 (★ 자주 같이 나옴)
ISTQB 7원칙 중 3번. **요구분석 / 설계 단계부터 QA가 참여**해야 결함 수정 비용이 줄어든다.

```
요구분석 단계 결함 수정 비용 = 1
구현 단계 결함 수정 비용 ≈ 10
운영 단계 결함 수정 비용 ≈ 100
```

## 면접 답변 템플릿 (30초)
> "SDLC는 계획·요구분석·설계·구현·테스트·유지보수 6단계로 이루어집니다. QA는 단순히 5번 테스트 단계만 담당하는 게 아니라, ISTQB 조기 테스팅 원칙에 따라 2번 요구분석 단계부터 참여해야 합니다. 요구사항의 모호성과 테스트 가능성을 미리 검토하면 후속 비용을 크게 줄일 수 있습니다."
