# 프로젝트 제약 3요소 (Triple Constraint / Iron Triangle)

> **한 줄**: 모든 프로젝트는 **품질 · 비용 · 일정** 3요소의 트레이드오프 안에서 움직인다.

## 3요소

| 요소 | 영문 | 의미 |
|---|---|---|
| **품질 (Quality / Scope)** | Quality | 결과물의 완성도, 기능 범위 |
| **비용 (Cost)** | Cost | 예산, 인력 |
| **일정 (Time)** | Time | 데드라인, 출시일 |

## Iron Triangle

```
       품질
        /\
       /  \
      /    \
     /      \
 비용 ──────── 일정
```

**3요소 중 2개를 고정하면 나머지 1개는 자동으로 결정**된다는 것이 핵심.
모두 다 좋게 가져갈 수는 없음.

## 트레이드오프 예시

| 우선 | 희생 | 사례 |
|---|---|---|
| 일정 + 품질 | 비용↑ | 인력 추가 투입해서 데드라인 + 품질 사수 |
| 일정 + 비용 | 품질↓ | MVP 출시 — 기능 축소, 결함 일부 감수 |
| 비용 + 품질 | 일정↑ | 적은 인력으로 꼼꼼하게 — 출시 지연 |

## QA 관점에서의 적용

### 1. 우선순위 산정
P0~P3 분류 시 "**일정 내 모든 결함을 잡을 수 없다**" 는 전제로 출발.

### 2. 테스트 범위 결정
- 일정 촉박 → **리스크 기반** 테스트 (군집 영역에 집중)
- 비용 부족 → 자동화 우선 (장기 회수)
- 품질 우선 → 회귀 + 탐색적 병행

### 3. ISTQB 원칙 2번과 연결
"완전한 테스팅은 불가능" — 제약 3요소 안에서 **트레이드오프**가 필수.

## 면접 답변 템플릿 (30초)
> "프로젝트 제약 3요소는 품질·비용·일정이며, 세 가지를 모두 최적화할 수는 없고 트레이드오프가 필수입니다. Iron Triangle이라고도 부릅니다. QA 관점에서는 ISTQB 원칙 중 '완전한 테스팅은 불가능' 과 직접 연결됩니다. 일정이 촉박하면 리스크 기반으로 군집 영역을 우선 테스트하고, 일정과 품질을 모두 사수해야 하면 비용을 추가해서 인력을 투입하는 식으로 의사결정합니다."
