# ISTQB 7가지 테스팅 원칙

> **한 줄**: 모든 QA 활동의 근간이 되는 7가지 원칙. ISTQB CTFL 필수 암기.

> **외우는 팁**: **"결완조군 / 살맥오"** — 결함·완전·조기·군집 / 살충·맥락·오류

## 7원칙

| # | 원칙 | 영문 | 한 줄 |
|---|---|---|---|
| 1 | **결함의 존재를 보여줌** | Testing shows the presence of defects | 테스트는 결함이 있다는 걸 보여줄 뿐, **없다는 걸 증명 못 함** |
| 2 | **완전한 테스팅은 불가능** | Exhaustive testing is impossible | 모든 입력 / 조합을 다 못 함. **리스크 기반 우선순위** |
| 3 | **조기 테스팅** | Early testing saves time and money | SDLC 초기 테스트일수록 비용↓. 요구사항 단계부터 |
| 4 | **결함의 군집** | Defect clustering | 결함은 특정 영역에 몰림. **파레토 (20% 영역에 80% 결함)** |
| 5 | **살충제 패러독스** | Pesticide paradox | 같은 TC 반복 → 새 결함 못 잡음. ([상세](../pesticide-paradox/README.md)) |
| 6 | **맥락 의존성** | Testing is context-dependent | 게임 / 금융 / 의료마다 테스트 방식 다름. **정답 없음** |
| 7 | **"오류 부재" 오류** | Absence-of-errors fallacy | 버그 없어도 요구사항 불충족이면 의미 없음 |

## 면접 빈출 조합

| 조합 | 답변 키워드 |
|---|---|
| **1 + 7** | "테스트는 결함이 없다는 걸 증명 못 하며, 버그가 없어도 요구사항을 못 채우면 의미 없다" |
| **2 + 4** | "완전한 테스트는 불가능하니, 결함이 군집되는 영역을 찾아 우선 검증한다" |
| **3 + 5** | "조기에 테스트하고, 같은 TC만 반복하지 말고 주기적으로 갱신해야 한다" |

## 면접 답변 템플릿 (30초)
> "ISTQB 7원칙은 1) 결함의 존재만 보여줌, 2) 완전 테스트 불가, 3) 조기 테스팅, 4) 결함 군집, 5) 살충제 패러독스, 6) 맥락 의존성, 7) 오류 부재의 오류입니다. 가장 중요하다고 생각하는 건 1번과 7번으로, 테스트가 결함 없음을 증명하지 못하며 버그가 없어도 요구사항을 못 채우면 의미 없다는 점입니다."

## 실무 적용
- 1번 → 테스트 통과 = 결함 없음이 아님. 리스크 관리 사고
- 2번 → 우선순위 / 페어와이즈 / 리스크 기반 테스팅
- 3번 → Shift-Left, 요구사항 단계부터 QA 참여
- 4번 → 변경된 모듈 / 버그 많이 났던 모듈 집중 테스트
- 5번 → 자동화 TC 주기적 리뷰, 탐색적 테스팅 병행
- 6번 → 회사 도메인에 맞는 테스트 전략 수립
- 7번 → UX / 비기능 요구사항도 함께 검증
