# 살충제 패러독스 (Pesticide Paradox)

> **한 줄**: 같은 TC만 반복하면 더 이상 새 결함을 못 잡는다.

## 비유
같은 농약을 계속 뿌리면 해충이 내성을 가져 안 죽는다.

## 정의
동일한 테스트 케이스를 반복 실행하면 **결함 발견 효과가 점차 감소**하는 현상.
ISTQB 7가지 테스팅 원칙 중 **5번**.

## 왜 생기나
- 그 TC가 잡는 영역의 결함은 이미 다 잡혔거나 깨끗하게 유지됨
- TC가 안 다루는 영역에 새 결함이 쌓여도 발견 불가
- 사각지대가 고정됨

## 해결 방안 (★ 외울 것)
1. **TC 주기적 개선·갱신** — 기능 변경에 맞춰 TC 업데이트
2. **새 TC 추가** — 기존에 없던 입력값·조합·흐름
3. **탐색적 테스팅 / Ad-hoc** — TC 밖의 시각
4. **다른 테스터 / 다른 환경** — 사각지대 회피

## 면접 답변 템플릿 (30초)
> "살충제 패러독스는 ISTQB 7가지 원칙 중 하나로, 동일한 TC를 반복하면 같은 결함만 잡고 새 결함은 못 잡게 되는 현상입니다. 농약 비유에서 왔습니다. 해결책으로는 TC를 주기적으로 개선·확장하고, 정형 TC로 못 잡는 영역은 탐색적 테스팅으로 보완합니다."

## 자동화 맥락
회귀 자동화는 살충제 패러독스에 **가장 취약**.
같은 스크립트를 같은 환경에서 매일 돌리니까.
→ **자동화 = 안전망**, **탐색적 테스팅 = 새 결함 발견** 두 축으로 가야 함.
