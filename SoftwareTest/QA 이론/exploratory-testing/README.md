# 탐색적 테스트 (Exploratory Testing)

> **한 줄**: **학습 + 설계 + 실행을 동시에** 하는 테스트. 미리 TC 만들지 않고 시스템과 대화하듯 진행.

> **핵심**: 즉흥(Ad-hoc) ≠ 탐색적. 탐색적은 **차터(목표)와 시간 박스**가 있는 구조화된 활동.

## 비교 — 탐색적 vs TC 기반

| 구분 | TC 기반 (Scripted) | 탐색적 (Exploratory) |
|---|---|---|
| TC 작성 시점 | 실행 전 사전 작성 | 실행 중 동시 생성 |
| 강점 | 재현성·추적성·자동화 | 살충제 해결, 새 결함 발견 |
| 약점 | 정형 케이스 외 결함 누락 | 재현성·추적성 약함 |
| 적합 상황 | 안정된 기능, 회귀 자동화 | 신규 기능, 명세 불명확, 짧은 시간 |
| 측정 | TC 수 / 통과율 | 차터 완료 / 발견 결함 수 |
| 의존 자원 | TC 문서 | 테스터의 도메인 경험 |

## 언제 쓰는가
- 명세가 불명확하거나 빠르게 변하는 신규 기능
- 회귀 자동화가 같은 영역만 반복해서 새 결함을 못 잡을 때 (살충제 패러독스 해결책)
- 출시 직전 짧은 시간 안에 핵심 흐름 + 예외 흐름 빠르게 훑기
- 사용성 / UX 관점의 결함 탐색 (정형 TC로는 잘 안 잡힘)
- 도메인 학습이 필요한 신규 영역 (학습과 검증을 동시에)

## 재현성·추적성 약점 보완

### 1. 차터 (Charter) 기반 진행
- 한 세션당 **명확한 목표 1개**를 차터로 작성
- 예) "결제 페이지에서 비정상 입력값 입력 시 에러 처리 검증"
- 차터 없이 마구잡이로 클릭하는 것은 Ad-hoc (탐색적 아님)

### 2. 세션 기반 테스트 관리 (SBTM, Session-Based Test Management)
- 60~90분 단위 **타임 박스**
- 세션 종료 후 **세션 리포트** 작성 (차터·소요시간·발견 결함·미해결 의문)
- TBS / OBS / SBS 비율 기록 (Test / On-charter / Bug / Setup)

### 3. 결함 발견 시 즉시 재현 절차 문서화
- 재현 가능 여부 확인 → 가능하면 정식 결함 리포트로 승격
- 재현 안 되는 결함도 "재현 불가" 메모와 환경 정보 기록

### 4. 보조 도구로 추적성 확보
- 화면 녹화 (Loom / OBS 등)로 결함 발견 직전 상황 보존
- 콘솔 로그 / 네트워크 탭 캡처
- 브라우저 / OS / 권한 / 데이터 상태 메모

### 5. 발견 후 자동화 회귀 스위트로 승격
- 탐색적으로 발견한 결함 → 재현 TC 작성 → 회귀 자동화에 추가
- 탐색적 ↔ 자동화 회귀가 보완 관계로 작동

## 차터 작성 예시
> **차터**: 결제 흐름에서 네트워크 끊김 / 타임아웃 / 중복 클릭 상황의 에러 처리를 60분간 탐색
> **세션 결과**: 차터 80% / 결함 3건 / 의문 1건 / 환경 정보 첨부

## 면접 답변 템플릿 (30초)
> "탐색적 테스트는 학습·설계·실행을 동시에 진행하는 테스트로, 사전 TC가 없는 대신 차터라는 명확한 목표와 시간 박스 안에서 구조화되게 수행합니다. TC 기반 테스트가 놓치는 영역, 특히 명세가 불명확한 신규 기능이나 살충제 패러독스에 빠진 회귀 영역에서 새 결함을 발견하는 강점이 있습니다. 재현성과 추적성이 약점이라 세션 기반 테스트 관리(SBTM)로 세션 단위 리포트를 작성하고, 발견 결함은 화면 녹화와 환경 정보로 추적성을 확보한 뒤 재현 가능한 것은 자동화 회귀 스위트로 승격시켜 보완합니다."
