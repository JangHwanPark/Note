# 테스트 타입 (Test Types)

> **한 줄**: **어떤 목적**으로 테스트하는가의 분류. 테스트 레벨(어디서)과 직교 개념.

## 4대 타입

| 타입 | 검증 대상 | 예시 |
|---|---|---|
| **기능 (Functional)** | 시스템이 **무엇을 하는가** | 로그인, 결제, 검색 |
| **비기능 (Non-functional)** | 시스템이 **얼마나 잘 하는가** | 성능, 보안, 사용성 |
| **구조 / 화이트박스** | 시스템이 **어떻게 만들어졌는가** | 코드 커버리지 |
| **변경 관련 (Change-related)** | 변경 후 영향 검증 | 회귀 / 확인 |

## 기능 테스트 (Functional)
- 요구사항 / 명세 기반
- "X 화면에서 Y 버튼 누르면 Z 결과가 나오는가"
- 기능 QA 의 주된 영역

## 비기능 테스트 (Non-functional) ★

| 종류 | 검증 |
|---|---|
| **성능 (Performance)** | 응답 시간, 처리량, 동시 사용자 수 |
| **부하 (Load)** | 정상 부하에서의 동작 |
| **스트레스 (Stress)** | 한계 초과 시 동작 |
| **보안 (Security)** | 인증 / 인가 / 데이터 보호 / SQL 인젝션 등 |
| **사용성 (Usability)** | UX, 접근성 |
| **접근성 (Accessibility)** | a11y, WCAG, 스크린리더 |
| **호환성 (Compatibility)** | OS / 브라우저 / 디바이스 |
| **신뢰성 (Reliability)** | MTBF, 가용성 |
| **유지보수성 (Maintainability)** | 코드 / 문서 품질 |
| **이식성 (Portability)** | 환경 이전 가능성 |

## 변경 관련 테스트 (Change-related)

| 종류 | 의미 |
|---|---|
| **확인 (Confirmation / Re-testing)** | 결함이 수정되었는지 **그 결함만** 다시 검증 |
| **회귀 (Regression)** | 변경으로 **기존 기능이 깨지지 않았는지** 검증 |

> 둘은 짝꿍. 결함 수정 → 확인 + 회귀 동시에 수행.

## 회귀 테스트 ★ (자주 묻는 영역)
- **자동화의 핵심 영역** (반복적 / 매번 같은 검증)
- 살충제 패러독스 주의 — 같은 회귀 스크립트만 돌리면 새 결함 못 잡음
- **선택적 회귀** — 변경 영향 범위만, **전체 회귀** — 전 영역

## 면접 답변 템플릿 (30초)
> "테스트 타입은 목적에 따라 기능·비기능·구조·변경 관련 4가지로 분류됩니다. 비기능에는 성능·보안·사용성·접근성 같은 것이 포함되고, 변경 관련에는 결함만 다시 검증하는 확인 테스트와 기존 기능이 깨지지 않았는지 보는 회귀 테스트가 짝으로 다닙니다. 회귀는 자동화의 핵심 영역이지만 살충제 패러독스에 취약하므로 주기적으로 갱신해야 합니다."

## 실무 적용
- 기능 QA → 기능 + 회귀 중심
- SDET → 자동화로 회귀 + 일부 통합 / 성능
- 보안 / 성능 → 별도 전문 인력 (보안 엔지니어, SRE)
