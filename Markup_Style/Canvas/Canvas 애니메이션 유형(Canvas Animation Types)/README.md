## Canvas로 자주 만드는 애니메이션
- Canvas에서 많이 쓰는 애니메이션 유형과, 각 유형이 어떤 계산으로 움직임을 만드는지 모은 목록이다
- 유형은 많아 보여도 뼈대는 같다. 매 프레임 상태를 계산하고(update), 지운 뒤 다시 그린다(draw)
- 반복은 `requestAnimationFrame` 으로 돌린다. 기본 예제는 [Canvas와 GSAP](../Canvas와%20GSAP(Canvas%20and%20GSAP)/README.md)의 파티클 예제에 있다

<br/>

## 왜 계산 방법으로 나눠 볼까
Canvas는 무엇을 그렸는지 기억하지 않는다. 그래서 "불꽃놀이"든 "비 내리기"든 결국 점이나 선의 위치를 프레임마다 어떻게 바꾸느냐의 문제가 된다. 같은 계산을 쓰는 유형끼리 묶어 보면, 하나를 만들 줄 알 때 나머지를 어떻게 만들지 짐작할 수 있다. 예를 들어 불꽃놀이, 비와 눈, 불과 연기는 모두 파티클에 규칙(중력, 수명, 색 변화)을 하나씩 더한 것이다.

<br/>

## 유형 목록
| 유형 | 움직임을 만드는 계산 | 사용 사례 |
|---|---|---|
| 파티클 (Particle) | 점마다 위치와 속도를 두고 매 프레임 속도를 위치에 더한다 | 배경 효과, 폭발, 입자 충돌 |
| 불꽃놀이 (Fireworks) | 한 점에서 여러 방향으로 퍼지는 파티클에 중력과 수명을 주고, 수명이 줄수록 흐리게 그린다 | 축제, 축하 화면 |
| 비와 눈 (Rain, Snow) | 위에서 떨어지는 파티클이 화면 아래로 나가면 다시 위에서 시작하게 한다 | 날씨 표현, 계절 배경 |
| 불과 연기 (Fire, Smoke) | 위로 올라가는 파티클에 수명, 색 변화, 흔들림을 준다 | 게임 이펙트, 배경 효과 |
| 별 이동 (Starfield) | 별마다 깊이(z)를 두고 z를 줄이면서 x/z, y/z로 화면 위치를 정해, 가까워질수록 바깥으로 빠르게 퍼지게 한다 | 우주 배경, 게임 배경 |
| 3D 원근감 (Depth Effect) | 별 이동과 같은 원근 나눗셈으로 먼 것은 작고 느리게, 가까운 것은 크고 빠르게 그린다 | 겹친 배경 레이어, 인터랙티브 배경 |
| 웨이브 (Wave) | `y = 진폭 × sin(주파수 × x + 시간)` 처럼 사인 함수에 시간을 더해 물결을 옮긴다 | 오디오 비주얼라이저, 배경 효과 |
| 펄린 노이즈 (Perlin Noise) | 가까운 입력에 비슷한 값을 돌려주는 노이즈 함수로 값을 정해, `Math.random()` 보다 부드럽게 변하는 무늬를 만든다 | 구름, 연기, 지형처럼 자연스러운 움직임 |
| 물리 기반 (Physics-based) | 속도에 중력 가속도를 더하고, 벽이나 다른 물체에 닿으면 반사시키며 반발 계수(0에서 1 사이 값)를 곱해 속도를 줄인다 | 공 튀기기, 로프, 충돌 |
| 보이드 (Boids) | 객체마다 이웃과 떨어지기(분리, Separation), 같은 방향 보기(정렬, Alignment), 가까이 모이기(응집, Cohesion) 세 규칙을 적용한다 | 새 떼, 물고기 떼 같은 군집 이동 |
| 유체 (Fluid) | 화면을 격자로 나눠 칸마다 속도와 밀도를 계산한다. 계산량이 많아 다른 유형보다 무겁다 | 물결, 바람, 연기 |
| 형태 변형 (Morphing) | 두 도형의 점 개수를 맞춘 뒤 점마다 처음 위치에서 끝 위치로 보간한다 | 로고 애니메이션, 전환 효과 |
| 텍스트 (Text) | `fillText` 로 글자를 그리고 글자마다 위치나 투명도를 바꾼다. 타이핑 효과는 보이는 글자 수를 늘린다 | 로딩 화면, 타이핑 효과 |
| 노이즈와 글리치 (Noise, Glitch) | 화면 일부를 어긋나게 다시 그리거나 `getImageData` 로 읽은 픽셀을 옮겨 깨진 듯 보이게 한다 | SF 느낌 UI, 오류 연출 |
| 시계 (Clock) | `Date` 에서 시, 분, 초를 읽어 바늘 각도를 계산하고 그 각도로 선을 그린다 | 대시보드, UI 컴포넌트 |

<br/>

## 고를 때 생각할 것
- 파티클 계열은 점의 개수에 비례해, 유체는 격자 칸 수에 비례해 계산이 늘어난다
- 반복을 `cancelAnimationFrame` 으로 멈추지 않으면 화면을 떠난 뒤에도 계산과 그리기가 계속된다
- OS에서 동작 줄이기를 켠 사용자에게는 배경 애니메이션을 멈추거나 느리게 하는 편이 좋다. 방법은 [스크롤 애니메이션](../../../React/스크롤%20애니메이션(Scroll%20Animation)/README.md)의 `prefers-reduced-motion` 부분에 정리했다
