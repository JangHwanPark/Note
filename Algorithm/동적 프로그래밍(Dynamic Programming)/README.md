## 동적 프로그래밍(DP)이란 ?
- 큰 문제를 작은 문제로 쪼개 풀고, 작은 문제의 답을 저장해 두었다가 다시 쓰는 풀이 방법
- 특정 알고리즘이라기보다는 문제를 푸는 방식에 가깝다
- 저장해 둔 값을 꺼내 쓰기 때문에 같은 계산을 두 번 하지 않는다

동적 프로그래밍(Dynamic Programming, DP)의 programming은 코드를 짠다는 뜻이 아니라 계획을 세운다, 표를 짠다는 뜻이다. 선형 계획법(Linear Programming)의 programming과 같은 쓰임이다. 작은 문제의 답을 표(DP 배열)에 하나씩 채워 가며 큰 문제의 답을 만든다는 의미로 이어진다. dynamic이라는 이름이 붙은 사연은 만든 사람(리처드 벨먼)의 회고로 전해지는데, 원문으로 확인하지 못했다(확인 필요).

구구단 표를 한 번 채워 두면 7 × 8을 다시 계산하지 않고 표에서 읽기만 하면 되는 것과 같다. DP는 작은 문제의 답을 표에 적어 두고, 큰 문제를 풀 때 그 표를 읽어 쓴다.

<br/>

## 왜 필요할까
피보나치 수열은 앞의 두 수를 더해 다음 수를 만든다. `fib(n) = fib(n-1) + fib(n-2)`를 재귀로 그대로 옮기면 아래와 같다.

```js
let calls = 0;
const fib = (n) => {
  calls++;
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
};

console.log(fib(10)); // 55
console.log(calls);   // 177
```

`fib(10)` 하나를 구하는데 함수가 177번 호출된다. `fib(8)`은 `fib(10)`에서도, `fib(9)`에서도 불려서 같은 계산을 여러 번 반복하기 때문이다. n이 커지면 호출 횟수가 지수적으로 는다. 호출 횟수는 `2 × fib(n+1) - 1` 이라 n이 1 늘 때마다 약 1.6배(황금비)씩 커진다. 흔히 O(2^n)이라고 쓰는 것은 이보다 넉넉한 위쪽 한계다. 실제로 `fib(20)` 은 21,891번, `fib(25)` 는 242,785번 호출된다.

이미 구한 `fib(8)`의 답을 어딘가 적어 두면 다시 계산할 필요가 없다. 이것이 DP의 핵심이다.

<br/>

## DP를 쓸 수 있는 조건
### 겹치는 부분 문제 (Overlapping Subproblems)
같은 작은 문제가 여러 번 반복해서 나와야 한다. 피보나치처럼 `fib(8)`을 여러 곳에서 다시 구해야 저장해 두는 의미가 있다. 작은 문제가 겹치지 않으면 그냥 분할 정복(Divide and Conquer)이다. 분할 정복은 문제를 겹치지 않는 작은 문제로 나눠 각각 푼 뒤 합치는 방법으로, 병합 정렬이 대표적이다.

### 최적 부분 구조 (Optimal Substructure)
큰 문제의 최적해가 작은 문제의 최적해로 만들어져야 한다. 최적(가장 작거나 큰 값)을 구하는 문제에서 따지는 조건이다.

계단 오르기 비용 문제로 보면, 계단마다 밟는 비용이 있고 한 번에 한 칸이나 두 칸을 오를 때 꼭대기까지 가는 최소 비용을 구한다. i번째 칸에 도착하는 최소 비용은 i-1번째 칸까지의 최소 비용과 i-2번째 칸까지의 최소 비용 중 작은 쪽에 그 칸을 밟는 비용을 더한 값이다. 작은 문제의 최적해만 알면 큰 문제의 최적해가 나오므로 최적 부분 구조를 가진다.

```js
const minCost = (cost) => {
  const n = cost.length;
  const dp = new Array(n + 1).fill(0); // dp[i]: i번째 칸에 도착하는 최소 비용
  for (let i = 2; i <= n; i++) {
    dp[i] = Math.min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2]);
  }
  return dp[n];
};

console.log(minCost([10, 15, 20])); // 15
```

## 탑다운 (Top-down)
큰 문제에서 시작해 작은 문제로 내려가는 방식이다. 재귀로 구현하고, 구한 답을 메모해 두었다가 같은 문제가 다시 오면 메모에서 꺼낸다. 이렇게 함수의 결과를 입력별로 기록해 두고 같은 입력이 오면 다시 계산하지 않고 꺼내 쓰는 기법을 메모이제이션(Memoization)이라고 한다. 메모(memo)에서 온 말로, 적어 둔다는 뜻이다.

```js
const memo = [];
let calls = 0;
const fib = (n) => {
  calls++;
  if (n <= 1) return n;
  if (memo[n] !== undefined) return memo[n]; // 이미 구했으면 꺼내 쓴다
  memo[n] = fib(n - 1) + fib(n - 2);
  return memo[n];
};

console.log(fib(10)); // 55
console.log(calls);   // 19
```

호출 횟수가 177번에서 19번으로 줄었다. 각 n을 한 번씩만 계산하므로 O(n)이다. 다만 n이 아주 크면 재귀가 깊어져 스택 오버플로가 날 수 있다.

<br/>

## 바텀업 (Bottom-up)
가장 작은 문제부터 시작해 n까지 차례로 표를 채우는 방식이다. 반복문으로 구현한다.

```js
const fib = (n) => {
  const dp = [0, 1];
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
};

console.log(fib(10)); // 55
console.log(fib(50)); // 12586269025
```

자바스크립트 숫자로 정확히 구할 수 있는 피보나치 수는 `fib(78)` 까지다. `fib(79)` 부터는 `Number.MAX_SAFE_INTEGER` 를 넘으므로 더 큰 n이 필요하면 `BigInt` 를 쓰거나, 문제에서 요구하는 대로 나머지(예: 1,000,000,007로 나눈 나머지)만 저장한다.

재귀를 쓰지 않아 스택 걱정이 없고, 코딩 테스트에서는 이쪽을 더 자주 쓴다. 탑다운과 마찬가지로 O(n)이다.

<br/>

## DP 문제 푸는 순서
1. DP 배열의 한 칸이 무엇을 뜻하는지 정한다. (예: `dp[i]`는 i번째 피보나치 수)
2. 큰 문제를 작은 문제로 나타내는 점화식을 세운다. (예: `dp[i] = dp[i-1] + dp[i-2]`)
3. 더 쪼갤 수 없는 초기값을 채운다. (예: `dp[0] = 0`, `dp[1] = 1`)
4. 작은 값부터 n까지 채우고 `dp[n]`을 답으로 쓴다.

점화식을 세우는 1, 2단계가 가장 어렵다. 처음에는 n이 작은 경우를 손으로 몇 개 써 보고 규칙을 찾는 것이 빠르다.
