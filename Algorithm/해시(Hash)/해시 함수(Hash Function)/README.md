## 해시 함수 (Hash Function)란 ?
- 임의의 크기의 입력을 받아 정해진 범위의 숫자(해시값)로 바꾸는 함수
- 같은 입력에는 항상 같은 해시값을 돌려준다
- [해시 테이블](../해시%20테이블(Hash%20Table)/README.md)에서 key를 배열 인덱스로 바꾸는 데 쓴다

hash의 사전적 의미는 잘게 다지다, 뒤섞다이다. 입력을 잘게 다지고 섞어서 원래 모양을 알아볼 수 없는 숫자로 만든다는 뜻이 그대로 이름이 됐다.

학번 끝자리로 사물함 줄을 정하는 것과 비슷하다. 같은 학생은 언제나 같은 줄로 가고, 끝자리는 0부터 9까지 고르게 나오므로 한 줄에 사람이 몰리지 않는다. 성으로 줄을 정하면 김, 이, 박 줄에만 사람이 몰리는데, 이것이 나쁜 해시 함수다.

<br/>

## 좋은 해시 함수의 조건
### 결정적이다
같은 입력은 언제 넣어도 같은 값이 나와야 한다. 저장할 때와 찾을 때 값이 다르면 넣어 둔 데이터를 다시 찾을 수 없다.

### 고르게 퍼뜨린다
비슷한 입력이라도 해시값은 범위 전체에 고르게 흩어져야 한다. 한쪽에 몰리면 충돌이 늘어 해시 테이블이 느려진다.

### 빠르다
해시 테이블은 저장하고 찾을 때마다 해시 함수를 부른다. 계산이 느리면 O(1)의 장점이 사라진다.

## 직접 만들어 보기
### 글자 코드를 더하는 방식
가장 단순한 방법은 문자열의 글자 코드를 모두 더해 버킷 수로 나눈 나머지를 쓰는 것이다.

```js
const sumHash = (key, size) => {
  let h = 0;
  for (const ch of key) h += ch.charCodeAt(0);
  return h % size;
};

console.log(sumHash('abc', 17)); // 5
console.log(sumHash('cba', 17)); // 5
console.log(sumHash('bca', 17)); // 5
```

글자의 순서를 전혀 반영하지 않아서 같은 글자로 이루어진 단어는 모두 같은 값이 된다. 고르게 퍼뜨린다는 조건을 지키지 못한다.

### 자리마다 곱하는 방식
앞에서 계산한 값에 일정한 수를 곱하고 다음 글자를 더하면 글자의 위치가 결과에 반영된다. 자바의 `String.hashCode()`도 31을 곱하는 이 방식을 쓴다.

```js
const polyHash = (key, size) => {
  let h = 0;
  for (const ch of key) h = (h * 31 + ch.charCodeAt(0)) % size;
  return h;
};

console.log(polyHash('abc', 17)); // 15
console.log(polyHash('cba', 17)); // 14
console.log(polyHash('bca', 17)); // 2
```

같은 글자로 된 단어도 순서가 다르면 다른 값이 나온다. 반복할 때마다 나머지를 구하는 이유는 숫자가 너무 커지지 않게 하기 위해서다.

버킷 수도 결과에 영향을 준다. 같은 코드에서 버킷 수를 16으로 바꾸면 'abc'와 'cba'가 둘 다 2가 되어 다시 충돌한다. 곱하는 수와 버킷 수 사이에 규칙이 생기면 값이 일부 칸에 몰리기 때문에, 버킷 수는 17처럼 소수(Prime Number)로 잡는 경우가 많다.

## 해시 함수의 다른 쓰임
해시 함수는 해시 테이블 말고도 쓰인다. 내려받은 파일이 원본과 같은지 확인할 때 쓰는 SHA-256 같은 암호학적 해시 함수(Cryptographic Hash Function)는 안전성에 초점을 둔다. 해시값만 보고 원래 입력을 알아내기 어려워야 하고, 같은 해시값이 나오는 다른 입력을 만들어 내기도 어려워야 한다. 파일 확인에는 뒤의 성질이 쓰인다. 해시 테이블용 해시 함수는 속도가 우선이라 이런 성질까지는 요구하지 않는다.
