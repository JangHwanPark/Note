## 상황을 일일이 가정해보고 진행하는 완전탐색

`상황을 일일이 가정해보고 진행하는 완전탐색`은 `시뮬레이션형 완전탐색(Brute Force Simulation)`이다.

시뮬레이션형 완전탐색 (Brute Force Simulation)은 완전탐색(Brute Force)의 한 종류로 가능한 모든 상황을 직접 시뮬레이션하면서 결과를 확인하는 방식이다.

모든 가능한 초기 상태를 일일이 가정하고, 각 상태에서 규칙에 따라 과정을 실제로 진행해보며 결과를 구하는 탐색 방식이다.

- 수학적으로 공식이나 규칙으로 바로 계산하기 어렵다.
- `이런 상황이면 이렇게 된다`라는 규칙 기반의 변화를 직접 반복 실행해야 하는 문제

## 잘 모르는 상황에서 완전탐색
### 일반적인 풀이 패턴
```js
let answer = 초기값;

// 가능한 모든 시작 상태를 하나씩 가정
for (let case of 가능한_모든_상황) {
  // 시뮬레이션에 사용할 현재 상태 변수
  let state = case;
  let cnt = 0;

  // 규칙에 따라 실제 변화 시뮬레이션
  while (종료조건_도달X) {
    state = 규칙(state);
    cnt++;
  }
  
  // 결과를 저장하거나 비교
  answer = 최댓값_또는_최솟값_갱신(answer, cnt);
}
```

### 실수 주의 (루프 변수 vs 상태 변수)
변수`state`는 루프변수 각 i의 복사본(시뮬레이션용 상태) 이어야 한다. 그런데 실수로 루프 변수 i를 직접 바꾸거나 `state`이 아닌 i를 업데이트하면 증감식이 꼬여서 사이드이펙이 터질수있다.
```js
for (let i = 1; i <= 9; i++) {
  let cnt = 0;
  
  // i를 직접 변경
  while (i > 1) {
    if (i % 2 === 0) i /= 2;
    else i = 3 * i + 1;
    cnt++;
  }

  console.log(i, cnt);
}
```
**문제점**
- i가 for 루프에서 `자동 증가`되기 전에 이미 값이 바뀌어버림.
- for의 증감식(i++)이 예측 불가능하게 되어 무한루프 또는 조기 종료 발생 가능.
- for가 제대로 순회하지 못함 (예: 1~9를 다 돌지 않음)

#### 풀이 아이디어 (시뮬레이션형 완전탐색)
가능한 모든 시작 수 1~9에 대해,
주어진 규칙을 그대로 시뮬레이션하면서 종료될 때까지 반복한다.
그리고 각 경우의 변화 횟수(cnt) 를 기록해 가장 긴 것을 찾는다.
```js
let maxCnt = 0;
let bestN = 0;

for (let i = 1; i <= 9; i++) {
  let num = i;
  let cnt = 0;
  let limit = 100; // 무한루프 방지용
  
  while (num > 1 && limit--) {
    if (num % 3 === 0) num = num / 3;
    else if (num % 2 === 0) num = num - 2;
    else num = num * 2 + 1;
    cnt++;
  }
  
  if (num <= 1 && cnt > maxCnt) {
    maxCnt = cnt;
    bestN = i;
  }
}

console.log(`가장 오래 걸린 n = ${bestN}, 단계 수 = ${maxCnt}`);
```

## 중첩 완전탐색 (Nested Brute Force)
중첩 완전탐색은 “상황을 일일이 가정”을 여러 선택에겐 겹쳐서 적용하는 패턴.
- 선택을 한 번에 처리하기 어렵다면, 선택 → 선택 → 결과 계산의 중첩 구조로 모든 조합을 시도 
- 각 케이스는 독립 상태에서 시뮬레이션해야 함 (원본 훼손 금지)

> Ex: 선택1(두 배로 만들 인덱스) × 선택2(제거 인덱스) 처럼 두 단계 이상의 선택을 모두 탐색.

### 일반적인 풀이 패턴
#### 코드 예시 — 안전성/가독성 소폭 개선
- 제거 후 길이는 고정값 n - 2 대신 동적 길이로 계산 (remainingArr.length - 1)
- 참고: d===r(두 배한 걸 곧바로 제거) 허용 여부는 문제 정의에 따라 다름. 지금 코드는 허용.
```js
const n = 5;
let arr = [1, 5, 2, 6, 8];
let res = -Infinity;

// i: 두 배로 만들 인덱스 선택
for (let i = 0; i < n; i++) {
    // 1.현재 케이스를 위해 실제 배열을 수정
    arr[i] *= 2;
  
    // j: 제거할 인덱스 선택
    for (let j = 0; j < n; j++) {
        let remainingArr = [];
      
        // 2.j번째 원소를 제외한 새 배열 구성
        for (let k = 0; k < n; k++) {
            if (k !== j) {
                remainingArr.push(arr[k]);
            }
        }
      
        // 3.인접한 숫자 간 차이의 합 계산
        let sumDiff = 0;
        for (let k = 0; k < n - 2; k++) {
            sumDiff += Math.abs(remainingArr[k] - remainingArr[k + 1]);
        }
        
        // 4.결과값 갱신
        res = Math.max(res, sumDiff);
    }
    
    // 5.원본배열 복구(다음 i 케이스를 위해 원래 값으로 되돌림)
    // 이 복구가 없으면 다음 루프에서 arr[i]가 이미 두 배인 상태로 남아
    // 다른 케이스 결과까지 오염(siede effect)됨
    arr[i] /= 2;
}

console.log(maxDiff);
```

#### 문제 요약
배열 arr=[1,5,2,6,8]에서 한 원소를 골라 두 배로 만든 뒤 또 다른 원소 하나를 제외한다. 남은 4개의 인접 절댓값 차이 합을 최대화하라.

#### 핵심 선택
- d: 두 배로 만들 인덱스 (0..n-1)
- r: 제외할 인덱스 (0..n-1) — d===r 허용 여부는 문제에 따름(보통 허용)
- 안전/깔끔한 구현(직접 계산 패턴 — 복사/필터 없이 계산)
```js
const arr = [1, 5, 2, 6, 8];
const n = arr.length;
let best = -Infinity;

for (let d = 0; d < n; d++) {      // (1) 두 배 인덱스
  for (let r = 0; r < n; r++) {    // (2) 제외 인덱스
    let prev = null;
    let score = 0;

    for (let k = 0; k < n; k++) {
      if (k === r) continue;       // 제외
      const val = (k === d) ? arr[k] * 2 : arr[k]; // 두 배 반영
      if (prev !== null) score += Math.abs(val - prev);
      prev = val;
    }

    best = Math.max(best, score);
  }
}

console.log(best); // 23
```
#### 포인트
- 배열 복사 없이 케이스별로 읽을 때”만 변환/제외를 반영 → 할당 0, 사이드 이펙트 0 
- 복사 방식으로 하고 싶다면 slice() 후 수정, filter()로 제거 (원본 보호)
```js
const arr = [1, 5, 2, 6, 8];
const n = arr.length;
let res = -Infinity;

for (let d = 0; d < n; d++) {          // 1.두 배 인덱스 선택
  for (let r = 0; r < n; r++) {        // 2.제외 인덱스 선택
    const tmp = arr.slice();           // 3.원본 복사 (매 케이스 독립)
    tmp[d] = tmp[d] * 2;               // 4.두 배 처리

    // 5.r번째 제거 (순서 유지)
    const remain = tmp.filter((_, i) => i !== r);

    // 6.인접 차이 합산
    let score = 0;
    for (let i = 0; i < remain.length - 1; i++) {
      score += Math.abs(remain[i + 1] - remain[i]);
    }

    res = Math.max(best, score);      // 7.결과 갱신
  }
}

console.log(res);
```

#### 복잡도
- 선택 O(n) × O(n) × 합산 O(n) = O(n³) — n=5면 충분히 작음

</details>

## 루프 선택 기준 (for vs while)
- 반복 횟수 명확(N번 고정) → for 
- Ex: 명령 N개를 순서대로 처리

- 종료 시점 불명확(상태가 만들 때까지) → while 
- Ex: n이 1이 될 때까지, 빙산이 분리될 때까지

## 상태(state) 다루기 — 배열/객체 변경 vs 복사
시뮬 시나리오마다 상태를 직접 수정(in-place) 할지, 복사(copy-on-write) 할지 결정해야 한다.

| 방식          | 설명                          | 장점              | 주의                      |
| ----------- | --------------------------- | --------------- | ----------------------- |
| in-place 수정 | 원본을 바꿨다가 복구                 | 메모리 적고 빠름       | 복구 누락·예외 시 값 오염(사이드이펙트) |
| 복사 후 수정     | `slice()`, `[...arr]`, 구조복사 | 각 케이스 독립, 안전    | 매 케이스 할당 비용 증가          |
| “읽을 때 변환”   | 값 읽는 순간만 변환/제외 반영           | 할당 0, 안전·가독성 우수 | 로직을 깔끔히 유지해야 함          |


## 시뮬레이션형 완전탐색의 핵심 사고
| 키워드           | 설명                                 |
|---------------|------------------------------------|
| **일일이 가정**    | 가능한 모든 초기 상태를 직접 시험                |
| **규칙 기반 진행**  | 상태 변화는 수식이 아니라 `조건 → 변화` 규칙        |
| **결과 관찰**     | 실제로 끝까지 돌려보고 결과를 확인                |
| **패턴 학습형 문제** | 보통 “이 규칙이 어떤 결과를 만드는지” 감 잡게 하는 문제들 |

## 실수 방지 체크리스트
- 바깥 루프 = 초기 상태 가정, 내부 루프 = 시뮬레이션/계산
- 루프 변수 i는 절대 수정 금지, 시뮬 변수는 복사본 사용
- 배열/객체는 원본 보호(복사 or 읽을 때 변환)
- `제외 후 길이`는 상수에 의존 X → remain.length - 1처럼 동적 기준
- d === r 허용 여부 등 정의 모호성은 명확히 고정
