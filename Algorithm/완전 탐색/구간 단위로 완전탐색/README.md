## 구간 단위로 완전탐색 (Brute Force by Range)
완전탐색(Brute Force)의 가장 기본적인 형태 중 하나가 바로 구간 단위 완전탐색이다.
이는 배열이나 수열에서 모든 연속된 구간을 전부 시도해보는 탐색 방식으로,
완전탐색의 핵심 개념인 `시작점과 끝점을 모두 시도한다`를 직접적으로 구현한 형태다.

즉, 가능한 모든 구간을 잡아보고, 각 구간 내의 합, 개수, 조건 등을 하나씩 검사하는 것이다.

### 구간 정하기
> 핵심 질문: 구간이란 무엇인가?

구간은 말 그대로 `시작점과 끝점 사이의 연속된 범위`로 완전탐색에서는 `모든 가능한 시작점 i와 끝점 j를 시도`해서 그 안에 있는 원소들을 검사한다.

단순히 모든 조합을 보는 게 아니라 `배열 내에서 연속된 부분(구간)`을 하나씩 정해서 그 안의 합, 최댓값, 조건 등을 전부 확인 하는 방식이다.

모든 가능한 (i, j) 쌍을 전부 고려하므로, 시간 복잡도는 O(n^2)이 된다.
```js
for (let i = 0; i < n; i++) {   // 시작점 고정
  for (let j = i; j < n; j++) { // 끝점 이동 (i부터 끝까지)
    // [i, j] 구간
  }
}
```
```text
n = 5 일떄 출력 예시
[0 ~ 0], [0 ~ 1], [0 ~ 2], [0 ~ 3], [0 ~ 4]
[1 ~ 1], [1 ~ 2], [1 ~ 3], [1 ~ 4]
[2 ~ 2], [2 ~ 3], [2 ~ 4]
[3 ~ 3], [3 ~ 4]
[4 ~ 4]
```

| 루프           | 역할                   | 비유                           |
| ------------ | -------------------- | ---------------------------- |
| **바깥 루프(i)** | 구간의 시작점을 정한다.      | 어디서부터 시작할지 정하는 사람          |
| **내부 루프(j)** | 끝점을 늘려가며 구간을 확장한다. | 시작한 곳에서 오른쪽으로 걸어가며 확인하는 사람 |

- 이때 i = 0, j = 0이면 길이 1짜리 구간 
- i = 0, j = 1이면 길이 2짜리 구간 
- 이렇게 모든 구간을 시도한다.

### 구간 개수 공식과 `n - k + 1`의 의미
> 핵심 질문: 길이가 k인 구간을 배열 길이 n에서 몇 개 만들 수 있을까?

배열의 인덱스가 `0 ~ n - 1`이라면 길이 k인 구간의 시작점과 끝점은 다음 관계를 가진다.

끝점: `j = i + k - 1`

| 시작 i | 끝 j | 포함 인덱스           | 길이  |
| ---- | --- | ---------------- | --- |
| 0    | k-1 | [0, 1, ..., k-1] | k   |
| 1    | k   | [1, 2, ..., k]   | k   |
| 2    | k+1 | [2, 3, ..., k+1] | k   |
| ...  | ... | ...              | ... |
| n-k  | n-1 | [n-k, ..., n-1]  | k   |

구간이 유효하려면 끝 인덱스 j가 배열 끝을 넘어가면 안 된다.
```text
i + k - 1 <= n - 1
= i <= n - k
```
```js
const n = 6;
const k = 3;

// 가능한 모든 길이 3짜리 구간 출력
for (let i = 0; i <= n - k; i++) {
  console.log(`[${i} ~ ${i + k - 1}]`);
}
```
출력 결과: 총 4개 = n - k + 1개의 구간
```text
[0 ~ 2]
[1 ~ 3]
[2 ~ 4]
[3 ~ 5]
```

| 구간 길이 k | 배열 길이 n | 가능한 구간 수 | i의 범위   |
| ------- | ------- | -------- | ------- |
| 1       | n       | n        | 0 ~ n-1 |
| 2       | n       | n-1      | 0 ~ n-2 |
| 3       | n       | n-2      | 0 ~ n-3 |
| …       | …       | …        | …       |
| k       | n       | n-k+1    | 0 ~ n-k |

### 길이가 정해지지 않은 모든 구간 탐색
> 핵심 질문: 문제에서 구간의 길이 k가 주어지지 않았다면 어떻게 해야 할까?

구간 길이가 주어졌을 때는 정해진 칸 수만큼의 서랍만 열어본다. 하지만 길이가 주어지지 않았다면 서랍 하나부터 전부 열어보는 모든 경우를 확인한다.

이 경우엔 가능한 모든 길이의 구간을 전부 시도해야 한다.
즉, 길이 1, 길이 2, ..., 길이 n까지 모든 구간을 완전탐색으로 확인한다.

이는 시작점(i)과 끝점(j)을 직접 모두 시도하는 2중 루프 형태로 구현할 수 있다.
```js
for (let i = 0; i < n; i++) {         // 구간 시작점 고정
  for (let j = i; j < n; j++) {       // 구간 끝점 확장
    const len = j - i + 1;            // 현재 구간의 길이
    console.log(`[${i} ~ ${j}] (길이: ${len})`);
  }
}
```
```text
n = 4일 때 출력 예시
[0 ~ 0] (길이 1)
[0 ~ 1] (길이 2)
[0 ~ 2] (길이 3)
[0 ~ 3] (길이 4)
[1 ~ 1] (길이 1)
[1 ~ 2] (길이 2)
[1 ~ 3] (길이 3)
[2 ~ 2] (길이 1)
[2 ~ 3] (길이 2)
[3 ~ 3] (길이 1)
```

이 방식은 **모든 구간 길이를 직접 시도**하기 때문에  결국 O(n^2)의 완전탐색 구조가 된다. 길이를 고정(k가 주어진 경우)하는 것보다 한 단계 더 일반화된 형태다.

| 상황            | 루프 구조           | 탐색 방식             | 시간 복잡도  |
| ------------- | --------------- | ----------------- | ------- |
| **k가 주어진 경우** | `i`를 0~n-k까지    | 길이 `k`짜리 고정 구간 탐색 | `O(n)`  |
| **k가 없는 경우**  | `i`, `j`를 모두 시도 | 모든 길이의 구간 탐색      | `O(n²)` |

### 배열 기록 후 구간 정하기 (좌표형 문제로 확장)
> 핵심 질문: 단순 배열이 아니라 `위치(pos)`가 있을 땐 어떻게 구간을 정할까?

일반적인 배열 문제에서는 인덱스(i, j)가 이미 순서(위치) 를 보장한다.
즉, i < j면 `왼쪽 → 오른쪽`순서가 자연스럽게 정해지므로 그 자체로 구간을 정의할 수 있다.

하지만 좌표형 문제에서는 다르다. 배열이 아니라 `(위치, 값)`형태의 데이터가 주어지기 때문에 인덱스 순서와 실제 위치 순서가 일치하지 않을 수 있다.
```js
// 입력이 '위치(pos)' 기준이 아니라 '입력 순서' 기준으로 주어졌다고 가정
const people = [
  { pos: 7, letter: 'H' },
  { pos: 1, letter: 'G' },
  { pos: 4, letter: 'H' },
  { pos: 3, letter: 'G' },
];
```
이 상태로 단순히 i < j 순으로 구간을 탐색하면, (pos 7 -> pos 1)처럼 실제 공간상으로는 거꾸로 된 구간을 계산하게 되어 `거리 계산`이나`좌표 차이`가 의미를 잃는다. 그래서 반드시 위치(pos) 기준으로 정렬을 먼저 해야 한다.
```js
// 위치 기준 정렬(핵심)
people.sort((a, b) => a.pos - b.pos);

const n = people.length;
let res = 0;

for (let i = 0; i < n; i++) {
  let g = 0, h = 0;
  for (let j = i; j < n; j++) {
    // 현재 구간 내 G/H 개수 누적
    if (people[j].letter === 'G') g++;
    else h++;

    // G와 H 개수가 같을 때 거리 계산
    if (g === h) {
      const length = people[j].pos - people[i].pos;
      res = Math.max(res, length);
      console.log(
        `[${people[i].pos} ~ ${people[j].pos}] (길이: ${length}), G:${g}, H:${h}`
      );
    }
  }
}

console.log("가장 긴 구간 거리:", res);
```
```text
실행 결과
[1 ~ 3] (길이: 2), G:1, H:1
[3 ~ 4] (길이: 1), G:1, H:1
[4 ~ 7] (길이: 3), G:1, H:1
[1 ~ 7] (길이: 6), G:2, H:2
가장 긴 구간 거리: 6
```

| 시작 pos | 끝 pos | 포함 데이터(letter) | G 개수 | H 개수 | G = H 여부 | 거리 |
| ------ | ----- | -------------- | ---- | ---- |----------| -- |
| 1      | 3     | G, G           | 2    | 0    | X        | 2  |
| 1      | 4     | G, G, H        | 2    | 1    | X        | 3  |
| 1      | 7     | G, G, H, H     | 2    | 2    | O        | 6  |
| 3      | 4     | G, H           | 1    | 1    | O        | 1  |
| 4      | 7     | H, H           | 0    | 2    | X        | 3  |

### 모든 구간 정하기 (완전탐색의 본질)
> 핵심 질문: `모든 구간`을 어떻게 전부 검사하나?

완전탐색의 본질은 **모든 경우의 수를 빠짐없이 시도해보는 것**이다.
구간 단위 탐색에서는 가능한 모든 시작점 i 와 모든 끝점 j 를 전부 시도해보는 구조로 표현된다.

1. 시작점을 하나 정하고(i)
2. 끝점을 하나씩 늘리면서(j)
3. 각 구간에서 합, 개수, 조건 등을 전부 검사

#### 왜 모든 구간을 봐야 할까?
- 어떤 조건(예: 부분합, 문자 개수, 평균 등)은 구간 전체를 직접 확인해야만 판단 가능
- 규칙이 명확하지 않거나 최적해가 특정 길이에 한정되지 않은 경우 모든 구간을 직접 살펴봐야 확실하게 답을 얻을 수 있다.
- 단순한 2중 반복문이 모든 완전탐색 문제의 기본 골격이 된다.

#### 부분합 계산 예시
모든 연속 구간의 합(sum) 을 구하기
```js
const arr = [2, -1, 3];
const n = arr.length;

for (let i = 0; i < n; i++) {       // 구간 시작점
  let sum = 0;
  for (let j = i; j < n; j++) {     // 구간 끝점 확장
    sum += arr[j];
    console.log(`[${i} ~ ${j}] 합: ${sum}`);
  }
}
```
```text
[0 ~ 0] 합: 2
[0 ~ 1] 합: 1
[0 ~ 2] 합: 4
[1 ~ 1] 합: -1
[1 ~ 2] 합: 2
[2 ~ 2] 합: 3
```

| 시작 i | 끝 j | 포함 값       | 구간 합 |
| ---- | --- | ---------- | ---- |
| 0    | 0   | [2]        | 2    |
| 0    | 1   | [2, -1]    | 1    |
| 0    | 2   | [2, -1, 3] | 4    |
| 1    | 1   | [-1]       | -1   |
| 1    | 2   | [-1, 3]    | 2    |
| 2    | 2   | [3]        | 3    |

#### 조건을 포함한 구간 검사
구간 합이 3 이상인 구간 찾기

완전탐색에서는 조건(예: 합 >= K, 문자 개수 동일 등)을 루프 안에서 직접 검사하면서`조건을 만족하는 모든 구간`을 하나씩 찾아낼 수 있다.
```js
const arr = [2, -1, 3];
const n = arr.length;

for (let i = 0; i < n; i++) {
  let sum = 0;
  for (let j = i; j < n; j++) {
    sum += arr[j];
    if (sum >= 3) {
      console.log(`[${i} ~ ${j}] (합=${sum}) ✅`);
    }
  }
}
```
```text
[0 ~ 2] (합=4)
[2 ~ 2] (합=3)
```

| 루프           | 역할           | 비유                    |
| ------------ | ------------ |-----------------------|
| **바깥 루프(i)** | 시작 위치를 정함    | 출발점을 고르는 사람           |
| **내부 루프(j)** | 구간 끝을 확장     | 출발한 뒤 오른쪽으로 걸어가며 확인   |
| **조건 검사**    | 각 구간 내 특성 판단 | 매번 이 구간이 조건을 만족하는지 확인 |

#### 시간 복잡도
모든 시작점 i에 대해 끝점 j를 확장하므로 구간의 총 개수는 다음과 같다.
```text
1 + 2 + 3 + ... + n = n(n + 1) / 2 = O(n^2)
```
즉, 구간 완전탐색의 시간 복잡도는 O(n^2)이다.

| n     | 가능한 구간 수 | 대략적인 연산 횟수 |
| ----- | -------- | ---------- |
| 5     | 15       | 15회 검사     |
| 10    | 55       | 55회 검사     |
| 100   | 5050     | 5천 회 검사    |
| 1,000 | 500,500  | 50만 회 검사   |
