## 완전탐색(Brute Force)
완전탐색(Brute Force)이란 모든 가능한 경우의 수를 직접 탐색하여 정답을 찾는 알고리즘 기법이다.
쉽게 말해, 가능한 모든 선택지를 하나씩 전부 시도해보는 방법으로 완전탐색의 핵심은 `시작점과 끝점을 전부 시도`해보는것이다.

예를 들어, 비밀번호를 찾기 위해 `0000`부터 `9999`까지 전부 입력해보는 방법이 바로 완전탐색이다.
비효율적으로 보일 수 있지만, `확실하게 정답을 찾을 수 있다`는 장점이 있다.

완전탐색은 모든 열쇠를 하나씩 꽂아보는 방식으로 정답이 반드시 나오지만, 문이 많아질수록 시간이 오래 걸린다.
이후 배울 백트래킹이나 DP는 `쓸모없는 열쇠는 일찍 버리자`는 더 똑똑한 방법으로 시간을 단축할 수 있다.

### 완전탐색 특징
| 구분                     | 설명                           |
| ---------------------- | ---------------------------- |
| **정확성(Accuracy)**      | 모든 경우를 시도하므로 반드시 정답을 찾음      |
| **단순성(Simplicity)**    | 로직이 단순하고 구현이 쉬움              |
| **비효율성(Inefficiency)** | 경우의 수가 많아지면 시간 복잡도가 급격히 증가   |
| **응용성(Applicability)** | 경우의 수가 작거나, 최적화가 어려운 문제에서 유용 |

### 완전탐색 언제 사용할까?
- 입력 크기가 작을 때 (예: N <= 10 ~ 20)
- 최적해를 반드시 찾아야 할 때 (예: 탐색/조합 문제)
- 다른 알고리즘(백트래킹, DP, 그리디 등)을 적용하기 전, 기본 아이디어를 떠올릴 때
- 규칙이 보이지 않을 때 `무식하게라도`답을 확인하기 위해

### 완전탐색의 종류
| 종류                      | 탐색 대상                  | 예시                                    | 시간 복잡도   |
| ----------------------- | ---------------------- | ------------------------------------- | -------- |
| **순열 탐색(Permutation)**  | 모든 순서 조합               | `1,2,3` → `123, 132, 213, ...`        | `O(n!)`  |
| **부분집합 탐색(Subsets)**    | 포함/비포함의 모든 경우          | `{1,2}` → `{}`, `{1}`, `{2}`, `{1,2}` | `O(2^n)` |
| **조합 탐색(Combination)**  | 일부 선택의 모든 경우           | `5C3` 등                               | `O(nCk)` |
| **구간 탐색(Range Search)** | 연속된 부분 확인              | 연속합, 최대 구간합                           | `O(n^2)` |
| **이동 탐색(Grid Search)**  | 2차원 공간 이동 (BFS/DFS 기반) | 미로 탐색, 경로 찾기                          | `O(n*m)` |

### 입력 크기별 계산량
- 완전탐색은 입력 크기 n에 따라 계산량이 폭발적으로 커진다.
- 아래 표는 시간 제한(약 1초)에 맞춰 대략적인 가능 범위를 나타낸다.

| 시간 복잡도    | 가능한 n의 최대 크기 (대략) | 예시       |
| --------- | ----------------- | -------- |
| `n!`      | n ≤ 8~10          | 순열 탐색    |
| `2^n`     | n ≤ 20            | 부분집합 탐색  |
| `n^3`     | n ≤ 500           | 3중 반복문   |
| `n^2`     | n ≤ 5,000         | 구간 합 등   |
| `n log n` | n ≤ 1,000,000     | 정렬, 이진탐색 |
| `n`       | n ≤ 100,000,000   | 단순 반복    |

### 한계와 대안
완전탐색은 단순하지만 입력 크기가 커지면 계산량이 폭발하기 떄문에 대안 알고리즘을 사용해야한다.

| 알고리즘           | 완전탐색의 한계 보완                     |
| -------------- | ------------------------------- |
| **백트래킹**       | 불필요한 경우를 “조기 가지치기(pruning)”로 제거 |
| **동적계획법(DP)**  | 중복 계산을 저장하여 효율적으로 탐색            |
| **그리디**        | 매 단계 최적 선택으로 빠르게 근사해            |
| **이분 탐색 / 정렬** | 탐색 공간 축소                        |
