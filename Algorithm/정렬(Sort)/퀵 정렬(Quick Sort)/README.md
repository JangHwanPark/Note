## 퀵 정렬이란 ?
- 기준값(피벗) 하나를 골라 그보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 나눈 뒤, 양쪽을 같은 방법으로 다시 정렬하는 알고리즘
- 나누고(Divide) 각각 처리하는(Conquer) 분할 정복(Divide and Conquer) 방식이고, 재귀로 구현한다
- 평균 O(n log n)으로 빠르지만, 피벗을 계속 나쁘게 고르면 O(n²)까지 느려진다

### 퀵 (Quick)
사전적 의미는 빠른이다. 토니 호어(Tony Hoare)가 1959년 무렵 고안해 1961년에 발표한 알고리즘이다(연도는 확인 필요). 이름처럼 같은 O(n log n) 정렬 가운데서도 실제로 빠른 편으로 알려져 있다.

학생들을 키 순으로 세울 때, 한 명을 기준으로 세우고 "이 친구보다 작으면 왼쪽, 크면 오른쪽"으로 보내는 것과 같다. 기준 학생은 그 자리가 최종 자리가 되고, 왼쪽 무리와 오른쪽 무리 안에서 각각 같은 일을 반복하면 전체가 정렬된다.

<br/>

## 용어
### 피벗 (Pivot)
사전적 의미는 회전축, 중심점이다. 퀵 정렬에서는 값을 왼쪽과 오른쪽으로 나누는 기준값을 말한다. 나누기가 끝나면 피벗은 정렬 후 자기 자리에 놓인다.

### 파티션 (Partition)
사전적 의미는 칸막이, 나누기다. 피벗보다 작은 값과 큰 값을 양쪽으로 나누는 과정 자체를 말한다.

### 파티션 방식 (Partition Scheme)
나누는 구체적인 방법이다. 대표적인 두 가지가 있다.

- 로무토(Lomuto) 방식은 피벗을 구간 끝에 두고, 앞에서부터 한 칸씩 보며 피벗보다 작은 값을 앞으로 모은다. 코드가 짧아 이해하기 쉽다.
- 호어(Hoare) 방식은 양쪽 끝에서 포인터를 안쪽으로 움직이다가, 자리가 잘못된 두 값을 바꾸며 좁혀 간다. 교환 횟수가 적어 보통 더 빠르다.

### 재귀 (Recursion)
함수가 자기 자신을 호출하는 기법이다. 호출을 멈추는 기본 조건(Base Case)이 꼭 있어야 한다. 퀵 정렬에서는 구간의 원소가 1개 이하일 때가 기본 조건이다. 자세한 내용은 [재귀 함수](../../../JavaScript/재귀%20함수(Recursive%20Function)/README.md) 노트에 있다.

<br/>

## 동작
로무토 방식으로 `[5, 3, 8, 1, 9, 2, 7]` 의 첫 번째 나누기를 따라가 본다. 피벗은 마지막 값 7이다.

1. `i` 는 "피벗보다 작은 값을 놓을 다음 자리"로, 0에서 시작한다.
2. `j` 로 앞에서부터 보면서 피벗보다 작은 값을 만나면 `i` 자리와 바꾸고 `i` 를 한 칸 옮긴다. 5, 3, 1, 2가 차례로 앞으로 모인다.
3. 끝까지 보면 배열은 `[5, 3, 1, 2, 9, 8, 7]` 이고 `i` 는 4다.
4. 피벗(7)을 `i` 자리와 바꾸면 `[5, 3, 1, 2, 7, 8, 9]` 가 된다. 7은 인덱스 4에서 최종 자리를 찾았다.
5. 왼쪽 `[5, 3, 1, 2]` 와 오른쪽 `[8, 9]` 를 같은 방법으로 정렬한다.

<br/>

## 구현
```js
function partition(arr, lo, hi) {
  const pivot = arr[hi]; // 구간 마지막 값을 피벗으로 쓴다
  let i = lo;            // 피벗보다 작은 값을 놓을 다음 자리
  for (let j = lo; j < hi; j++) {
    if (arr[j] < pivot) {
      [arr[i], arr[j]] = [arr[j], arr[i]];
      i++;
    }
  }
  [arr[i], arr[hi]] = [arr[hi], arr[i]]; // 피벗을 제자리에 놓는다
  return i;
}

function quickSort(arr, lo = 0, hi = arr.length - 1) {
  if (lo >= hi) return arr; // 원소가 1개 이하면 이미 정렬된 상태다
  const p = partition(arr, lo, hi);
  quickSort(arr, lo, p - 1);  // 피벗 왼쪽
  quickSort(arr, p + 1, hi);  // 피벗 오른쪽
  return arr;
}

console.log(quickSort([5, 3, 8, 1, 9, 2, 7]));
// 값만 적으면 1, 2, 3, 5, 7, 8, 9 (Node.js는 여러 줄로 나눠 출력한다)
```

새 배열을 만들지 않고 원래 배열 안에서 자리를 바꾸므로(제자리 정렬, In-place) 추가 메모리는 재귀 호출 스택만큼만 든다. 0~19 사이 정수 배열 2,000개를 무작위로 만들어 `sort((a, b) => a - b)` 결과와 비교했고 모두 같았다.

## 시간 복잡도
| 경우 | 시간 | 언제 |
| --- | --- | --- |
| 최선 | O(n log n) | 피벗이 매번 구간을 반으로 나눌 때 |
| 평균 | O(n log n) | 값이 무작위로 섞여 있을 때 |
| 최악 | O(n²) | 피벗이 매번 가장 작거나 가장 큰 값일 때 |

나누기 한 번에 구간의 원소를 한 번씩 보므로 O(n)이 들고, 반씩 나뉘면 단계가 log n개라 O(n log n)이다. 피벗이 한쪽 끝 값이면 한쪽은 비고 다른 쪽에 n-1개가 남아서 단계가 n개로 늘어난다.

위 구현으로 비교 횟수를 세어 보면 차이가 그대로 보인다. 원소 1,000개를 무작위로 섞었을 때는 13,949번이었는데, 이미 정렬된 1,000개를 넣으면 499,500번(n(n-1)/2)이었다. 마지막 값을 피벗으로 쓰므로 정렬된 입력에서는 피벗이 늘 가장 큰 값이 되기 때문이다. 이 경우 재귀 깊이도 n이 되어, 정렬된 20,000개를 넣자 `RangeError: Maximum call stack size exceeded` 가 났다.

### 최악을 피하는 방법
피벗을 구간 안에서 무작위로 고르면 정렬된 입력이 들어와도 피벗이 한쪽 끝 값일 확률이 낮아진다.

```js
function partition(arr, lo, hi) {
  const r = lo + Math.floor(Math.random() * (hi - lo + 1));
  [arr[r], arr[hi]] = [arr[hi], arr[r]]; // 무작위로 고른 피벗을 끝으로 보낸다
  // 이후는 위와 같다
}
```

이렇게 바꾸자 정렬된 1,000개의 비교 횟수가 12,493번으로 줄었고, 정렬된 20,000개도 오류 없이 정렬됐다. 다만 모든 값이 같은 배열은 여전히 최악이다. 로무토 방식은 피벗과 같은 값을 모두 한쪽으로 보내기 때문이다. 같은 값 20,000개를 넣으면 무작위 피벗으로도 같은 오류가 났다. 같은 값이 많을 때는 호어 방식이나, 작은 값, 같은 값, 큰 값 세 구역으로 나누는 3분할 방식을 쓴다.

<br/>

## 코딩 테스트에서는
정렬만 필요하면 직접 구현하지 않고 [sort()](../배열%20정렬(JS%20sort)/README.md)를 쓴다. 퀵 정렬을 직접 짜는 것은 정렬 원리를 묻는 문제나, 파티션 아이디어로 k번째로 작은 값을 찾는 문제(퀵 셀렉트)에서다.
