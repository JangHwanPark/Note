## 구간 단위 완전 탐색이란 ?
- 배열이나 수열에서 연속된 구간을 모두 잡아 보고, 구간마다 합, 개수, 조건을 하나씩 검사하는 완전 탐색
- 가능한 모든 시작점과 끝점의 쌍을 시도하므로 보통 2중 반복문이 된다
- 구간 개수가 `n(n+1)/2` 개라서 시간 복잡도는 O(n^2)이다

### 구간 (Interval)
사전적 의미는 어떤 지점과 다른 지점 사이다.
배열에서는 시작 인덱스 i와 끝 인덱스 j 사이의 연속된 원소들을 말한다. `[i, j]` 로 쓰고, 중간을 건너뛴 원소 묶음은 구간이 아니다.

책장의 책을 고르는 것과 같다. 몇 번째 책부터 몇 번째 책까지를 한 묶음으로 뽑는 방법을 모두 세어 보는 것이 구간 완전 탐색이다.

## 모든 구간 만들기
바깥 반복문이 구간의 시작점 i를 정하고, 안쪽 반복문이 끝점 j를 i부터 배열 끝까지 늘려 간다. 시작점을 정한 사람이 그 자리에서 오른쪽으로 한 칸씩 걸어가며 구간을 넓히는 셈이다.

```js
for (let i = 0; i < n; i++) {   // 시작점 고정
  for (let j = i; j < n; j++) { // 끝점을 i부터 끝까지 이동
    // [i, j] 구간
  }
}
```

n = 5일 때 만들어지는 구간은 아래와 같다.

```text
[0 ~ 0], [0 ~ 1], [0 ~ 2], [0 ~ 3], [0 ~ 4]
[1 ~ 1], [1 ~ 2], [1 ~ 3], [1 ~ 4]
[2 ~ 2], [2 ~ 3], [2 ~ 4]
[3 ~ 3], [3 ~ 4]
[4 ~ 4]
```

i = 0, j = 0이면 길이 1인 구간이고, i = 0, j = 1이면 길이 2인 구간이다. 끝점에 길이를 함께 찍어 보면 길이 1부터 n까지 모든 구간이 나온다.

```js
for (let i = 0; i < n; i++) {
  for (let j = i; j < n; j++) {
    const len = j - i + 1; // 현재 구간의 길이
    console.log(`[${i} ~ ${j}] (길이: ${len})`);
  }
}
```

```text
n = 4일 때 출력
[0 ~ 0] (길이: 1)
[0 ~ 1] (길이: 2)
[0 ~ 2] (길이: 3)
[0 ~ 3] (길이: 4)
[1 ~ 1] (길이: 1)
[1 ~ 2] (길이: 2)
[1 ~ 3] (길이: 3)
[2 ~ 2] (길이: 1)
[2 ~ 3] (길이: 2)
[3 ~ 3] (길이: 1)
```

## 길이가 정해진 구간의 개수
길이가 k인 구간만 보면 되는 문제도 있다. 배열의 인덱스가 `0 ~ n - 1` 이라면 시작점이 i인 길이 k 구간의 끝점은 `j = i + k - 1` 이다.

| 시작 i | 끝 j | 포함 인덱스 | 길이 |
| --- | --- | --- | --- |
| 0 | k-1 | [0, 1, ..., k-1] | k |
| 1 | k | [1, 2, ..., k] | k |
| ... | ... | ... | ... |
| n-k | n-1 | [n-k, ..., n-1] | k |

끝점이 배열 끝을 넘으면 안 되므로 `i + k - 1 <= n - 1` 이고, 정리하면 `i <= n - k` 이다. 시작점은 0부터 n-k까지라서 구간은 `n - k + 1` 개다.

```js
const n = 6;
const k = 3;

for (let i = 0; i <= n - k; i++) {
  console.log(`[${i} ~ ${i + k - 1}]`);
}
```

```text
[0 ~ 2]
[1 ~ 3]
[2 ~ 4]
[3 ~ 5]
```

n = 6, k = 3이면 6 - 3 + 1 = 4개다.

| 구간 길이 k | 가능한 구간 수 | i의 범위 |
| --- | --- | --- |
| 1 | n | 0 ~ n-1 |
| 2 | n-1 | 0 ~ n-2 |
| 3 | n-2 | 0 ~ n-3 |
| k | n-k+1 | 0 ~ n-k |

길이가 주어지면 구간 수는 O(n)이다. 다만 구간마다 합을 처음부터 더하면 구간 하나에 k번씩 더하므로 O(n·k)가 된다. 한 칸씩 밀면서 빠지는 값은 빼고 들어오는 값은 더하는 슬라이딩 윈도(Sliding Window)를 쓰면 O(n)으로 줄일 수 있다. 길이가 주어지지 않으면 앞의 2중 반복문으로 모든 길이를 시도해야 하므로 O(n^2)이다.

## 위치가 따로 있는 좌표형 문제
일반 배열에서는 인덱스가 곧 위치라서 i < j면 왼쪽에서 오른쪽 순서가 저절로 정해진다. 좌표형 문제는 다르다. 위치와 값의 쌍이 입력 순서대로 주어지기 때문에 인덱스 순서와 실제 위치 순서가 다를 수 있다.

```js
// 입력이 위치 순서가 아니라 입력 순서대로 주어졌다고 가정
const people = [
  { pos: 7, letter: 'H' },
  { pos: 1, letter: 'G' },
  { pos: 4, letter: 'H' },
  { pos: 3, letter: 'G' },
];
```

이대로 i < j 순으로 구간을 잡으면 위치 7에서 위치 1로 가는 거꾸로 된 구간을 계산하게 되어 거리가 의미를 잃는다. 그래서 위치 기준으로 먼저 정렬한다.

```js
people.sort((a, b) => a.pos - b.pos); // 위치 기준 정렬

const n = people.length;
let res = 0;

for (let i = 0; i < n; i++) {
  let g = 0, h = 0;
  for (let j = i; j < n; j++) {
    // 현재 구간 안의 G, H 개수 누적
    if (people[j].letter === 'G') g++;
    else h++;

    // G와 H 개수가 같을 때 거리 계산
    if (g === h) {
      const length = people[j].pos - people[i].pos;
      res = Math.max(res, length);
      console.log(
        `[${people[i].pos} ~ ${people[j].pos}] (길이: ${length}), G:${g}, H:${h}`
      );
    }
  }
}

console.log("가장 긴 구간 거리:", res);
```

```text
[1 ~ 7] (길이: 6), G:2, H:2
[3 ~ 4] (길이: 1), G:1, H:1
가장 긴 구간 거리: 6
```

정렬하면 위치 순서는 1(G), 3(G), 4(H), 7(H)이다. G와 H의 개수가 같은 구간은 1부터 7까지 전체와 3부터 4까지 두 개뿐이다. 바깥 반복문이 시작점 1에서 먼저 돌기 때문에 `[1 ~ 7]` 이 먼저 출력된다.

| 시작 pos | 끝 pos | 포함 글자 | G 개수 | H 개수 | G = H | 거리 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 3 | G, G | 2 | 0 | X | 2 |
| 1 | 4 | G, G, H | 2 | 1 | X | 3 |
| 1 | 7 | G, G, H, H | 2 | 2 | O | 6 |
| 3 | 4 | G, H | 1 | 1 | O | 1 |
| 3 | 7 | G, H, H | 1 | 2 | X | 4 |
| 4 | 7 | H, H | 0 | 2 | X | 3 |

## 구간마다 값 계산하기
구간 합, 문자 개수, 평균 같은 조건은 구간 안의 값을 직접 확인해야 판단할 수 있다. 답이 특정 길이에만 있다는 규칙이 보이지 않으면 모든 구간을 살펴봐야 확실하게 답을 얻는다.

### 모든 구간의 합
끝점을 한 칸 늘릴 때마다 새로 들어온 값만 더하면 되므로, 구간 합을 구간마다 처음부터 다시 더할 필요가 없다.

```js
const arr = [2, -1, 3];
const n = arr.length;

for (let i = 0; i < n; i++) {
  let sum = 0;
  for (let j = i; j < n; j++) {
    sum += arr[j];
    console.log(`[${i} ~ ${j}] 합: ${sum}`);
  }
}
```

```text
[0 ~ 0] 합: 2
[0 ~ 1] 합: 1
[0 ~ 2] 합: 4
[1 ~ 1] 합: -1
[1 ~ 2] 합: 2
[2 ~ 2] 합: 3
```

### 조건을 만족하는 구간 찾기
구간 합이 3 이상인 구간만 찾으려면 안쪽 반복문에 조건 검사를 한 줄 더하면 된다.

```js
const arr = [2, -1, 3];
const n = arr.length;

for (let i = 0; i < n; i++) {
  let sum = 0;
  for (let j = i; j < n; j++) {
    sum += arr[j];
    if (sum >= 3) {
      console.log(`[${i} ~ ${j}] (합=${sum})`);
    }
  }
}
```

```text
[0 ~ 2] (합=4)
[2 ~ 2] (합=3)
```

## 시간 복잡도
모든 시작점 i에 대해 끝점 j를 늘려 가므로 구간의 총 개수는 아래와 같다.

```text
1 + 2 + 3 + ... + n = n(n + 1) / 2 = O(n^2)
```

| n | 가능한 구간 수 |
| --- | --- |
| 5 | 15 |
| 10 | 55 |
| 100 | 5,050 |
| 1,000 | 500,500 |

구간 하나를 O(1)에 검사한다면 n이 수천 정도까지는 시간 안에 들어온다.
