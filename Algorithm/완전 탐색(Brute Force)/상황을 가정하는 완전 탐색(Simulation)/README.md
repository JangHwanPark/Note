## 시뮬레이션형 완전 탐색이란 ?
- 가능한 시작 상태를 하나씩 가정하고, 각 상태에서 문제의 규칙대로 과정을 직접 진행해 결과를 구하는 완전 탐색
- 결과를 공식으로 바로 계산하기 어렵고 "이런 상황이면 이렇게 된다"는 규칙만 주어진 문제에 쓴다
- 바깥 반복문은 시작 상태를 정하고, 안쪽 반복문은 규칙대로 상태를 바꿔 나간다

### 시뮬레이션 (Simulation)
사전적 의미는 모의 실험, 흉내 내기다. 실제로 해 보기 어려운 일을 비슷한 조건으로 따라 해 보는 것을 말한다.
알고리즘 문제에서 시뮬레이션은 문제에 적힌 규칙과 과정을 코드로 한 단계씩 그대로 따라 하는 풀이를 말한다. 영리한 공식 대신 시키는 대로 진행하는 것이 핵심이라, 규칙을 하나라도 빠뜨리거나 순서를 바꾸면 답이 틀린다.

보드게임을 처음 배울 때 규칙서를 펴 놓고 말을 한 칸씩 직접 옮겨 보는 것과 같다. 시뮬레이션형 완전 탐색은 가능한 출발 칸마다 이 과정을 한 번씩 해 보는 것이다.

## 시작 상태를 모두 가정해 보기
### 일반적인 풀이 패턴
```js
let answer = 초기값;

// 가능한 모든 시작 상태를 하나씩 가정
for (const start of 가능한_모든_상황) {
  // 시뮬레이션에 사용할 현재 상태 변수
  let state = start;
  let cnt = 0;

  // 규칙에 따라 실제 변화 시뮬레이션
  while (종료조건_도달X) {
    state = 규칙(state);
    cnt++;
  }

  // 결과를 저장하거나 비교
  answer = 최댓값_또는_최솟값_갱신(answer, cnt);
}
```

### 루프 변수와 상태 변수를 나눠야 하는 이유
시뮬레이션에서 바꿔 나갈 값은 루프 변수 `i` 를 복사한 별도의 변수(`state`)여야 한다. 루프 변수 `i` 를 직접 바꾸면 `for` 의 증감식과 시뮬레이션이 같은 변수를 건드려 흐름이 꼬인다.
```js
for (let i = 1; i <= 9; i++) {
  let cnt = 0;

  // i를 직접 변경
  while (i > 1) {
    if (i % 2 === 0) i /= 2;
    else i = 3 * i + 1;
    cnt++;
  }

  console.log(i, cnt);
}
```
이 코드는 끝나지 않는다. `i = 2` 일 때 `while` 이 `i` 를 1로 만들고, `for` 의 `i++` 가 다시 2로 올린다. 그러면 또 `while` 이 1로 만들어서 `i` 는 1과 2 사이를 영원히 오간다. Node.js v22.13.0에서 반복 횟수에 상한을 두고 실행해 상한까지 멈추지 않는 것을 확인했다.

고치려면 `let num = i;` 로 복사한 뒤 `num` 만 바꾼다.

시작 수 1~9를 모두 가정하고 규칙대로 직접 진행해, n이 1 이하가 될 때까지 가장 오래 걸리는 시작 수를 찾는 문제다. 답은 n=8일 때 3단계다.

```text
한 자리 자연수 n에서 시작하여
다음 규칙에 따라 수를 바꿔나갑니다.

n이 3의 배수이면 n = n / 3
n이 3의 배수가 아니고 짝수이면 n = n - 2
n이 3의 배수가 아니고 홀수이면 n = n * 2 + 1

이 과정을 반복하다가 n이 1 이하가 되면 종료합니다.
1 이하가 될 때까지 가장 오래 걸리는 시작 수 n (1~9 중에서) 과
그때의 변화 횟수(cnt) 를 구하세요.
```

예를 들어, n = 5라면
```text
5 → 11 → 23 → 47 → 95 → 191 → 383 → 767 → 1535 → ...
```

계속 커지기만 해서 1 이하가 되지 않는다. 3으로 나눈 나머지가 2인 홀수 x에 `2x + 1` 을 하면 나머지가 다시 2가 되므로, 5에서 출발하면 3의 배수를 영영 만나지 못한다. 그래서 이 경우는 종료되지 않는 것으로 보고 단계 수를 세지 않는다.

n = 6이면
```text
6 → 2 → 0
```

이므로 2단계 만에 종료된다(`cnt = 2`).

#### 풀이 아이디어 (시뮬레이션형 완전 탐색)
가능한 시작 수 1~9를 하나씩 가정하고, 규칙을 그대로 따라 종료될 때까지 반복한다. 각 경우의 변화 횟수(cnt)를 기록해 가장 긴 것을 찾는다. 종료되지 않는 경우가 있으므로 반복 횟수에 상한(`limit`)을 둔다.
```js
let maxCnt = 0;
let bestN = 0;

for (let i = 1; i <= 9; i++) {
  let num = i;
  let cnt = 0;
  let limit = 40; // 끝나지 않는 경우를 끊는 상한

  // num이 1보다 크면 반복
  // 종료 조건이 num <= 1일 때 반복이 멈춤
  // 1 이하가 되면 종료 상태
  while (num > 1 && limit--) {
    if (num % 3 === 0) num = num / 3;
    else if (num % 2 === 0) num = num - 2;
    else num = num * 2 + 1;
    cnt++;
  }

  if (num <= 1 && cnt > maxCnt) {
    maxCnt = cnt;
    bestN = i;
  }
}

console.log(`가장 오래 걸린 n = ${bestN}, 단계 수 = ${maxCnt}`);
// 가장 오래 걸린 n = 8, 단계 수 = 3
```

상한은 40으로 잡았다. 5와 7은 값이 매번 두 배 가까이 커져서, 상한을 100으로 두면 `Number.MAX_SAFE_INTEGER`(2^53 - 1)를 넘어 정수를 정확히 표현하지 못한다. 40번이면 가장 큰 값이 약 6.6조로 안전한 범위 안이고, 결과도 n=8, 3단계로 같다.

#### 실행 결과 해석

| n | 시뮬레이션 과정 (요약)       | 단계 수(cnt) |
|---|---------------------|-----------|
| 1 | 종료                  | 0         |
| 2 | 2 → 0               | 1         |
| 3 | 3 → 1               | 1         |
| 4 | 4 → 2 → 0           | 2         |
| 5 | 무한루프                | X         |
| 6 | 6 → 2 → 0           | 2         |
| 7 | 7 → 15 → 5 → (무한루프) | X         |
| 8 | 8 → 6 → 2 → 0       | 3         |
| 9 | 9 → 3 → 1           | 2         |

## 중첩 완전 탐색 (Nested Brute Force)
선택이 두 번 이상 이어지는 문제는 상황을 가정하기를 선택마다 겹쳐서 적용한다. 예를 들어 두 배로 만들 인덱스를 고르고, 이어서 제거할 인덱스를 고르는 문제라면 두 선택의 모든 조합을 시도한다. 이때 각 경우는 서로 독립이어야 한다. 앞 경우에서 바꾼 값이 다음 경우에 남아 있으면 안 된다.

### 일반적인 풀이 패턴
#### 원본을 바꿨다가 되돌리는 방식
아래 코드는 원본 배열을 직접 두 배로 바꾸고, 그 경우를 다 본 뒤 원래 값으로 되돌린다. 같은 인덱스를 두 배로 만들고 곧바로 제거하는 경우(i === j)도 허용하는데, 허용할지는 문제 정의에 따라 다르다.
```js
const n = 5;
let arr = [1, 5, 2, 6, 8];
let res = -Infinity;

// i: 두 배로 만들 인덱스 선택
for (let i = 0; i < n; i++) {
  // 1.현재 케이스를 위해 실제 배열을 수정
  arr[i] *= 2;

  // j: 제거할 인덱스 선택
  for (let j = 0; j < n; j++) {
    let remainingArr = [];

    // 2.j번째 원소를 제외한 새 배열 구성
    for (let k = 0; k < n; k++) {
      if (k !== j) {
        remainingArr.push(arr[k]);
      }
    }

    // 3.인접한 숫자 간 차이의 합 계산
    let sumDiff = 0;
    for (let k = 0; k < n - 2; k++) {
      sumDiff += Math.abs(remainingArr[k] - remainingArr[k + 1]);
    }

    // 4.결과값 갱신
    res = Math.max(res, sumDiff);
  }

  // 5.원본배열 복구(다음 i 케이스를 위해 원래 값으로 되돌림)
  // 이 복구가 없으면 다음 루프에서 arr[i]가 이미 두 배인 상태로 남아
  // 다른 경우의 결과까지 오염된다(부수 효과, side effect)
  arr[i] /= 2;
}

console.log(res); // 23
```

합산 반복이 `k < n - 2` 로 고정된 것은 하나를 제거하면 원소가 `n - 1` 개, 인접 쌍이 `n - 2` 개이기 때문이다. 상수에 기대면 문제가 바뀔 때 틀리기 쉬우므로 `remainingArr.length - 1` 처럼 실제 길이로 쓰는 편이 안전하다.

#### 일반 패턴
```js
for (선택1) {             // 첫 번째 경우의 수
  for (선택2) {           // 두 번째 경우의 수
    상태복사/초기화();
    변화 시뮬레이션();
    점수/결과 계산();
    최댓값/최소값 갱신();
  }
}
```

#### 문제 요약
배열 arr=[1,5,2,6,8]에서 한 원소를 골라 두 배로 만든 뒤 또 다른 원소 하나를 제외한다. 남은 4개의 인접 절댓값 차이 합을 최대화하라.

#### 핵심 선택
두 배로 만들 인덱스 d와 제외할 인덱스 r을 0부터 n-1까지 모두 고른다. 같은 원소를 두 배로 만든 뒤 바로 제외하는 경우(d와 r이 같은 경우)를 허용할지는 문제에 따른다. 아래 코드는 허용한다. 아래 코드는 배열을 복사하거나 바꾸지 않고, 값을 읽는 순간에만 두 배와 제외를 반영한다.
```js
const arr = [1, 5, 2, 6, 8];
const n = arr.length;
let best = -Infinity;

for (let d = 0; d < n; d++) {      // (1) 두 배 인덱스
  for (let r = 0; r < n; r++) {    // (2) 제외 인덱스
    let prev = null;
    let score = 0;

    for (let k = 0; k < n; k++) {
      if (k === r) continue;       // 제외
      const val = (k === d) ? arr[k] * 2 : arr[k]; // 두 배 반영
      if (prev !== null) score += Math.abs(val - prev);
      prev = val;
    }

    best = Math.max(best, score);
  }
}

console.log(best); // 23
```

인덱스 1의 5를 10으로 바꾸고 인덱스 3의 6을 빼면 `[1, 10, 2, 8]` 이 되어 9 + 8 + 6 = 23으로 가장 크다. 새 배열을 만들지 않으므로 원본이 바뀔 걱정이 없다.

복사 방식으로 하고 싶다면 `slice()` 로 복사한 뒤 수정하고, `filter()` 로 제거한다. 원본은 그대로 남는다.
```js
const arr = [1, 5, 2, 6, 8];
const n = arr.length;
let res = -Infinity;

for (let d = 0; d < n; d++) {          // 1.두 배 인덱스 선택
  for (let r = 0; r < n; r++) {        // 2.제외 인덱스 선택
    const tmp = arr.slice();           // 3.원본 복사 (매 케이스 독립)
    tmp[d] = tmp[d] * 2;               // 4.두 배 처리

    // 5.r번째 제거 (순서 유지)
    const remain = tmp.filter((_, i) => i !== r);

    // 6.인접 차이 합산
    let score = 0;
    for (let i = 0; i < remain.length - 1; i++) {
      score += Math.abs(remain[i + 1] - remain[i]);
    }

    res = Math.max(res, score);      // 7.결과 갱신
  }
}

console.log(res); // 23
```

#### 복잡도
두 선택이 각각 n가지이고 경우마다 합산에 O(n)이 들어 전체는 O(n^3)이다. n=5면 125번 정도라 충분히 작다.

## 상태를 바꿀까, 복사할까
경우마다 상태를 원본에서 직접 바꿨다가 되돌릴지(in-place), 복사본을 만들어 바꿀지 정해야 한다.

| 방식 | 설명 | 장점 | 주의 |
| --- | --- | --- | --- |
| 원본 수정 후 복구 (in-place) | 원본을 바꿨다가 되돌린다 | 메모리를 적게 쓴다 | 복구를 빠뜨리면 다음 경우가 오염된다 |
| 복사 후 수정 | `slice()`, `[...arr]` 로 복사해 바꾼다 | 경우마다 독립이라 안전하다 | 경우마다 새 배열을 만든다 |
| 읽을 때 반영 | 값을 읽는 순간에만 바꾼 값을 쓴다 | 새 배열이 없고 원본도 안전하다 | 조건이 많아지면 읽는 코드가 복잡해진다 |


<br/>

## 실수 방지 체크리스트
- 바깥 반복문은 시작 상태를 정하고, 안쪽 반복문은 규칙대로 진행한다
- 루프 변수 `i` 는 바꾸지 않는다. 시뮬레이션할 값은 복사본에 담는다
- 배열과 객체는 원본을 보호한다(복사하거나 읽을 때 반영)
- 제외한 뒤의 길이는 상수 대신 `remain.length - 1` 처럼 실제 길이로 쓴다
- d와 r이 같은 경우처럼 문제 정의가 모호한 부분은 먼저 정해 둔다
- 끝나지 않을 수 있는 시뮬레이션에는 반복 횟수에 상한을 둔다
