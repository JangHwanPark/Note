## 완전 탐색이란 ?
- 가능한 경우를 하나도 빼지 않고 모두 시도해서 정답을 찾는 풀이 방법
- 단순하지만 정답을 반드시 찾는다. 대신 경우의 수가 많아지면 시간이 급격히 늘어난다
- 모든 경우를 다 보는 사고는 이후 배울 백트래킹, 동적 프로그래밍(DP), 그리디, 이분 탐색의 밑바탕이 된다

### 완전 탐색 (Brute Force)
brute의 사전적 의미는 짐승, 무지막지한 것이고, brute force는 요령 없이 힘으로 밀어붙이는 것을 말한다.
알고리즘에서는 영리한 규칙을 찾지 않고 가능한 경우를 전부 계산해 보는 방법을 말한다. 비밀번호를 찾으려고 `0000` 부터 `9999` 까지 전부 입력해 보는 것이 완전 탐색이다.

모든 열쇠를 하나씩 꽂아 보는 것과 같다. 언젠가는 반드시 문이 열리지만, 열쇠가 많을수록 오래 걸린다. 백트래킹은 맞지 않는 열쇠 묶음을 일찍 골라내고, DP는 이미 꽂아 본 결과를 적어 두어 같은 시도를 반복하지 않는 방법이다.

<br/>

## 언제 쓸까
- 입력 크기가 작을 때. 대략 `n ≤ 10` 이면 순열, `n ≤ 20` 이면 부분집합까지 다 볼 수 있다(아래 표 참고)
- 최적해를 반드시 찾아야 하는데 더 빠른 규칙이 보이지 않을 때
- 다른 알고리즘을 쓰기 전에 정답을 확인하는 기준 풀이가 필요할 때. 느려도 정답이 확실하므로, 빠른 풀이의 결과와 비교하는 데 쓴다

<br/>

## 완전 탐색의 분류
### 어떻게 시도하는가 (접근 방법)
같은 완전 탐색이라도 경우를 만드는 방식이 다르다.

| 유형 | 경우를 만드는 방식 | 예시 |
| --- | --- | --- |
| 순열·조합형 | 가능한 모든 순서나 조합을 만든다 | 모든 순열 만들어 보기 |
| 값·구간형 | 값의 범위나 구간의 시작점과 끝점을 하나씩 정한다 | [값을 기준으로 완전 탐색](./값을%20기준으로%20완전%20탐색(Value-based)/README.md), [구간 단위로 완전 탐색](./구간%20단위로%20완전%20탐색(Range-based)/README.md) |
| 시뮬레이션형 | 시작 상태를 하나씩 가정하고 규칙대로 직접 진행해 본다 | [상황을 가정하는 완전 탐색](./상황을%20가정하는%20완전%20탐색(Simulation)/README.md) |

### 무엇을 탐색하는가 (탐색 대상)
탐색 대상에 따라 반복문의 깊이와 시간 복잡도가 달라진다.

| 종류 | 탐색 대상 | 예시 | 경우의 수 |
| --- | --- | --- | --- |
| 순열 탐색 (Permutation) | 모든 순서 | `1,2,3` → `123, 132, 213, ...` | `n!` |
| 부분집합 탐색 (Subset) | 각 원소를 넣을지 뺄지 | `{1,2}` → `{}`, `{1}`, `{2}`, `{1,2}` | `2^n` |
| 조합 탐색 (Combination) | n개 중 k개를 고르는 경우 | `5C3` | `nCk` |
| 구간 탐색 (Range) | 연속된 부분 | 연속합, 최대 구간합 | `n(n+1)/2`, 즉 `O(n^2)` |
| 격자 탐색 (Grid) | 2차원 칸 전체 | 미로 탐색, 경로 찾기 | 칸 수 `n*m` |

격자 탐색은 보통 너비 우선 탐색(BFS), 깊이 우선 탐색(DFS)으로 칸을 한 번씩 방문하므로 엄밀히는 그래프 탐색이지만, 모든 칸을 빠짐없이 본다는 점에서 함께 묶었다.

## 입력 크기로 가능한지 가늠하기
완전 탐색을 쓸지는 경우의 수가 시간 제한 안에 들어오는지로 정한다. 흔히 1초에 1억 번 안팎의 단순 연산을 기준으로 잡는데, 이는 C++ 기준의 경험칙이다. JavaScript(Node.js)는 그보다 느린 경우가 많으므로 아래 표의 경계 근처라면 여유를 두고 판단한다(정확한 배수는 확인 필요).

| 시간 복잡도 | 가능한 n의 대략적인 최대 | 예시 |
| --- | --- | --- |
| `n!` | 10 안팎 (10! = 3,628,800) | 순열 탐색 |
| `2^n` | 20 안팎 (2^20 = 1,048,576) | 부분집합 탐색 |
| `n^3` | 500 안팎 | 3중 반복문 |
| `n^2` | 5,000 안팎 | 모든 구간 탐색 |
| `n log n` | 1,000,000 안팎 | 정렬, 이진 탐색 |
| `n` | 10,000,000 이상 | 단순 반복 |

## 한계와 대안
입력이 커지면 경우의 수가 폭발하므로 다른 방법으로 넘어가야 한다.

| 방법 | 완전 탐색과 다른 점 |
| --- | --- |
| 백트래킹 | 조건을 이미 어긴 경우는 끝까지 가지 않고 일찍 버린다(가지치기, pruning) |
| 동적 프로그래밍 | 같은 작은 문제의 답을 저장해 두고 다시 계산하지 않는다. [동적 프로그래밍](../동적%20프로그래밍(Dynamic%20Programming)/README.md) 참고 |
| 그리디 | 매 단계에서 가장 좋아 보이는 선택만 한다. 그 선택이 전체 최적이라는 증명이 있는 문제에서만 정답이 보장된다 |
| 이분 탐색, 정렬 | 정렬된 성질을 이용해 탐색 범위를 절반씩 줄인다 |

<br/>

## 풀기 전에 확인할 것
완전 탐색 문제를 만나면 아래 네 가지를 먼저 정한다.

1. 탐색 공간: 어디서부터 어디까지 볼지, 그 경계를 왜 그렇게 잡았는지 문장으로 적는다
2. 조건 판별: 한 경우가 조건을 만족하는지 확인하는 부분을 `isValid(x)` 같은 함수로 떼어 내면 따로 확인하기 쉽다
3. 중복: 순열인지 조합인지, 같은 원소를 다시 써도 되는지, 방문 체크가 필요한지
4. 시간: 경우의 수에 경우 하나를 판별하는 비용을 곱해 대략의 연산 횟수를 어림한다

카드 문제에 이 네 가지를 적용한 예는 [값을 기준으로 완전 탐색](./값을%20기준으로%20완전%20탐색(Value-based)/README.md)에 있다.
