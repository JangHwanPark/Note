## 이징이란 ?
- 애니메이션이 시작에서 끝까지 가는 동안 빠르기를 어떻게 바꿀지 정하는 함수
- GSAP에서는 `ease` 설정에 `"power2.out"` 같은 이름을 넣어 고른다. 적지 않으면 `power1.out` 이 쓰인다
- 같은 1초, 같은 100px이라도 이징에 따라 미끄러지듯 서거나, 튕기거나, 목표를 살짝 지나쳤다 돌아온다

### 이징 (Easing)
ease의 사전적 의미는 편함, 완화. 동사로는 누그러뜨리다, 살살 움직이다이다.
애니메이션에서는 움직임의 처음이나 끝을 누그러뜨려 갑자기 출발하거나 서지 않게 하는 것을 말한다. 지금은 넓게 쓰여 빠르기의 변화를 정하는 함수 전체를 이징이라고 부른다.

자동차 운전과 같다. 같은 거리를 가도 출발할 때 가속 페달을 천천히 밟고 설 때 브레이크를 서서히 밟으면 부드럽게 느껴진다. 이징은 그 가속과 감속의 모양이다.

<br/>

## 어떻게 동작할까
이징 함수는 시간의 진행률(0에서 1)을 받아 값의 진행률을 돌려준다. 시간이 절반 지났을 때 `power1.out` 은 0.75를 돌려주므로, 0에서 100px로 가는 애니메이션이라면 그 순간 75px에 있다. 아무 변화 없이 일정한 속도로 가는 `"none"` 이라면 50px이다.

이름 뒤의 `.in`, `.out`, `.inOut` 은 효과가 어디에 걸리는지를 뜻한다.

| 뒤에 붙는 말 | 움직임 |
| --- | --- |
| `.in` | 천천히 출발해 끝으로 갈수록 빨라진다 |
| `.out` | 빨리 출발해 끝으로 갈수록 느려진다 |
| `.inOut` | 천천히 출발해 가운데서 빠르고 끝에서 다시 느려진다 |

화면 안에서 무언가가 멈춰 서는 움직임에는 `.out` 이 자연스럽다. 실제 물체도 멈출 때 서서히 서기 때문이다. GSAP의 기본값도 `.out` 계열인 `power1.out` 이다.

<br/>

## 이징 계열
아래 값은 `gsap.parseEase(이름)` 으로 이징 함수를 꺼내 시간 진행률 0.1, 0.3, 0.5, 0.7, 0.9를 넣어 본 결과다.

| 이징 | 0.1 | 0.3 | 0.5 | 0.7 | 0.9 | 가장 큰 값 |
| --- | --- | --- | --- | --- | --- | --- |
| `power1.out` | 0.190 | 0.510 | 0.750 | 0.910 | 0.990 | 1 |
| `power4.out` | 0.410 | 0.832 | 0.969 | 0.998 | 1.000 | 1 |
| `back.out(1.7)` | 0.409 | 0.907 | 1.087 | 1.080 | 1.014 | 1.100 |
| `back.in(1.7)` | -0.014 | -0.080 | -0.087 | 0.093 | 0.591 | 1 (가장 작은 값 -0.100) |
| `elastic.out(1, 0.3)` | 1.250 | 0.875 | 1.016 | 1.004 | 0.998 | 1.373 |
| `bounce.out` | 0.076 | 0.681 | 0.766 | 0.931 | 0.988 | 1 |

1보다 크면 목표를 지나친 것이고, 0보다 작으면 출발점 반대쪽으로 물러난 것이다.

### Power 계열
가장 많이 쓴다. 숫자가 클수록 가속과 감속이 강하다. `power4.out` 은 시간이 절반 지났을 때 이미 97% 가까이 가 있고 나머지 시간 동안 아주 천천히 다가간다.

| 이징 | 느낌 |
| --- | --- |
| `power1.out` | 빠르게 출발해 점점 느려진다. GSAP 기본값 |
| `power2.out` | `power1` 보다 감속이 조금 강하다 |
| `power3.out` | 감속이 더 강하다 |
| `power4.out` | 처음에 거의 다 가고 끝에서 아주 천천히 멈춘다 |

`power1.in`, `power1.inOut` 처럼 다른 방향도 같은 규칙으로 쓴다.

### Back 계열
`back.out` 은 목표를 살짝 지나쳤다가 돌아와 멈춘다. 위 표에서 `back.out(1.7)` 은 중간에 1.087까지 올라가 목표를 넘는다. 반대로 `back.in` 은 출발하자마자 반대쪽으로 살짝 물러났다가 앞으로 나간다. 1000등분해 찾아보니 가장 많이 물러나는 곳은 시간 진행률 0.42 무렵의 약 -0.100이었다. 괄호 안 숫자는 지나치는 정도로, 클수록 많이 넘어간다.

### Elastic 계열
고무줄처럼 목표 근처에서 여러 번 흔들리다 멈춘다. `elastic.out(1, 0.3)` 은 시작하자마자 목표를 크게 지나치고(가장 큰 값 1.373) 흔들림이 점점 줄어든다. 첫 숫자는 흔들림의 크기, 둘째 숫자는 흔들리는 주기다.

### Bounce 계열
공이 바닥에 튕기듯 목표에 몇 번 부딪혔다 멈춘다. Back, Elastic과 달리 목표를 넘지 않는다(가장 큰 값 1). `bounce.out` 은 끝에서 튕기고, `bounce.in` 은 처음에 튕기다가 출발한다.

<br/>

## 언제 무엇을 쓸까
| 하려는 것 | 이징 |
| --- | --- |
| 기본적인 부드러운 감속 | `power1.out`, `power2.out` |
| 강한 감속 (빠르게 나타나 천천히 자리 잡기) | `power3.out`, `power4.out` |
| 튀어나오는 느낌 (버튼, 팝업) | `back.out(1.7)` |
| 스프링처럼 흔들리기 | `elastic.out(1, 0.3)` |
| 떨어진 공이 튕기기 | `bounce.out` |
| 스크롤 진행률과 그대로 맞추기 | `"none"` |

스크롤에 직접 묶는 애니메이션(ScrollTrigger의 `scrub`)은 스크롤 자체가 빠르기를 정하므로 `"none"` 을 쓰는 경우가 많다.

<br/>

## 예시
```js
// 빠르게 출발해 점점 느려진다
gsap.to(".box", { x: 300, duration: 2, ease: "power1.out" });

// 바닥에 떨어진 공처럼 튕긴다
gsap.to(".ball", { y: 300, duration: 2, ease: "bounce.out" });

// 목표에서 스프링처럼 흔들린다
gsap.to(".box", { x: 300, duration: 2, ease: "elastic.out(1, 0.3)" });

// 목표를 살짝 지나쳤다가 돌아와 멈춘다
gsap.to(".box", { x: 300, duration: 2, ease: "back.out(1.7)" });
```

<br/>

## 확인한 환경
- gsap 3.15.0, Node.js v22.13.0. 표의 숫자는 `gsap.parseEase()` 로 꺼낸 함수에 값을 넣어 소수 셋째 자리까지 적었고, 가장 큰 값은 0부터 1까지 1000등분해 찾았다
- 기본 이징이 `power1.out` 인 것은 `gsap.defaults().ease(0.5)` 가 `power1.out` 과 같은 0.75를 돌려주는 것으로 확인했다
- 화면에서 보이는 움직임은 브라우저로 확인하지 않았다
- `elastic` 두 숫자의 이름(크기, 주기)은 GSAP 문서의 설명을 옮긴 것이고, 값에 따른 변화는 실행해 비교하지 않았다
